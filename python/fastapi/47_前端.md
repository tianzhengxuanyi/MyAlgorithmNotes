# 47 · 前端（Frontend）

> 官方文档：<https://fastapi.tiangolo.com/zh/tutorial/frontend/>
> 前置依赖：静态文件、`APIRouter`、Depends、Middleware · 难度：⭐⭐

## 一、章节笔记

### 1. 本章要解决什么问题

用 `app.frontend()`（或 `router.frontend()`）在同一个 FastAPI 应用中提供**静态前端应用**。适合生成静态文件的前端工具：Vite + React、TanStack Router、Astro、Vue、Svelte、Angular、Solid 等。这类工具通常执行 `npm run build` 生成 `./dist/` 目录。

**优先级规则**：FastAPI 先检查路径操作，只有没有普通路由匹配时才检查前端文件，因此你的 API 不受影响。

### 2. 基本用法

项目结构：

```text
.
├── pyproject.toml
├── app
│   ├── __init__.py
│   └── main.py
└── dist
    ├── index.html
    └── assets
        └── app.js
```

```python
from fastapi import FastAPI

app = FastAPI()

app.frontend("/", directory="dist")
```

这样 `/assets/app.js` 会提供 `dist/assets/app.js`。若同时定义了 FastAPI 路径操作，**路径操作优先**。

### 3. 客户端路由与 Fallback

SPA 中 `/dashboard/settings` 往往不是真实文件，直接访问该 URL 时后端应返回 `index.html`，让前端框架接管路由：

```python
app.frontend("/", directory="dist", fallback="index.html")
```

Fallback 的触发条件很严格：

| 条件 | 是否满足 |
|---|---|
| 方法为 `GET`/`HEAD` | ✅ |
| Accept 头明确为 `text/html` 或 `application/xhtml+xml` | ✅（浏览器导航请求通常如此） |
| 缺失的 JS/CSS/图片等文件 | ❌ 仍返回 404 |
| `POST`/`PUT` 等只匹配 fallback 的请求 | ❌ 返回 404 |
| 常规 FastAPI 路径操作 | ✅ 优先级高于前端 |

### 4. 自定义 404 页面

```python
app.frontend("/", directory="dist", fallback="404.html")
```

缺失的前端路径返回 `404.html`，**状态码保持 404**。适合为每个页面生成静态 HTML 的工具（如 Astro）。

### 5. 自动 Fallback（默认）

默认 `fallback="auto"`：

- 若前端目录中有 `404.html` → 缺失路径以状态码 404 返回该文件；
- 否则若有 `index.html` → 缺失的浏览器导航路径返回它（SPA 客户端路由所需）。

因此大多数情况下**无需指定 fallback**：

```python
app.frontend("/", directory="dist")
```

显式禁用：`fallback=None`，缺失路径返回普通 404。

### 6. 检查目录 `check_dir`

默认 `check_dir="auto"`：

| 环境 | 行为 |
|---|---|
| `FASTAPI_ENV=development`（`fastapi dev` 会自动设置） | 目录缺失只警告，方便先启动后端再构建前端 |
| 其他环境 | 创建应用时抛错，尽早发现部署配置错误 |

- `check_dir=True`：始终在创建应用时检查。
- `check_dir=False`：不在创建时检查，请求时目录仍缺失才抛错。适合前端文件由后续构建步骤生成的情况：

```python
app.frontend("/", directory="dist", check_dir=False)
```

### 7. 与 `APIRouter` 一起使用

```python
from fastapi import APIRouter, FastAPI

app = FastAPI()
router = APIRouter()

router.frontend("/", directory="dist", fallback="index.html")
app.include_router(router, prefix="/app")
```

前端文件在 `/app` 下提供；应用中任何常规路径操作（包括其他 router 的）仍优先。

### 8. 依赖项和中间件

- 前端响应运行在普通 FastAPI 应用内部，**HTTP 中间件会作用于它们**。
- 来自 app、`APIRouter`、`include_router()` 的**依赖项也会应用**，可用于用 cookie 认证保护前端。
- 依赖项同样可以修改响应标头、添加后台任务。

### 9. 局限

`app.frontend()` 只提供**已构建好的静态文件**，不运行服务端渲染（SSR）。适用于生成静态文件的框架，不适用于需要服务端逐请求动态渲染的框架。

### 10. 易错点

| 易错点 | 正确做法 |
|---|---|
| 用 `StaticFiles` 托管 SPA 却不知道客户端路由 | 用 `app.frontend()`，它处理 fallback |
| 以为 fallback 对所有请求生效 | 只对 `GET`/`HEAD` 且 Accept 为 HTML 的浏览器导航生效；缺失静态资源仍 404 |
| 部署时前端目录还没构建导致启动报错 | 开发用 `fastapi dev`（自动 development 模式仅警告），或 `check_dir=False` |
| 以为前端路由会覆盖 API | 常规路径操作始终优先 |
| 想用它做 SSR | 不支持，只服务静态构建产物 |

## 二、NestJS 对比

| 维度 | FastAPI（Python） | NestJS（TypeScript） |
|---|---|---|
| 静态前端托管 | `app.frontend("/", directory="dist")`，框架内置 | `ServeStaticModule.forRoot({ rootPath })`（`@nestjs/serve-static`）或 `Fastify` 静态插件 |
| SPA fallback | 内置 `fallback="auto"/"index.html"/"404.html"/None`，按 Accept 头精确触发 | 需 `serveRoot` + 通配路由 `@Get('*')` 手动返回 `index.html` |
| 优先级 | 常规路径操作自动优先于前端文件 | 需自己安排通配路由顺序（通配放最后） |
| 目录检查 | `check_dir="auto"/True/False`，按 `FASTAPI_ENV` 决定警告或报错 | 无内置检查，需自行验证路径 |
| 中间件/守卫 | 中间件与 Depends 自动作用于前端响应 | Middleware/Guard 可作用于静态路由，需按路径匹配配置 |
| 挂载到子路径 | `router.frontend(...)` + `include_router(prefix="/app")` | `ServeStaticModule.forRoot({ serveRoot: '/app' })` |
| SSR 支持 | 不支持，仅静态构建产物 | 通常也不由此模块提供，SSR 用 Next.js 等独立框架 |

**核心差异一句话**：FastAPI 的 `app.frontend()` 把 SPA 托管里最麻烦的客户端路由 fallback、Accept 头判定、404 语义与目录检查都内置并在 API 路由之后兜底；NestJS 需装 `ServeStaticModule` 并手写通配路由来处理 SPA fallback，还要自己注意路由顺序。

## 三、针对性练习题

### 题 1（基础）
`app.frontend()` 适合什么场景？它能否运行 SSR？路径操作与前端文件的优先级如何？

<details>
<summary>参考答案</summary>

适合由前端工具（Vite/React/Astro/Vue/Svelte 等）`npm run build` 生成的静态文件目录（如 `dist/`）。它**不运行服务端渲染**，只提供已构建好的静态文件。优先级：FastAPI 先匹配常规路径操作，只有没有路由匹配时才检查前端文件，因此 API 不受影响。
</details>

### 题 2（理解）
为什么 SPA 需要 `fallback="index.html"`？Fallback 对哪些请求生效，对哪些不生效？

<details>
<summary>参考答案</summary>

SPA 的 `/dashboard/settings` 之类路径不是真实文件，直接访问时后端需返回 `index.html`，让前端框架处理客户端路由。Fallback 只对 `GET`/`HEAD` 且明确接受 HTML（`Accept: text/html` 或 `application/xhtml+xml`）的浏览器导航请求生效；缺失的 JS/CSS/图片仍返回 404；`POST`/`PUT` 等只匹配 fallback 的请求也返回 404；常规 FastAPI 路径操作优先级更高。
</details>

### 题 3（辨析/代码）
默认情况下需要手动写 `fallback="index.html"` 吗？说明 `fallback="auto"` 的行为，以及如何彻底禁用 fallback、如何自定义 404 页面。

<details>
<summary>参考答案</summary>

不需要，默认就是 `fallback="auto"`：若目录中有 `404.html`，缺失路径以 404 状态返回它；否则若有 `index.html`，缺失的浏览器导航路径返回它。因此通常写 `app.frontend("/", directory="dist")` 即可。禁用用 `fallback=None`；自定义 404 用 `fallback="404.html"`（保持 404 状态码）。
</details>

### 题 4（进阶 · NestJS 迁移视角）
在 NestJS 中用 `ServeStaticModule` 托管 `dist/` 并放在 `/app` 下。写出功能等价的 FastAPI 代码，并说明如何让常规 API 路由优先、如何用依赖保护前端。

<details>
<summary>参考答案</summary>

```python
from fastapi import APIRouter, Depends, FastAPI

app = FastAPI()

async def require_cookie_auth():
    # 在这里校验 cookie，失败抛 HTTPException
    pass

router = APIRouter(dependencies=[Depends(require_cookie_auth)])
router.frontend("/", directory="dist", fallback="index.html")
app.include_router(router, prefix="/app")
```

FastAPI 天然让常规路径操作（包括其他 router 的）优先于前端文件；来自 app、`APIRouter` 和 `include_router()` 的依赖项都作用于前端响应，也能改响应头、加后台任务；HTTP 中间件同样生效。NestJS 则需保证通配路由注册在 API 路由之后，依赖保护要按静态路径配置 Guard/Middleware。
</details>

### 题 5（思考）
为什么 `check_dir` 默认在 `development` 环境下只警告而不报错？生产环境为何要报错？

<details>
<summary>参考答案</summary>

开发时常见流程是先启动后端再构建前端（或前端 dev server 单独运行），此时 `dist/` 可能还不存在；`fastapi dev` 会自动设置 `FASTAPI_ENV=development`，仅警告让开发者能先起服务，不阻断迭代。生产环境若目录缺失说明部署配置有误，创建应用时立即报错能在部署前尽早暴露问题，避免上线后所有前端请求 404。
</details>
