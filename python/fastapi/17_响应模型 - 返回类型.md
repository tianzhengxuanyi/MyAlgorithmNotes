# 17 · 响应模型 - 返回类型（Response Model - Return Type）

> 官方文档：<https://fastapi.tiangolo.com/zh/tutorial/response-model/>
> 前置依赖：Pydantic 模型基础 · 难度：⭐⭐

## 一、章节笔记

### 1. 本章要解决什么问题

响应的**结构**也应该像请求一样被声明和约束。通过给路径操作函数的**返回类型**加注解，或用装饰器的 **`response_model`** 参数，可以让 FastAPI 自动完成：校验返回数据、写入 OpenAPI/文档、序列化，以及最重要的 —— **过滤掉不该返回的字段**（如密码）。

### 2. 用返回类型注解声明响应

```python
from fastapi import FastAPI
from pydantic import BaseModel

app = FastAPI()

class Item(BaseModel):
    name: str
    description: str | None = None
    price: float
    tax: float | None = None
    tags: list[str] = []

@app.post("/items/")
async def create_item(item: Item) -> Item:
    return item

@app.get("/items/")
async def read_items() -> list[Item]:
    return [
        Item(name="Portal Gun", price=42.0),
        Item(name="Plumbus", price=32.0),
    ]
```

返回类型可以是 Pydantic 模型、`list`、`dict`、标量（int/bool 等）。FastAPI 据此：

| 作用 | 说明 |
|---|---|
| 校验返回数据 | 数据无效（缺字段等）说明是**应用代码**出错，返回服务器错误，而不是发出错误数据 |
| JSON Schema | 在 OpenAPI 中为响应添加 JSON Schema |
| 自动文档 | `/docs`、`/redoc` 直接使用该模型 |
| 客户端代码生成 | 第三方工具据模式生成客户端 |
| 序列化 | 用 Pydantic 转 JSON（基于 Rust，性能高） |
| **输出过滤** | 只保留返回类型中声明的字段，对安全至关重要 |

### 3. `response_model` 参数

当想返回字典或数据库对象、却希望按 Pydantic 模型来文档化/校验/过滤时，用装饰器参数 `response_model`：

```python
from typing import Any

from fastapi import FastAPI
from pydantic import BaseModel

app = FastAPI()

class Item(BaseModel):
    name: str
    description: str | None = None
    price: float
    tax: float | None = None
    tags: list[str] = []

@app.post("/items/", response_model=Item)
async def create_item(item: Item) -> Any:
    return item

@app.get("/items/", response_model=list[Item])
async def read_items() -> Any:
    return [
        {"name": "Portal Gun", "price": 42.0},
        {"name": "Plumbus", "price": 32.0},
    ]
```

要点：

- `response_model` 是 **装饰器方法**（`get`/`post`/`put`/`delete` 等）的参数，**不是**路径操作函数的参数。
- 接受的类型与 Pydantic 字段注解相同：单个模型、由模型组成的 `list` 等。
- 严格类型检查时，把函数返回类型标为 `Any`，既安抚编辑器/mypy，又让 FastAPI 继续用 `response_model` 工作。
- **优先级**：同时写返回类型和 `response_model` 时，`response_model` 优先。
- `response_model=None` 可**禁用**响应模型的生成。

### 4. 安全：不要让输入模型直接成为输出模型

```python
from fastapi import FastAPI
from pydantic import BaseModel, EmailStr

app = FastAPI()

class UserIn(BaseModel):
    username: str
    password: str
    email: EmailStr
    full_name: str | None = None

# 不要在生产环境这样做！
@app.post("/user/")
async def create_user(user: UserIn) -> UserIn:
    return user
```

这样响应会把明文密码原样发回客户端。发送者是自己时看似无碍，但同一模型若用于其它路径操作，就可能把密码泄露给每个客户端。

> ⚠️ 除非清楚所有注意事项，否则**永远不要存储明文密码，也不要在响应中发送它**。使用 `EmailStr` 需先安装 `email-validator`（`uv add email-validator` 或 `uv add "pydantic[email]"`）。

正确做法 —— 定义不含密码的输出模型：

```python
from typing import Any

from fastapi import FastAPI
from pydantic import BaseModel, EmailStr

app = FastAPI()

class UserIn(BaseModel):
    username: str
    password: str
    email: EmailStr
    full_name: str | None = None

class UserOut(BaseModel):
    username: str
    email: EmailStr
    full_name: str | None = None

@app.post("/user/", response_model=UserOut)
async def create_user(user: UserIn) -> Any:
    return user
```

即便函数返回的是含密码的 `UserIn` 实例，FastAPI 仍按 `UserOut` **过滤掉未声明的数据**，响应中不会出现密码。

### 5. 用继承兼得「类型检查」与「数据过滤」

上例中两个模型是不同类，若把返回类型标为 `UserOut`，编辑器会认为「返回 `UserIn` 类型错误」。更优雅的方案是用继承：

```python
from fastapi import FastAPI
from pydantic import BaseModel, EmailStr

app = FastAPI()

class BaseUser(BaseModel):
    username: str
    email: EmailStr
    full_name: str | None = None

class UserIn(BaseUser):
    password: str

@app.post("/user/")
async def create_user(user: UserIn) -> BaseUser:
    return user
```

- **工具链视角**：`UserIn` 是 `BaseUser` 的子类，返回 `UserIn` 时声明 `-> BaseUser` 完全合法，编辑器/mypy 满意。
- **FastAPI 视角**：按返回类型 `BaseUser` 过滤数据，不会因继承关系多返回字段，密码被过滤。
- 两全其美：类型注解支持 + 数据过滤。

### 6. 其它返回类型注解

| 场景 | 写法 | 结果 |
|---|---|---|
| 直接返回 Response | `-> Response` | FastAPI 自动处理，跳过响应模型 |
| 返回 Response 子类 | `-> RedirectResponse` | 同上，子类也合法 |
| 无效注解 | `-> Response \| dict` | 💥 失败：既不是有效 Pydantic 类型，也不是单一 Response 类/子类 |
| 禁用响应模型 | `@app.get(..., response_model=None)` | 保留注解供 mypy，但 FastAPI 跳过生成 |

```python
from fastapi import FastAPI, Response
from fastapi.responses import JSONResponse, RedirectResponse

app = FastAPI()

@app.get("/portal")
async def get_portal(teleport: bool = False) -> Response:
    if teleport:
        return RedirectResponse(url="https://www.youtube.com/watch?v=dQw4w9WgXcQ")
    return JSONResponse(content={"message": "Here's your interdimensional portal."})

# 联合类型 + 禁用响应模型
@app.get("/portal2", response_model=None)
async def get_portal2(teleport: bool = False) -> Response | dict:
    if teleport:
        return RedirectResponse(url="https://www.youtube.com/watch?v=dQw4w9WgXcQ")
    return {"message": "Here's your interdimensional portal."}
```

### 7. 响应模型的编码参数

```python
from fastapi import FastAPI
from pydantic import BaseModel

app = FastAPI()

class Item(BaseModel):
    name: str
    description: str | None = None
    price: float
    tax: float = 10.5
    tags: list[str] = []

items = {
    "foo": {"name": "Foo", "price": 50.2},
    "bar": {"name": "Bar", "description": "The bartenders", "price": 62, "tax": 20.2},
    "baz": {"name": "Baz", "description": None, "price": 50.2, "tax": 10.5, "tags": []},
}

@app.get("/items/{item_id}", response_model=Item, response_model_exclude_unset=True)
async def read_item(item_id: str):
    return items[item_id]
```

| 参数 | 作用 |
|---|---|
| `response_model_exclude_unset=True` | 只返回**显式设置**过的字段，未设置的默认值（如 `tax=10.5`、`tags=[]`）不出现在响应里。请求 `foo` 时响应为 `{"name": "Foo", "price": 50.2}` |
| `response_model_exclude_defaults=True` | 排除值与默认值相同的字段 |
| `response_model_exclude_none=True` | 排除值为 `None` 的字段 |
| `response_model_include={"name", "description"}` | 只包含这些字段（用 `set`；误写 `list`/`tuple` 也会被转成 `set`） |
| `response_model_exclude={"tax"}` | 排除这些字段 |
| `response_model_by_alias` | 控制是否用字段别名输出 |

细节：

- `bar` 的 `tax=20.2` 是显式数据 → 会输出；`baz` 的 `description=None`、`tax=10.5`、`tags=[]` 虽然等于默认值，但**是显式设置的** → 也会输出。Pydantic 能区分「显式设置」与「取自默认值」。
- ⚠️ 用 `include`/`exclude` 只是运行时过滤，OpenAPI 中生成的仍是**完整模型**的 Schema；更推荐使用多个模型类。

### 8. 易错点

- ✅ `response_model` / `status_code` 这类是**装饰器参数**，别写进函数签名。
- ✅ 返回模型必须能表达实际返回内容，否则校验失败会变成 500（这是应用 bug 的信号）。
- ✅ 想隐藏敏感字段，优先用「输出模型 + 继承」，而不是 `include`/`exclude`（后者文档仍暴露完整结构）。
- ✅ `-> Response | dict` 这种联合注解必须配合 `response_model=None`，否则 FastAPI 尝试建响应模型会失败。

## 二、NestJS 对比

| 维度 | FastAPI（Python） | NestJS（TypeScript） |
|---|---|---|
| 响应结构声明 | 函数返回类型注解 `-> Item` 或装饰器参数 `response_model=Item` | 无强制返回类型推断；返回 DTO/实体由开发者决定，Swagger 需 `@ApiResponse({ type: ... })` |
| 输出过滤 | 响应模型自动过滤未声明字段（密码等） | `@UseInterceptors(ClassSerializerInterceptor)` + DTO 上的 `@Exclude()` / `class-transformer` 才过滤 |
| 输入/输出模型分离 | `UserIn` / `UserOut` 两个 Pydantic 模型，`response_model=UserOut` | `CreateUserDto` / `UserResponseDto` 两个类，handler 手动 `plainToInstance(UserResponseDto, ...)` |
| 继承减少重复 | `UserBase` 基类 + `UserIn(UserBase)`，返回类型标 `-> BaseUser` 仍可过滤 | DTO 继承 + `PartialType`/`PickType`/`OmitType`（`@nestjs/mapped-types`） |
| 排除默认值 | `response_model_exclude_unset/exclude_defaults/exclude_none` | ClassSerializerInterceptor 的 `excludeExtraneousValues` / `@Expose()` 策略 |
| 字段包含/排除 | `response_model_include/exclude` 传 `set`（但 OpenAPI 仍完整） | `@Exclude()` 装饰器或序列化组 `groups`，需 Swagger 额外标注 |
| 直接返回原始响应 | `-> Response` / `RedirectResponse`，FastAPI 自动识别 | `@Res()` 注入 Express `Response`（注意失去框架封装），或 `@Redirect()` |
| 校验时机 | 返回数据不符合响应模型 → 500（服务端错误） | 默认不校验返回值；需自定义 Interceptor/Pipe 或启用严格序列化 |
| 自动生成文档 | OpenAPI 自动含响应 Schema | 需 `@nestjs/swagger` + `@ApiOkResponse()` + DTO 的 `@ApiProperty()` |

**核心差异一句话**：FastAPI 把响应模型当成与请求模型对称的一等公民 —— 一个返回类型注解就同时驱动校验、序列化、字段过滤和 OpenAPI 文档，密码等敏感字段的过滤是默认行为；NestJS 默认「返回什么就发什么」，要获得同等过滤能力必须显式启用 `ClassSerializerInterceptor` 并用 `@Exclude()`/`@Expose()` 装饰 DTO，文档也需 `@nestjs/swagger` 单独接线。

## 三、针对性练习题

### 题 1（基础）

写一个 `POST /items/` 端点：请求体用 `Item` 模型（含 `name: str`、`price: float`），并通过**返回类型注解**声明响应也是 `Item`。说明 FastAPI 据此做了哪两件最重要的事。

<details>
<summary>参考答案</summary>

```python
from fastapi import FastAPI
from pydantic import BaseModel

app = FastAPI()

class Item(BaseModel):
    name: str
    price: float

@app.post("/items/")
async def create_item(item: Item) -> Item:
    return item
```

最重要的两件事：① 校验返回数据，数据不合法时返回服务器错误而非错误数据；② 用 Pydantic 序列化为 JSON，并把响应 Schema 写入 OpenAPI/文档。若返回的是 `dict` 或数据库对象，应改用 `response_model=Item`。
</details>

### 题 2（理解）

`UserIn` 含 `password`，`UserOut` 不含。若端点写成 `async def create_user(user: UserIn) -> UserIn`，有什么安全隐患？如何用 `response_model` 修复？

<details>
<summary>参考答案</summary>

直接用 `-> UserIn` 会把明文密码原样返回给客户端；若同一模型用于其它路径操作，密码可能泄露给所有客户端。

修复：定义不含密码的 `UserOut`，并声明 `response_model=UserOut`：

```python
from typing import Any
from fastapi import FastAPI
from pydantic import BaseModel, EmailStr

app = FastAPI()

class UserIn(BaseModel):
    username: str
    password: str
    email: EmailStr

class UserOut(BaseModel):
    username: str
    email: EmailStr

@app.post("/user/", response_model=UserOut)
async def create_user(user: UserIn) -> Any:
    return user
```

FastAPI 即使收到含密码的 `UserIn`，也会按 `UserOut` 过滤掉 `password`。
</details>

### 题 3（辨析/代码）

下面两种写法都能隐藏密码。请说明为什么第二种能让编辑器/mypy 也满意。

```python
# A
@app.post("/user/", response_model=UserOut)
async def create_user(user: UserIn) -> Any:
    return user

# B
@app.post("/user/")
async def create_user(user: UserIn) -> BaseUser:  # UserIn 继承 BaseUser
    return user
```

<details>
<summary>参考答案</summary>

A 中函数实际返回 `UserIn`，却声明 `-> Any`（或 `UserOut`），类型检查器无法确认正确性，只能靠 `Any` 绕过。

B 中 `UserIn` 继承自 `BaseUser`，按类型系统「子类可替代父类」，返回 `UserIn` 时声明 `-> BaseUser` 是合法的，编辑器/mypy 都能通过；同时 FastAPI 按 `BaseUser` 过滤数据，不会因继承关系泄露 `password`。因此 B 兼顾了工具链支持与数据过滤。
</details>

### 题 4（进阶 · NestJS 迁移视角）

NestJS 中你这样写：

```ts
@Post('user')
@UseInterceptors(ClassSerializerInterceptor)
createUser(@Body() dto: CreateUserDto): UserResponseDto {
  return this.service.create(dto); // 内部返回含 password 的实体
}
```

请写出等价的 FastAPI 写法（要求：密码不出现在响应中），并说明「过滤」机制的差异。

<details>
<summary>参考答案</summary>

```python
from fastapi import FastAPI
from pydantic import BaseModel, EmailStr

app = FastAPI()

class BaseUser(BaseModel):
    username: str
    email: EmailStr

class UserIn(BaseUser):
    password: str

@app.post("/user/")
async def create_user(user: UserIn) -> BaseUser:
    return user
```

差异：FastAPI 的过滤由响应模型/返回类型**自动完成**，无需拦截器；NestJS 需显式启用 `ClassSerializerInterceptor`，并用 DTO 上的 `@Exclude()` / `@Expose()` 控制字段，否则实体字段会原样序列化出去。此外 FastAPI 的响应 Schema 自动进 OpenAPI，NestJS 还需 `@ApiResponse({ type: UserResponseDto })`。
</details>

### 题 5（思考）

`response_model_exclude_unset=True` 时，模型字段 `tax: float = 10.5`，数据里显式写了 `tax: 10.5`（与默认值相同）。响应中会包含 `tax` 吗？为什么？再说明 `include`/`exclude` 参数与「多模型」方案相比的缺点。

<details>
<summary>参考答案</summary>

会包含。Pydantic 能区分「显式设置的值」与「取自默认值」：只要数据中显式给了 `tax`（哪怕值等于默认值 10.5），就算「已设置」，会被输出；只有完全未设置的字段才被 `exclude_unset` 省略。

`include`/`exclude` 的缺点：① 它们是运行时过滤，OpenAPI 生成的仍是完整模型 Schema，文档会暴露本来想隐藏的字段；② 过滤规则散落在各个装饰器参数里，不如多模型方案（基类 + 专用输出模型）集中、可复用且类型安全。因此官方更推荐用多个类来表达不同「视图」。
</details>
