## 一、章节笔记

### 1. 用 Pydantic `Field` 为模型属性声明校验与元数据

正如在函数参数中用 `Query`、`Path`、`Body` 声明校验与元数据，模型**内部属性**用 Pydantic 的 `Field` 做同样的事。

⚠️ **注意导入来源**：`Field` 要从 **`pydantic`** 导入，而不是从 `fastapi`（与 `Query`/`Path`/`Body` 不同）。

```python
from typing import Annotated
from fastapi import Body, FastAPI
from pydantic import BaseModel, Field

app = FastAPI()

class Item(BaseModel):
    name: str
    description: str | None = Field(
        default=None, title="The description of the item", max_length=300
    )
    price: float = Field(gt=0, description="The price must be greater than zero")
    tax: float | None = None

@app.put("/items/{item_id}")
async def update_item(item_id: int, item: Annotated[Item, Body(embed=True)]):
    results = {"item_id": item_id, "item": item}
    return results
```

旧式写法：`item: Item = Body(embed=True)`。

### 2. `Field` 与 `Query`/`Path`/`Body` 的关系

`Field` 的工作方式与 `Query`、`Path`、`Body` **完全相同，参数也相同**（`default`、`title`、`description`、`max_length`、`gt` 等）。模型属性的"类型 + 默认值 + `Field`"结构，与路径操作函数参数的结构一一对应，只是用 `Field` 替换了 `Path`/`Query`/`Body`：

| 位置 | 声明方式 |
|---|---|
| 函数参数（路径） | `item_id: Annotated[int, Path(ge=1)]` |
| 函数参数（查询） | `q: Annotated[str, Query(max_length=50)] = None` |
| 函数参数（请求体） | `importance: Annotated[int, Body(gt=0)]` |
| 模型属性 | `price: float = Field(gt=0, description="...")` |

### 3. 底层技术细节

- `Query`、`Path` 等会创建公共 `Param` 类的子类对象，而 `Param` 本身是 Pydantic `FieldInfo` 的子类。
- Pydantic 的 `Field` 返回 `FieldInfo` 的实例；`Body` 直接返回 `FieldInfo` 子类的对象（后续章节还会看到更多 `Body` 的子类）。
- 从 `fastapi` 导入的 `Query`、`Path` 等实际上是**函数**，调用时返回特殊类的实例（目的是避免编辑器误报类型错误）。

这条继承链解释了为什么这些对象能共享同一批校验与元数据参数。

### 4. 添加更多信息：`json_schema_extra`

可在 `Field`、`Query`、`Body` 等对象里用 `json_schema_extra` 声明额外信息，这些信息会被集成进生成的 JSON Schema：

```python
class Item(BaseModel):
    name: str = Field(json_schema_extra={"examples": ["Foo", "Bar"]})
```

后续"声明请求示例数据"一章会详细介绍。

⚠️ **警告**：传进 `json_schema_extra` 的额外键也会出现在应用生成的 OpenAPI 架构中。由于这些键**不一定属于 OpenAPI 规范**，某些 OpenAPI 工具（例如 OpenAPI 验证器）可能无法处理你生成的架构，使用时需权衡。

### 5. 易错点小结

- ✅ `Field` 从 `pydantic` 导入，`Query`/`Path`/`Body` 从 `fastapi` 导入。
- ✅ `Field` 与 `Query`/`Path`/`Body` 参数相同，可写 `gt`、`max_length`、`title`、`description` 等。
- ✅ 模型属性有默认值（或 `Field(default=...)`）即为可选，否则必选。
- ✅ `json_schema_extra` 的自定义键可能不被 OpenAPI 工具兼容。

## 二、NestJS 对比

| 维度 | FastAPI（Python） | NestJS（TypeScript） |
|---|---|---|
| 模型属性校验位置 | Pydantic 模型内用 `Field(gt=0, max_length=300)` | DTO 类属性上用 `class-validator` 装饰器 `@Min(0)` `@MaxLength(300)` |
| 元数据/文档 | `Field(title=..., description=...)` 自动进 JSON Schema | `@ApiProperty({ description: ..., maximum: ... })`（`@nestjs/swagger`） |
| 导入来源 | `Field` 来自 `pydantic`；`Query`/`Path`/`Body` 来自 `fastapi` | 校验装饰器来自 `class-validator`，文档装饰器来自 `@nestjs/swagger` |
| 默认值 / 可选 | `Field(default=None, ...)` 或 `x: T | None = None` | `@IsOptional()` + 属性初始化 |
| 底层数据结构 | `Field` → `FieldInfo`；`Param` 继承 `FieldInfo` | 装饰器写入类的元数据，由 `ValidationPipe` 读取执行 |
| 额外 JSON Schema 键 | `json_schema_extra={...}` | `@ApiProperty({ example: ... })` 等固定字段，任意键较受限 |
| 校验错误 | Pydantic 统一 `422` + `loc:["body","item","price"]` | `ValidationPipe` 抛 `BadRequestException`（400） |

**核心差异一句话**：FastAPI 把函数参数与模型属性统一到同一套 `FieldInfo` 机制上（`Query`/`Path`/`Body`/`Field` 共享参数），模型内用 `Field` 一处声明校验与文档；NestJS 的模型校验靠 `class-validator` 装饰器元数据、文档靠 `@ApiProperty()`，两套装饰器各管一摊且都需要 `ValidationPipe` 介入。

## 三、针对性练习题

### 题 1（基础）

定义 `Item` 模型：`name: str`；`price: float` 要求 > 0 并带描述；`description` 可选、最长 300。用 `Field` 实现。

<details>
<summary>参考答案</summary>

```python
from fastapi import FastAPI
from pydantic import BaseModel, Field

class Item(BaseModel):
    name: str
    description: str | None = Field(
        default=None, title="The description of the item", max_length=300
    )
    price: float = Field(gt=0, description="The price must be greater than zero")
```

`Field` 从 `pydantic` 导入；`gt=0` 与 `max_length=300` 分别校验数值与字符串长度。
</details>

### 题 2（理解）

为什么 `Field` 能使用与 `Query`、`Path`、`Body` 相同的参数（如 `gt`、`description`）？请用继承关系说明。

<details>
<summary>参考答案</summary>

因为底层同属一条继承链：`Query`/`Path` 等创建公共 `Param` 类的子类对象，而 `Param` 是 Pydantic `FieldInfo` 的子类；Pydantic 的 `Field` 返回 `FieldInfo` 实例，`Body` 返回 `FieldInfo` 子类的对象。它们共享 `FieldInfo` 定义的校验与元数据参数，因此 `gt`、`description` 等参数在各处都可用。
</details>

### 题 3（辨析/代码）

下面导入哪个是正确的？说明另一个为什么错。

```python
A: from fastapi import Field
B: from pydantic import Field
```

<details>
<summary>参考答案</summary>

B 正确。`Field` 是 Pydantic 提供的，用于模型属性声明；`fastapi` 提供的是 `Query`、`Path`、`Body` 等（它们本身是返回 `FieldInfo` 子类实例的函数）。`from fastapi import Field` 会导入失败（除非某版本兼容导出，规范上应从 `pydantic` 导入）。
</details>

### 题 4（进阶 · NestJS 迁移视角）

NestJS DTO 中这样校验价格：

```ts
class ItemDto {
  @Min(0.01)
  @ApiProperty({ description: 'The price must be greater than zero' })
  price: number;
}
```

请写出等价的 FastAPI 模型声明，并说明两者校验与文档元数据的组织方式差异。

<details>
<summary>参考答案</summary>

```python
from pydantic import BaseModel, Field

class Item(BaseModel):
    price: float = Field(gt=0, description="The price must be greater than zero")
```

差异：FastAPI 在**一个** `Field(...)` 调用里同时声明校验（`gt=0`）与文档元数据（`description`），由 Pydantic 统一执行并写入 JSON Schema；NestJS 则拆成 `class-validator` 的 `@Min(0.01)`（校验）与 `@ApiProperty()`（文档）两个装饰器，分别由 `ValidationPipe` 和 Swagger 模块消费。
</details>

### 题 5（思考）

想在模型字段中加入自定义 JSON Schema 信息（如示例值），应使用什么？有什么风险？

<details>
<summary>参考答案</summary>

使用 `Field(json_schema_extra={...})`，例如：

```python
name: str = Field(json_schema_extra={"examples": ["Foo", "Bar"]})
```

这些信息会集成进生成的 JSON Schema。风险：`json_schema_extra` 中的额外键也会出现在 OpenAPI 架构中，而这些键**不一定属于 OpenAPI 规范**，某些 OpenAPI 工具（如 OpenAPI 验证器）可能无法处理该架构，因此自定义键要谨慎使用。
</details>
