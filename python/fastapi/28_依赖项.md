## 一、章节笔记

### 1. 什么是「依赖注入」

**依赖注入（Dependency Injection, DI）**指：你的代码（路径操作函数）声明它运行所需的「依赖」，由框架（FastAPI）负责执行必要逻辑并把结果「注入」进来。

适用场景：

- 共享业务逻辑（同一段代码反复复用）
- 共享数据库连接
- 实施安全、认证、角色权限
- 尽量消除代码重复

它在其他语境下的别名：资源（resources）、提供方（providers）、服务（services）、可注入（injectables）、组件（components）。

### 2. 最小示例：声明并使用一个依赖

依赖就是一个普通函数，能接收与路径操作函数相同的所有参数；可以把它理解为「没有装饰器的路径操作函数」，可返回任意内容。

```python
from typing import Annotated

from fastapi import Depends, FastAPI

app = FastAPI()

async def common_parameters(q: str | None = None, skip: int = 0, limit: int = 100):
    return {"q": q, "skip": skip, "limit": limit}

@app.get("/items/")
async def read_items(commons: Annotated[dict, Depends(common_parameters)]):
    return commons

@app.get("/users/")
async def read_users(commons: Annotated[dict, Depends(common_parameters)]):
    return commons
```

收到新请求时 FastAPI 会：

1. 用正确的参数调用依赖函数（"dependable"）；
2. 拿到返回值；
3. 把返回值赋给路径操作函数的对应参数。

> 无需创建专门的类去「注册」；只要传给 `Depends`，FastAPI 就知道怎么做。

### 3. 关键语法规则

| 要点 | 说明 |
|---|---|
| 导入 | `from fastapi import Depends`，推荐配合 `from typing import Annotated` |
| 参数形式 | `Annotated[类型, Depends(func)]`（推荐），或旧式 `参数: 类型 = Depends(func)` |
| `Depends` 参数个数 | **只能传一个参数**，且必须是「类似函数的可调用对象」 |
| 不要加括号 | 传函数本身 `Depends(common_parameters)`，不要写成 `Depends(common_parameters())` |
| 版本要求 | `Annotated` 支持自 FastAPI 0.95.0 引入，建议 ≥ 0.95.1 |

> 与 `Body`、`Query` 用法形似，但 `Depends` 只接收一个「可调用对象」，而非校验元数据。

### 4. 共享 `Annotated` 依赖项（类型别名）

每次写完整注解有重复。利用 `Annotated` 是标准 Python 的特性，可把它存成类型别名复用：

```python
from typing import Annotated

from fastapi import Depends, FastAPI

app = FastAPI()

async def common_parameters(q: str | None = None, skip: int = 0, limit: int = 100):
    return {"q": q, "skip": skip, "limit": limit}

CommonsDep = Annotated[dict, Depends(common_parameters)]

@app.get("/items/")
async def read_items(commons: CommonsDep):
    return commons

@app.get("/users/")
async def read_users(commons: CommonsDep):
    return commons
```

这不是 FastAPI 专有功能，而是 Python 的「类型别名」。好处：类型信息被保留，编辑器仍能自动补全、行内报错，`mypy` 等工具同样有效；在大型代码库中价值明显。

### 5. async 与依赖

依赖由 FastAPI 调用，规则与路径操作函数完全相同：

- 依赖可以是 `async def` 或普通 `def`；
- 路径操作函数与依赖的 `async`/同步形式可任意混用（如同步路径函数里声明异步依赖，反之亦然）；
- FastAPI 知道如何正确处理。

### 6. 层级依赖与 OpenAPI 集成

依赖项可以依赖其他依赖项，形成任意深度的**依赖树**。例如 `current_user → active_user → admin_user / paying_user`，可为不同端点挂不同权限要求。

所有依赖（及子依赖）中声明的请求参数、校验、需求，都会合并进同一个 **OpenAPI 模式**，因此交互式文档（`/docs`）会自动展示依赖引入的参数与验证信息。

### 7. 能力版图与易错点

依赖注入系统可集成：关系型/NoSQL 数据库、外部包、外部 API、认证授权系统、API 监控、响应注入等；无需造「插件」，导入包后几行代码即可接入。

易错点：

- ✅ `Depends(func)` 传函数本身，不要调用它（无括号）。
- ✅ `Annotated` 需要较新版本 FastAPI。
- ✅ 依赖的参数会被当作查询/路径/Cookie/Header 等处理，并写入文档。
- ✅ 复用 `Annotated` 别名时，注意它本质是类型别名，不是新的依赖实例声明方式。

## 二、NestJS 对比

| 维度 | FastAPI（Python） | NestJS（TypeScript） |
|---|---|---|
| DI 核心写法 | 函数参数标注 `Depends(func)`，无注册步骤 | Provider 加 `@Injectable()`，在模块 `providers` 注册，构造器注入 `constructor(private svc: Svc)` |
| 注入单位 | 任意「可调用对象」（函数、类等） | 带 `@Injectable()` 的类（provider） |
| 注册位置 | 无需注册，直接在参数中声明 | 必须在 `@Module({ providers: [...] })` 中声明，并在需要处注入 |
| 作用域 | 依赖默认按请求解析（可被缓存） | Provider 默认单例（singleton），可用 `Scope.REQUEST` / `Scope.TRANSIENT` |
| 参数来源 | 依赖函数的参数即请求参数，自动从请求提取 | 注入的是实例，请求数据需另用 `@Req/@Param/@Query/@Body` 获取 |
| 文档集成 | 依赖参数自动并入 OpenAPI | Provider 不自动进文档；请求结构需 DTO + `@nestjs/swagger` |
| 组合方式 | 函数式、任意嵌套树，轻量 | 基于模块的 Provider 图，配合 `@Inject()` 处理循环/自定义 token |
| 测试替换 | 测试时用 `app.dependency_overrides[func] = 假实现` | 测试模块中用 `overrideProvider(Svc).useValue(mock)` |

**核心差异一句话**：FastAPI 的依赖是「写在参数上的可调用对象」，框架按请求解析、自动参与文档与校验，零注册；NestJS 的依赖是可注入的 Provider 类，必须先经 `@Module` 注册再构造器注入，默认是单例且文档需显式 DTO 支撑。

## 三、针对性练习题

### 题 1（基础）
写一个依赖 `get_pagination(skip: int = 0, limit: int = 100)`，并在 `GET /items/` 中用 `Annotated` 方式注入它，返回依赖结果。

<details>
<summary>参考答案</summary>

```python
from typing import Annotated
from fastapi import Depends, FastAPI

app = FastAPI()

def get_pagination(skip: int = 0, limit: int = 100):
    return {"skip": skip, "limit": limit}

@app.get("/items/")
async def read_items(page: Annotated[dict, Depends(get_pagination)]):
    return page
```

`skip`、`limit` 是可选查询参数，FastAPI 会自动解析、校验并写入 OpenAPI 文档。
</details>

### 题 2（理解）
为什么说依赖是「没有装饰器的路径操作函数」？`Depends(common_parameters)` 与 `Depends(common_parameters())` 有何区别？

<details>
<summary>参考答案</summary>

依赖与路径操作函数一样，可声明任意请求参数（Query/Path/Cookie/Header/Body 等），FastAPI 用相同机制从请求中提取并调用，只是它没有 `@app.get(...)` 装饰器、不直接对外暴露为路由。

`Depends(common_parameters)` 传入的是**函数对象本身**，由 FastAPI 在请求时调用；`Depends(common_parameters())` 会**在应用代码执行时立即调用**函数，并把返回值（如 dict）传给 `Depends`——这不是可调用对象，会报错/行为异常。正确做法是传函数不加括号。
</details>

### 题 3（辨析 / 代码）
下面两种声明都能工作吗？第二种写法有什么好处？

```python
# A
async def read_items(commons: Annotated[dict, Depends(common_parameters)]): ...

# B
CommonsDep = Annotated[dict, Depends(common_parameters)]
async def read_items(commons: CommonsDep): ...
```

<details>
<summary>参考答案</summary>

都能工作。B 利用了 Python 的「类型别名」，`Annotated` 值被存成变量在多处复用，消除重复。由于这是标准 Python 类型别名，类型信息会保留：编辑器仍能补全、检查，`mypy` 等工具仍有效，在大型代码库中尤其有用。
</details>

### 题 4（进阶 · NestJS 迁移视角）
在 NestJS 中你会写 `@Injectable() class CommonService` 并在模块的 `providers` 注册、控制器构造器注入。请说明 FastAPI 的等价做法，并指出一个关键差异。

<details>
<summary>参考答案</summary>

FastAPI 无需类、无需注册：定义一个函数（或可调用对象），在路径操作参数上写 `commons: Annotated[dict, Depends(common_parameters)]` 即可。关键差异：NestJS Provider 默认单例、需显式注册且请求数据另用装饰器获取；FastAPI 依赖按请求解析、参数即请求参数、零注册且自动并入 OpenAPI 文档。
</details>

### 题 5（思考）
为什么说依赖注入系统能充当 FastAPI 的「插件机制」，而无需专门的插件体系？

<details>
<summary>参考答案</summary>

任何外部能力（数据库会话、认证、监控、第三方 API）都可封装成一个「可调用对象」作为依赖——只要导入包并用几行代码把其参数声明出来，FastAPI 就会按请求调用并注入结果。由于依赖可任意嵌套成树，且自动参与校验和 OpenAPI 文档，所以不需要设计专门的插件注册协议，这使 FastAPI 能与各种数据库、认证系统、外部服务自然兼容。
</details>
