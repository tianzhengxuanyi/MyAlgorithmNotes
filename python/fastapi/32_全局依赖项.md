## 一、章节笔记

### 1. 适用场景

有时要为**整个应用**添加依赖项。做法与把 `dependencies` 加到路径操作装饰器类似，只是把它加到 `FastAPI()` 应用实例上。这样该依赖会应用于**所有路径操作**。

```python
from typing import Annotated

from fastapi import Depends, FastAPI, Header, HTTPException

async def verify_token(x_token: Annotated[str, Header()]):
    if x_token != "fake-super-secret-token":
        raise HTTPException(status_code=400, detail="X-Token header invalid")

async def verify_key(x_key: Annotated[str, Header()]):
    if x_key != "fake-super-secret-key":
        raise HTTPException(status_code=400, detail="X-Key header invalid")
    return x_key

app = FastAPI(dependencies=[Depends(verify_token), Depends(verify_key)])

@app.get("/items/")
async def read_items():
    return [{"item": "Portal Gun"}, {"item": "Plumbus"}]

@app.get("/users/")
async def read_users():
    return [{"username": "Rick"}, {"username": "Morty"}]
```

本例中，`/items/` 和 `/users/` 都会执行 `verify_token` 与 `verify_key`。

### 2. 规则继承

「路径操作装饰器依赖项」一章的所有思路都适用于全局依赖项：

- 依赖可以是任意可调用对象，可声明请求需求（Header 等）与子依赖；
- 返回值不会传给任何路径操作函数；
- 抛出的异常会阻断对应请求；
- 可复用带返回值的普通依赖，即使此处不使用其返回值。

### 3. 三种作用域对比

| 作用域 | 声明位置 | 影响范围 |
|---|---|---|
| 函数参数注入 | `def read(x = Depends(dep))` | 单个路径操作，且能拿到返回值 |
| 装饰器 `dependencies` | `@app.get(..., dependencies=[...])` | 单个路径操作，丢弃返回值 |
| 应用全局 `dependencies` | `app = FastAPI(dependencies=[...])` | **所有**路径操作，丢弃返回值 |

### 4. 为一组路径操作定义依赖项

若只需为**部分**路径操作（一组）共享依赖，而非整个应用，则使用 `APIRouter`，在「大型应用 - 多文件」章节介绍——可给 `APIRouter(prefix=..., dependencies=[...])` 声明单个 `dependencies` 参数。

### 5. 易错点

- ✅ 全局依赖写在 `FastAPI(dependencies=[...])` 构造参数中，而不是某个装饰器上。
- ✅ 它作用于应用中**每一个**路径操作，因此应保持通用（如全局鉴权、公共头校验），避免把只针对个别端点的逻辑放进去。
- ✅ 与装饰器依赖一样，返回值不会注入 handler；需要返回值请用函数参数 `Depends`。
- ✅ 全局依赖抛出的异常会影响所有请求，务必谨慎设计。

## 二、NestJS 对比

| 维度 | FastAPI（Python） | NestJS（TypeScript） |
|---|---|---|
| 全局挂载 | `app = FastAPI(dependencies=[Depends(fn)])` | `app.useGlobalGuards(...)` / `useGlobalInterceptors(...)`，或在 `AppModule` 用 `APP_GUARD` provider |
| 作用于范围 | 应用内所有路径操作 | 全应用所有路由 |
| 返回值 | 全局依赖返回值被丢弃 | Guard 返回布尔决定是否放行；Interceptor 可包装响应 |
| 分组粒度 | 单路由用装饰器参数；分组用 `APIRouter`；全局用 `FastAPI()` | 方法级 `@UseGuards()`；控制器级；全局 `useGlobalGuards`；模块级 provider |
| 请求数据 | 依赖参数可用 `Header()` 等 | Guard 通过 `ExecutionContext` 取 request |
| 异常 | `raise HTTPException` 阻断请求 | `throw HttpException` 阻断请求 |
| 注册时机 | 构造应用时一次性声明 | 启动时通过 provider/token 或 `useGlobal*` 装配 |

**核心差异一句话**：FastAPI 把全局依赖作为 `FastAPI()` 的构造参数一次声明、作用于全部路由且丢弃返回值；NestJS 通过 `useGlobalGuards()` 或 `APP_GUARD` 等 provider 在模块层装配全局 Guard/Interceptor，抽象更专门但装配路径更长。

## 三、针对性练习题

### 题 1（基础）
给整个应用加一个全局依赖，要求所有请求都必须带 `X-Api-Key: secret`，否则返回 401。写出代码并说明它影响哪些路由。

<details>
<summary>参考答案</summary>

```python
from typing import Annotated
from fastapi import Depends, FastAPI, Header, HTTPException

async def verify_api_key(x_api_key: Annotated[str, Header()]):
    if x_api_key != "secret":
        raise HTTPException(status_code=401, detail="Invalid API key")

app = FastAPI(dependencies=[Depends(verify_api_key)])

@app.get("/a/")
async def a(): return {"route": "a"}

@app.get("/b/")
async def b(): return {"route": "b"}
```

`/a/` 和 `/b/` 乃至应用中所有路径操作都会先执行 `verify_api_key`。
</details>

### 题 2（理解）
全局依赖与「函数参数里的 `Depends`」有什么关键区别？如果全局依赖返回了一个值，handler 能拿到吗？

<details>
<summary>参考答案</summary>

区别：① 作用范围不同——全局依赖作用于所有路径操作，函数参数依赖只作用于所在函数；② 返回值处理不同——全局依赖（同装饰器依赖）的返回值会被丢弃，不会注入任何 handler，而函数参数依赖的返回值会注入对应参数。因此 handler 拿不到全局依赖的返回值；需要值时应改用函数参数 `Depends`。
</details>

### 题 3（辨析 / 代码）
某开发者把「只有 `/admin/` 才需要的管理员校验」放进了全局依赖。这有什么问题？应如何改进？

<details>
<summary>参考答案</summary>

问题：全局依赖作用于所有路径操作，会导致普通接口也被要求管理员权限，破坏正常访问；且全局抛异常影响面大。改进：把该校验移到 `/admin/` 的装饰器 `dependencies=[Depends(verify_admin)]` 上，或用 `APIRouter(dependencies=[...])` 只作用于一组管理员路由，不要放进 `FastAPI(dependencies=[...])`。
</details>

### 题 4（进阶 · NestJS 迁移视角）
NestJS 中用 `app.useGlobalGuards(new AuthGuard())` 做全局鉴权。请写出 FastAPI 的等价实现，并指出返回值语义的差异。

<details>
<summary>参考答案</summary>

```python
from typing import Annotated
from fastapi import Depends, FastAPI, Header, HTTPException

app = FastAPI()

async def auth(x_token: Annotated[str, Header()]):
    if not x_token:
        raise HTTPException(status_code=401, detail="Unauthorized")

# 全局依赖需在构造时声明，故调整如下：
app = FastAPI(dependencies=[Depends(auth)])

@app.get("/public/")
async def public(): return {"ok": True}
```

差异：NestJS Guard 的 `canActivate` 返回布尔值决定放行/拒绝；FastAPI 依赖靠「正常返回即放行、抛异常即拒绝」，其返回值本身被丢弃，不参与放行判定。
</details>

### 题 5（思考）
文档说要为「一组路径操作」定义依赖项需等到「大型应用 - 多文件」章节。请推断这样做的意义是什么——为什么不全部用全局依赖？

<details>
<summary>参考答案</summary>

因为全局依赖粒度太粗：真实应用常有多个路由组（如 `/users`、`/admin`、`/public`），各组权限/预处理不同。用 `APIRouter(prefix="/admin", dependencies=[Depends(admin_only)])` 可让依赖只作用于该组，既复用代码又不误伤其他路由。这是模块化/分层思想的体现，也是大型应用可维护性的关键。
</details>
