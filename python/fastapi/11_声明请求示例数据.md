## 一、章节笔记

### 1. 为什么需要声明示例

可以为应用接收的数据声明**示例（examples）**，这些示例会进入生成的 JSON Schema / OpenAPI，并显示在 `/docs` 文档中，方便调用方了解该传什么。实现方式有多种。

### 2. 方式一：Pydantic 模型的 `model_config` + `json_schema_extra`

在模型内用 `model_config` 声明 `examples`，会被加入该模型生成的 JSON Schema：

```python
from fastapi import FastAPI
from pydantic import BaseModel

app = FastAPI()

class Item(BaseModel):
    name: str
    description: str | None = None
    price: float
    tax: float | None = None

    model_config = {
        "json_schema_extra": {
            "examples": [
                {
                    "name": "Foo",
                    "description": "A very nice Item",
                    "price": 35.4,
                    "tax": 3.2,
                }
            ]
        }
    }

@app.put("/items/{item_id}")
async def update_item(item_id: int, item: Item):
    return {"item_id": item_id, "item": item}
```

- `model_config` 接收一个 `dict`（详见 Pydantic 配置文档）。
- `"json_schema_extra"` 可放任意附加数据（包括 `examples`），原样加入 JSON Schema 并被文档使用。
- 也可用此技巧扩展 JSON_schema，例如给前端 UI 加元数据。

### 3. 方式二：`Field` 的 `examples` 参数

模型字段用 `Field(examples=[...])` 声明字段级示例：

```python
from fastapi import FastAPI
from pydantic import BaseModel, Field

app = FastAPI()

class Item(BaseModel):
    name: str = Field(examples=["Foo"])
    description: str | None = Field(default=None, examples=["A very nice Item"])
    price: float = Field(examples=[35.4])
    tax: float | None = Field(default=None, examples=[3.2])

@app.put("/items/{item_id}")
async def update_item(item_id: int, item: Item):
    return {"item_id": item_id, "item": item}
```

### 4. 方式三：`Path`/`Query`/`Body` 等的 `examples`

`examples` 可用于以下所有声明函数：

| 函数 | 说明 |
|---|---|
| `Path()` / `Query()` | 路径/查询参数 |
| `Header()` / `Cookie()` | 头/Cookie 参数 |
| `Body()` / `Form()` / `File()` | 请求体/表单/文件 |

示例将添加到它们在 OpenAPI 中的 JSON Schema 里。以 `Body` 为例：

```python
from typing import Annotated
from fastapi import Body, FastAPI
from pydantic import BaseModel

app = FastAPI()

class Item(BaseModel):
    name: str
    description: str | None = None
    price: float
    tax: float | None = None

@app.put("/items/{item_id}")
async def update_item(
    item_id: int,
    item: Annotated[
        Item,
        Body(
            examples=[
                {
                    "name": "Foo",
                    "description": "A very nice Item",
                    "price": 35.4,
                    "tax": 3.2,
                }
            ],
        ),
    ],
):
    return {"item_id": item_id, "item": item}
```

**多个 `examples`**：`examples` 是一个列表，可传多个示例。但这些示例属于 JSON Schema 的一部分，而 Swagger UI **不支持显示 JSON Schema 中的多个示例**——此时需下面的变通方案。

### 5. 方式四：OpenAPI 特定的 `examples` → `openapi_examples`

在 JSON Schema 支持 `examples` 之前，OpenAPI 就有同名字段 `examples`，但它位于 OpenAPI 规范的**另一处**（每个路径操作的详细信息中，而非 JSON Schema 里）。Swagger UI 很早就支持它，可用来在文档中展示多个示例。

- 结构是一个 **dict**（不是 list），键用于标识每个示例。
- 每个示例的值是一个 dict，可包含：

| 字段 | 含义 |
|---|---|
| `summary` | 简短描述 |
| `description` | 较长描述，可含 Markdown |
| `value` | 实际展示的示例（如一个 dict） |
| `externalValue` | 指向示例 URL，作为 `value` 的替代，工具支持度较低 |

自 FastAPI **0.103.0** 起，这个旧的 OpenAPI 特定参数由 `examples` 改名为 `openapi_examples`，用于 `Path()`/`Query()`/`Header()`/`Cookie()`/`Body()`/`Form()`/`File()`：

```python
from typing import Annotated
from fastapi import Body, FastAPI
from pydantic import BaseModel

app = FastAPI()

class Item(BaseModel):
    name: str
    description: str | None = None
    price: float
    tax: float | None = None

@app.put("/items/{item_id}")
async def update_item(
    *,
    item_id: int,
    item: Annotated[
        Item,
        Body(
            openapi_examples={
                "normal": {
                    "summary": "A normal example",
                    "description": "A **normal** item works correctly.",
                    "value": {
                        "name": "Foo",
                        "description": "A very nice Item",
                        "price": 35.4,
                        "tax": 3.2,
                    },
                },
                "converted": {
                    "summary": "An example with converted data",
                    "description": "FastAPI can convert price `strings` to actual `numbers` automatically",
                    "value": {"name": "Bar", "price": "35.4"},
                },
                "invalid": {
                    "summary": "Invalid data is rejected with an error",
                    "value": {"name": "Baz", "price": "thirty five point four"},
                },
            },
        ),
    ],
):
    return {"item_id": item_id, "item": item}
```

这样 `/docs` 中会出现多个可选示例的下拉展示。

### 6. 历史背景（技术细节，可跳过）

- OpenAPI 3.1.0 之前使用旧版修改过的 JSON Schema，当时 JSON Schema 没有 `examples`，OpenAPI 自定义了单个示例字段 `example`。
- OpenAPI 3.1.0 基于 JSON Schema 2020-12，引入 `examples`（一个示例列表），**优先于已弃用的 `example`**；建议把 `example` 迁移到 `examples`。
- FastAPI **0.99.0** 起使用 OpenAPI 3.1.0；此前因 Swagger UI 不支持 3.1.0（Swagger UI 5.0.0 起支持）而使用更低版本。
- 截至 2023-08-26，Swagger UI 不支持多个 JSON Schema 示例，故 FastAPI 0.103.0 增加 `openapi_examples` 作为变通。
- 结论：**升级到 FastAPI 0.99.0+ 一切更简单一致**，这些历史细节可不必深究。

### 7. 方式对比速查

| 方式 | 作用位置 | 特点 |
|---|---|---|
| `model_config["json_schema_extra"]["examples"]` | 模型 JSON Schema | 模型级示例，可加任意元数据 |
| `Field(examples=[...])` | 字段 JSON Schema | 字段级示例 |
| `Query()/Body()...examples=[...]` | 参数 JSON Schema | 参数级示例（列表） |
| `...openapi_examples={...}` | OpenAPI 路径操作 | 多示例、带 summary/description，Swagger UI 支持 |

### 8. 易错点小结

- ✅ 推荐新版 `examples`（复数），`example`（单数）已弃用且非 JSON Schema 标准。
- ✅ `examples` 是**列表**，`openapi_examples` 是**字典**（按名称标识示例）。
- ✅ Swagger UI 不展示 JSON Schema 中的多个示例，要多示例展示用 `openapi_examples`。
- ✅ `json_schema_extra` 可放任意自定义键，但可能不被 OpenAPI 工具兼容。

## 二、NestJS 对比

| 维度 | FastAPI（Python） | NestJS（TypeScript） |
|---|---|---|
| 模型级示例 | `model_config = {"json_schema_extra": {"examples": [...]}}` | `@ApiProperty({ example: ... })` 逐字段声明；类级可用 `@ApiExtraModels` 配合 |
| 字段级示例 | `Field(examples=["Foo"])` | `@ApiProperty({ example: 'Foo', examples: [...] })` |
| 参数级示例 | `Query(examples=[...])` / `Body(examples=[...])` | `@ApiQuery({ examples: {...} })` / `@ApiBody({ examples: {...} })` |
| 多示例（UI 可见） | `Body(openapi_examples={...})`，带 summary/description/value | `@ApiBody({ examples: { normal: { summary, value }, ... } })` 类似结构 |
| 示例归属 | JSON Schema（新版 `examples`）与 OpenAPI 路径操作两处 | 全部由 `@nestjs/swagger` 装饰器汇总进 OpenAPI |
| 标准兼容 | FastAPI 0.99.0+ 用 OpenAPI 3.1.0 / JSON Schema 2020-12 | 取决于所用 `@nestjs/swagger` 版本输出的 OpenAPI 版本 |
| 自定义 Schema 元数据 | `json_schema_extra` 可放任意键 | `@ApiProperty` 字段有限，自定义键需扩展或手动改文档 |

**核心差异一句话**：FastAPI 把示例直接挂到 Pydantic 模型/`Field`/参数声明上，并区分"JSON Schema 的 `examples`（列表）"与"OpenAPI 路径操作的 `openapi_examples`（带元数据的字典）"两套机制以应对 Swagger UI 的限制；NestJS 则统一通过 `@nestjs/swagger` 的 `@ApiProperty`/`@ApiBody` 等装饰器提供 `example`/`examples` 字段，概念更少但依赖 Swagger 模块的版本能力。

## 三、针对性练习题

### 题 1（基础）

用 Pydantic 模型的 `model_config` 为 `Item` 声明一个请求示例（name=Foo、price=35.4）。

<details>
<summary>参考答案</summary>

```python
from fastapi import FastAPI
from pydantic import BaseModel

app = FastAPI()

class Item(BaseModel):
    name: str
    price: float

    model_config = {
        "json_schema_extra": {
            "examples": [
                {"name": "Foo", "price": 35.4}
            ]
        }
    }
```

`examples` 会被加入模型生成的 JSON Schema，并显示在 `/docs`。
</details>

### 题 2（理解）

`examples` 与 `openapi_examples` 有什么区别？为什么需要后者？

<details>
<summary>参考答案</summary>

`examples`（FastAPI 0.99.0+，OpenAPI 3.1.0 / JSON Schema 2020-12）是一个**列表**，位于数据的 JSON Schema 中。`openapi_examples`（FastAPI 0.103.0 起，由旧 `examples` 改名）是一个**字典**，位于 OpenAPI 的路径操作详情中，每个示例可带 `summary`、`description`、`value`、`externalValue`。

需要后者是因为 Swagger UI 不支持显示 JSON Schema 中的多个示例；`openapi_examples` 是变通方案，能在文档 UI 中展示多个带说明的示例。
</details>

### 题 3（辨析/代码）

下面想展示 3 个带说明的请求体示例，哪种写法能被 Swagger UI 正确展示？

```python
A: Body(examples=[{...}, {...}, {...}])
B: Body(openapi_examples={"normal": {"summary": ..., "value": {...}}, ...})
```

<details>
<summary>参考答案</summary>

B 能被 Swagger UI 正确展示多个示例。A 的 `examples` 属于 JSON Schema，多个示例会写入 Schema，但 Swagger UI 不支持显示 JSON Schema 中的多个示例（截至 2023-08-26）。B 的 `openapi_examples` 写入 OpenAPI 路径操作，Swagger UI 一直支持，能以带 summary/description 的方式展示多个示例。
</details>

### 题 4（进阶 · NestJS 迁移视角）

NestJS 中你这样给请求体加示例：

```ts
@ApiBody({
  examples: {
    normal: { summary: 'A normal example', value: { name: 'Foo', price: 35.4 } },
    invalid: { summary: 'Invalid data', value: { name: 'Baz', price: 'bad' } },
  },
})
```

请写出等价的 FastAPI 声明，并指出它对应 `examples` 还是 `openapi_examples`。

<details>
<summary>参考答案</summary>

```python
from typing import Annotated
from fastapi import Body, FastAPI
from pydantic import BaseModel

app = FastAPI()

class Item(BaseModel):
    name: str
    price: float

@app.put("/items/{item_id}")
async def update_item(
    item_id: int,
    item: Annotated[
        Item,
        Body(
            openapi_examples={
                "normal": {
                    "summary": "A normal example",
                    "value": {"name": "Foo", "price": 35.4},
                },
                "invalid": {
                    "summary": "Invalid data",
                    "value": {"name": "Baz", "price": "bad"},
                },
            },
        ),
    ],
):
    return {"item_id": item_id, "item": item}
```

对应 `openapi_examples`：因为 NestJS 的 `@ApiBody({ examples: { 名称: {...} } })` 是按名称组织的字典、带 summary/value，与 FastAPI 的 `openapi_examples` 结构一致（而非 `examples` 列表）。
</details>

### 题 5（思考）

项目仍用 FastAPI 0.98.0，代码里写 `Query(example="foo")`。升级到 0.99.0+ 后应如何迁移？为什么？

<details>
<summary>参考答案</summary>

迁移为 `Query(examples=["foo"])`（用复数 `examples`，值为列表）。

原因：FastAPI 0.99.0 起使用 OpenAPI 3.1.0（基于 JSON Schema 2020-12），JSON Schema 标准引入 `examples` 字段并**优先于旧的单个 `example`**；`example` 已被弃用且不属于 JSON Schema 标准。迁移后示例会正确进入 JSON Schema，行为与新版本一致、更面向未来。
</details>
