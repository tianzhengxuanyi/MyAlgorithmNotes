## 一、章节笔记

### 1. 混合使用 `Path`、`Query` 与请求体

三者可随意混合，FastAPI 各自处理。请求体参数也能通过默认值 `None` 变为可选：

```python
from typing import Annotated
from fastapi import FastAPI, Path
from pydantic import BaseModel

app = FastAPI()

class Item(BaseModel):
    name: str
    description: str | None = None
    price: float
    tax: float | None = None

@app.put("/items/{item_id}")
async def update_item(
    item_id: Annotated[int, Path(title="The ID of the item to get", ge=0, le=1000)],
    q: str | None = None,
    item: Item | None = None,
):
    results = {"item_id": item_id}
    if q:
        results.update({"q": q})
    if item:
        results.update({"item": item})
    return results
```

`item: Item | None = None` 使请求体整体可选——请求可以不带请求体。

### 2. 多个请求体参数 → JSON 按参数名分键

虽然一次请求只有一个请求体，但函数可声明多个 Pydantic 模型参数（如 `item`、`user`）。此时 FastAPI **用参数名作为请求体中的键**，期望嵌套结构：

```python
from fastapi import FastAPI
from pydantic import BaseModel

app = FastAPI()

class Item(BaseModel):
    name: str
    description: str | None = None
    price: float
    tax: float | None = None

class User(BaseModel):
    username: str
    full_name: str | None = None

@app.put("/items/{item_id}")
async def update_item(item_id: int, item: Item, user: User):
    results = {"item_id": item_id, "item": item, "user": user}
    return results
```

期望的请求体：

```json
{
  "item": {
    "name": "Foo",
    "description": "The pretender",
    "price": 42.0,
    "tax": 3.2
  },
  "user": {
    "username": "dave",
    "full_name": "Dave Grohl"
  }
}
```

注意：同一个 `Item` 声明，在只有一个模型参数时期望的是"平铺"的 JSON（模型字段直接在顶层）；一旦出现多个请求体参数，就被**包裹进 `item` 键**里。

### 3. 请求体中的单一值：`Body()`

单一类型（如 `int`）的参数默认被解释为**查询参数**。若想让它成为请求体里的一个键，需要用 `Body()` 标注：

```python
from typing import Annotated
from fastapi import Body, FastAPI
from pydantic import BaseModel

app = FastAPI()

class Item(BaseModel):
    name: str
    description: str | None = None
    price: float
    tax: float | None = None

class User(BaseModel):
    username: str
    full_name: str | None = None

@app.put("/items/{item_id}")
async def update_item(
    item_id: int, item: Item, user: User, importance: Annotated[int, Body()]
):
    results = {"item_id": item_id, "item": item, "user": user, "importance": importance}
    return results
```

期望请求体（`importance` 作为顶层的一个键）：

```json
{
  "item": { "name": "Foo", "price": 42.0 },
  "user": { "username": "dave" },
  "importance": 5
}
```

`Body` 与 `Query`、`Path` 拥有**完全相同的额外校验与元数据参数**（如 `gt=0`、`title` 等）。

### 4. 多个请求体参数 + 查询参数

单一值默认走查询参数，因此无需显式写 `Query`：

```python
from typing import Annotated
from fastapi import Body, FastAPI
from pydantic import BaseModel

app = FastAPI()

class Item(BaseModel):
    name: str
    description: str | None = None
    price: float
    tax: float | None = None

class User(BaseModel):
    username: str
    full_name: str | None = None

@app.put("/items/{item_id}")
async def update_item(
    *,
    item_id: int,
    item: Item,
    user: User,
    importance: Annotated[int, Body(gt=0)],
    q: str | None = None,
):
    results = {"item_id": item_id, "item": item, "user": user, "importance": importance}
    if q:
        results.update({"q": q})
    return results
```

- `importance` 用 `Body(gt=0)`：请求体中的整数且 > 0。
- `q` 不标注：默认作为查询参数。

### 5. 嵌入单个请求体参数：`Body(embed=True)`

只有一个模型参数时，默认期望"平铺"请求体。若希望即使只有一个参数也把它包进参数名的键里，用 `embed=True`：

```python
from typing import Annotated
from fastapi import Body, FastAPI
from pydantic import BaseModel

app = FastAPI()

class Item(BaseModel):
    name: str
    description: str | None = None
    price: float
    tax: float | None = None

@app.put("/items/{item_id}")
async def update_item(item_id: int, item: Annotated[Item, Body(embed=True)]):
    results = {"item_id": item_id, "item": item}
    return results
```

期望请求体：

```json
{
  "item": {
    "name": "Foo",
    "description": "The pretender",
    "price": 42.0,
    "tax": 3.2
  }
}
```

而不是平铺的 `{"name": "Foo", ...}`。旧式写法：`item: Item = Body(embed=True)`。

### 6. 参数来源判定规则速查

| 声明形式 | 来源 |
|---|---|
| 名字在路径模板中 | 路径参数 |
| 单一类型（`int`/`str`/`bool`...），无标注 | 查询参数 |
| Pydantic 模型类型 | 请求体 |
| 单一类型 + `Body()` | 请求体中的同名键 |
| 请求体参数 + `Body(embed=True)` | 请求体中被包裹进参数名的键 |

### 7. 易错点小结

- ✅ 多个模型请求体参数 → JSON 自动按参数名分键嵌套。
- ✅ 单一值想进请求体必须写 `Body()`，否则默认当查询参数。
- ✅ 只有一个模型参数时默认平铺；要嵌套用 `embed=True`。
- ✅ 请求体参数可有默认值 `None` 变成可选。
- ✅ `Body` 与 `Query`/`Path` 共享校验与元数据参数。

## 二、NestJS 对比

| 维度 | FastAPI（Python） | NestJS（TypeScript） |
|---|---|---|
| 多请求体参数 | 函数声明多个模型参数，FastAPI 自动按**参数名**分键嵌套 | 多个 `@Body('item')` / `@Body('user')` 装饰器分别取键 |
| 请求体单值 | `importance: Annotated[int, Body()]` | `@Body('importance') importance: number` |
| 嵌入单模型 | `item: Annotated[Item, Body(embed=True)]` | 无直接等价开关；通常直接 `@Body() dto`，客户端自己发嵌套结构 |
| 默认值 / 可选请求体 | `item: Item | None = None` | `@Body() item?: Item` + DTO 字段可选 |
| 来源判定 | 类型 + 标注自动区分（单一值默认 query，`Body()` 改 body） | 由装饰器 `@Param`/`@Query`/`@Body` 显式决定 |
| 校验元数据 | `Body(gt=0)` 与 `Query(ge=1)` 参数通用 | DTO 字段用 `class-validator`，与取参装饰器分离 |
| 校验错误 | Pydantic 统一 `422` + `loc:["body","importance"]` | `ValidationPipe` 抛 `BadRequestException`（400） |
| 文档 | 多请求体参数/嵌入结构自动写入 OpenAPI | 需 `@ApiBody({ schema: ... })` 描述复合请求体结构 |

**核心差异一句话**：FastAPI 靠"参数名 + 类型 + 标注"自动推导请求体的嵌套形状（多个模型自动分键、`embed=True` 手动包裹），无需装饰器；NestJS 用 `@Body('key')` 显式指定每个键，请求体形状由客户端 JSON 与 DTO 共同决定，没有 `embed` 这类自动包裹开关。

## 三、针对性练习题

### 题 1（基础）

写 `PUT /items/{item_id}`，同时接收路径参数 `item_id: int`、`Item` 模型请求体、可选查询参数 `q`。

<details>
<summary>参考答案</summary>

```python
from fastapi import FastAPI
from pydantic import BaseModel

app = FastAPI()

class Item(BaseModel):
    name: str
    price: float

@app.put("/items/{item_id}")
async def update_item(item_id: int, item: Item, q: str | None = None):
    result = {"item_id": item_id, "item": item}
    if q:
        result["q"] = q
    return result
```

`item_id` 来自路径，`item` 来自请求体（平铺 JSON），`q` 来自查询字符串。
</details>

### 题 2（理解）

函数声明 `item: Item, user: User` 两个模型参数时，为什么请求体变成 `{"item": {...}, "user": {...}}` 而不是把两个模型字段平铺到顶层？

<details>
<summary>参考答案</summary>

因为一次请求只能有一个请求体，FastAPI 检测到多个请求体参数后，用**函数参数名作为请求体中的键**来区分各模型的数据，因此期望嵌套结构 `{"item": {...}, "user": {...}}`。若只有一个模型参数，则没有歧义，直接期望平铺的 `{"name": ..., "price": ...}`。
</details>

### 题 3（辨析/代码）

想把 `importance: int` 作为请求体里的一个键（与 `item` 同级）。下面哪种写法正确？为什么？

```python
A: importance: int
B: importance: Annotated[int, Body()]
```

<details>
<summary>参考答案</summary>

B 正确。单一类型参数默认被 FastAPI 解释为**查询参数**（A 会从 `?importance=5` 取）。用 `Annotated[int, Body()]` 显式标注后，FastAPI 才把它作为请求体中的同名键，期望 `{"item": {...}, "importance": 5}`。`Body()` 也支持与 `Query`/`Path` 相同的校验参数，如 `Body(gt=0)`。
</details>

### 题 4（进阶 · NestJS 迁移视角）

NestJS 中你这样取请求体的某个键：

```ts
@Put(':id')
update(@Param('id') id: number, @Body('importance') importance: number) { ... }
```

请写出等价 FastAPI 声明，并说明为什么 FastAPI 里单一值默认不会进请求体。

<details>
<summary>参考答案</summary>

```python
from typing import Annotated
from fastapi import Body, FastAPI

app = FastAPI()

@app.put("/items/{item_id}")
async def update(
    item_id: int, importance: Annotated[int, Body(gt=0)]
):
    return {"item_id": item_id, "importance": importance}
```

原因：FastAPI 的参数识别规则中，单一类型（`int`/`str`/`bool` 等）且未标注的参数一律视为查询参数；Pydantic 模型类型才视为请求体。这是为了让最常见的"路径 + 查询 + 一个模型请求体"写法最简洁。若要把单一值放进请求体，必须显式用 `Body()` 覆盖默认判定，相当于 NestJS 中显式写 `@Body('importance')`。
</details>

### 题 5（思考）

只有一个 `item: Item` 参数时，如何用 `Body(embed=True)` 改变期望的请求体形状？请写出代码并对比两种请求体。

<details>
<summary>参考答案</summary>

```python
from typing import Annotated
from fastapi import Body, FastAPI
from pydantic import BaseModel

app = FastAPI()

class Item(BaseModel):
    name: str
    price: float

@app.put("/items/{item_id}")
async def update_item(item_id: int, item: Annotated[Item, Body(embed=True)]):
    return {"item": item}
```

- 默认（不加 `embed`）：期望平铺 `{"name": "Foo", "price": 42.0}`。
- 加 `Body(embed=True)`：期望 `{"item": {"name": "Foo", "price": 42.0}}`。

`embed=True` 的作用是即使只有一个请求体参数，也把它包裹进参数名的键里，使形状与"多请求体参数"时一致。旧式写法为 `item: Item = Body(embed=True)`。
</details>
