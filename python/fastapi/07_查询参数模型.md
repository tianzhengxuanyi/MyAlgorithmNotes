## 一、章节笔记

### 1. 用 Pydantic 模型归类一组查询参数

当多个查询参数彼此相关（如分页、筛选），可用一个 Pydantic 模型统一声明，从而**在多处复用**，并一次性为所有字段定义校验与元数据。

> 该特性自 FastAPI **0.115.0** 起支持。

```python
from typing import Annotated, Literal
from fastapi import FastAPI, Query
from pydantic import BaseModel, Field

app = FastAPI()

class FilterParams(BaseModel):
    limit: int = Field(100, gt=0, le=100)
    offset: int = Field(0, ge=0)
    order_by: Literal["created_at", "updated_at"] = "created_at"
    tags: list[str] = []

@app.get("/items/")
async def read_items(filter_query: Annotated[FilterParams, Query()]):
    return filter_query
```

关键点：

- 模型参数用 `Annotated[FilterParams, Query()]` 标注（旧式写法：`filter_query: FilterParams = Query()`）。
- FastAPI 从请求的查询参数中提取**每个字段**的数据，组装成 Pydantic 模型交给函数。
- 字段级校验用 Pydantic 的 `Field`（`gt`、`le`、`ge`），枚举约束用 `Literal`。
- 所有参数会显示在 `/docs` 文档中。

### 2. 禁止额外的查询参数

默认会忽略未声明的查询参数。若想严格限制，用 Pydantic 模型配置 `extra="forbid"`：

```python
class FilterParams(BaseModel):
    model_config = {"extra": "forbid"}

    limit: int = Field(100, gt=0, le=100)
    offset: int = Field(0, ge=0)
    order_by: Literal["created_at", "updated_at"] = "created_at"
    tags: list[str] = []
```

客户端发送额外参数 `?limit=10&tool=plumbus` 时返回 `422`：

```json
{
  "detail": [
    {
      "type": "extra_forbidden",
      "loc": ["query", "tool"],
      "msg": "Extra inputs are not permitted",
      "input": "plumbus"
    }
  ]
}
```

### 3. 组合多个参数模型

可声明多个查询参数模型，并与单独的查询参数、依赖项组合：

```python
from typing import Annotated
from fastapi import FastAPI, Query
from pydantic import BaseModel, Field

app = FastAPI()

class Pagination(BaseModel):
    limit: int = Field(10, ge=1)
    offset: int = Field(0, ge=0)

class Filters(BaseModel):
    tags: list[str] = []

@app.get("/items/")
def read_items(
    pagination: Annotated[Pagination, Query()],
    filters: Annotated[Filters, Query()],
    search: str | None = None,
):
    return {"pagination": pagination, "filters": filters, "search": search}
```

请求示例：

```
/items/?limit=5&offset=10&tags=red&tags=blue&search=shirt
```

重要行为：

| 行为 | 说明 |
|---|---|
| 参数层级 | 仍是**同一层级**（扁平），URL 中没有 `pagination` 或 `filters` 键 |
| 独立校验 | 每个模型用自己的默认值、字段验证器、模型验证器独立校验 |
| 共享参数名 | 若模型间共享参数名/别名，各自独立校验；OpenAPI 只列出一次 |
| `extra` 配置作用域 | 作用于**所有**查询参数（含其他模型/依赖项中声明的） |
| `extra="forbid"` | 模型之外的任何参数都被拒绝 |
| `extra="allow"` | 额外参数作为该模型的额外数据被纳入 |

> 这些规则同样适用于 `Header` 与 `Cookie` 模型。

### 4. 可选查询参数模型

用 `| None` 并把默认值设为 `None`，可让整组参数变为可选：

```python
from datetime import date
from typing import Annotated
from fastapi import FastAPI, Query
from pydantic import BaseModel

app = FastAPI()

class DateRange(BaseModel):
    start: date
    end: date

@app.get("/items/")
async def read_items(
    limit: int = 10,
    date_range: Annotated[DateRange | None, Query()] = None,
):
    return {"limit": limit, "date_range": date_range}
```

行为规则：

| 请求情况 | 结果 |
|---|---|
| 既未发 `start` 也未发 `end` | `date_range` 为 `None` |
| 发送了其中任意一个 | FastAPI 校验整个模型，要求两个字段都提供 |
| 只写 `| None` 但不设默认值 | 参数仍**必需** |
| 被忽略的额外参数 | 不会让模型被视为"已提供" |

OpenAPI 会逐一列出这组字段并标记为可选。也可声明可选的 header 模型与 cookie 模型。

### 5. 易错点小结

- ✅ 模型参数必须标 `Query()`，否则会被当作请求体（Pydantic 模型默认按请求体解析）。
- ✅ 查询参数在 URL 中是**扁平**的，不会嵌套成 `pagination[limit]` 之类。
- ✅ 是否可选看**默认值**：`= None` 才可选，仅 `| None` 仍必需。
- ✅ `extra="forbid"` 会拒绝所有"模型之外"的查询参数，包括其他模型里的字段——组合多模型时慎用。
- ✅ 该特性需 FastAPI ≥ 0.115.0。

## 二、NestJS 对比

| 维度 | FastAPI（Python） | NestJS（TypeScript） |
|---|---|---|
| 参数模型定义 | Pydantic `BaseModel` 字段 + `Field(gt=...)`, 用 `Annotated[Model, Query()]` 标注 | DTO 类 + `class-validator` 装饰器，用 `@Query() dto: Dto` 注入 |
| 复用方式 | 同一模型可在多个路径操作复用，校验规则随模型走 | 同一 DTO 类可在多个 handler 复用，规则随 DTO 走 |
| 多模型组合 | `pagination: Annotated[Pagination, Query()]`, `filters: Annotated[Filters, Query()]` | 多个 `@Query()` 参数，或用 `@Query() dto` + `@Query('search')` 混用 |
| 扁平 vs 嵌套 | URL 参数始终扁平，模型只是"视图"，不产生嵌套键 | `@Query()` 取平铺参数；`@Query('obj')` 配合 `allowDots`/`transform` 可解析嵌套 |
| 禁止额外字段 | `model_config = {"extra": "forbid"}`（Pydantic） | `ValidationPipe({ forbidNonWhitelisted: true, whitelist: true })` |
| 可选整组参数 | `date_range: Annotated[DateRange | None, Query()] = None` | DTO 字段 `@IsOptional()`，或用 `@Query()` 可选注入 |
| 错误格式 | `422` + `loc:["query","tool"]` + `type:"extra_forbidden"` | `BadRequestException`（400），可自定义 `exceptionFactory` |
| 文档生成 | 模型字段自动进入 OpenAPI，共享参数只列一次 | 需 `@ApiProperty()` 标注 DTO 字段；共享参数需手动保持一致 |

**核心差异一句话**：FastAPI 的查询参数模型是 Pydantic 模型的一种"使用姿势"——同一套模型声明既能做请求体也能做查询参数，靠 `Query()` 切换来源；NestJS 的 DTO 本身不区分来源，靠 `@Query()`/`@Body()` 装饰器决定从哪取，禁止额外字段则依赖全局 `ValidationPipe` 配置而非 DTO 自身。

## 三、针对性练习题

### 题 1（基础）

用 Pydantic 模型声明一组查询参数：`limit`（int，默认 10，范围 1～100）、`offset`（int，默认 0，≥0），并写 `GET /items/` 使用它。

<details>
<summary>参考答案</summary>

```python
from typing import Annotated
from fastapi import FastAPI, Query
from pydantic import BaseModel, Field

app = FastAPI()

class Pagination(BaseModel):
    limit: int = Field(10, ge=1, le=100)
    offset: int = Field(0, ge=0)

@app.get("/items/")
async def read_items(page: Annotated[Pagination, Query()]):
    return page
```

访问 `/items/?limit=5&offset=10` → `{"limit":5,"offset":10}`；不传则用默认值。
</details>

### 题 2（理解）

为什么模型参数必须写 `Annotated[FilterParams, Query()]`（或旧式 `= Query()`）？如果只写 `filter_query: FilterParams` 会怎样？

<details>
<summary>参考答案</summary>

因为 Pydantic 模型类型的函数参数默认会被 FastAPI 解释为**请求体**（见第 04 章的参数识别规则）。显式加 `Query()` 是把来源"改写"为查询参数，让 FastAPI 从 URL 查询字符串中逐字段提取并组装模型。

若只写 `filter_query: FilterParams`，FastAPI 会从请求体中解析该模型，查询参数不会进入它；对 GET 请求而言请求体通常为空，会导致校验失败（缺少必填字段）或模型为空。
</details>

### 题 3（辨析/代码）

设置 `model_config = {"extra": "forbid"}` 后，下面请求分别返回什么？

```python
class FilterParams(BaseModel):
    model_config = {"extra": "forbid"}
    limit: int = 100
```

- `/items/?limit=10`
- `/items/?limit=10&tool=plumbus`

<details>
<summary>参考答案</summary>

- `/items/?limit=10` → 正常，`limit=10`。
- `/items/?limit=10&tool=plumbus` → `422` 错误：
```json
{"detail":[{"type":"extra_forbidden","loc":["query","tool"],"msg":"Extra inputs are not permitted","input":"plumbus"}]}
```

`extra="forbid"` 拒绝任何模型未声明的查询参数。注意它会作用于所有查询参数，包括其他模型或依赖项中声明的字段——组合多模型时要小心。
</details>

### 题 4（进阶 · NestJS 迁移视角）

NestJS 中用 DTO + 全局 `ValidationPipe({ whitelist: true, forbidNonWhitelisted: true })` 限制查询参数。请写出等价的 FastAPI 声明，并说明两者"禁止额外字段"的实现位置有何不同。

<details>
<summary>参考答案</summary>

```python
from typing import Annotated
from fastapi import FastAPI, Query
from pydantic import BaseModel

app = FastAPI()

class FilterParams(BaseModel):
    model_config = {"extra": "forbid"}
    limit: int = 100

@app.get("/items/")
async def read_items(f: Annotated[FilterParams, Query()]):
    return f
```

不同点：NestJS 的"禁止额外字段"是**全局管道配置**（`whitelist` + `forbidNonWhitelisted`），对所有 DTO 统一生效，DTO 本身不表达该策略；FastAPI 则把策略写在**模型自身**（`model_config = {"extra":"forbid"}`），随模型复用，粒度更细但需每个模型自行声明。
</details>

### 题 5（思考）

声明 `date_range: Annotated[DateRange | None, Query()] = None`（`DateRange` 有必填 `start`、`end`）。请说明：只传 `?start=2024-01-01`、什么都不传、以及只写 `| None` 但去掉 `= None` 时分别会怎样？

<details>
<summary>参考答案</summary>

- 只传 `?start=2024-01-01`：FastAPI 认为要校验该模型，由于 `end` 缺失 → `422`（`type: missing`，`loc: ["query","end"]`）。模型是"要么整体不提供，要提供就必须两个字段齐全"。
- 什么都不传：`date_range` 为 `None`，正常返回。
- 去掉 `= None`（只写 `| None`）：参数变为**必需**，即使类型含 `None` 也不会让请求可省略——`date_range` 必须被提供，否则 `422`。`| None` 只影响类型检查，可选性只看默认值。

补充：被 `extra` 配置忽略的额外参数不会让模型被视为"已提供"。
</details>
