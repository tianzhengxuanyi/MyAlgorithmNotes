## 一、章节笔记

### 1. 核心概念

FastAPI 支持依赖其他依赖的依赖项，且可声明**任意深度**的子依赖嵌套。框架负责解析不同深度的子依赖并按正确顺序调用。

术语：

- **dependable（可依赖对象）**：被别人依赖、本身可被调用的对象。
- **dependant（依赖方）**：声明了自己依赖的对象。

一个函数可以同时是 dependable 和 dependant——它既被上层使用，自身又声明依赖。

### 2. 第一层依赖

```python
def query_extractor(q: str | None = None):
    return q
```

它声明可选查询参数 `q` 并返回其值。虽然简单，但有助于专注理解子依赖机制。

### 3. 第二层依赖：既依赖别人，又被别人依赖

```python
from typing import Annotated

from fastapi import Cookie, Depends, FastAPI

app = FastAPI()

def query_extractor(q: str | None = None):
    return q

def query_or_cookie_extractor(
    q: Annotated[str, Depends(query_extractor)],
    last_query: Annotated[str | None, Cookie()] = None,
):
    if not q:
        return last_query
    return q

@app.get("/items/")
async def read_query(
    query_or_default: Annotated[str, Depends(query_or_cookie_extractor)],
):
    return {"q_or_cookie": query_or_default}
```

参数要点：

| 参数 | 来源 | 说明 |
|---|---|---|
| `q` | 子依赖 `query_extractor` | 依赖 `query_extractor`，并把其返回值赋给 `q` |
| `last_query` | Cookie（可选） | 用户未提供查询参数 `q` 时，使用上次保存在 cookie 中的查询 |

注意：路径操作函数里**只声明了一个依赖** `query_or_cookie_extractor`，但 FastAPI 必须先处理 `query_extractor`，再用其返回值调用上层依赖。

调用链：`query_extractor → query_or_cookie_extractor → read_query(/items/)`。

### 4. 多次使用同一依赖与缓存

若同一路径操作中多次声明同一依赖（例如多个依赖共用一个子依赖），FastAPI 在同一请求内**只调用一次**该子依赖，并把返回值**缓存**后传给所有依赖方。

若不想用缓存、希望每一步都真正调用，可用 `Depends(..., use_cache=False)`：

```python
from typing import Annotated
from fastapi import Depends

async def needy_dependency(
    fresh_value: Annotated[str, Depends(get_value, use_cache=False)],
):
    return {"fresh_value": fresh_value}
```

旧式写法：`async def needy_dependency(fresh_value: str = Depends(get_value, use_cache=False)): ...`

### 5. 小结与易错点

依赖注入本质就是「与路径操作函数一样的函数」，但能声明任意嵌套深度的树/图结构。当前例子虽简单，但在后续「安全」章节中会成为减少重复代码的关键。

易错点：

- ✅ 子依赖的返回值通过参数名注入（如 `q: Annotated[str, Depends(query_extractor)]`）。
- ✅ 同一请求内依赖默认被缓存，避免重复执行；必要时设 `use_cache=False`。
- ✅ 子依赖本身也可以有子依赖，`Cookie`、`Header` 等可混用。
- ✅ 路径操作函数只需声明顶层依赖，整条链由 FastAPI 自动解析。

## 二、NestJS 对比

| 维度 | FastAPI（Python） | NestJS（TypeScript） |
|---|---|---|
| 子依赖声明 | 依赖函数的参数里再写 `Depends(child)` | Provider 构造器里再注入另一个 Provider：`constructor(private child: ChildService)` |
| 解析方式 | 框架自动解析任意深度依赖树 | IoC 容器按元数据解析 Provider 依赖图 |
| 请求数据混入 | 子依赖参数可为 Query/Cookie/Header 等，自动提取 | Provider 不直接拿请求数据；需配合 `@Req/@Query` 或 `REQUEST` 作用域 |
| 缓存 / 复用 | 同一请求内同一依赖默认只执行一次并缓存 | Provider 默认单例；请求作用域 provider 每次请求新建 |
| 关闭缓存 | `Depends(func, use_cache=False)` | 无直接等价；改用 `Scope.TRANSIENT` 或多实例 |
| 注册要求 | 无需注册，函数直接传 `Depends` | 每个 Provider 需 `@Injectable()` 并在模块注册 |
| 文档集成 | 子依赖参数自动并入 OpenAPI | Provider 参数不进文档，需 DTO + Swagger |

**核心差异一句话**：FastAPI 用「参数里再嵌 `Depends`」即可形成任意深度子依赖树并按请求缓存；NestJS 通过构造器注入已注册的 Provider 形成依赖图，默认是单例语义，请求数据需另行用装饰器获取。

## 三、针对性练习题

### 题 1（基础）
写一个依赖 `token_from_header(x_token: str = Header())` 返回 token，再写第二层依赖 `wrap_token(t: str = Depends(token_from_header))` 返回 `{"token": t}`，在 `GET /secure/` 中注入并返回。

<details>
<summary>参考答案</summary>

```python
from typing import Annotated
from fastapi import Depends, FastAPI, Header

app = FastAPI()

def token_from_header(x_token: Annotated[str, Header()]):
    return x_token

def wrap_token(t: Annotated[str, Depends(token_from_header)]):
    return {"token": t}

@app.get("/secure/")
async def secure(wrapped: Annotated[dict, Depends(wrap_token)]):
    return wrapped
```

调用链：`token_from_header → wrap_token → secure`，只声明顶层依赖 `wrap_token`。
</details>

### 题 2（理解）
什么是「dependable」和「dependant」？为什么一个函数可以同时是两者？

<details>
<summary>参考答案</summary>

dependable 是被依赖、可被 FastAPI 调用的对象；dependant 是声明了自己依赖的对象。当函数 A 依赖函数 B、同时又被路径操作函数依赖时，A 既要被上层调用（是 dependable），自身又声明了对 B 的依赖（是 dependant），所以可兼具两种角色。FastAPI 会先解析 B，再调用 A。
</details>

### 题 3（辨析 / 代码）
下面的例子里，路径操作函数只声明了一个依赖。实际执行顺序是什么？

```python
def a(q: str | None = None): return q
def b(x: str = Depends(a)): return x or "default"
@app.get("/x/")
def read(x: str = Depends(b)): return {"x": x}
```

<details>
<summary>参考答案</summary>

执行顺序：`a → b → read`。FastAPI 看到 `read` 依赖 `b`，而 `b` 又依赖 `a`，因此先调用 `a`（提取查询参数 `q`），把返回值赋给 `b` 的参数 `x` 再调用 `b`，最后把 `b` 的返回值注入 `read` 的 `x`。无需手动串联。
</details>

### 题 4（进阶 · NestJS 迁移视角）
在 NestJS 中，Service A 依赖 Service B，通过构造器注入。请用 FastAPI 写出功能等价的「两层依赖」示例，并说明缓存行为差异。

<details>
<summary>参考答案</summary>

```python
from typing import Annotated
from fastapi import Depends, FastAPI

app = FastAPI()

def service_b(): return {"value": 42}

def service_a(b: Annotated[dict, Depends(service_b)]):
    return {"a": b["value"]}

@app.get("/data/")
def get_data(a: Annotated[dict, Depends(service_a)]):
    return a
```

差异：FastAPI 在同一请求内对同一依赖默认缓存（只执行一次），所有依赖方共享结果；若需每次重算，设 `Depends(service_b, use_cache=False)`。NestJS Provider 默认单例（跨请求共享同一实例），请求作用域需 `Scope.REQUEST`，没有「同一请求内缓存函数结果」的直接对应概念。
</details>

### 题 5（思考）
为什么「同一请求内同一依赖只执行一次并缓存」很重要？什么场景下需要 `use_cache=False`？

<details>
<summary>参考答案</summary>

缓存避免在同一请求中因多个依赖共用同一子依赖而重复执行昂贵逻辑（如重复查数据库、重复鉴权），提升效率并保证同一请求内结果一致。若依赖有副作用或必须每次获取最新值（如每次都要重新读取计数器、生成随机数、刷新 token），则应设 `use_cache=False`，让每一步真实调用。
</details>
