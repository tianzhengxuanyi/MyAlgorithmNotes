## 一、章节笔记

### 1. 请求体与响应体

- **请求体（Request Body）**：客户端发送给 API 的数据。
- **响应体（Response Body）**：API 返回给客户端的数据。

API 几乎总要发送响应体，但客户端不一定发送请求体（可能只请求路径 + 查询参数）。发送数据的推荐方法是 `POST`（最常用）、`PUT`、`DELETE`、`PATCH`。规范未定义 `GET` 携带请求体的行为——FastAPI 虽支持，但仅用于极复杂场景，且 Swagger UI 不会显示其请求体文档、中间代理也可能不支持。

用 **Pydantic 模型**声明请求体，可充分利用其类型校验、序列化、文档生成等能力。

### 2. 定义 Pydantic 模型

从 `pydantic` 导入 `BaseModel`，把数据模型声明为继承它的类，用 Python 标准类型注解声明属性：

```python
from fastapi import FastAPI
from pydantic import BaseModel

class Item(BaseModel):
    name: str
    description: str | None = None
    price: float
    tax: float | None = None

app = FastAPI()

@app.post("/items/")
async def create_item(item: Item):
    return item
```

- 带默认值的属性是**可选**的，没有默认值的是**必选**的；默认值设为 `None` 使其可选。
- 因此 `{"name":"Foo","price":45.2}` 合法（省略 `description`、`tax`），带全字段的也合法。

### 3. 把模型声明为参数

像声明路径/查询参数一样，把模型加到路径操作并把类型设为模型类 `Item`：

```python
@app.post("/items/")
async def create_item(item: Item):
    return item
```

仅凭这些类型声明，FastAPI 就会：

| 能力 | 说明 |
|---|---|
| 读取请求体 | 以 JSON 形式读入 |
| 类型转换 | 必要时转为模型声明的类型 |
| 数据校验 | 不符合声明返回清晰错误，并指出确切位置与内容 |
| 参数赋值 | 把解析后的数据赋给参数 `item` |
| 编辑器支持 | 函数内获得属性补全、类型检查 |
| Schema 生成 | 为模型生成 JSON Schema，纳入 OpenAPI，供文档 UI 使用 |

### 4. 自动文档与编辑器支持

- 模型的 JSON Schema 成为 OpenAPI Schema 的一部分，显示在交互文档（`/docs`）中，并被每个使用该模型的路径操作复用。
- 若函数参数是 Pydantic 模型，编辑器内可获得所有属性的补全与错误类型检查；换成普通 `dict` 则没有这些支持。
- PyCharm 用户可安装 Pydantic PyCharm 插件，增强补全、类型检查、重构、查找与代码审查。

### 5. 在函数中使用模型

函数内可直接访问模型对象的所有属性；用 `model_dump()` 转成 dict：

```python
from fastapi import FastAPI
from pydantic import BaseModel

class Item(BaseModel):
    name: str
    description: str | None = None
    price: float
    tax: float | None = None

app = FastAPI()

@app.post("/items/")
async def create_item(item: Item):
    item_dict = item.model_dump()
    if item.tax is not None:
        price_with_tax = item.price + item.tax
        item_dict.update({"price_with_tax": price_with_tax})
    return item_dict
```

### 6. 请求体 + 路径参数

可同时声明路径参数与请求体；FastAPI 按类型与位置自动区分：

```python
from fastapi import FastAPI
from pydantic import BaseModel

class Item(BaseModel):
    name: str
    description: str | None = None
    price: float
    tax: float | None = None

app = FastAPI()

@app.put("/items/{item_id}")
async def update_item(item_id: int, item: Item):
    return {"item_id": item_id, **item.model_dump()}
```

### 7. 请求体 + 路径 + 查询参数

三者可同时声明，FastAPI 分别从不同位置取数：

```python
from fastapi import FastAPI
from pydantic import BaseModel

class Item(BaseModel):
    name: str
    description: str | None = None
    price: float
    tax: float | None = None

app = FastAPI()

@app.put("/items/{item_id}")
async def update_item(item_id: int, item: Item, q: str | None = None):
    result = {"item_id": item_id, **item.model_dump()}
    if q:
        result.update({"q": q})
    return result
```

**参数识别规则**：

| 参数特征 | 判定为 |
|---|---|
| 名字在路径中声明过 | 路径参数 |
| 单一类型（`int`/`float`/`str`/`bool` 等） | 查询参数 |
| 类型声明为 Pydantic 模型 | 请求体 |

> 注意：`q` 的非必填是由默认值 `= None` 决定的，**不是**由 `str | None` 决定；类型注解主要是为编辑器提供更好支持。

### 8. 不使用 Pydantic 也能用 Body

即便不用 Pydantic 模型也能声明 Body 参数（如请求体中的单值），详见后续"请求体 - 多个参数"章节。

### 9. 易错点小结

- ✅ 请求体用 Pydantic 模型声明；模型属性默认值决定必选/可选。
- ✅ `GET` 虽可接受请求体但不推荐，文档与代理支持都不佳。
- ✅ 是否必填看**默认值**，不看类型里的 `None`。
- ✅ 用 `item.model_dump()` 获取 dict，而非手动逐字段取值。

## 二、NestJS 对比

| 维度 | FastAPI（Python） | NestJS（TypeScript） |
|---|---|---|
| 请求体声明 | 函数参数类型标注为 Pydantic 模型 `item: Item` | 参数装饰器 `@Body() item: CreateItemDto` |
| DTO / 模型定义 | `class Item(BaseModel)` + 类型注解 | DTO 类 + `class-validator` 装饰器（`@IsString()` 等） |
| 类型转换 | Pydantic 自动从 JSON 转换并校验 | `ValidationPipe`（配合 `transform: true`）用 `class-transformer` 转 DTO 实例 |
| 必选/可选判定 | 属性有无默认值；`= None` 表可选 | `@IsOptional()` 表可选，否则必填 |
| 多来源参数 | 路径/查询/请求体靠类型与名字自动区分 | 需分别用 `@Param` / `@Query` / `@Body` 装饰器显式标注 |
| 校验错误格式 | Pydantic 统一 `422` + `loc/type/msg` | `ValidationPipe` 抛 `BadRequestException`（400），结构可自定义 |
| 编辑器支持 | Pydantic 模型带来属性补全与类型检查 | TypeScript DTO + IDE 同样有补全，依赖装饰器元数据 |
| 文档 / Schema | 模型 JSON Schema 自动进入 OpenAPI | 需 `@nestjs/swagger` 的 `@ApiProperty()` 标注每个 DTO 字段 |

**核心差异一句话**：FastAPI 用一个 Pydantic 模型类同时承担 DTO、校验、序列化与文档 Schema 四种角色，靠类型注解"隐式"接线；NestJS 把 DTO 定义、`class-validator` 校验、`ValidationPipe` 转换、`@nestjs/swagger` 文档拆成多个显式部分，配置更繁琐但每层都可独立替换与定制。

## 三、针对性练习题

### 题 1（基础）

定义一个 `Item` 模型（`name: str`、`price: float`，`description` 与 `tax` 可选），写 `POST /items/` 接收它并原样返回。说明哪些 JSON 是合法的。

<details>
<summary>参考答案</summary>

```python
from fastapi import FastAPI
from pydantic import BaseModel

class Item(BaseModel):
    name: str
    description: str | None = None
    price: float
    tax: float | None = None

app = FastAPI()

@app.post("/items/")
async def create_item(item: Item):
    return item
```

合法 JSON 包括：
```json
{"name": "Foo", "description": "An optional description", "price": 45.2, "tax": 3.5}
```
以及省略可选字段的：
```json
{"name": "Foo", "price": 45.2}
```
`name` 和 `price` 没有默认值，是必选的。
</details>

### 题 2（理解）

仅靠 `item: Item` 这一行类型声明，FastAPI 完成了哪些事情？请至少列出 5 项。

<details>
<summary>参考答案</summary>

① 以 JSON 形式读取请求体；② 必要时把请求体转换为声明的类型；③ 校验数据；④ 数据无效时返回清晰错误并指出确切位置与内容；⑤ 把数据赋给参数 `item`；⑥ 提供属性补全等编辑器支持；⑦ 为模型生成 JSON Schema 并纳入 OpenAPI，供文档 UI 使用。
</details>

### 题 3（辨析/代码）

下面代码中，`q` 是否必填由什么决定？如果把 `q: str | None = None` 改成 `q: str | None`（去掉默认值），会出现什么情况？

```python
@app.put("/items/{item_id}")
async def update_item(item_id: int, item: Item, q: str | None = None):
    ...
```

<details>
<summary>参考答案</summary>

`q` 是否必填由**默认值**决定：`= None` 使其可选，而不是 `str | None` 类型本身。

改成 `q: str | None`（无默认值）后，`q` 变成**必选查询参数**——请求必须提供 `?q=...`，否则返回 `422`（`type: missing`）。类型里保留 `| None` 只是告诉编辑器它可能为 `None`，但若没默认值且传了 `q=null` 之外的请求仍会因缺失而报错。结论：是否必填看默认值，类型注解服务于静态检查。
</details>

### 题 4（进阶 · NestJS 迁移视角）

NestJS 中你这样写：

```ts
@Put(':id')
update(@Param('id', ParseIntPipe) id: number, @Body() dto: UpdateItemDto) {
  return this.service.update(id, dto);
}
```

请写出等价 FastAPI 代码，并说明 NestJS 的 DTO + `ValidationPipe` 在 FastAPI 中对应什么。

<details>
<summary>参考答案</summary>

```python
from fastapi import FastAPI
from pydantic import BaseModel

class Item(BaseModel):
    name: str
    description: str | None = None
    price: float
    tax: float | None = None

app = FastAPI()

@app.put("/items/{item_id}")
async def update_item(item_id: int, item: Item):
    return {"item_id": item_id, **item.model_dump()}
```

对应关系：NestJS 的 DTO 类对应 FastAPI 的 Pydantic 模型 `Item`；`ValidationPipe` 的转换与校验职责在 FastAPI 中由 Pydantic 依据类型注解自动完成（无需显式挂载 Pipe）。此外 FastAPI 靠参数名和类型自动区分路径参数与请求体，取代了 `@Param` / `@Body` 装饰器。
</details>

### 题 5（思考）

在 `PUT /items/{item_id}` 中同时声明 `item_id: int`、`item: Item`、`q: str | None = None`，FastAPI 依据什么规则把三者分别从 URL 路径、请求体、查询字符串中取出？

<details>
<summary>参考答案</summary>

依据"名字 + 类型"两条规则：
- `item_id` 出现在路径模板 `/items/{item_id}` 中 → 从路径取；
- `item` 的类型是 Pydantic 模型 → 从请求体取；
- `q` 是单一类型 `str` 且不在路径中 → 从查询字符串取，默认值 `None` 使其可选。

FastAPI 在解析请求时按这些规则自动分流，开发者无需为每个来源写装饰器。
</details>
