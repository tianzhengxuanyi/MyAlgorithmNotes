## 一、章节笔记

### 1. 总览：任意深度的嵌套模型

借助 Pydantic，FastAPI 可以定义、校验、记录文档并使用**任意深度嵌套**的模型，同时保持代码简洁。

### 2. `List` 字段与带类型参数的 list

把属性声明为 `list` 即可接收列表，但不声明元素类型时**不校验元素**：

```python
class Item(BaseModel):
    name: str
    tags: list = []
```

用 Python 标准泛型语法 `list[str]` 明确元素类型，FastAPI 会校验并记录每个元素必须是字符串：

```python
from fastapi import FastAPI
from pydantic import BaseModel

app = FastAPI()

class Item(BaseModel):
    name: str
    description: str | None = None
    price: float
    tax: float | None = None
    tags: list[str] = []

@app.put("/items/{item_id}")
async def update_item(item_id: int, item: Item):
    return {"item_id": item_id, "item": item}
```

类型参数语法 `Type[Inner]` 适用于 `list`、`dict`、`tuple` 等。

### 3. `Set` 类型：元素唯一

标签通常不应重复，用 `set[str]` 替代 `list[str]`：

```python
from pydantic import BaseModel

class Item(BaseModel):
    tags: set[str] = set()
```

效果：

- 即使请求带重复数据，也会被转换为**唯一项集合**。
- 输出时（即便源数据有重复）也以唯一项形式输出。
- 文档中相应标记为 set 类型。

### 4. 嵌套模型（子模型作为属性类型）

模型的属性类型可以是另一个 Pydantic 模型，从而描述具有特定字段名、类型与校验的深层 JSON 对象。

定义子模型 `Image` 并用作 `Item.image` 的类型：

```python
from fastapi import FastAPI
from pydantic import BaseModel

app = FastAPI()

class Image(BaseModel):
    url: str
    name: str

class Item(BaseModel):
    name: str
    description: str | None = None
    price: float
    tax: float | None = None
    tags: set[str] = set()
    image: Image | None = None

@app.put("/items/{item_id}")
async def update_item(item_id: int, item: Item):
    return {"item_id": item_id, "item": item}
```

期望请求体：

```json
{
  "name": "Foo",
  "description": "The pretender",
  "price": 42.0,
  "tax": 3.2,
  "tags": ["rock", "metal", "bar"],
  "image": {
    "url": "http://example.com/baz.jpg",
    "name": "The Foo live"
  }
}
```

对嵌套的子模型同样获得：编辑器支持（补全）、数据转换、数据校验、自动文档。

### 5. 特殊类型与校验：`HttpUrl`

属性类型可以是继承自 `str` 的更复杂类型。例如把 `Image.url` 从 `str` 改为 Pydantic 的 `HttpUrl`：

```python
from fastapi import FastAPI
from pydantic import BaseModel, HttpUrl

app = FastAPI()

class Image(BaseModel):
    url: HttpUrl
    name: str

class Item(BaseModel):
    name: str
    tags: set[str] = set()
    image: Image | None = None

@app.put("/items/{item_id}")
async def update_item(item_id: int, item: Item):
    return {"item_id": item_id, "item": item}
```

该字符串会被检查是否为**有效 URL**，并在 JSON Schema / OpenAPI 中记录。更多可用类型见 Pydantic 类型概览（下一章会举例）。

### 6. 一组子模型：`list[Image]`

Pydantic 模型也可作为 `list`、`set` 等的元素类型：

```python
from pydantic import BaseModel, HttpUrl

class Image(BaseModel):
    url: HttpUrl
    name: str

class Item(BaseModel):
    name: str
    tags: set[str] = set()
    images: list[Image] | None = None
```

期望请求体：

```json
{
  "name": "Foo",
  "tags": ["rock", "metal", "bar"],
  "images": [
    { "url": "http://example.com/baz.jpg", "name": "The Foo live" },
    { "url": "http://example.com/dave.jpg", "name": "The Baz" }
  ]
}
```

`images` 是一个 image 对象列表，其中每个元素都会被转换、校验并记录文档。

### 7. 深度嵌套模型

可以任意组合嵌套层次。例如 `Offer` 包含 `Item` 列表，而 `Item` 又包含可选的 `Image` 列表：

```python
from fastapi import FastAPI
from pydantic import BaseModel, HttpUrl

app = FastAPI()

class Image(BaseModel):
    url: HttpUrl
    name: str

class Item(BaseModel):
    name: str
    description: str | None = None
    price: float
    tax: float | None = None
    tags: set[str] = set()
    images: list[Image] | None = None

class Offer(BaseModel):
    name: str
    description: str | None = None
    price: float
    items: list[Item]

@app.post("/offers/")
async def create_offer(offer: Offer):
    return offer
```

### 8. 纯列表请求体

若期望 JSON 最外层就是一个数组（Python `list`），像声明模型一样声明该类型即可：

```python
from fastapi import FastAPI
from pydantic import BaseModel, HttpUrl

app = FastAPI()

class Image(BaseModel):
    url: HttpUrl
    name: str

@app.post("/images/multiple/")
async def create_multiple_images(images: list[Image]):
    return images
```

参数声明 `images: list[Image]` 对应顶层 JSON 数组，其中每个元素按 `Image` 模型校验。

### 9. 无处不在的编辑器支持

即使是列表中的元素也能获得编辑器补全等支持。若直接用 `dict` 而非 Pydantic 模型，则没有这些支持——不过传入的 dict 会自动转换、输出会自动转为 JSON，无需担心转换本身。

### 10. 任意 `dict` 构成的请求体

可将请求体声明为"键为某类型、值为另一类型"的 `dict`，适合事先不知道有效字段名、或键不是字符串的场景：

```python
from fastapi import FastAPI

app = FastAPI()

@app.post("/index-weights/")
async def create_index_weights(weights: dict[int, float]):
    return weights
```

要点：

- JSON 只支持 `str` 作为键，但 Pydantic 会自动转换数据。
- 客户端只能发字符串键，只要字符串内容是整数（如 `"1"`），Pydantic 就会转成 `int` 键并校验。
- 函数收到的 `weights` 实际是 `int` 键、`float` 值的 `dict`。

### 11. 易错点小结

- ✅ `list` 不写元素类型就不校验内容；`list[str]`、`list[Image]` 才会逐元素校验。
- ✅ `set[str]` 自动去重，适合标签类数据。
- ✅ 嵌套模型与子模型的容器（`list[Image]`、`dict[int, float]`）同样享受转换、校验、文档。
- ✅ 顶层是数组时用 `images: list[Image]`，不用 Pydantic 模型。
- ✅ JSON 键是字符串，但 `dict[int, float]` 由 Pydantic 自动把字符串数字键转为 int。

## 二、NestJS 对比

| 维度 | FastAPI（Python） | NestJS（TypeScript） |
|---|---|---|
| 列表字段 | `tags: list[str] = []`，元素类型直接写在泛型里 | DTO 属性 `tags: string[]` + `@IsString({ each: true })` |
| 去重集合 | `tags: set[str] = set()`，自动去重并输出唯一项 | TS 无 set 类型自动去重；需 `@Transform(({value}) => [...new Set(value)])` |
| 子模型嵌套 | 属性类型直接是另一个 `BaseModel`（`image: Image | None`） | DTO 属性用嵌套 DTO 类型 + `@ValidateNested()` + `@Type(() => ImageDto)` |
| 特殊类型 | `HttpUrl` 校验 URL 并写入 Schema | `@IsUrl()` 校验；类型仍是 `string` |
| 子模型列表 | `images: list[Image] | None` | `images: ImageDto[]` + `@ValidateNested({ each: true })` + `@Type(() => ImageDto)` |
| 顶层数组请求体 | `images: list[Image]` 直接作为参数 | `@Body() images: ImageDto[]`（需 `ValidationPipe({ transform: true })`） |
| 任意键 dict | `weights: dict[int, float]`，Pydantic 自动转换字符串数字键 | `@IsObject()` + Record 类型；数字键需自行转换 |
| 编辑器支持 | Pydantic 模型使列表元素、嵌套字段都有补全 | TypeScript 类型提供静态补全，但装饰器元数据与运行时校验分离 |

**核心差异一句话**：FastAPI 的嵌套完全由 Python 类型注解表达（`list[Image]`、`dict[int, float]`），Pydantic 据此自动完成嵌套转换、逐元素校验、去重与文档；NestJS 的嵌套 DTO 除了 TS 类型外，还必须显式加 `@ValidateNested()` + `@Type()` 让 `class-transformer` 在运行时知道如何实例化，配置更繁琐。

## 三、针对性练习题

### 题 1（基础）

定义 `Item` 模型：`tags` 为字符串列表、`image` 为可选的 `Image` 子模型（`url: str`、`name: str`）。写出模型与 `PUT /items/{item_id}`。

<details>
<summary>参考答案</summary>

```python
from fastapi import FastAPI
from pydantic import BaseModel

app = FastAPI()

class Image(BaseModel):
    url: str
    name: str

class Item(BaseModel):
    name: str
    tags: list[str] = []
    image: Image | None = None

@app.put("/items/{item_id}")
async def update_item(item_id: int, item: Item):
    return {"item_id": item_id, "item": item}
```

期望请求体中 `image` 是嵌套对象：`{"name":"Foo","tags":["a"],"image":{"url":"...","name":"..."}}`。
</details>

### 题 2（理解）

`tags: list`、`tags: list[str]`、`tags: set[str]` 三种声明有什么差别？

<details>
<summary>参考答案</summary>

- `list`：只要求是列表，**不校验元素类型**，文档也不体现元素类型。
- `list[str]`：校验每个元素都是字符串，并写入文档；允许重复元素。
- `set[str]`：校验每个元素是字符串，并**自动去重**——请求中的重复数据会被转换为唯一项集合，输出时也是唯一项，文档中标记为 set。
</details>

### 题 3（辨析/代码）

想接收一个顶层为 JSON 数组的请求体（元素为 `Image` 模型），下面哪种声明正确？

```python
A: images: Image
B: images: list[Image]
```

<details>
<summary>参考答案</summary>

B 正确。`images: Image` 期望顶层是单个对象；`images: list[Image]` 才期望顶层是 JSON 数组，且每个元素按 `Image` 模型转换与校验。示例：

```python
@app.post("/images/multiple/")
async def create_multiple_images(images: list[Image]):
    return images
```
</details>

### 题 4（进阶 · NestJS 迁移视角）

NestJS 中嵌套 DTO 通常这样写：

```ts
class ItemDto {
  @ValidateNested({ each: true })
  @Type(() => ImageDto)
  images: ImageDto[];
}
```

请写出等价的 FastAPI 声明，并说明为什么 FastAPI 不需要 `@Type()` 这类装饰器。

<details>
<summary>参考答案</summary>

```python
from pydantic import BaseModel, HttpUrl

class Image(BaseModel):
    url: HttpUrl
    name: str

class Item(BaseModel):
    images: list[Image] | None = None
```

原因：FastAPI/Pydantic 直接读取 Python 类型注解 `list[Image]`，从中就知道元素应解析为 `Image` 模型，并自动完成转换、嵌套校验与 Schema 生成；不需要像 `class-transformer` 那样靠 `@Type()` 在运行时告知"这个数组元素应实例化为哪个类"。NestJS 的 TS 类型在编译后擦除，所以必须靠装饰器保留运行时元信息。
</details>

### 题 5（思考）

声明 `weights: dict[int, float]`，但客户端只能发送 JSON（键必须是字符串，如 `{"1": 1.5}`）。这个请求能被正确处理吗？为什么？

<details>
<summary>参考答案</summary>

能。JSON 只支持字符串键，但 Pydantic 会自动转换数据：只要字符串键的内容是整数（如 `"1"`），Pydantic 就把它转成 `int` 键，并把值转为 `float`。因此函数收到的 `weights` 实际是 `{1: 1.5}` 这样的 `int → float` 字典，同时完成校验与文档记录。若字符串键不是合法整数（如 `"abc"`），则转换失败返回 `422`。
</details>
