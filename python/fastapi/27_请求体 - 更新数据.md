## 一、章节笔记

### 1. 本章要解决什么问题

更新数据有两种语义：**`PUT` 替换式更新**与 **`PATCH` 部分更新**。本章学习如何避免部分更新时被模型的默认值覆盖掉已存储的数据，核心工具是 `exclude_unset` + `model_copy(update=...)` + `jsonable_encoder`。

### 2. 用 PUT 替换式更新

```python
from fastapi import FastAPI
from fastapi.encoders import jsonable_encoder
from pydantic import BaseModel

app = FastAPI()

class Item(BaseModel):
    name: str | None = None
    description: str | None = None
    price: float | None = None
    tax: float = 10.5
    tags: list[str] = []

items = {
    "foo": {"name": "Foo", "price": 50.2},
    "bar": {"name": "Bar", "description": "The bartenders", "price": 62, "tax": 20.2},
    "baz": {"name": "Baz", "description": None, "price": 50.2, "tax": 10.5, "tags": []},
}

@app.get("/items/{item_id}", response_model=Item)
async def read_item(item_id: str):
    return items[item_id]

@app.put("/items/{item_id}", response_model=Item)
async def update_item(item_id: str, item: Item):
    update_item_encoded = jsonable_encoder(item)
    items[item_id] = update_item_encoded
    return update_item_encoded
```

- `PUT` 用于接收**替换现有数据**的数据；客户端应发送完整对象。
- `jsonable_encoder(item)` 把模型转为可存入数据库的 JSON 兼容数据（如 `datetime` → `str`）。

### 3. 替换的陷阱：默认值会覆盖已存储数据

用 `PUT` 把 `bar` 更新为：

```json
{
    "name": "Barz",
    "price": 3,
    "description": null
}
```

因为请求体**未包含**已存储的 `"tax": 20.2`，输入模型会取默认值 `tax: float = 10.5`，最终保存的数据变成 `tax: 10.5` —— 这是 `PUT` 语义下的常见坑。

### 4. 用 PATCH 进行部分更新

`PATCH` 只发送想更新的字段，其余保持不变。它不如 `PUT` 常见，很多团队只用 `PUT` 实现部分更新；**FastAPI 不做任何限制**，但下面展示预期用法。

**核心技巧：三步走**

```python
@app.patch("/items/{item_id}")
async def update_item(item_id: str, item: Item) -> Item:
    stored_item_data = items[item_id]                       # ① 取已存储数据
    stored_item_model = Item(**stored_item_data)            # ② 放入 Pydantic 模型
    update_data = item.model_dump(exclude_unset=True)       # ③ 只取显式设置的字段
    updated_item = stored_item_model.model_copy(update=update_data)  # ④ 生成副本并更新
    items[item_id] = jsonable_encoder(updated_item)         # ⑤ 转为可存库数据并保存
    return updated_item
```

关键点：

| 步骤 | API | 作用 |
|---|---|---|
| 提取已存数据 | `items[item_id]` | 从数据库/存储读取 |
| 构建模型 | `Item(**stored_item_data)` | dict 解包成 Pydantic 模型 |
| 只取更新字段 | `item.model_dump(exclude_unset=True)` | 生成只含**请求中显式设置**字段的 dict，**不含默认值** |
| 合并更新 | `stored_item_model.model_copy(update=update_data)` | 为已存模型创建副本并更新属性（原模型不变） |
| 存储 | `jsonable_encoder(updated_item)` | 类似 `model_dump()`，但确保值可 JSON 化（如 `datetime` → `str`） |

### 5. 部分更新小结（标准流程）

1. （可选）用 `PATCH` 而非 `PUT`。
2. 提取已存储的数据。
3. 把数据放入 Pydantic 模型。
4. 用 `exclude_unset` 生成**不含输入模型默认值**的 dict —— 只更新用户实际设置的值，避免默认值覆盖已存数据。
5. 用 `model_copy(update=...)` 为已存模型创建副本并更新。
6. 用 `jsonable_encoder` 转为可存库形式。
7. 保存到数据库。
8. 返回更新后的模型。

> 💡 事实上 `PUT` 也能用同样技巧实现部分更新，只是 `PATCH` 就是为这种用例设计的，所以用它举例。

### 6. 注意事项

- ⚠️ **输入模型仍会被验证**：想让部分更新可以省略所有属性，需要一个**所有属性都可选**（带默认值或 `None`）的模型。
- 为区分「更新用模型（全部可选）」与「创建用模型（必填）」，可参考第 18 章《更多模型》的多模型思路。
- `Item(**stored_item_data)` 用 `**` 把 dict 解包为关键字参数构造模型。

### 7. 易错点

- ✅ `PUT` 是替换语义：请求体没写的字段会被默认值覆盖，别拿它做部分更新。
- ✅ 部分更新必须用 `model_dump(exclude_unset=True)`，不能用普通 `model_dump()`（后者会带上默认值）。
- ✅ `model_copy(update=...)` 返回**新副本**，不修改原模型。
- ✅ 输入模型字段要全部可选，否则省略字段时校验就失败了。

## 二、NestJS 对比

| 维度 | FastAPI（Python） | NestJS（TypeScript） |
|---|---|---|
| 替换式更新 | `@Put()` + 输入模型 + `jsonable_encoder(item)` 整体替换 | `@Put()` + DTO，Service 里整体 `save(entity)` 覆盖 |
| 部分更新 | `@Patch()` + `model_dump(exclude_unset=True)` + `model_copy(update=...)` | `@Patch()` + `PartialType(CreateDto)`（`@nestjs/mapped-types`），Service 里 `Object.assign(entity, patch)` |
| 区分「未提供」与「默认值」 | `exclude_unset` 只取请求中显式出现的字段 | `PartialType` 让字段可选，但需自行判断 `undefined` 是否等于「未提供」 |
| 更新合并 | `model_copy(update=...)` 返回新副本，类型安全 | `Object.assign` / ORM 的 `merge()`（TypeORM）直接改对象 |
| 存储前转换 | `jsonable_encoder()` 确保 JSON 兼容（`datetime` → str） | ORM 驱动处理；或用 `class-transformer` 转普通对象 |
| 校验 | 输入模型照常校验；要全可选需专门定义更新模型 | `PartialType` 把 `@IsNotEmpty()` 等约束部分转为可选，仍由 `ValidationPipe` 校验 |
| 创建/更新模型分离 | 多 Pydantic 模型 + 继承（第 18 章） | `CreateXDto` / `UpdateXDto extends PartialType(CreateXDto)` |
| 语义约束 | FastAPI 不强制 PUT/PATCH 语义，由开发者选择 | NestJS 同样不强制，可自由用 PUT 实现部分更新 |

**核心差异一句话**：FastAPI 的部分更新靠 Pydantic 的 `exclude_unset` 精确区分「客户端显式提供」与「模型默认值」，再用 `model_copy(update=...)` 不可变地合并，避免默认值覆盖已有数据；NestJS 通常用 `PartialType` 让 DTO 字段可选后由 Service 手动 `Object.assign`/ORM `merge`，是否真正区分「未提供」与 `undefined` 需要开发者自己处理。

## 三、针对性练习题

### 题 1（基础）

写一个 `PUT /items/{item_id}`：请求体为 `Item` 模型，用 `jsonable_encoder` 转换后整体替换 `items[item_id]` 并返回。

<details>
<summary>参考答案</summary>

```python
from fastapi import FastAPI
from fastapi.encoders import jsonable_encoder
from pydantic import BaseModel

app = FastAPI()

class Item(BaseModel):
    name: str | None = None
    description: str | None = None
    price: float | None = None
    tax: float = 10.5

items = {}

@app.put("/items/{item_id}", response_model=Item)
async def update_item(item_id: str, item: Item):
    encoded = jsonable_encoder(item)
    items[item_id] = encoded
    return encoded
```

`PUT` 是替换语义，客户端应发送完整对象。
</details>

### 题 2（理解）

已存储的数据为 `{"name": "Bar", "price": 62, "tax": 20.2}`，用 `PUT` 发送 `{"name": "Barz", "price": 3, "description": null}` 后，`tax` 会变成多少？为什么？

<details>
<summary>参考答案</summary>

会变成默认值 `10.5`。因为请求体没有包含 `tax`，Pydantic 输入模型使用 `tax: float = 10.5` 的默认值，`jsonable_encoder(item)` 后整体替换已存数据，原来的 `20.2` 被默认值覆盖。这正是 `PUT` 替换语义的陷阱 —— 想保留未提供的字段应使用部分更新技巧。
</details>

### 题 3（辨析/代码）

下面 `PATCH` 实现里，把 `item.model_dump(exclude_unset=True)` 换成普通的 `item.model_dump()` 会有什么后果？

```python
@app.patch("/items/{item_id}")
async def update_item(item_id: str, item: Item) -> Item:
    stored_item_model = Item(**items[item_id])
    update_data = item.model_dump(exclude_unset=True)
    updated_item = stored_item_model.model_copy(update=update_data)
    items[item_id] = jsonable_encoder(updated_item)
    return updated_item
```

<details>
<summary>参考答案</summary>

普通 `model_dump()` 会导出**所有字段**（含未提供的字段及其默认值，如 `tax=10.5`、`tags=[]`），用它们去 `update` 会覆盖已存储的值，退化成 `PUT` 式替换。`exclude_unset=True` 保证只取请求中**显式设置**的字段，才是真正的部分更新。
</details>

### 题 4（进阶 · NestJS 迁移视角）

NestJS 中用 `PartialType(CreateItemDto)` 定义更新 DTO，Service 里 `Object.assign(entity, patch)`。写出等价的 FastAPI 部分更新实现，并说明「区分未提供字段」的差异。

<details>
<summary>参考答案</summary>

```python
from fastapi import FastAPI
from fastapi.encoders import jsonable_encoder
from pydantic import BaseModel

app = FastAPI()

class Item(BaseModel):
    name: str | None = None
    description: str | None = None
    price: float | None = None
    tax: float = 10.5
    tags: list[str] = []

items = {}

@app.patch("/items/{item_id}")
async def update_item(item_id: str, item: Item) -> Item:
    stored = Item(**items[item_id])
    update_data = item.model_dump(exclude_unset=True)
    updated = stored.model_copy(update=update_data)
    items[item_id] = jsonable_encoder(updated)
    return updated
```

差异：FastAPI 用 `exclude_unset=True` 精确区分「请求中显式提供的字段」与「模型默认值」；NestJS 的 `PartialType` 只是把字段标记为可选，`Object.assign` 时 `undefined` 与「未提供」的界限需开发者自己判断（例如显式传 `null` 要保留还是忽略），通常还需结合 DTO 校验与 ORM 的 `merge` 策略。
</details>

### 题 5（思考）

为什么部分更新时输入模型的字段要全部可选（带默认值或 `None`）？如果某个字段必填，客户端只想更新另一个字段会怎样？

<details>
<summary>参考答案</summary>

因为输入模型在读取请求时**照常校验**：必填字段缺失会直接返回 422，请求根本到不了更新逻辑。若 `name: str` 必填，客户端只发 `{"price": 9.9}` 想更新价格，会因缺 `name` 被拒绝。解决方法是为更新场景定义**所有字段都可选**的模型（可参考第 18 章：创建用必填模型、更新用全可选模型，通过继承区分），这样才允许省略任意字段实现部分更新。
</details>
