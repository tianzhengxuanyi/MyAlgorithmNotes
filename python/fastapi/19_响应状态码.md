# 19 · 响应状态码（Response Status Code）

> 官方文档：<https://fastapi.tiangolo.com/zh/tutorial/response-status-code/>
> 前置依赖：路径操作基础 · 难度：⭐

---

## 一、章节笔记

### 1. 本章要解决什么问题

HTTP 响应除了数据，还有**三位数的状态码**。FastAPI 默认用 `200`，但创建资源应返回 `201`、删除成功可用 `204`。本章学习用装饰器参数 `status_code` 声明状态码，并用 `fastapi.status` 常量避免死记数字。

### 2. `status_code` 参数

与 `response_model` 一样，`status_code` 是**装饰器方法**（`get`/`post`/`put`/`delete` 等）的参数，**不是**路径操作函数的参数：

```python
from fastapi import FastAPI

app = FastAPI()

@app.post("/items/", status_code=201)
async def create_item(name: str):
    return {"name": name}
```

它接收表示 HTTP 状态码的数字，也可以接收 `IntEnum` 类型（如 Python 的 `http.HTTPStatus`）。作用：

- 在响应中返回该状态码。
- 在 OpenAPI Schema（及文档 UI）中把该状态码记录下来。

> ⚠️ 某些状态码表示「无响应体」（如 `204`），FastAPI 能识别并生成表明无响应体的 OpenAPI 文档。

### 3. `fastapi.status` 快捷常量

不必记住每个数字，用 `fastapi.status` 中语义化的常量，还能获得编辑器自动补全：

```python
from fastapi import FastAPI, status

app = FastAPI()

@app.post("/items/", status_code=status.HTTP_201_CREATED)
async def create_item(name: str):
    return {"name": name}
```

技术细节：`fastapi.status` 与 `starlette.status` **完全相同**，FastAPI 只是为了方便直接来自 Starlette 重新导出（`from starlette import status` 亦可）。

### 4. HTTP 状态码速览

| 范围 | 含义 | 常见码与说明 |
|---|---|---|
| `100-199` | 信息 | 很少直接使用；**不能包含响应体** |
| `200-299` | 成功 | 最常用。`200` 默认「OK」；`201`「已创建」用于新建记录；`204`「无内容」，**不能包含响应体** |
| `300-399` | 重定向 | 不一定有响应体；`304`「未修改」**不得包含响应体** |
| `400-499` | 客户端错误 | 第二常用。`404`「未找到」；一般客户端错误用 `400` |
| `500-599` | 服务端错误 | 几乎不直接手写；应用代码或服务器出问题时自动返回 |

想深入了解各码适用场景，可查阅 MDN 的 HTTP 状态码文档。

### 5. 易错点

- ✅ `status_code` 写在装饰器里，别写进函数参数（那是请求数据的位置）。
- ✅ `201` 这类数字与 `status.HTTP_201_CREATED` 完全等价，优先用常量提升可读性。
- ✅ `204` 等无响应体状态码：FastAPI 会识别并让 OpenAPI 表明无响应体，别给它塞返回数据。
- ✅ 想按条件返回**不同的**状态码（例如有时 `200`、有时 `404`），本章的 `status_code` 只设默认值；具体做法在高级用户指南（返回 `Response` 或抛 `HTTPException`）中介绍。

## 二、NestJS 对比

| 维度 | FastAPI（Python） | NestJS（TypeScript） |
|---|---|---|
| 声明默认状态码 | 装饰器参数 `@app.post("/items/", status_code=201)` | `@HttpCode(201)` 方法装饰器（`@nestjs/common`） |
| 语义化常量 | `status.HTTP_201_CREATED`（来自 `fastapi.status` / `starlette.status`） | `HttpStatus.CREATED`（枚举，来自 `@nestjs/common`） |
| POST 默认码 | `200`（FastAPI 默认，需显式改 `201`） | `201`（NestJS 默认即 Created） |
| 作用范围 | 单个路径操作的装饰器参数 | 方法级 `@HttpCode()`，也可在控制器类上设置 |
| 动态状态码 | 返回 `Response`/`JSONResponse(status_code=...)` 或抛 `HTTPException` | `@Res() res.status(404).json(...)` 或抛 `HttpException` |
| 错误状态码 | `raise HTTPException(status_code=404, detail="...")` | `throw new NotFoundException()` / `new HttpException(msg, 404)` |
| 重定向 | 返回 `RedirectResponse(url=...)` | `@Redirect(url, code)` 装饰器 |
| OpenAPI 文档 | 状态码自动记录在 OpenAPI Schema | 需 `@ApiResponse({ status: 201, ... })`（`@nestjs/swagger`）补充 |
| 无响应体状态码 | 识别 `204` 等并生成「无响应体」Schema | 需配合 `@HttpCode(204)` 且 handler 不返回内容，Swagger 同样需手动标注 |

**核心差异一句话**：FastAPI 用装饰器参数 `status_code=status.HTTP_201_CREATED` 声明默认状态码，且会自动写入 OpenAPI 并识别 `204` 这类无响应体码；NestJS 用 `@HttpCode()` 配合 `HttpStatus` 枚举，默认 POST 就是 `201`，但文档里的状态码仍需 `@ApiResponse()` 显式声明，两者默认值约定不同（FastAPI 200 vs NestJS 201）是迁移时最容易踩的坑。

## 三、针对性练习题

### 题 1（基础）

写一个 `POST /items/` 端点，返回 `201 Created`，并说明默认状态码是多少。

<details>
<summary>参考答案</summary>

```python
from fastapi import FastAPI

app = FastAPI()

@app.post("/items/", status_code=201)
async def create_item(name: str):
    return {"name": name}
```

不声明时 FastAPI 默认返回 `200 OK`；声明后响应与 OpenAPI 文档都记录为 `201`。
</details>

### 题 2（理解）

写出用 `fastapi.status` 常量重写上题的代码，并说明常量与数字的关系以及 `fastapi.status` 的来源。

<details>
<summary>参考答案</summary>

```python
from fastapi import FastAPI, status

app = FastAPI()

@app.post("/items/", status_code=status.HTTP_201_CREATED)
async def create_item(name: str):
    return {"name": name}
```

`status.HTTP_201_CREATED` 就是数字 `201`，只是语义化命名，提供编辑器自动补全。技术细节：`fastapi.status` 与 `starlette.status` 完全相同，FastAPI 为了方便直接从 Starlette 导出。
</details>

### 题 3（辨析/代码）

下面状态码的范围划分是否都正确？如有错误请指出。

- `204` 表示「无内容」，不能包含响应体。
- `304` 表示「未修改」，不得包含响应体。
- `1xx` 响应可以带响应体。
- `5xx` 通常由应用代码或服务器问题自动触发，很少手写。

<details>
<summary>参考答案</summary>

有一条错误：`1xx`（信息类）响应**不能包含响应体**，不是「可以带」。其余均正确：
- `204 No Content` —— 无响应体，FastAPI 会识别并生成相应 OpenAPI 文档；
- `304 Not Modified` —— 不得包含响应体；
- `5xx` —— 几乎不直接手写，出错时自动返回。
</details>

### 题 4（进阶 · NestJS 迁移视角）

你在 NestJS 中这样写：

```ts
@Post('items')
@HttpCode(HttpStatus.CREATED)
create(@Body() dto: CreateItemDto) { return dto; }
```

请写出等价的 FastAPI 代码，并指出两者「默认状态码」的差异。

<details>
<summary>参考答案</summary>

```python
from fastapi import FastAPI, status

app = FastAPI()

@app.post("/items/", status_code=status.HTTP_201_CREATED)
async def create_item(name: str):
    return {"name": name}
```

差异：NestJS 的 POST **默认就是 201**（`@HttpCode(HttpStatus.CREATED)` 甚至可省略）；FastAPI 所有方法默认 `200`，必须显式写 `status_code=201`。从 NestJS 迁移时若忘记设置，创建类接口会错误地返回 200。
</details>

### 题 5（思考）

某个端点想根据情况返回 `200` 或 `404`：数据存在返回数据，不存在返回 404。仅靠 `status_code=200` 够吗？本章给出的边界是什么？

<details>
<summary>参考答案</summary>

不够。`status_code` 只设定该路径操作的**默认/固定**状态码，无法按运行时条件切换。本章明确指出：若需要返回与所声明默认值**不同的**状态码，将在高级用户指南中介绍（例如返回 `Response`/`JSONResponse(status_code=404)` 或抛出 `HTTPException(status_code=404, detail=...)`）。本章范围内只需知道 `status_code` 是静态声明，且会被记录进 OpenAPI。
</details>
