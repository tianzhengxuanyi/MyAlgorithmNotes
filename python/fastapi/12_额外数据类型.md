## 一、章节笔记

### 1. 不止 `int`/`float`/`str`/`bool`

前面主要使用常见类型，但 FastAPI 支持更复杂的 Pydantic 数据类型。使用它们时，依然享有与之前**完全相同的能力**：

- 出色的编辑器支持
- 请求数据转换
- 响应数据转换
- 数据校验
- 自动注解与文档

### 2. 可用的额外数据类型速查

| 类型 | 说明 | 请求/响应中的表示 |
|---|---|---|
| `UUID` | 通用唯一标识符，常用作数据库/系统中的 ID | `str` |
| `datetime.datetime` | Python datetime | ISO 8601 字符串，如 `2008-09-15T15:53:00+05:00` |
| `datetime.date` | Python date | ISO 8601 字符串，如 `2008-09-15` |
| `datetime.time` | Python time | ISO 8601 字符串，如 `14:23:55.003` |
| `datetime.timedelta` | Python 时间差 | `float`（总秒数）；Pydantic 也支持 ISO 8601 时间差异编码 |
| `frozenset` | 不可变集合 | 请求中读取列表、去重、转为 `set`；响应中 `set` 转为 `list` |
| `bytes` | Python 字节串 | 当作 `str` 处理，Schema 指定为 `binary` 格式 |
| `Decimal` | Python 高精度小数 | 当作 `float` 处理 |

完整列表见 Pydantic 数据类型文档。

### 3. 各类型的注意点

- **`frozenset`**：请求中列表会被读取、消除重复、转为 `set`；响应中 `set` 被转为 `list`。生成的 Schema 会用 JSON Schema 的 `uniqueItems` 标明值是唯一的。
- **`timedelta`**：默认表示为总秒数的 `float`，Pydantic 也允许 ISO 8601 时间差异编码（详见 Pydantic 文档）。
- **`UUID`/日期时间类**：线上是 ISO 字符串，函数内是原生 Python 对象，可直接做运算。

### 4. 综合示例

下面路径操作同时使用上述多种类型：

```python
from datetime import datetime, time, timedelta
from typing import Annotated
from uuid import UUID

from fastapi import Body, FastAPI

app = FastAPI()

@app.put("/items/{item_id}")
async def read_items(
    item_id: UUID,
    start_datetime: Annotated[datetime, Body()],
    end_datetime: Annotated[datetime, Body()],
    process_after: Annotated[timedelta, Body()],
    repeat_at: Annotated[time | None, Body()] = None,
):
    start_process = start_datetime + process_after
    duration = end_datetime - start_process
    return {
        "item_id": item_id,
        "start_datetime": start_datetime,
        "end_datetime": end_datetime,
        "process_after": process_after,
        "repeat_at": repeat_at,
        "start_process": start_process,
        "duration": duration,
    }
```

要点：

- `item_id: UUID` 出现在路径模板中 → 路径参数，自动把字符串解析为 `UUID`。
- 其余单一类型默认会被当成查询参数，所以用 `Body()` 显式标注为请求体字段。
- `repeat_at` 用 `= None` 使其可选。
- 函数内拿到的是**原生 Python 类型**，可直接做日期运算：`start_datetime + process_after`、`end_datetime - start_process`。

### 5. 易错点小结

- ✅ 这些特殊类型在线上是字符串/数字，在函数内是原生对象，转换由 Pydantic 自动完成。
- ✅ `timedelta` 线上是总秒数 `float`；`bytes` 以 `binary` 格式字符串表示；`Decimal` 按 `float` 处理。
- ✅ `frozenset` 请求去重、响应转 list、Schema 标记 `uniqueItems`。
- ✅ 想放进请求体的单一类型必须显式用 `Body()`。

## 二、NestJS 对比

| 维度 | FastAPI（Python） | NestJS（TypeScript） |
|---|---|---|
| UUID | 类型注解 `UUID` 自动解析与校验 | `@IsUUID()`（class-validator），TS 中是 `string` |
| 日期时间 | `datetime` / `date` / `time` 自动解析 ISO 8601 字符串 | `@IsDateString()`，配合 `class-transformer` 的 `@Type(() => Date)` 转 Date |
| 时间差 | `timedelta` 原生支持（秒数 / ISO 8601） | 无内建类型，需自定义 Pipe/transform 处理 |
| 集合去重 | `frozenset` / `set` 自动去重并写入 `uniqueItems` | 需 `@Transform(({value}) => [...new Set(value)])` 手动去重 |
| 字节 / 高精度 | `bytes`（binary 格式）、`Decimal` 内建 | 需自定义校验器或库支持，无内建 DTO 类型 |
| 函数内类型 | 原生 Python 对象，可直接做日期运算 | TS 类型多为 `string`/`Date`，运算需手动转换 |
| 文档集成 | 类型自动进入 JSON Schema / OpenAPI | 需 `@ApiProperty({ format: 'date-time' })` 等手动声明格式 |

**核心差异一句话**：FastAPI 直接把 Pydantic 支持的丰富Python 类型（UUID、datetime 家族、timedelta、frozenset、Decimal）当作参数注解，转换、校验、文档一气呵成且函数内是可用原生对象；NestJS 的 TS 类型系统缺少这些运行时类型，需靠 `class-validator` 装饰器与 `class-transformer` 转换手工补齐，文档格式也要用 `@ApiProperty()` 单独声明。

## 三、针对性练习题

### 题 1（基础）

写 `PUT /items/{item_id}`，路径参数为 `UUID`，另有两个 `datetime` 请求体字段 `start_datetime`、`end_datetime`，返回它们。

<details>
<summary>参考答案</summary>

```python
from datetime import datetime
from typing import Annotated
from uuid import UUID

from fastapi import Body, FastAPI

app = FastAPI()

@app.put("/items/{item_id}")
async def read_items(
    item_id: UUID,
    start_datetime: Annotated[datetime, Body()],
    end_datetime: Annotated[datetime, Body()],
):
    return {
        "item_id": item_id,
        "start_datetime": start_datetime,
        "end_datetime": end_datetime,
    }
```

`item_id` 由字符串自动解析为 `UUID`；两个 `datetime` 用 `Body()` 标注为请求体字段，由 ISO 8601 字符串解析为原生 `datetime`。
</details>

### 题 2（理解）

客户端请求/响应中，`datetime`、`timedelta`、`frozenset`、`bytes`、`Decimal` 分别以什么形式出现？

<details>
<summary>参考答案</summary>

- `datetime` / `date` / `time`：ISO 8601 格式字符串（如 `2008-09-15T15:53:00+05:00`）。
- `timedelta`：`float`，表示总秒数（Pydantic 也支持 ISO 8601 时间差异编码）。
- `frozenset`：请求中列表去重后转为 `set`，响应中 `set` 转为 `list`，Schema 标记 `uniqueItems`。
- `bytes`：当作 `str` 处理，Schema 指定 `binary` 格式。
- `Decimal`：当作 `float` 处理。
</details>

### 题 3（辨析/代码）

示例函数中为什么要写 `start_datetime: Annotated[datetime, Body()]` 而不是 `start_datetime: datetime`？

<details>
<summary>参考答案</summary>

因为单一类型（包括 `datetime`）的参数默认会被 FastAPI 解释为**查询参数**。该示例中希望它来自请求体，所以必须用 `Body()` 显式标注来源。不写的话，FastAPI 会去查询字符串里找 `start_datetime`，请求体中的数据不会被读取。
</details>

### 题 4（进阶 · NestJS 迁移视角）

NestJS DTO 中接收 ISO 日期字符串：

```ts
class ItemDto {
  @IsDateString()
  startDatetime: string;
}
```

请写出等价 FastAPI 声明，并说明函数内拿到的值在类型上有何不同。

<details>
<summary>参考答案</summary>

```python
from datetime import datetime
from typing import Annotated
from fastapi import Body, FastAPI

app = FastAPI()

@app.post("/items/")
async def create_item(start_datetime: Annotated[datetime, Body()]):
    return {"start_datetime": start_datetime}
```

差异：NestJS 中 `@IsDateString()` 只校验字符串格式，字段仍是 `string`，要做日期运算需手动 `new Date(...)`；FastAPI 中 `datetime` 类型注解会让 Pydantic 把 ISO 字符串解析成原生 `datetime` 对象，函数内可直接做 `+ timedelta(...)`、比较等运算，无需手动转换。
</details>

### 题 5（思考）

示例函数里能直接写 `start_datetime + process_after` 与 `end_datetime - start_process` 的前提是什么？为什么 FastAPI 能做到这点？

<details>
<summary>参考答案</summary>

前提是参数被正确注解为原生 Python 类型（`datetime`、`timedelta` 等），FastAPI/Pydantic 已把请求中的字符串/数字**转换并校验**为这些原生对象。

能做到的原因是：Pydantic 依据类型注解在数据进入函数之前完成解析（ISO 字符串 → `datetime`、秒数 → `timedelta`），所以函数内拿到的就是真正的 Python 对象，支持标准运算符。这也体现了 FastAPI "类型注解即契约"的设计——同一份声明同时驱动转换、校验与文档。
</details>
