## 一、章节笔记

### 1. 本章要解决什么问题

API 需要向客户端（浏览器、他人代码、物联网设备等）返回明确的错误：无权限、无访问权、资源不存在等。这类错误通常用 **400 范围**（400-499）的状态码表示。本章学习用 `HTTPException` 返回错误、自定义异常处理器，以及覆盖 FastAPI 的默认错误响应。

### 2. `HTTPException`：返回错误响应

```python
from fastapi import FastAPI, HTTPException

app = FastAPI()

items = {"foo": "The Foo Wrestlers"}

@app.get("/items/{item_id}")
async def read_item(item_id: str):
    if item_id not in items:
        raise HTTPException(status_code=404, detail="Item not found")
    return {"item": items[item_id]}
```

要点：

- `HTTPException` 是**额外包含 API 相关数据的常规 Python 异常**。
- 因为是 Python 异常，只能 `raise`，**不能 `return`**。
- 在路径操作函数调用的工具函数内部 `raise` 时，后续代码**不再执行**，请求立即终止并把错误发给客户端 —— 这比 `return` 值更利于在依赖项/安全场景中提前中断。
- `detail` 可传**任何能转换为 JSON 的值**：`str`、`dict`、`list` 等，FastAPI 自动转换。

响应结果：

- 请求 `/items/foo` → `200` + `{"item": "The Foo Wrestlers"}`
- 请求 `/items/bar`（不存在）→ `404` + `{"detail": "Item not found"}`

### 3. 添加自定义响应头

出于某些安全需要，可给错误响应加自定义头：

```python
@app.get("/items-header/{item_id}")
async def read_item_header(item_id: str):
    if item_id not in items:
        raise HTTPException(
            status_code=404,
            detail="Item not found",
            headers={"X-Error": "There goes my error"},
        )
    return {"item": items[item_id]}
```

### 4. 安装自定义异常处理器

用 `@app.exception_handler()` 全局处理自定义异常：

```python
from fastapi import FastAPI, Request
from fastapi.responses import JSONResponse

class UnicornException(Exception):
    def __init__(self, name: str):
        self.name = name

app = FastAPI()

@app.exception_handler(UnicornException)
async def unicorn_exception_handler(request: Request, exc: UnicornException):
    return JSONResponse(
        status_code=418,
        content={"message": f"Oops! {exc.name} did something. There goes a rainbow..."},
    )

@app.get("/unicorns/{name}")
async def read_unicorn(name: str):
    if name == "yolo":
        raise UnicornException(name=name)
    return {"unicorn_name": name}
```

请求 `/unicorns/yolo` → `418` + `{"message": "Oops! yolo did something..."}`。

技术细节：`Request`、`JSONResponse` 也可从 `starlette.requests` / `starlette.responses` 导入；FastAPI 提供的是同款便捷入口。

### 5. 覆盖默认异常处理器

FastAPI 自带默认处理器，处理 `HTTPException` 和无效请求数据（`RequestValidationError`）。两者都可覆盖。

**覆盖请求验证异常** —— 导入 `RequestValidationError`，用 `@app.exception_handler(RequestValidationError)` 装饰处理器：

```python
from fastapi import FastAPI, HTTPException
from fastapi.exceptions import RequestValidationError
from fastapi.responses import PlainTextResponse
from starlette.exceptions import HTTPException as StarletteHTTPException

app = FastAPI()

@app.exception_handler(StarletteHTTPException)
async def http_exception_handler(request, exc):
    return PlainTextResponse(str(exc.detail), status_code=exc.status_code)

@app.exception_handler(RequestValidationError)
async def validation_exception_handler(request, exc: RequestValidationError):
    message = "Validation errors:"
    for error in exc.errors():
        message += f"\nField: {error['loc']}, Error: {error['msg']}"
    return PlainTextResponse(message, status_code=400)

@app.get("/items/{item_id}")
async def read_item(item_id: int):
    if item_id == 3:
        raise HTTPException(status_code=418, detail="Nope! I don't like 3.")
    return {"item_id": item_id}
```

- 访问 `/items/foo`：默认 JSON 错误变为纯文本 `Validation errors:\nField: ('path', 'item_id'), Error: ...`（状态码 400）。
- 覆盖 `HTTPException` 处理器时注册的是 **Starlette 的** `HTTPException`（见下）。
- ⚠️ 安全提示：`RequestValidationError` 包含发生错误的**文件名与行号**信息；直接转成字符串返回可能泄露系统细节，建议像示例那样逐条提取 `loc`/`msg`。

**使用 `RequestValidationError` 的请求体**（`exc.body`，用于调试/记录）：

```python
from fastapi import FastAPI, Request
from fastapi.encoders import jsonable_encoder
from fastapi.exceptions import RequestValidationError
from fastapi.responses import JSONResponse
from pydantic import BaseModel

app = FastAPI()

@app.exception_handler(RequestValidationError)
async def validation_exception_handler(request: Request, exc: RequestValidationError):
    return JSONResponse(
        status_code=422,
        content=jsonable_encoder({"detail": exc.errors(), "body": exc.body}),
    )

class Item(BaseModel):
    title: str
    size: int

@app.post("/items/")
async def create_item(item: Item):
    return item
```

发送 `{"title": "towel", "size": "XL"}` 时，响应同时包含 `detail`（校验错误）和 `body`（收到的原始数据）。

### 6. FastAPI 与 Starlette 的 HTTPException

- FastAPI 的 `HTTPException` **继承自** Starlette 的同名类。
- 唯一区别：FastAPI 的 `detail` 接受**任意可 JSON 化数据**，Starlette 的只接受 `str`。
- 代码中照常 `raise` **FastAPI** 的 `HTTPException`；但**注册处理器时要用 Starlette 的**（别名 `StarletteHTTPException`），这样 Starlette 内部代码、扩展或插件触发的异常也能被捕获：

```python
from starlette.exceptions import HTTPException as StarletteHTTPException
```

### 7. 复用 FastAPI 默认异常处理器

从 `fastapi.exception_handlers` 导入默认处理器，可在自定义处理器里先做日志等处理，再委托默认逻辑：

```python
from fastapi import FastAPI, HTTPException
from fastapi.exception_handlers import (
    http_exception_handler,
    request_validation_exception_handler,
)
from fastapi.exceptions import RequestValidationError
from starlette.exceptions import HTTPException as StarletteHTTPException

app = FastAPI()

@app.exception_handler(StarletteHTTPException)
async def custom_http_exception_handler(request, exc):
    print(f"OMG! An HTTP error!: {repr(exc)}")
    return await http_exception_handler(request, exc)

@app.exception_handler(RequestValidationError)
async def validation_exception_handler(request, exc):
    print(f"OMG! The client sent invalid data!: {exc}")
    return await request_validation_exception_handler(request, exc)

@app.get("/items/{item_id}")
async def read_item(item_id: int):
    if item_id == 3:
        raise HTTPException(status_code=418, detail="Nope! I don't like 3.")
    return {"item_id": item_id}
```

### 8. 易错点

- ✅ 错误必须 `raise`，不能 `return`（异常会立即终止请求处理）。
- ✅ 注册 HTTP 异常处理器用 `StarletteHTTPException`，不要注册 FastAPI 的子类。
- ✅ 校验错误里含文件名/行号，别原样返回给客户端。
- ✅ 覆盖验证错误时状态码可改为 400（示例），但 FastAPI 默认校验错误是 422。

## 二、NestJS 对比

| 维度 | FastAPI（Python） | NestJS（TypeScript） |
|---|---|---|
| 抛出 HTTP 错误 | `raise HTTPException(status_code=404, detail="...")` | `throw new NotFoundException()` / `new HttpException(msg, 404)` |
| 错误载荷 | `detail` 可是 `str`/`dict`/`list`，统一包成 `{"detail": ...}` | 默认 `{"statusCode": 404, "message": "...", "error": "Not Found"}` |
| 提前中断 | `raise` 异常即终止，工具函数/依赖项中亦有效 | `throw` 异常，由异常层统一捕获 |
| 错误响应头 | `HTTPException(..., headers={"X-Error": "..."})` | `HttpException` 可传第三参数或 `@Res()` 手动设置 |
| 自定义异常处理器 | `@app.exception_handler(MyException)` 全局注册 | `@Catch(MyException)` 自定义 ExceptionFilter + `@UseFilters()` |
| 校验错误处理 | 覆盖 `RequestValidationError` 处理器，读 `exc.errors()` / `exc.body` | `ValidationPipe` 的 `exceptionFactory` 自定义，或全局 Filter 捕获 `BadRequestException` |
| 默认状态码 | 校验错误默认 422，HTTP 错误按所抛状态码 | 校验错误默认 400，内置异常类自带状态码 |
| 复用默认处理器 | `from fastapi.exception_handlers import ...` 显式 `await` 委托 | `BaseExceptionFilter` / `catch()` 委托给内置处理 |
| 内部信息泄露防护 | 需注意 `RequestValidationError` 含文件名/行号，逐条提取 | 生产环境关闭 `ValidationPipe` 的 `errorHttpStatusCode` 细节或自定义_FILTER |

**核心差异一句话**：FastAPI 的 `raise HTTPException(status_code=..., detail=...)` 是最常用的错误表达方式，`detail` 可为任意 JSON 数据，异常处理器通过 `@app.exception_handler()` 全局注册且可复用默认实现；NestJS 用丰富的内置异常类与 `@Catch()` ExceptionFilter 组织错误处理，校验错误默认走 `ValidationPipe` 的 400 响应，二者在默认状态码（422 vs 400）和错误载荷结构上迁移时需特别对齐。

## 三、针对性练习题

### 题 1（基础）

写一个 `GET /items/{item_id}`：从 `items` 字典取数据，不存在时抛 404 错误 `{"detail": "Item not found"}`。

<details>
<summary>参考答案</summary>

```python
from fastapi import FastAPI, HTTPException

app = FastAPI()
items = {"foo": "The Foo Wrestlers"}

@app.get("/items/{item_id}")
async def read_item(item_id: str):
    if item_id not in items:
        raise HTTPException(status_code=404, detail="Item not found")
    return {"item": items[item_id]}
```

必须用 `raise` 而非 `return`；`detail` 会作为 JSON 的 `detail` 字段返回。
</details>

### 题 2（理解）

为什么在工具函数里 `raise HTTPException` 也能中断请求？`detail` 可以传哪些类型？

<details>
<summary>参考答案</summary>

`HTTPException` 是 Python 异常，一旦抛出会沿调用栈上抛，FastAPI 捕获后立刻终止请求并返回对应 HTTP 错误，路径操作函数后续代码不再执行 —— 因此在工具函数/依赖项中同样有效。

`detail` 可传任何可转换为 JSON 的值：`str`、`dict`、`list` 等，FastAPI 会自动序列化，不限于字符串。
</details>

### 题 3（辨析/代码）

下面注册处理器时导入的 `HTTPException` 来自哪里？为什么要这样写？

```python
from starlette.exceptions import HTTPException as StarletteHTTPException

@app.exception_handler(StarletteHTTPException)
async def http_exception_handler(request, exc):
    return PlainTextResponse(str(exc.detail), status_code=exc.status_code)
```

<details>
<summary>参考答案</summary>

来自 Starlette。FastAPI 的 `HTTPException` 继承自 Starlette 的同名类，注册处理器时要用**父类** `StarletteHTTPException`，这样不仅路径操作里 `raise` 的 FastAPI 异常能被捕获，Starlette 内部代码、扩展或插件抛出的 HTTPException 也能被这个处理器捕获。业务代码里仍照常用 FastAPI 的 `HTTPException`（其 `detail` 支持任意 JSON 数据）。
</details>

### 题 4（进阶 · NestJS 迁移视角）

NestJS 中你写：

```ts
@Get('items/:id')
readOne(@Param('id') id: string) {
  const item = this.items[id];
  if (!item) throw new NotFoundException('Item not found');
  return item;
}
```

写出等价的 FastAPI 代码，并指出错误响应结构的差异。

<details>
<summary>参考答案</summary>

```python
from fastapi import FastAPI, HTTPException

app = FastAPI()
items = {"foo": "The Foo Wrestlers"}

@app.get("/items/{item_id}")
async def read_item(item_id: str):
    if item_id not in items:
        raise HTTPException(status_code=404, detail="Item not found")
    return items[item_id]
```

差异：NestJS 的 `NotFoundException` 默认生成 `{"statusCode": 404, "message": "Item not found", "error": "Not Found"}`；FastAPI 生成 `{"detail": "Item not found"}`。字段结构不同，前端错误处理代码迁移时需适配。
</details>

### 题 5（思考）

覆盖 `RequestValidationError` 处理器时，为什么不应该直接把 `str(exc)` 全部返回给客户端？如何在返回错误信息的同时把无效请求体也包含进响应？

<details>
<summary>参考答案</summary>

因为 `RequestValidationError` 包含发生验证错误的文件名和行号等系统内部信息，直接字符串化返回可能泄露实现细节。正确做法是逐条提取 `exc.errors()` 中的 `loc`、`msg` 等字段再返回。

若要包含无效请求体，用 `exc.body` 并通过 `jsonable_encoder` 保证可 JSON 化：

```python
@app.exception_handler(RequestValidationError)
async def validation_exception_handler(request: Request, exc: RequestValidationError):
    return JSONResponse(
        status_code=422,
        content=jsonable_encoder({"detail": exc.errors(), "body": exc.body}),
    )
```
</details>
