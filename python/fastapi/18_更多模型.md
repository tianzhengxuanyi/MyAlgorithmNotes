## 一、章节笔记

### 1. 本章要解决什么问题

一个「用户」实体在不同环节有不同形态：**输入要含密码**、**输出不能含密码**、**数据库里存的是哈希密码**。本章学习用多个 Pydantic 模型表达同一实体的不同状态，并通过继承减少重复；同时介绍 `Union`、`list[Model]`、`dict[str, T]` 等更丰富的响应声明。

> ⚠️ 永远不要存储明文密码，只存储之后可用于校验的**安全哈希**。

### 2. 多个模型：同一实体的三种形态

```python
from fastapi import FastAPI
from pydantic import BaseModel, EmailStr

app = FastAPI()

class UserIn(BaseModel):
    username: str
    password: str
    email: EmailStr
    full_name: str | None = None

class UserOut(BaseModel):
    username: str
    email: EmailStr
    full_name: str | None = None

class UserInDB(BaseModel):
    username: str
    hashed_password: str
    email: EmailStr
    full_name: str | None = None

def fake_password_hasher(raw_password: str):
    return "supersecret" + raw_password

def fake_save_user(user_in: UserIn):
    hashed_password = fake_password_hasher(user_in.password)
    user_in_db = UserInDB(**user_in.model_dump(), hashed_password=hashed_password)
    print("User saved! ..not really")
    return user_in_db

@app.post("/user/", response_model=UserOut)
async def create_user(user_in: UserIn):
    user_saved = fake_save_user(user_in)
    return user_saved
```

| 模型 | 用途 | 关键字段 |
|---|---|---|
| `UserIn` | 请求体（输入） | `password: str` 明文 |
| `UserOut` | `response_model`（输出） | 无密码 |
| `UserInDB` | 内部/持久化表示 | `hashed_password: str` |

> 辅助函数 `fake_password_hasher` / `fake_save_user` 仅演示数据流，不提供真实安全性。

### 3. 拆解 `**user_in.model_dump()`

**① `.model_dump()`**：Pydantic 模型方法，返回包含模型数据的普通 `dict`。

```python
user_in = UserIn(username="john", password="secret", email="john.doe@example.com")
user_dict = user_in.model_dump()
# {'username': 'john', 'password': 'secret',
#  'email': 'john.doe@example.com', 'full_name': None}
```

**② `**` 解包**：把 dict 的键值对作为**关键字参数**传给函数/类。

```python
UserInDB(**user_dict)
# 等价于 UserInDB(username=..., password=..., email=..., full_name=...)
```

**③ 组合写法**：

```python
UserInDB(**user_in.model_dump(), hashed_password=hashed_password)
# 等价于用 user_dict 的各字段 + 额外的 hashed_password 构造 UserInDB
```

`。model_dump()` 返回 `dict`，加 `**` 解包即可**用另一个模型的数据生成新模型**，并可追加额外关键字参数。

### 4. 用继承减少重复

上面三个模型共享大量属性名和类型。FastAPI 的核心思想之一是**减少重复**（重复会导致 bug、安全问题、代码失步）。做法：声明 `UserBase` 作为基类，子类只声明差异部分。

```python
from fastapi import FastAPI
from pydantic import BaseModel, EmailStr

app = FastAPI()

class UserBase(BaseModel):
    username: str
    email: EmailStr
    full_name: str | None = None

class UserIn(UserBase):
    password: str

class UserOut(UserBase):
    pass

class UserInDB(UserBase):
    hashed_password: str

def fake_password_hasher(raw_password: str):
    return "supersecret" + raw_password

def fake_save_user(user_in: UserIn):
    hashed_password = fake_password_hasher(user_in.password)
    user_in_db = UserInDB(**user_in.model_dump(), hashed_password=hashed_password)
    print("User saved! ..not really")
    return user_in_db

@app.post("/user/", response_model=UserOut)
async def create_user(user_in: UserIn):
    user_saved = fake_save_user(user_in)
    return user_saved
```

- 所有数据转换、校验、文档功能照常工作。
- 只需在子类声明差异：明文 `password`、哈希 `hashed_password`、或「什么都不加」（`pass`）。
- 一个实体无需只定义一个模型 —— 按「状态」拆多个模型是正常且推荐的做法。

### 5. `Union` / `anyOf`：响应是多种类型之一

响应可以声明为多个类型的 `Union`，在 OpenAPI 中表现为 `anyOf`：

```python
from fastapi import FastAPI
from pydantic import BaseModel

app = FastAPI()

class BaseItem(BaseModel):
    description: str
    type: str

class CarItem(BaseItem):
    type: str = "car"

class PlaneItem(BaseItem):
    type: str = "plane"
    size: int

items = {
    "item1": {"description": "All my friends drive a low rider", "type": "car"},
    "item2": {
        "description": "Music is my aeroplane, it's my aeroplane",
        "type": "plane",
        "size": 5,
    },
}

@app.get("/items/{item_id}", response_model=PlaneItem | CarItem)
async def read_item(item_id: str):
    return items[item_id]
```

要点：

- **更具体的类型写在前面**：`PlaneItem` 比 `CarItem` 字段更多（多 `size`），所以放前面。
- 正文示例在 `response_model` 参数值位置用 `PlaneItem | CarItem`（类型注解位置也可用 `typing.Union[...]`）。注意 `Union[...]` 写法在所有 Python 版本都适用，是更稳妥的表达。

### 6. 模型列表与任意 dict

**模型列表** —— 用标准 `list[Item]`：

```python
from fastapi import FastAPI
from pydantic import BaseModel

app = FastAPI()

class Item(BaseModel):
    name: str
    description: str

items = [
    {"name": "Foo", "description": "There comes my hero"},
    {"name": "Red", "description": "It's my aeroplane"},
]

@app.get("/items/", response_model=list[Item])
async def read_items():
    return items
```

**任意 dict** —— 只需声明键/值类型，适合事先不知道字段名的情况：

```python
from fastapi import FastAPI

app = FastAPI()

@app.get("/keyword-weights/", response_model=dict[str, float])
async def read_keyword_weights():
    return {"foo": 2.3, "bar": 3.4}
```

### 7. 速查表

| 需求 | 方案 |
|---|---|
| 输入含密码、输出不含 | `UserIn` / `UserOut` 两个模型，`response_model=UserOut` |
| 存储哈希密码 | `UserInDB`，`hashed_password` 字段 |
| 模型间转换 | `UserInDB(**user_in.model_dump(), hashed_password=...)` |
| 多模型共享字段 | 提取 `UserBase` 基类，子类只写差异 |
| 响应是多种类型之一 | `response_model=PlaneItem | CarItem`（具体类型在前），OpenAPI 为 `anyOf` |
| 响应是对象列表 | `response_model=list[Item]` |
| 字段名未知 | `response_model=dict[str, float]` |

## 二、NestJS 对比

| 维度 | FastAPI（Python） | NestJS（TypeScript） |
|---|---|---|
| 多形态实体 | `UserIn` / `UserOut` / `UserInDB` 三个 Pydantic 模型 | `CreateUserDto` / `UserResponseDto` / `UserEntity` 多个类 |
| 减少重复 | `UserBase` 基类 + 子类继承 | `PartialType` / `PickType` / `OmitType`（`@nestjs/mapped-types`）或普通基类继承 |
| 模型转模型 | `Target(**source.model_dump(), extra=...)` 解包构造 | `plainToInstance(TargetDto, source)`（`class-transformer`），或手动映射 |
| 哈希密码处理 | `UserInDB` 存 `hashed_password`，`fake_password_hasher` 演示 | Service 层用 bcrypt/argon2 生成 hash，实体存 `passwordHash` |
| 联合类型响应 | `response_model=PlaneItem | CarItem` → OpenAPI `anyOf` | DTO 联合类型 + `@ApiProperty({ oneOf: [...] })`（`@nestjs/swagger`） |
| 列表响应 | `response_model=list[Item]`，自动写入 Schema | 返回 `ItemDto[]`，Swagger 需 `@ApiOkResponse({ type: [ItemDto] })` |
| 任意键值响应 | `response_model=dict[str, float]` | `Record<string, number>` 返回类型 + `@ApiProperty({ additionalProperties: ... })` |
| 文档自动化 | 响应模型自动进入 OpenAPI | DTO 需 `@ApiProperty()` 逐字段标注才能生成完整 Schema |
| 敏感字段过滤 | 输出模型声明即过滤（无需额外拦截器） | 需 `ClassSerializerInterceptor` + `@Exclude()` 或 `excludeExtraneousValues` |

**核心差异一句话**：FastAPI 用「一个实体多个 Pydantic 模型 + 基类继承」把输入/输出/持久化三种形态表达得极其紧凑，模型间可用 `model_dump()` 解包转换且响应 Schema 自动进 OpenAPI；NestJS 的等价实现要组合多个 DTO、`@nestjs/mapped-types` 工具类型、`class-transformer` 转换和 Swagger 装饰器，显式程度更高。

## 三、针对性练习题

### 题 1（基础）

为一个「产品」实体设计三个 Pydantic 模型：输入含 `secret_code`，输出不含，数据库模型含 `hashed_code`。只写模型定义。

<details>
<summary>参考答案</summary>

```python
from pydantic import BaseModel

class ProductBase(BaseModel):
    name: str
    price: float

class ProductIn(ProductBase):
    secret_code: str

class ProductOut(ProductBase):
    pass

class ProductInDB(ProductBase):
    hashed_code: str
```

用基类 `ProductBase` 抽取公共字段，子类只声明差异，避免重复。
</details>

### 题 2（理解）

解释 `UserInDB(**user_in.model_dump(), hashed_password=hashed_password)` 每一步在做什么。

<details>
<summary>参考答案</summary>

1. `user_in.model_dump()` 把 Pydantic 模型 `user_in` 转成普通 `dict`（键为字段名，值为字段值）。
2. `**dict` 在函数调用/构造时解包，把每个键值对作为关键字参数传入，等价于 `UserInDB(username=..., password=..., email=..., full_name=...)`。
3. 追加 `hashed_password=hashed_password` 关键字参数，作为 `UserInDB` 的额外字段值。

整体实现「用另一个模型的数据 + 额外字段，构造新模型」。
</details>

### 题 3（辨析/代码）

响应模型写成 `response_model=CarItem | PlaneItem`（`PlaneItem` 字段更多、更具体）。官方文档建议的顺序是什么？为什么？

<details>
<summary>参考答案</summary>

建议把**更具体的类型放前面**，即 `response_model=PlaneItem | CarItem`。因为 OpenAPI 的 `anyOf` 按顺序匹配，具体类型（字段多、约束强，如带 `size` 的 `PlaneItem`）放前面，能优先被正确匹配；若把宽泛的 `CarItem` 放前面，可能吞掉本应属于 `PlaneItem` 的数据。
</details>

### 题 4（进阶 · NestJS 迁移视角）

NestJS 中用 `PickType(UserEntity, ['username', 'email'])` 生成响应 DTO。请写出等价的 FastAPI 继承写法，并说明为什么不能直接把 `UserIn` 作为响应模型。

<details>
<summary>参考答案</summary>

```python
from pydantic import BaseModel, EmailStr

class UserBase(BaseModel):
    username: str
    email: EmailStr
    full_name: str | None = None

class UserIn(UserBase):
    password: str

class UserOut(UserBase):
    pass
```

`UserOut` 通过继承 `UserBase` 得到 `username`/`email`/`full_name`，等价于 `PickType` 选出公共字段。

不能直接把 `UserIn` 作响应模型：它包含 `password` 字段，FastAPI 会按响应模型原样输出，导致明文密码泄露给用户（甚至在所有使用它的端点中泄露）。
</details>

### 题 5（思考）

什么情况下应该用 `response_model=dict[str, float]` 而不是定义一个 Pydantic 模型？请举一个正文中的例子并说明原因。

<details>
<summary>参考答案</summary>

当**事先不知道有效的字段名**时用 `dict`。例如正文的关键词权重接口：

```python
@app.get("/keyword-weights/", response_model=dict[str, float])
async def read_keyword_weights():
    return {"foo": 2.3, "bar": 3.4}
```

关键词（键）是动态生成的，无法预先枚举成 Pydantic 模型的固定字段；`dict[str, float]` 只约束「键为字符串、值为浮点数」，既能校验类型又能生成正确的 OpenAPI Schema。Pydantic 模型适合字段集合固定的场景，`dict` 适合键值对集合动态的场景。
</details>
