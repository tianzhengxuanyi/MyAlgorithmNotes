## 一、章节笔记

### 1. 本章要解决什么问题

在编辑器（如 VS Code 或 PyCharm）中连接调试器调试 FastAPI 应用：打断点、单步执行、查看变量。关键是把 uvicorn 的启动写进自己的代码，让调试器能直接启动 Python 程序。

### 2. 在代码中直接调用 `uvicorn`

```python
import uvicorn
from fastapi import FastAPI

app = FastAPI()

@app.get("/")
def root():
    a = "a"
    b = "b" + a
    return {"hello world": b}

if __name__ == "__main__":
    uvicorn.run(app, host="0.0.0.0", port=8000)
```

这样你就可以从调试器直接启动这个 Python 程序（你的 FastAPI 应用），它会开启服务器、停在断点处，等等。

| 要点 | 说明 |
|---|---|
| `import uvicorn` | 直接用代码启动服务器，而非命令行 |
| `uvicorn.run(app, host="0.0.0.0", port=8000)` | 传入 `app` 对象、监听地址与端口 |
| 断点 | 直接打在路径操作函数里（如 `b = "b" + a` 行） |

### 3. `__name__ == "__main__"` 的作用

该判断让代码**只在直接运行文件时**执行，被其他文件导入时不执行：

| 运行方式 | `__name__` 的值 | `uvicorn.run(...)` 是否执行 |
|---|---|---|
| `uv run python myapp.py` | `"__main__"` | ✅ 执行 |
| 其他文件 `from myapp import app` | 模块名（如 `"myapp"`） | ❌ 不执行 |

细节：Python 在运行文件时会自动创建内部变量 `__name__`；直接运行脚本时其值为字符串 `"__main__"`，导入模块时则是模块名。

示例：若 `importer.py` 写 `from myapp import app`，则 `myapp.py` 中的 `__name__` 不会是 `"__main__"`，那段 `uvicorn.run(...)` 不会执行——这正是我们想要的：导入应用对象时不要顺带启动服务器。

### 4. 用调试器运行

**VS Code**：

1. 打开「调试」面板；
2. 「添加配置...」；
3. 选中「Python」；
4. 使用 `Python: Current File (Integrated Terminal)` 运行调试器。

它会用你的 FastAPI 代码开启服务器，在断点处停下。

**PyCharm**：

1. 打开「运行」菜单；
2. 选中「调试...」；
3. 在上下文菜单中选择要调试的文件（如 `main.py`）。

同样会启动服务器并停在断点处。

### 5. 易错点

| 易错点 | 正确做法 |
|---|---|
| 把 `uvicorn.run(...)` 写在模块顶层 | 放进 `if __name__ == "__main__":`，否则被导入时也会启动服务器 |
| 用命令行 `fastapi dev` 却困惑断点进不去 | 想用编辑器调试就改成代码里 `uvicorn.run(app, ...)`，从调试器启动 |
| 调试配置选错 | VS Code 用 `Python: Current File (Integrated Terminal)`；PyCharm 用「调试...」选目标文件 |
| 以为 `host="0.0.0.0"` 是本地专用 | `0.0.0.0` 监听所有网卡；只本机可用 `127.0.0.1` |

## 二、NestJS 对比

| 维度 | FastAPI（Python） | NestJS（TypeScript） |
|---|---|---|
| 调试启动方式 | 在代码中 `uvicorn.run(app, host=..., port=...)`，放到 `if __name__ == "__main__"` 里，由调试器运行该文件 | `npm run start:dev`（`nest start --watch`），VS Code 常用 `launch.json` 附加到进程或直接 debug `src/main.ts` |
| 应用启动代码 | `uvicorn.run(app, ...)` | `await NestFactory.create(AppModule)` + `app.listen(port)` |
| 条件执行 | `__name__ == "__main__"` 防止导入时启动服务器 | 通常 `main.ts` 是入口，模块导入不会触发 `listen()` |
| 调试器配置 | VS Code `Python: Current File` / PyCharm「调试...」 | VS Code `launch.json`（`node` / `ts-node` / `pwa-node`） |
| 热重载 | `fastapi dev` 提供；调试时常用 `uvicorn.run(..., reload=True)`（进阶） | `nest start --watch`（webpack/tsc watch） |
| 底层运行时 | Uvicorn + ASGI | Node.js + Express/Fastify |

**核心差异一句话**：FastAPI 的调试要点是把服务器启动搬进自己代码并用 `__name__ == "__main__"` 守卫，从而让编辑器"调试当前文件"直接拉起应用；NestJS 依靠 `main.ts` 入口与 `launch.json` 调试 Node 进程，启动逻辑本身不依赖类似 `__main__` 的守卫。

## 三、针对性练习题

### 题 1（基础）
写出能在调试器中直接运行的最小 FastAPI 应用：包含 `GET /` 返回 `{"hello": "world"}`，并用代码启动 uvicorn 监听 `0.0.0.0:8000`。

<details>
<summary>参考答案</summary>

```python
import uvicorn
from fastapi import FastAPI

app = FastAPI()

@app.get("/")
def root():
    return {"hello": "world"}

if __name__ == "__main__":
    uvicorn.run(app, host="0.0.0.0", port=8000)
```
</details>

### 题 2（理解）
为什么要写 `if __name__ == "__main__":`？分别说明直接运行和被导入时 `__name__` 的值与结果。

<details>
<summary>参考答案</summary>

直接运行 `python myapp.py` 时，Python 把 `__name__` 设为 `"__main__"`，因此 `uvicorn.run(...)` 执行，启动服务器。当被其他文件 `from myapp import app` 导入时，`__name__` 是模块名（如 `"myapp"`），条件不成立，不会启动服务器——避免导入应用对象时意外拉起服务，便于测试和多模块组织。
</details>

### 题 3（辨析/代码）
下面代码有什么问题？如何修正才能既可被安全导入，又能在调试器中启动？

```python
import uvicorn
from fastapi import FastAPI

app = FastAPI()
uvicorn.run(app, host="0.0.0.0", port=8000)
```

<details>
<summary>参考答案</summary>

`uvicorn.run(...)` 写在模块顶层，任何导入该模块的代码（如测试、其他模块）都会立刻启动服务器，造成阻塞或端口冲突。修正：

```python
import uvicorn
from fastapi import FastAPI

app = FastAPI()

if __name__ == "__main__":
    uvicorn.run(app, host="0.0.0.0", port=8000)
```

这样只有直接运行该文件时才启动，调试器"调试当前文件"也能正常工作。
</details>

### 题 4（进阶 · NestJS 迁移视角）
NestJS 用 `main.ts` 作为入口调用 `NestFactory.create()` 与 `app.listen()`，一般不需要 `__name__` 守卫。请写出功能等价的 FastAPI 代码，并说明为什么 FastAPI 教程特别强调这个守卫。

<details>
<summary>参考答案</summary>

```python
import uvicorn
from fastapi import FastAPI

app = FastAPI()

@app.get("/")
def root():
    return {"hello": "world"}

if __name__ == "__main__":
    uvicorn.run(app, host="0.0.0.0", port=8000)
```

原因：FastAPI 应用常通过 `from myapp import app` 被测试（`TestClient(app)`）或 ASGI 服务器命令加载；若启动代码在顶层，导入时就启动服务，破坏这些流程。Python 没有像 TypeScript 编译入口那样天然区分，必须显式用 `__name__ == "__main__"` 守卫来区分"作为脚本运行"与"作为模块导入"。
</details>

### 题 5（思考）
为什么把 `uvicorn.run(app, ...)` 放进代码后，就能在 VS Code / PyCharm 里打断点调试，而用 `fastapi dev` 命令启动则不容易？

<details>
<summary>参考答案</summary>

因为调试器需要"由自己启动"目标 Python 程序才能在调用栈上挂载断点。当服务器通过代码里的 `uvicorn.run(app, ...)` 启动时，编辑器调试配置（如 VS Code 的 `Python: Current File`）直接运行这个文件，路径操作函数就在被调试的进程里执行，断点自然命中。`fastapi dev` 是另一个命令行进程，调试器默认没有附加到它，需要额外配置"附加到进程"才行。
</details>
