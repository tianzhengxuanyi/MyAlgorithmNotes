## 一、章节笔记

### 1. 从 token 到「当前用户」

上一章的安全依赖只向路径操作传递了 `str` 类型的 `token`，并不实用。本章用依赖注入把令牌「解码」成当前用户对象，让 handler 直接拿到用户。

### 2. 完整示例

```python
from typing import Annotated

from fastapi import Depends, FastAPI
from fastapi.security import OAuth2PasswordBearer
from pydantic import BaseModel

app = FastAPI()

oauth2_scheme = OAuth2PasswordBearer(tokenUrl="token")

class User(BaseModel):
    username: str
    email: str | None = None
    full_name: str | None = None
    disabled: bool | None = None

def fake_decode_token(token):
    return User(
        username=token + "fakedecoded", email="john@example.com", full_name="John Doe"
    )

async def get_current_user(token: Annotated[str, Depends(oauth2_scheme)]):
    user = fake_decode_token(token)
    return user

@app.get("/users/me")
async def read_users_me(current_user: Annotated[User, Depends(get_current_user)]):
    return current_user
```

### 3. 逐步拆解

| 步骤 | 代码 | 说明 |
|---|---|---|
| ① 用户模型 | `class User(BaseModel)` | Pydantic 模型，与声明请求体方式相同，可用于任意位置 |
| ② 伪解码 | `fake_decode_token(token)` | 接收 `str` 令牌，返回一个 `User`（真实场景这里应校验令牌） |
| ③ 依赖 | `get_current_user` | **自身依赖 `oauth2_scheme`**，从子依赖拿到 `str` token，再返回 `User` |
| ④ 注入 | `current_user: Annotated[User, Depends(get_current_user)]` | handler 直接得到当前用户对象 |

关键点：**依赖可以有子依赖**——`get_current_user` 依赖 `oauth2_scheme`，形成 `oauth2_scheme → get_current_user → read_users_me` 的链。FastAPI 自动解析整条链。

### 4. 类型声明的价值

把 `current_user` 声明为 Pydantic `User` 模型，可在函数内部获得**代码补全与类型检查**。虽然请求体也用 Pydantic 模型声明，但因为用了 `Depends`，FastAPI 不会混淆二者。

依赖系统的设计允许**不同的可依赖对象返回同一个 `User` 模型**，不局限于只能有一个返回该类型的依赖。

### 5. 模型自由度

安全需求可使用**任何模型或数据**：

- 不一定用 `username`，可用 `id` + `email`；
- 可用字符串、字典、数据库模型实例；
- 登录主体也可以是机器人、程序或其他系统（只有访问令牌）——工作方式一样。

FastAPI 通过依赖注入系统都能处理。

### 6. 「只写一次」的复用价值

示例文件看似冗长（安全工具 + 数据模型 + 路径操作混在一起），但关键是：**安全与依赖注入代码只写一次**。无论多复杂，只在一个位置写一次；即便有数千个端点，都复用同一套安全系统，每个路径操作只需几行：

```python
@app.get("/users/me")
async def read_users_me(current_user: Annotated[User, Depends(get_current_user)]):
    return current_user
```

### 7. 易错点

- ✅ `get_current_user` 是依赖，且它自身依赖 `oauth2_scheme`（子依赖）。
- ✅ `fake_decode_token` 是占位实现，真实项目必须在此**验证令牌有效性**，不能只解码。
- ✅ `current_user` 标注为 Pydantic 模型只为编辑器服务，数据来自 `Depends`。
- ✅ 至此安全只完成一半：还缺真正发送 `username`/`password` 换令牌的端点（下一章）。

## 二、NestJS 对比

| 维度 | FastAPI（Python） | NestJS（TypeScript） |
|---|---|---|
| 当前用户注入 | `current_user: Annotated[User, Depends(get_current_user)]` | 自定义 `@CurrentUser()` 参数装饰器 + Guard 把用户挂到 `request.user` |
| 用户获取逻辑 | 写在依赖函数 `get_current_user` 中，可依赖 `oauth2_scheme` | 写在 Passport Strategy 的 `validate()`，返回对象成为 `request.user` |
| 用户模型 | Pydantic `User` 模型，仅用于类型提示与序列化 | DTO / interface 或实体类，配合 `@nestjs/swagger` 标注 |
| 子依赖链 | 依赖天然可嵌套：`oauth2_scheme → get_current_user → handler` | Strategy → Guard → 自定义装饰器，需分层装配 |
| 复用范围 | 数千端点共用同一依赖，每处仅一行 `Depends` | 一处 Strategy + Guard，端点用 `@UseGuards()` / `@CurrentUser()` |
| 主体类型 | 用户/机器人/系统皆可，模型自由 | 同样是任意对象，但需策略返回并约定到 request 上 |

**核心差异一句话**：FastAPI 用「依赖函数返回用户对象」一站式完成令牌解码与注入，靠子依赖链自然衔接、类型注解辅助编辑器；NestJS 需 Passport Strategy 产出用户、Guard 挂载到 request，再用自定义参数装饰器取出，分三层协作。

## 三、针对性练习题

### 题 1（基础）
定义 Pydantic 模型 `User`（含 `id`、`email`），写依赖 `get_current_user` 依赖 `oauth2_scheme` 并返回一个伪造 User，最后在 `GET /me/` 注入它返回。

<details>
<summary>参考答案</summary>

```python
from typing import Annotated
from fastapi import Depends, FastAPI
from fastapi.security import OAuth2PasswordBearer
from pydantic import BaseModel

app = FastAPI()
oauth2_scheme = OAuth2PasswordBearer(tokenUrl="token")

class User(BaseModel):
    id: int
    email: str

async def get_current_user(token: Annotated[str, Depends(oauth2_scheme)]):
    return User(id=1, email="user@example.com")

@app.get("/me/")
async def me(current_user: Annotated[User, Depends(get_current_user)]):
    return current_user
```

`get_current_user` 自身依赖 `oauth2_scheme`，形成子依赖链。
</details>

### 题 2（理解）
为什么说依赖系统允许「不同的可依赖项返回同一个 User 模型」有什么好处？

<details>
<summary>参考答案</summary>

因为注入靠 `Depends(...)` 指定具体依赖，而类型注解只服务于编辑器与类型检查。于是可以为不同登录方式（密码、第三方、机器人令牌）分别写多个依赖，它们都返回 `User`，handler 无需关心来自哪条路径，统一用 `current_user: Annotated[User, Depends(...)]` 接收，灵活且可替换。
</details>

### 题 3（辨析 / 代码）
下面代码里 `current_user: User` 的类型标注会被 FastAPI 当成请求体来解析吗？为什么？

```python
@app.get("/users/me")
async def read_users_me(current_user: User = Depends(get_current_user)):
    return current_user
```

<details>
<summary>参考答案</summary>

不会。虽然请求体也用 Pydantic 模型声明，但这里参数带了 `Depends(get_current_user)`，FastAPI 会把它当作依赖注入处理，从依赖返回值获取数据，而不是从请求体解析。类型标注仅用于编辑器补全与检查。
</details>

### 题 4（进阶 · NestJS 迁移视角）
NestJS 中你写 `AuthGuard('jwt')` 把用户挂到 `request.user`，再用 `@CurrentUser()` 取出。请用 FastAPI 写出等价实现，并说明「主体类型自由度」。

<details>
<summary>参考答案</summary>

```python
from typing import Annotated
from fastapi import Depends, FastAPI
from fastapi.security import OAuth2PasswordBearer
from pydantic import BaseModel

app = FastAPI()
oauth2_scheme = OAuth2PasswordBearer(tokenUrl="token")

class User(BaseModel):
    username: str

async def get_current_user(token: Annotated[str, Depends(oauth2_scheme)]):
    return User(username="rick")  # 真实场景应校验 token 并查库

@app.get("/me/")
async def me(current_user: Annotated[User, Depends(get_current_user)]):
    return current_user
```

差异：FastAPI 直接在依赖函数里返回对象并注入，链式调用由框架管理；NestJS 需 Strategy.validate 产出用户、Guard 挂到 request、自定义装饰器取三层。主体自由度：FastAPI 返回字符串、dict、数据库模型或机器人对象都一样工作，不绑定特定类。
</details>

### 题 5（思考）
文档说「至此安全的内容已经讲了一半」。还缺什么？为什么 `fake_decode_token` 只是占位？

<details>
<summary>参考答案</summary>

还缺真正让客户端用 `username`/`password` 换取令牌的 `/token` 路径操作（以及密码哈希、令牌签名等）。`fake_decode_token` 只是把令牌字符串拼成用户名，完全没有验证令牌是否有效、是否过期、是否被篡改——真实项目必须在此校验 JWT 签名或查询会话，否则任何人都能伪造令牌，毫无安全性。
</details>
