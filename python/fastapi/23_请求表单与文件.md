## 一、章节笔记

### 1. 本章要解决什么问题

实际业务中经常需要**一次请求同时上传文件和表单字段**（例如上传头像 + 令牌）。本章把 `File` 与 `Form` 组合到同一个路径操作中。

> 📦 前置安装：`uv add python-multipart`（文件和/或表单数据都需要它）。

### 2. 同时声明 File 与 Form 参数

```python
from typing import Annotated

from fastapi import FastAPI, File, Form, UploadFile

app = FastAPI()

@app.post("/files/")
async def create_file(
    file: Annotated[bytes, File()],
    fileb: Annotated[UploadFile, File()],
    token: Annotated[str, Form()],
):
    return {
        "file_size": len(file),
        "token": token,
        "fileb_content_type": fileb.content_type,
    }
```

非 `Annotated` 等价写法：

```python
@app.post("/files/")
async def create_file(
    file: bytes = File(), fileb: UploadFile = File(), token: str = Form()
):
    return {
        "file_size": len(file),
        "token": token,
        "fileb_content_type": fileb.content_type,
    }
```

要点：

- 文件和表单字段都作为**表单数据**上传与接收，编码为 `multipart/form-data`。
- 可以把**部分文件声明为 `bytes`**（内容直接读进内存，适合小文件），**部分声明为 `UploadFile`**（spooled 存储、带元数据，适合大文件）。
- 创建参数的方式与 `Body`、`Query` 一样；声明方式清晰统一。

### 3. 编码限制（重要警告）

一个路径操作可声明多个 `File` 与 `Form` 参数，但**不能同时声明要接收 JSON 的 `Body` 字段**：

- 此时请求体编码为 `multipart/form-data`，不是 `application/json`。
- 这是 **HTTP 协议的规定**，不是 FastAPI 的限制。

### 4. 三种参数形态对照

| 参数 | 类型声明 | 数据来源 | 适用场景 |
|---|---|---|---|
| 小文件 | `Annotated[bytes, File()]` | multipart 文件字段 | 小文件内容直接读进内存，`len(file)` 得大小 |
| 大文件 | `Annotated[UploadFile, File()]` 或 `UploadFile` | multipart 文件字段 | 可访问 `filename`、`content_type`、`.file`，spooled 存储 |
| 普通字段 | `Annotated[str, Form()]` | multipart 表单字段 | 令牌、描述等文本数据 |

### 5. 易错点

- ✅ 同时有文件和表单字段时，客户端必须用 `multipart/form-data` 发送。
- ✅ `bytes` 与 `UploadFile` 可以混用在同一请求中，按文件大小/需求分别选择。
- ✅ 绝对不要再加 JSON `Body` 参数 —— HTTP 请求体只能有一种编码。
- ✅ 别忘了安装 `python-multipart`。

## 二、NestJS 对比

| 维度 | FastAPI（Python） | NestJS（TypeScript） |
|---|---|---|
| 文件 + 表单字段 | `file: bytes = File()`、`fileb: UploadFile`、`token: str = Form()` 直接并列声明 | `@UseInterceptors(FileFieldsInterceptor(...))` + `@UploadedFiles()` + `@Body()` 取表单字段 |
| 参数装饰器 | `File()` / `Form()` 标记数据来源，类型注解即校验 | `@UploadedFile()` / `@UploadedFiles()` + `@Body('token')`，装饰器来自 `@nestjs/common` |
| 混合文件类型 | 同一请求中部分 `bytes`、部分 `UploadFile`，无需额外配置 | Multer 统一产 `Express.Multer.File`，`bytes` 对应 `buffer`（需 `memoryStorage`），大文件走 `path` |
| 请求体编码 | 自动识别 `multipart/form-data`，无需声明 | 拦截器自动处理 multipart；Swagger 需 `@ApiConsumes('multipart/form-data')` |
| 与 JSON 混用 | 禁止（HTTP 协议限制） | 同样禁止：multipart 与 application/json 不能共存于一个请求体 |
| 元数据访问 | `fileb.content_type`、`fileb.filename` | `file.mimetype`、`file.originalname` |
| 解析依赖 | `python-multipart` | Multer（Express 适配器内置）或 `@fastify/multipart`（Fastify 适配器） |
| 文档标注 | `File`/`Form` 参数自动写入 OpenAPI | DTO + `@ApiProperty()` + `@ApiConsumes()` 手动描述 |

**核心差异一句话**：FastAPI 把「文件 + 表单字段」当作普通函数参数并列声明，`File()`/`Form()` 各自标记来源，类型（`bytes`/`UploadFile`）自动决定处理方式；NestJS 要靠 `FileFieldsInterceptor`（或 `FileInterceptor` + `AnyFilesInterceptor`）接管 multipart 解析，再用 `@UploadedFiles()` 与 `@Body()` 分别取文件和字段，配置更繁琐但可精细控制上传限制。

## 三、针对性练习题

### 题 1（基础）

写一个 `POST /files/` 端点：同时接收两个文件（一个 `bytes`、一个 `UploadFile`）和一个表单字段 `token`，返回字节文件大小、令牌、以及 `UploadFile` 的 `content_type`。

<details>
<summary>参考答案</summary>

```python
from typing import Annotated
from fastapi import FastAPI, File, Form, UploadFile

app = FastAPI()

@app.post("/files/")
async def create_file(
    file: Annotated[bytes, File()],
    fileb: Annotated[UploadFile, File()],
    token: Annotated[str, Form()],
):
    return {
        "file_size": len(file),
        "token": token,
        "fileb_content_type": fileb.content_type,
    }
```

文件与字段都作为表单数据以 `multipart/form-data` 发送。
</details>

### 题 2（理解）

为什么同一个请求里可以让一个文件用 `bytes`、另一个用 `UploadFile`？各自适合什么场景？

<details>
<summary>参考答案</summary>

因为 `File` 参数的类型注解决定解析方式：`bytes` 让 FastAPI 把文件内容整体读入内存，`UploadFile` 则用 spooled 临时文件并提供元数据与 async 接口。小文件用 `bytes` 简单直接（`len(file)` 即可知大小）；大文件（图像、视频、二进制）用 `UploadFile` 避免占用全部内存，并可访问 `filename`、`content_type`、`.file`。
</details>

### 题 3（辨析/代码）

下面代码错在哪里？

```python
@app.post("/files/")
async def create_file(
    file: bytes = File(),
    token: str = Form(),
    payload: dict = Body(...),
):
    return {"size": len(file), "token": token, "payload": payload}
```

<details>
<summary>参考答案</summary>

不能同时声明 `File`/`Form` 与 JSON `Body`。存在文件时请求体编码必须是 `multipart/form-data`，而 JSON `Body` 需要 `application/json`，一个 HTTP 请求体只能有一种编码 —— 这是 HTTP 协议规定，不是 FastAPI 限制。修正：去掉 `payload: dict = Body(...)`，把所需数据也声明为 `Form()` 字段。
</details>

### 题 4（进阶 · NestJS 迁移视角）

NestJS 中你写：

```ts
@Post('files')
@UseInterceptors(FileFieldsInterceptor([
  { name: 'file', maxCount: 1 }, { name: 'fileb', maxCount: 1 },
]))
upload(@UploadedFiles() files, @Body('token') token: string) {
  return { token };
}
```

写出等价的 FastAPI 代码，并指出「文件字段分组」的差异。

<details>
<summary>参考答案</summary>

```python
from typing import Annotated
from fastapi import FastAPI, File, Form, UploadFile

app = FastAPI()

@app.post("/files/")
async def upload(
    file: Annotated[bytes, File()],
    fileb: Annotated[UploadFile, File()],
    token: Annotated[str, Form()],
):
    return {"token": token, "file_size": len(file), "fileb_type": fileb.content_type}
```

差异：NestJS 需 `FileFieldsInterceptor` 显式列出字段名与数量上限，再用 `@UploadedFiles()` 拿到分组后的对象；FastAPI 直接按**函数参数名**匹配同名的 multipart 字段，无需拦截器配置，数量限制需自行在代码中检查或用 `list[...]` 表达多值。
</details>

### 题 5（思考）

客户端用 `application/json` 发送请求体到上面这个同时声明 `File` + `Form` 的端点，会发生什么？从 HTTP 编码角度解释。

<details>
<summary>参考答案</summary>

请求会校验失败（422）：FastAPI 按 `multipart/form-data` 解析请求体，找不到文件字段和表单字段，必填参数缺失。原因是端点声明了 `File`/`Form`，请求体编码必须是 `multipart/form-data`；客户端却用 `application/json` 发送，两者不匹配。这正是「不能同时声明 JSON Body」警告的另一面 —— 编码由端点声明决定，客户端必须用对应编码发送。
</details>
