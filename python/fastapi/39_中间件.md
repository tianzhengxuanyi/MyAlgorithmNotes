## 一、章节笔记

### 1. 什么是中间件

「中间件」是一个函数，在**每个请求**被路径操作处理之前运行，也在**每个响应**返回之前运行。流程：

1. 接收应用的每一个 `request`；
2. 对请求做处理或执行任意代码；
3. 把请求传给应用其他部分（某个路径操作）；
4. 拿到路径操作产生的 `response`；
5. 对响应做处理或执行任意代码；
6. 返回响应。

技术细节：

- 若有带 `yield` 的依赖，其**退出代码在中间件之后**运行；
- 若有后台任务，它们在**所有中间件之后**运行。

### 2. 创建中间件

用 `@app.middleware("http")` 装饰函数。中间件接收两个参数：

| 参数 | 说明 |
|---|---|
| `request` | 当前请求对象（`Request`） |
| `call_next` | 函数，接收 `request`，把它传给对应路径操作，返回路径操作产生的 `response`；返回前你可修改该 response |

### 3. 示例：添加处理时间响应头

```python
import time

from fastapi import FastAPI, Request

app = FastAPI()

@app.middleware("http")
async def add_process_time_header(request: Request, call_next):
    start_time = time.perf_counter()
    response = await call_next(request)
    process_time = time.perf_counter() - start_time
    response.headers["X-Process-Time"] = str(process_time)
    return response
```

要点：

- 用 `X-` 前缀添加自定义请求头（专有约定）；
- 用 `time.perf_counter()` 而非 `time.time()`，因为前者在此场景更精确；
- 若希望浏览器端 JavaScript 读取自定义头，需把它加入 CORS 配置的 `expose_headers`（见下一章）。

> `Request` 可直接来自 `fastapi`，也可用 `from starlette.requests import Request`——FastAPI 为方便重导出，对象本身来自 Starlette。

### 4. 请求前 / 响应后

中间件可：

- 在路径操作收到请求**之前**插入代码（如日志、鉴权、计时起点）；
- 在响应生成之后、返回**之前**插入代码（如加响应头、计时终点）。

### 5. 多个中间件的执行顺序

用 `@app.middleware()` 或 `app.add_middleware()` 添加多个中间件时，每个新中间件都会**包裹**应用形成栈：最后添加的是最外层，最先添加的是最内层。

```python
app.add_middleware(MiddlewareA)
app.add_middleware(MiddlewareB)
```

执行顺序：

| 阶段 | 顺序 |
|---|---|
| 请求 | MiddlewareB → MiddlewareA → 路由 |
| 响应 | 路由 → MiddlewareA → MiddlewareB |

栈式行为保证中间件顺序可预测、可控（最外层先见请求、最后见响应）。

### 6. 易错点

- ✅ 中间件函数必须是 `async`，并 `await call_next(request)`。
- ✅ 修改响应头要在 `call_next` 返回 response 之后、`return` 之前。
- ✅ 浏览器要读的自定义头必须配置到 CORS `expose_headers`。
- ✅ 多层中间件是「栈」：后加的在外层，请求先过它、响应后过它。
- ✅ `yield` 依赖的清理代码在中间件之后、后台任务在更之后。

## 二、NestJS 对比

| 维度 | FastAPI（Python） | NestJS（TypeScript） |
|---|---|---|
| 声明方式 | `@app.middleware("http")` 装饰函数 | 实现 `NestMiddleware` 接口的 `use(req, res, next)` 类，在模块 `configure()` 中 `consumer.apply(...).forRoutes(...)` |
| 函数签名 | `async def middleware(request, call_next)`，`await call_next(request)` | `use(req, res, next)`，需手动调 `next()` 放行 |
| 请求前/后 | `call_next` 前后写代码 | `next()` 前后写代码 |
| 多中间件顺序 | 栈式：后添加的最外层（请求先过） | `apply(A, B)` 按注册顺序执行（请求 A→B），需自行注意顺序 |
| 全局中间件 | 装饰器/ `add_middleware` 作用于全应用 | `app.use(...)`（底层 Express）或 `configure()` 中 `forRoutes('*')` |
| 响应头修改 | `response.headers[...] = ...` | `res.setHeader(...)` |
| 浏览器可见头 | 配 CORS `expose_headers` | 配 `@nestjs/swagger`/CORS `exposedHeaders` |
| 底层 | Starlette 中间件栈（ASGI） | Express 中间件（或 Fastify 钩子） |

**核心差异一句话**：FastAPI 用单个 `async` 函数加 `@app.middleware("http")` 定义中间件，靠 `await call_next()` 前后分界并以后加者为外层的栈序执行；NestJS 需实现 `NestMiddleware` 类并在模块 `configure()` 注册，靠 `next()` 放行、按 `apply()` 顺序执行，更贴近 Express 风格。

## 三、针对性练习题

### 题 1（基础）
写一个中间件，为每个响应添加自定义头 `X-App-Version: 1.0`。

<details>
<summary>参考答案</summary>

```python
from fastapi import FastAPI, Request

app = FastAPI()

@app.middleware("http")
async def add_version_header(request: Request, call_next):
    response = await call_next(request)
    response.headers["X-App-Version"] = "1.0"
    return response
```

中间件必须 `async`，并 `await call_next(request)` 取得响应后再改响应头。
</details>

### 题 2（理解）
中间件函数接收的 `call_next` 是什么？为什么修改响应头要在它之后？

<details>
<summary>参考答案</summary>

`call_next` 是一个函数，接收 `request` 并把它传给对应的路径操作，返回该路径操作生成的 `response`。只有在调用 `await call_next(request)` 之后才拿到真实响应对象，因此要修改响应头（如加 `X-Process-Time`），必须在 `call_next` 返回之后、`return response` 之前进行。
</details>

### 题 3（辨析 / 代码）
下面两个中间件按如此顺序添加，请求和响应的经过顺序分别是什么？

```python
app.add_middleware(MiddlewareA)
app.add_middleware(MiddlewareB)
```

<details>
<summary>参考答案</summary>

后添加的 `MiddlewareB` 是最外层。请求：MiddlewareB → MiddlewareA → 路由；响应：路由 → MiddlewareA → MiddlewareB。即最外层先见请求、最后见响应，形成包裹栈。
</details>

### 题 4（进阶 · NestJS 迁移视角）
NestJS 中间件用 `use(req, res, next)` 且需调用 `next()`。请写出 FastAPI 中等价的「请求前打日志 + 响应后加头」中间件，并指出放行机制差异。

<details>
<summary>参考答案</summary>

```python
import time
from fastapi import FastAPI, Request

app = FastAPI()

@app.middleware("http")
async def log_and_tag(request: Request, call_next):
    print(f"before: {request.url.path}")
    response = await call_next(request)   # 放行并等待路径操作
    response.headers["X-Handled"] = "true"
    print("after response")
    return response
```

差异：NestJS 靠显式调用 `next()` 把请求交给后续处理链；FastAPI 靠 `await call_next(request)`——它同时完成「放行」与「取回响应」，之后的代码即响应后逻辑，无需手动 next。
</details>

### 题 5（思考）
文档提醒：若希望浏览器中的客户端看到自定义响应头，需配置 CORS 的 `expose_headers`。为什么？

<details>
<summary>参考答案</summary>

出于同源策略，浏览器默认只允许前端 JS 访问有限的「简单」响应头；中间件加的自定义头（如 `X-Process-Time`）即使随响应返回，浏览器 JS 也读不到，除非服务端在 CORS 响应中通过 `Access-Control-Expose-Headers`（即 FastAPI CORS 配置的 `expose_headers`）显式声明允许暴露这些头。
</details>
