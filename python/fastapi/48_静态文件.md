## 一、章节笔记

### 1. 用 `StaticFiles` 提供静态文件

`StaticFiles` 可以从某个目录自动提供静态文件。导入 `StaticFiles`，把一个实例**挂载（Mount）**到指定路径：

```python
from fastapi import FastAPI
from fastapi.staticfiles import StaticFiles

app = FastAPI()

app.mount("/static", StaticFiles(directory="static"), name="static")
```

之后任何以 `/static` 开头的路径都由这个子应用处理，例如 `/static/logo.png` → `static/logo.png`。

技术细节：也可 `from starlette.staticfiles import StaticFiles`。FastAPI 的 `fastapi.staticfiles` 只是从 Starlette 直接重新导出，方便开发者使用。

### 2. 三个参数

| 参数 | 含义 |
|---|---|
| `"/static"` | 挂载点：子路径，任何以它开头的请求都交给这个子应用处理 |
| `directory="static"` | 存放静态文件的目录名 |
| `name="static"` | 供 FastAPI 内部使用的名称（反向生成 URL 时用） |

这三个值都可以按你的应用需求改成别的名字。

### 3. 什么是"挂载"（Mounting）

"挂载"表示在特定路径添加一个**完全独立**的应用，由它负责处理所有子路径。

**与 `APIRouter` 的本质区别**：

| 对比 | `app.mount()` 挂载 | `app.include_router()` |
|---|---|---|
| 是否独立 | 完全独立的子应用 | 不是挂载，不隔离 |
| OpenAPI/文档 | 主应用的 OpenAPI 与文档**不包含**挂载应用的任何内容 | 路由与元数据合并进同一份 OpenAPI |
| 路由生成 | 子应用自己处理所有子路径 | FastAPI 保留原始 router/route 处于活动状态并组合元数据 |

更多细节见高级用户指南。

### 4. 何时用 `StaticFiles`、何时用 `app.frontend()`

正文特别提示：

- 如果要**托管前端**，请改用 `app.frontend()`（见"前端"一章）。
- `app.frontend()` 底层使用 `StaticFiles`，但为前端提供了额外优势，例如**处理客户端路由**（SPA fallback）。
- `StaticFiles` 适合提供零碎的静态资源（图片、CSS、JS 文件等），而不适合直接托管带客户端路由的前端应用。

### 5. 易错点

| 易错点 | 正确做法 |
|---|---|
| 用 `StaticFiles` 托管 SPA 后直接访问 `/dashboard` 报 404 | 用 `app.frontend()`，它处理 SPA fallback |
| 以为挂载的静态文件会出现在 `/docs` | 挂载的应用完全独立，不进主应用 OpenAPI |
| 以为 `mount` 只匹配精确路径 | `mount` 会接管该路径下**所有子路径** |
| 目录路径写成绝对路径且不存在 | 确保 `directory` 指向存在的静态文件目录 |

## 二、NestJS 对比

| 维度 | FastAPI（Python） | NestJS（TypeScript） |
|---|---|---|
| 静态文件模块 | `from fastapi.staticfiles import StaticFiles`（源自 Starlette） | `@nestjs/serve-static` 的 `ServeStaticModule.forRoot()` |
| 配置方式 | `app.mount("/static", StaticFiles(directory="static"), name="static")` | `ServeStaticModule.forRoot({ rootPath, serveRoot: '/static' })` |
| 机制 | Mount：挂载一个完全独立的子应用 | 由模块注册静态中间件/处理器，仍在 Nest 应用体系内 |
| OpenAPI 可见性 | 挂载内容不出现在主应用文档 | 静态资源通常也不进 Swagger |
| SPA 支持 | 用 `app.frontend()`（内置 fallback） | `ServeStaticModule` + 手写通配路由 |
| 命名用途 | `name="static"` 供内部反向 URL 使用 | 通过 `renderPath` 等配置自定义 |

**核心差异一句话**：FastAPI 的 `StaticFiles` 是 Starlette 的挂载式子应用，通过 `app.mount()` 一行接入且完全独立于主应用的 OpenAPI；NestJS 通过 `ServeStaticModule` 在 Module 层配置静态服务，SPA 路由等仍需额外手写通配处理。

## 三、针对性练习题

### 题 1（基础）
写出用 `StaticFiles` 把项目下的 `static` 目录挂载到 `/static` 的代码，并说明三个参数的含义。

<details>
<summary>参考答案</summary>

```python
from fastapi import FastAPI
from fastapi.staticfiles import StaticFiles

app = FastAPI()
app.mount("/static", StaticFiles(directory="static"), name="static")
```

- `"/static"`：挂载的子路径，所有以它开头的请求由该子应用处理。
- `directory="static"`：静态文件所在目录。
- `name="static"`：供 FastAPI 内部使用的名称。
</details>

### 题 2（理解）
"挂载（Mount）"与 `include_router()` 有什么本质区别？为什么说挂载的应用是"完全独立"的？

<details>
<summary>参考答案</summary>

挂载是在特定路径添加一个完全独立的子应用，由它处理所有子路径；`include_router()` 则把 router 的路径组合进主应用，FastAPI 保留原 router/route 活动状态，合并前缀、依赖、标签、响应等元数据。独立性体现在：主应用的 OpenAPI 与文档**不包含**挂载应用的任何内容，路由也不参与主应用的文档生成。
</details>

### 题 3（辨析/代码）
你想托管一个 Vite 构建的 SPA（`dist/` 目录），包含 `/dashboard/settings` 这样的客户端路由。用 `StaticFiles` 挂载会不会有问题？应该怎么做？

<details>
<summary>参考答案</summary>

会有问题：`StaticFiles` 只按文件路径提供静态资源，`/dashboard/settings` 并不是真实文件，直接访问会 404。应改用 `app.frontend()`：

```python
from fastapi import FastAPI

app = FastAPI()
app.frontend("/", directory="dist")  # 默认 fallback="auto"，目录有 index.html 时自动支持 SPA 路由
```

`app.frontend()` 底层也用 `StaticFiles`，但额外提供客户端路由 fallback 等前端专用能力。
</details>

### 题 4（进阶 · NestJS 迁移视角）
NestJS 中用 `ServeStaticModule.forRoot({ rootPath, serveRoot: '/static' })` 提供静态文件。写出 FastAPI 等价代码，并指出两者在"独立性"与 OpenAPI 上的差异。

<details>
<summary>参考答案</summary>

```python
from fastapi import FastAPI
from fastapi.staticfiles import StaticFiles

app = FastAPI()
app.mount("/static", StaticFiles(directory="static"), name="static")
```

FastAPI 这里是真正的"挂载子应用"，完全独立，主应用 OpenAPI/文档不含其任何内容；NestJS 的 `ServeStaticModule` 在 Module 层注册静态处理，仍属于同一应用体系，静态资源同样不会进 Swagger，但没有"独立子应用"这一层语义。
</details>

### 题 5（思考）
`fastapi.staticfiles.StaticFiles` 与 `starlette.staticfiles.StaticFiles` 是什么关系？为什么 FastAPI 要再导出一次？

<details>
<summary>参考答案</summary>

二者是同一个类：FastAPI 的 `fastapi.staticfiles` 直接从 `starlette.staticfiles` 重新导出。FastAPI 基于 Starlette 构建，这样做只是为了方便开发者统一从 `fastapi` 导入，避免记两套路径，不改变功能。
</details>
