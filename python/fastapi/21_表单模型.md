## 一、章节笔记

### 1. 本章要解决什么问题

一组相关表单字段可用 **Pydantic 模型**统一声明，复用字段、校验与元数据，就像 Cookie/Header 参数模型一样。

- 模型声明表单字段：**FastAPI 0.113.0+** 支持。
- 禁止额外字段（extra forbid）：**0.114.0+** 支持。
- 仍需安装 `python-multipart`（`uv add python-multipart`）。

### 2. 表单的 Pydantic 模型

```python
from typing import Annotated

from fastapi import FastAPI, Form
from pydantic import BaseModel

app = FastAPI()

class FormData(BaseModel):
    username: str
    password: str

@app.post("/login/")
async def login(data: Annotated[FormData, Form()]):
    return data
```

非 `Annotated` 等价写法：`data: FormData = Form()`。

- FastAPI 从表单数据中提取各字段，组装成 `FormData` 模型实例。
- HTML 复选框：把布尔字段默认值声明为 `False`。
- 在 `/docs` 中可查看生成的文档。

### 3. 禁止额外的表单字段

```python
from typing import Annotated

from fastapi import FastAPI, Form
from pydantic import BaseModel

app = FastAPI()

class FormData(BaseModel):
    username: str
    password: str
    model_config = {"extra": "forbid"}

@app.post("/login/")
async def login(data: Annotated[FormData, Form()]):
    return data
```

客户端若发送额外字段 `extra: Mr. Poopybutthole`，错误响应：

```json
{
    "detail": [
        {
            "type": "extra_forbidden",
            "loc": ["body", "extra"],
            "msg": "Extra inputs are not permitted",
            "input": "Mr. Poopybutthole"
        }
    ]
}
```

注意 `loc` 为 `["body", "extra"]`。

### 4. 组合表单模型

多个表单模型可与单独的 `Form` 参数组合使用：

```python
from typing import Annotated

from fastapi import FastAPI, Form
from pydantic import BaseModel

app = FastAPI()

class Profile(BaseModel):
    name: str

class Preferences(BaseModel):
    tags: list[str] = []

@app.post("/profiles/")
async def create_profile(
    profile: Annotated[Profile, Form()],
    preferences: Annotated[Preferences, Form()],
    token: Annotated[str, Form()],
):
    return {"profile": profile, "preferences": preferences, "token": token}
```

- 客户端把 `name`、`tags`、`token` 都作为表单字段发送；每个模型**独立验证**自己的字段。
- 每个模型的 `extra` 配置适用于**所有**表单字段，包括其它参数或依赖项中声明的字段和文件：`forbid` 拒绝模型外任何字段，`allow` 则把额外字段并入模型。
- 多个声明使用**相同的表单字段名**时，每个声明都会验证该值；共享字段应使用兼容的类型与约束，保证 OpenAPI 描述一致。

### 5. 可选表单模型

```python
from typing import Annotated

from fastapi import FastAPI, Form
from pydantic import BaseModel

app = FastAPI()

class Profile(BaseModel):
    name: str
    age: int

@app.post("/profiles/")
async def create_profile(
    token: Annotated[str, Form()],
    profile: Annotated[Profile | None, Form()] = None,
):
    return {"token": token, "profile": profile}
```

规则（与可选查询参数模型类似，但细节更细）：

| 情况 | 结果 |
|---|---|
| `name`、`age` 都不发 | `profile` 为 `None` |
| 发了任意一个（**包括空值**） | 触发完整模型校验，要求两个字段都在 |
| 用 `| None` 但**不设默认值** | 参数仍然**必填** |
| 额外字段被忽略 | 不会让模型被视为「已提供」 |
| 只有未勾选的复选框 | 可选模型被省略；发 `enabled=false` 可显式提供模型 |

### 6. 可选/组合的判别联合模型

用 `Form(discriminator="字段")` + `Literal` 实现「按标记选择模型」：

```python
from typing import Annotated, Literal

from fastapi import FastAPI, Form
from pydantic import BaseModel

app = FastAPI()

class Person(BaseModel):
    kind: Literal["person"]
    name: str

class Company(BaseModel):
    kind: Literal["company"]
    company_name: str

@app.post("/contacts/")
async def create_contact(
    contact: Annotated[Person | Company | None, Form(discriminator="kind")] = None,
):
    return contact
```

- 不发任何表单字段 → `contact` 为 `None`。
- 发送 `kind=person` + `name` 或 `kind=company` + `company_name` → 判别器选择对应模型验证。
- 联合类型可与其它表单模型、单独 `Form` 参数、`File` 参数组合，**每个联合类型独立验证**：

```python
from typing import Annotated, Literal

from fastapi import FastAPI, Form
from pydantic import BaseModel

app = FastAPI()

class Person(BaseModel):
    contact_type: Literal["person"]
    name: str

class Company(BaseModel):
    contact_type: Literal["company"]
    company_name: str

class Email(BaseModel):
    notification_type: Literal["email"]
    email: str

class SMS(BaseModel):
    notification_type: Literal["sms"]
    phone: str

@app.post("/contacts/")
async def create_contact(
    contact: Annotated[Person | Company, Form(discriminator="contact_type")],
    token: Annotated[str, Form()],
    notification: Annotated[
        Email | SMS | None, Form(discriminator="notification_type")
    ] = None,
):
    return {"contact": contact, "notification": notification, "token": token}
```

### 7. 表单模型与文件组合

```python
from typing import Annotated

from fastapi import FastAPI, Form, UploadFile
from pydantic import BaseModel

app = FastAPI()

class Profile(BaseModel):
    name: str

@app.post("/profiles/")
async def create_profile(profile: Annotated[Profile, Form()], avatar: UploadFile):
    return {"profile": profile, "filename": avatar.filename}
```

客户端以 `multipart/form-data` 发送 `name` 字段和 `avatar` 文件。

### 8. 易错点

- ✅ 忘记 `Form()` 标记 → 模型被当作 JSON 请求体解析。
- ✅ `extra="forbid"` 是全局的，多模型/文件组合时需注意不要互相冲突。
- ✅ 可选模型「发一个字段就要求全部字段」，且空值也算「已提供」。
- ✅ 判别联合必须提供判别字段（如 `kind`），否则无法选择模型。

## 二、NestJS 对比

| 维度 | FastAPI（Python） | NestJS（TypeScript） |
|---|---|---|
| 表单字段建模 | Pydantic 模型 + `Annotated[FormData, Form()]`，一次声明全部字段 | DTO 类 + `@Body()` 绑定整个表单对象，`class-validator` 逐字段校验 |
| 禁止额外字段 | `model_config = {"extra": "forbid"}`（0.114.0+），错误 `loc: ["body", ...]` | `ValidationPipe({ whitelist: true, forbidNonWhitelisted: true })` |
| 多模型组合 | 多个模型参数各自独立验证，`extra` 对所有表单字段生效 | 多个 DTO 或 `@Body()` 分块取字段，需手动拆分 body 对象 |
| 可选整组字段 | `Model | None = None` 原生表达，空值也算「已提供」 | DTO 属性 `@IsOptional()` + `?`，由验证器解释「缺失 vs 空值」 |
| 判别联合 | `Form(discriminator="kind")` + `Literal` 自动选模型 | 需 `@ValidateIf` / 自定义 Pipe 按判别字段分支校验，样板更多 |
| 联合与文件组合 | 联合类型 + `Form` 参数 + `UploadFile` 可在同一请求中共存 | `FileInterceptor` + `@UploadedFile()` + `@Body()`，需手工拼装 |
| 表单模型 + 文件 | `profile: Annotated[Profile, Form()]` + `avatar: UploadFile` | `@Body()` DTO + `@UploadedFile('avatar')`，且需 `@UseInterceptors(FileInterceptor(...))` |
| 文档生成 | 模型字段自动进 OpenAPI | DTO 字段需 `@ApiProperty()`，multipart 需 `@ApiConsumes('multipart/form-data')` |

**核心差异一句话**：FastAPI 把表单字段组当作一个 Pydantic 模型参数，`extra` 策略、可选语义、判别联合都由模型与 `Form()` 声明式表达，且自动写入 OpenAPI；NestJS 依靠 `@Body()` + DTO + `ValidationPipe` 的组合，判别联合与可选语义要写自定义校验逻辑，文件与字段的组合还需 `FileInterceptor` 显式接线。

## 三、针对性练习题

### 题 1（基础）

用 Pydantic 模型声明登录表单（`username`、`password` 必填），写 `POST /login/` 返回该模型。

<details>
<summary>参考答案</summary>

```python
from typing import Annotated
from fastapi import FastAPI, Form
from pydantic import BaseModel

app = FastAPI()

class FormData(BaseModel):
    username: str
    password: str

@app.post("/login/")
async def login(data: Annotated[FormData, Form()]):
    return data
```

FastAPI 从表单数据提取各字段组装成 `FormData`；此功能自 0.113.0 起支持，需先安装 `python-multipart`。
</details>

### 题 2（理解）

客户端发送 `extra=Mr. Poopybutthole` 时，如何拒绝？写出关键配置与错误响应的 `loc`。

<details>
<summary>参考答案</summary>

在模型里加 `model_config = {"extra": "forbid"}`（0.114.0+）：

```python
class FormData(BaseModel):
    username: str
    password: str
    model_config = {"extra": "forbid"}
```

错误响应中 `loc` 为 `["body", "extra"]`，`type` 为 `extra_forbidden`，`msg` 为 `Extra inputs are not permitted`。
</details>

### 题 3（辨析/代码）

对于可选模型 `profile: Annotated[Profile | None, Form()] = None`（字段 `name`、`age`），判断：

1. 只发 `name=Rick` → 通过还是报错？
2. 发 `name=`（空值）→ 模型算「已提供」吗？
3. 写成 `profile: Annotated[Profile | None, Form()]`（无 `= None`）→ 还可选吗？

<details>
<summary>参考答案</summary>

1. 报错。发了任意一个字段就触发完整模型校验，要求 `name`、`age` 都在，缺 `age` → 422。
2. 算已提供。正文明确：提交空值也算提供了字段，因此会触发完整校验。
3. 不再可选。`| None` 但不设默认值 `= None` 时，该参数仍是**必填**的。
</details>

### 题 4（进阶 · NestJS 迁移视角）

用 `Form(discriminator="kind")` + `Literal` 写一个可选判别联合：`Person(kind="person", name)` 与 `Company(kind="company", company_name)`，什么都不发返回 `None`。

<details>
<summary>参考答案</summary>

```python
from typing import Annotated, Literal
from fastapi import FastAPI, Form
from pydantic import BaseModel

app = FastAPI()

class Person(BaseModel):
    kind: Literal["person"]
    name: str

class Company(BaseModel):
    kind: Literal["company"]
    company_name: str

@app.post("/contacts/")
async def create_contact(
    contact: Annotated[Person | Company | None, Form(discriminator="kind")] = None,
):
    return contact
```

`kind=person` + `name=...` 选 `Person`；`kind=company` + `company_name=...` 选 `Company`；都不发 → `None`。NestJS 的等价实现需用 `@ValidateIf` 或自定义 Pipe 根据判别字段分支，远不如 `discriminator` 声明简洁。
</details>

### 题 5（思考）

两个表单模型组合时，模型 A 设 `extra="allow"`，模型 B 设 `extra="forbid"`。客户端发送一个模型 A 里没有、但模型 B 里有的字段，会发生什么？为什么？

<details>
<summary>参考答案</summary>

会触发 `extra_forbidden` 错误。因为每个模型的 `extra` 配置适用于**所有**表单字段（包括其他参数、依赖项中声明的字段和文件）：模型 B 的 `forbid` 会拒绝任何不属于模型 B 的字段，即使它属于模型 A。因此组合使用时应统一 `extra` 策略，避免一个模型 `allow`、另一个 `forbid` 的冲突配置。
</details>
