## 一、章节笔记

### 1. 用 `Path` 为路径参数声明校验与元数据

正如用 `Query` 为查询参数添加校验/元数据，路径参数用 `Path`，写法完全对称：

```python
from typing import Annotated
from fastapi import FastAPI, Path, Query

app = FastAPI()

@app.get("/items/{item_id}")
async def read_items(
    item_id: Annotated[int, Path(title="The ID of the item to get")],
    q: Annotated[str | None, Query(alias="item-query")] = None,
):
    results = {"item_id": item_id}
    if q:
        results.update({"q": q})
    return results
```

旧式写法（把 `Path`/`Query` 当默认值）也支持，但依然推荐 `Annotated`：

```python
item_id: int = Path(title="The ID of the item to get")
```

### 2. 路径参数天生必填

- 路径参数必须是 URL 的一部分，因此**总是必填**。
- 类型里加 `None` 也不会让它变成可选。
- 用 `Path` 声明的参数**不能有默认值**。

这与查询参数"看默认值决定必填"的规则不同。

### 3. 参数排序问题（旧式写法才需注意）

Python 语法规定：**没有默认值的参数不能写在有默认值的参数之后**。旧式写法中 `Path(...)` 相当于给参数加了默认值，因此若 `q` 是必填查询参数（无默认值），需要把它前置：

```python
from fastapi import FastAPI, Path

app = FastAPI()

@app.get("/items/{item_id}")
async def read_items(q: str, item_id: int = Path(title="The ID of the item to get")):
    ...
```

对 FastAPI 而言参数顺序无关紧要——它靠**参数名、类型、默认值声明（`Query`/`Path` 等）**来检测参数。

**技巧**：想在旧式写法中保持原顺序，可在第一个参数位置放一个 `*`，其后的参数都变成仅关键字参数（`kwargs`），即使没有默认值也不会触发语法错误：

```python
async def read_items(*, item_id: int = Path(title="The ID of the item to get"), q: str):
    ...
```

> **使用 `Annotated` 时完全没这个问题**：因为没用 `Query()`/`Path()` 当默认值，参数顺序随意，通常也用不到 `*`。

### 4. 数值校验：`ge` / `gt` / `le` / `lt`

`Query` 与 `Path`（以及后续其他类）支持数值约束：

| 参数 | 含义 | 英文记忆 |
|---|---|---|
| `ge` | 大于等于 | **g**reater than or **e**qual |
| `gt` | 大于 | **g**reater **t**han |
| `le` | 小于等于 | **l**ess than or **e**qual |
| `lt` | 小于 | **l**ess **t**han |

**大于等于**：

```python
from typing import Annotated
from fastapi import FastAPI, Path

app = FastAPI()

@app.get("/items/{item_id}")
async def read_items(
    item_id: Annotated[int, Path(title="The ID of the item to get", ge=1)],
    q: str,
):
    results = {"item_id": item_id}
    if q:
        results.update({"q": q})
    return results
```

`ge=1` 要求 `item_id` 是整数且 ≥ 1。

**大于 + 小于等于**：

```python
item_id: Annotated[int, Path(title="The ID of the item to get", gt=0, le=1000)]
```

**浮点数校验**：数值校验同样适用于 `float`。对浮点数，`gt` 比 `ge` 更有意义——可要求值 > 0 即便它小于 1，`0.5` 有效而 `0.0`/`0` 无效。

```python
from typing import Annotated
from fastapi import FastAPI, Path, Query

app = FastAPI()

@app.get("/items/{item_id}")
async def read_items(
    *,
    item_id: Annotated[int, Path(title="The ID of the item to get", ge=0, le=1000)],
    q: str,
    size: Annotated[float, Query(gt=0, lt=10.5)],
):
    results = {"item_id": item_id}
    if q:
        results.update({"q": q})
    if size:
        results.update({"size": size})
    return results
```

### 5. 底层机制小结

- `Query`、`Path` 及后续其他类都是通用 `Param` 类的**子类**，共享相同的额外校验与元数据参数。
- 从 `fastapi` 导入的 `Query`、`Path` 实际上是**函数**：调用时返回同名类的实例。之所以用函数而非直接用类，是为了让编辑器不因类型标注而误报错误，无需额外配置即可正常使用编辑器工具。

### 6. 校验参数速查

| 类别 | 可用参数 |
|---|---|
| 元数据 | `title`、`description`、`alias`、`deprecated`、`include_in_schema` 等 |
| 字符串校验 | `min_length`、`max_length`、`pattern` |
| 数值校验 | `ge`、`gt`、`le`、`lt` |

### 7. 易错点小结

- ✅ 路径参数永远必填，`Path` 声明不能带默认值；加 `None` 也不会变可选。
- ✅ 用 `Annotated` 可绕开 Python"默认值参数必须在后"的顺序限制，无需 `*`。
- ✅ 数值约束区分开闭区间：`ge/le` 含边界，`gt/lt` 不含。
- ✅ 数值校验对 `int` 和 `float` 都有效。

## 二、NestJS 对比

| 维度 | FastAPI（Python） | NestJS（TypeScript） |
|---|---|---|
| 路径参数校验声明 | `Annotated[int, Path(title=..., ge=1, le=1000)]` | `@Param('id', new ParseIntPipe())` + DTO/`@Min(1)` `@Max(1000)` |
| 路径参数必填性 | 天生必填，不能有默认值 | 路由 `:id` 本身必填，缺失即不匹配路由 |
| 数值范围校验 | `ge/gt/le/lt` 直接写在 `Path`/`Query` 上 | `class-validator` 的 `@Min()`/`@Max()` 写在 DTO，或自定义 Pipe |
| 元数据（title 等） | `Path(title=...)` 内联声明 | 需 `@ApiParam({ name:'id', description:... })`（`@nestjs/swagger`） |
| 参数顺序限制 | `Annotated` 下无限制；旧式需前置无默认值参数或用 `*` | 方法参数顺序由装饰器决定，无 Python 式默认值顺序问题 |
| 类型转换 + 校验合一 | `int` 注解 + `Path(ge=1)` 一步完成 | `ParseIntPipe` 转换、`@Min` 校验分两步（DTO + Pipe） |
| 底层共享机制 | `Query`/`Path` 等均继承 `Param`，参数通用 | 各类 Pipe 实现 `PipeTransform` 接口，可组合复用 |
| 错误响应 | Pydantic 统一 `422` + `loc/type/msg`（loc 为 `["path","id"]`） | `ParseIntPipe` 抛 `BadRequestException`（400），格式可自定义 |

**核心差异一句话**：FastAPI 用 `Path(ge=1, le=1000)` 把路径参数的转换、范围校验、文档元数据合并为一条声明；NestJS 需要 `ParseIntPipe` 负责转换、`class-validator` 装饰器负责范围、Swagger 装饰器负责文档，职责更细分但需多处配置。

## 三、针对性练习题

### 题 1（基础）

声明 `GET /items/{item_id}`，要求 `item_id` 为整数且 ≥ 1，并带 `title="The ID of the item to get"`。

<details>
<summary>参考答案</summary>

```python
from typing import Annotated
from fastapi import FastAPI, Path

app = FastAPI()

@app.get("/items/{item_id}")
async def read_items(
    item_id: Annotated[int, Path(title="The ID of the item to get", ge=1)],
):
    return {"item_id": item_id}
```

`ge=1` 表示 ≥ 1；`item_id` 因在路径中而必填。
</details>

### 题 2（理解）

`Query(ge=1)` 与 `Path(ge=1)` 的校验行为是否一致？它们为什么能使用同一批参数（如 `ge`、`title`）？

<details>
<summary>参考答案</summary>

校验行为一致（都是"值 ≥ 1"），区别仅在参数来源：`Query` 从查询字符串取，`Path` 从 URL 路径取。

它们能共享参数是因为 `Query`、`Path`（及后续的 `Body`、`Header`、`Cookie` 等）都是通用 `Param` 类的子类，继承同一批用于校验与元数据的参数定义。
</details>

### 题 3（辨析/代码）

下面旧式写法会报 Python 语法错误，请解释原因并给出两种修复方式。

```python
async def read_items(
    item_id: int = Path(title="The ID"),   # 有"默认值"
    q: str,                                 # 无默认值
): ...
```

<details>
<summary>参考答案</summary>

原因：Python 要求无默认值的参数不能出现在有默认值的参数之后。`Path(...)` 作为默认值让 `item_id` 变成"有默认值"的参数，而 `q: str` 无默认值且在其后，故报错。

修复方式一：把无默认值的 `q` 前置：
```python
async def read_items(q: str, item_id: int = Path(title="The ID")): ...
```

修复方式二：用 `*` 让后续参数都变为仅关键字参数：
```python
async def read_items(*, item_id: int = Path(title="The ID"), q: str): ...
```

最佳实践：改用 `Annotated` 写法 `item_id: Annotated[int, Path(title="The ID")]`，不再用 `Path()` 当默认值，顺序随意且不会报错。
</details>

### 题 4（进阶 · NestJS 迁移视角）

NestJS 中你这样限制路径 ID 范围：

```ts
@Get(':id')
get(@Param('id', ParseIntPipe) id: number) { ... }
// 另需在 DTO 中用 @Min(1) @Max(1000) 校验范围
```

请写出等价 FastAPI 代码（ID 为 1～1000 的整数），并说明 NestJS 的 `ParseIntPipe` + `@Min/@Max` 在 FastAPI 中如何体现。

<details>
<summary>参考答案</summary>

```python
from typing import Annotated
from fastapi import FastAPI, Path

app = FastAPI()

@app.get("/items/{item_id}")
async def get_item(
    item_id: Annotated[int, Path(ge=1, le=1000)],
):
    return {"item_id": item_id}
```

NestJS 的 `ParseIntPipe` 负责把字符串转成数字、失败抛 400；`@Min(1)/@Max(1000)` 负责范围校验（需 DTO + `ValidationPipe`）。FastAPI 中这两步由 `item_id: int` 类型注解（自动转换）与 `Path(ge=1, le=1000)`（范围校验）一条声明完成，失败统一返回 `422`，无需额外的管道或 DTO。
</details>

### 题 5（思考）

对 `float` 参数 `size`，为什么用 `gt=0, lt=10.5`（而非 `ge`/`le`）更有意义？请举例说明哪些值有效、哪些无效。

<details>
<summary>参考答案</summary>

因为浮点数可以取 0 到 1 之间的小数值，用 `gt=0` 能排除 0 但保留正小数，这是 `ge=0` 做不到的（后者允许 0）。

- 有效：`0.5`、`1.0`、`10.4`（>0 且 <10.5）。
- 无效：`0.0`、`0`（不大于 0）；`10.5`（不小于 10.5）；`-1`（负数）。

同理 `lt=10.5` 排除了恰好等于 10.5 的情况。这体现了 `ge/le`（含边界）与 `gt/lt`（不含边界）的语义差别。
</details>
