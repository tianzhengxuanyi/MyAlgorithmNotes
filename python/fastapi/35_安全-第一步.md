## 一、章节笔记

### 1. 场景与目标

后端 API 在一个域名，前端在另一个域名/路径（或移动应用）。希望前端用 `username` 和 `password` 完成认证。FastAPI 用 OAuth2 的 **password 流程 + Bearer 令牌**实现，且不必读冗长规范——直接用内置安全工具。

### 2. 最小示例

```python
from typing import Annotated

from fastapi import Depends, FastAPI
from fastapi.security import OAuth2PasswordBearer

app = FastAPI()

oauth2_scheme = OAuth2PasswordBearer(tokenUrl="token")

@app.get("/items/")
async def read_items(token: Annotated[str, Depends(oauth2_scheme)]):
    return {"token": token}
```

运行 `uv run fastapi dev`，打开 `/docs` 会看到：

- 右上角出现 **Authorize** 按钮；
- 每个路径操作右上角有可点击的**小锁图标**；
- 点击弹出授权表单，可输入 `username` / `password`（此刻输入什么都不会真正生效，令牌校验尚未实现）。

### 3. `python-multipart` 依赖

OAuth2 使用「表单数据」发送 `username` 和 `password`，因此需要 `python-multipart`：

- `uv add "fastapi[standard]"` 会自动安装它；
- `uv add fastapi` 默认**不含**它，需手动 `uv add python-multipart`。

### 4. `password` 流程

OAuth2 的设计目标是让后端/API 与认证服务器**解耦**；本例中 FastAPI 应用同时处理 API 与认证。简化流程：

1. 用户在前端输入 `username` / `password`；
2. 前端把它发到 API 的特定 URL（`tokenUrl="token"` 声明）；
3. API 校验后返回「令牌」（尚未实现）——一个含信息、会过期的字符串；
4. 令牌过期后用户需重新登录，被窃风险较小；
5. 前端临时存储令牌；
6. 访问需认证的端点时，发送 `Authorization: Bearer <token>` 头（如 `Bearer foobar`）。

### 5. `OAuth2PasswordBearer` 详解

| 要点 | 说明 |
|---|---|
| 所属模块 | `fastapi.security` |
| 用途 | OAuth2 的 Password 流程 + Bearer 令牌 |
| `tokenUrl` | 客户端用 `username`/`password` 换令牌的 URL；**相对 URL**（`token` ≡ `./token`），使应用在代理等场景仍正确工作 |
| 是否创建端点 | **不会**创建 `/token` 路径操作，只是声明给 OpenAPI/文档用 |
| 命名 | 用 `tokenUrl` 而非 `token_url`，为与 OpenAPI 规范名称一致，便于查文档 |
| 可调用性 | 实例是可调用的（`oauth2_scheme(...)`），因此能作为 `Depends` 的依赖 |

**OpenAPI 集成原理**：`OAuth2PasswordBearer` 继承自 `OAuth2`，再继承自 `SecurityBase`。所有与 OpenAPI 集成的安全工具都继承 `SecurityBase`，这是 FastAPI 能自动生成安全方案的原因。

### 6. 它做了什么

- 在请求中查找 `Authorization` 头，检查是否为 `Bearer` + 令牌，把令牌作为 `str` 返回并赋给参数 `token`；
- 若没有 `Authorization` 头或不含 Bearer 令牌，直接返回 **401（UNAUTHORIZED）**；
- 因此**无需自己检查令牌存在性**——函数一旦执行，拿到的必定是 `str` 令牌。

### 7. 易错点

- ✅ 只需三四行代码就获得初步安全机制，但此时**令牌有效性尚未校验**。
- ✅ `tokenUrl` 只是声明，不会自动创建 `/token` 端点。
- ✅ 用表单数据传用户名密码 → 需要 `python-multipart`。
- ✅ 用相对 URL（如 `token`）以兼容代理/前缀场景。
- ✅ Bearer 是推荐默认方案，除非是 OAuth2 专家且有明确理由才换其他。

## 二、NestJS 对比

| 维度 | FastAPI（Python） | NestJS（TypeScript） |
|---|---|---|
| Bearer 提取 | `oauth2_scheme = OAuth2PasswordBearer(tokenUrl="token")`，作为 `Depends` 注入 | Passport `jwt` 策略 + `AuthGuard('jwt')`，从请求头提取并校验 |
| 缺失令牌 | 安全工具自动返回 401 | Guard 返回 false / 抛 `UnauthorizedException` |
| tokenUrl 声明 | `tokenUrl` 写入 OpenAPI 供文档使用，不建端点 | 无内置 tokenUrl 概念；`@ApiBearerAuth()` 仅标注方案 |
| 文档集成 | 自动生成 Authorize 按钮、锁图标，零配置 | 需 `@nestjs/swagger` + `ApiBearerAuth()` 等手动标注 |
| 表单解析 | 依赖 `python-multipart` 解析 OAuth2 表单 | 需 `ValidationPipe` / `@Body()` 与 `class-validator` DTO |
| 抽象层级 | 单一「可调用依赖」贯穿提取与文档 | 拆成 Strategy（校验）+ Guard（拦截）+ Swagger 装饰器（文档） |

**核心差异一句话**：FastAPI 用一个 `OAuth2PasswordBearer` 依赖同时搞定「提取 Bearer 令牌」「缺失即 401」「写入 OpenAPI 文档」三件事；NestJS 需 Passport 策略、Guard 和 Swagger 装饰器分工协作才能达到同等效果。

## 三、针对性练习题

### 题 1（基础）
写出一个最小 FastAPI 应用：创建 `OAuth2PasswordBearer(tokenUrl="token")`，定义 `GET /items/` 注入 token 并返回它。

<details>
<summary>参考答案</summary>

```python
from typing import Annotated
from fastapi import Depends, FastAPI
from fastapi.security import OAuth2PasswordBearer

app = FastAPI()
oauth2_scheme = OAuth2PasswordBearer(tokenUrl="token")

@app.get("/items/")
async def read_items(token: Annotated[str, Depends(oauth2_scheme)]):
    return {"token": token}
```

访问 `/docs` 可见 Authorize 按钮与锁图标。此时令牌还只是原样返回，未做有效性校验。
</details>

### 题 2（理解）
`tokenUrl="token"` 会创建 `/token` 端点吗？为什么要使用相对 URL？

<details>
<summary>参考答案</summary>

不会。它只是声明客户端应到 `/token` 获取令牌，该信息写入 OpenAPI 供交互文档使用，实际端点需自己实现。使用相对 URL（`token` ≡ `./token`）是为了让 API 在不同前缀/代理下都能正确解析——若 API 在 `https://example.com/api/v1/`，它指向 `https://example.com/api/v1/token`。
</details>

### 题 3（辨析 / 代码）
请求没有 `Authorization` 头时，`read_items` 函数体会执行吗？为什么无需在函数里检查 token 是否为空？

<details>
<summary>参考答案</summary>

不会执行。`OAuth2PasswordBearer` 依赖会在检查失败时直接返回 401（UNAUTHORIZED），阻止请求继续。因此只要路径操作函数被执行，就一定能拿到 `str` 类型的令牌，无需再手动判空。
</details>

### 题 4（进阶 · NestJS 迁移视角）
NestJS 里你用 `AuthGuard('jwt')` 保护路由。请写出 FastAPI 中功能等价的最小实现，并说明「文档集成」的差异。

<details>
<summary>参考答案</summary>

```python
from typing import Annotated
from fastapi import Depends, FastAPI
from fastapi.security import OAuth2PasswordBearer

app = FastAPI()
oauth2_scheme = OAuth2PasswordBearer(tokenUrl="token")

@app.get("/protected/")
async def protected(token: Annotated[str, Depends(oauth2_scheme)]):
    return {"token": token}
```

差异：FastAPI 的 `oauth2_scheme` 自动向 OpenAPI 注册安全方案，`/docs` 立即可交互（Authorize 按钮、锁图标），无需额外配置；NestJS 需安装 `@nestjs/swagger` 并用 `ApiBearerAuth()` 等装饰器手动标注，才能在 Swagger 页面中体现 Bearer 认证。
</details>

### 题 5（思考）
为什么 OAuth2 的「令牌会过期」被视为一种安全优势？

<details>
<summary>参考答案</summary>

令牌只在有限时间内有效，过期后用户需重新登录，攻击者即使窃取令牌可利用的窗口也很短；它不像一把永久有效的钥匙。这降低了令牌泄露带来的风险，因此教程推荐用 Bearer 令牌配合合理过期时间。
</details>
