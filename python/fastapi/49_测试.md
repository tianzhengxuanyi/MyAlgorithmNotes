## 一、章节笔记

### 1. 测试体系概览

得益于 Starlette，FastAPI 测试轻松愉快。它基于 **HTTPX**（而 HTTPX 基于 Requests 设计），可直接与 **pytest** 配合使用。

依赖安装：

```bash
uv add httpx
uv add pytest
```

### 2. `TestClient` 基础用法

```python
from fastapi import FastAPI
from fastapi.testclient import TestClient

app = FastAPI()

@app.get("/")
async def read_main():
    return {"msg": "Hello World"}

client = TestClient(app)

def test_read_main():
    response = client.get("/")
    assert response.status_code == 200
    assert response.json() == {"msg": "Hello World"}
```

步骤：

1. 导入 `TestClient`；
2. 传入 FastAPI 应用创建 `client`；
3. 定义以 `test_` 开头的函数（pytest 约定）；
4. 像用 `httpx` 一样调用 `client`；
5. 用普通 Python `assert` 断言。

**注意：测试函数是普通 `def`，不是 `async def`；client 调用也不用 `await`。** 这样可直接使用 pytest 而不惹麻烦。

技术细节：`fastapi.testclient.TestClient` 与 `starlette.testclient.TestClient` 是同一个，前者为方便开发者重新导出。若测试中还要调用应用里的 `async` 函数（如异步数据库函数），见高级教程的"异步测试"。

### 3. 分离测试文件

真实项目结构（参考"更大的应用"一章）：

```text
.
├── app
│   ├── __init__.py
│   ├── main.py
│   └── test_main.py
```

因为 `test_main.py` 与 `main.py` 在同一 Python 包中，可用**相对导入**：

```python
from fastapi.testclient import TestClient

from .main import app

client = TestClient(app)

def test_read_main():
    response = client.get("/")
    assert response.status_code == 200
    assert response.json() == {"msg": "Hello World"}
```

### 4. 扩展示例：带错误分支的接口

应用侧（`main.py`）：两个路径操作都要求 `X-Token` 头；`GET` 可能返回 400/404，`POST` 可能返回 400/409：

```python
from typing import Annotated
from fastapi import FastAPI, Header, HTTPException
from pydantic import BaseModel

fake_secret_token = "coneofsilence"
fake_db = {
    "foo": {"id": "foo", "title": "Foo", "description": "There goes my hero"},
    "bar": {"id": "bar", "title": "Bar", "description": "The bartenders"},
}
app = FastAPI()

class Item(BaseModel):
    id: str
    title: str
    description: str | None = None

@app.get("/items/{item_id}", response_model=Item)
async def read_main(item_id: str, x_token: Annotated[str, Header()]):
    if x_token != fake_secret_token:
        raise HTTPException(status_code=400, detail="Invalid X-Token header")
    if item_id not in fake_db:
        raise HTTPException(status_code=404, detail="Item not found")
    return fake_db[item_id]

@app.post("/items/")
async def create_item(item: Item, x_token: Annotated[str, Header()]) -> Item:
    if x_token != fake_secret_token:
        raise HTTPException(status_code=400, detail="Invalid X-Token header")
    if item.id in fake_db:
        raise HTTPException(status_code=409, detail="Item already exists")
    fake_db[item.id] = item.model_dump()
    return item
```

测试侧（`test_main.py`）——覆盖成功和失败路径：

```python
from fastapi.testclient import TestClient
from .main import app

client = TestClient(app)

def test_read_item():
    response = client.get("/items/foo", headers={"X-Token": "coneofsilence"})
    assert response.status_code == 200
    assert response.json() == {
        "id": "foo", "title": "Foo", "description": "There goes my hero",
    }

def test_read_item_bad_token():
    response = client.get("/items/foo", headers={"X-Token": "hailhydra"})
    assert response.status_code == 400
    assert response.json() == {"detail": "Invalid X-Token header"}

def test_read_nonexistent_item():
    response = client.get("/items/baz", headers={"X-Token": "coneofsilence"})
    assert response.status_code == 404
    assert response.json() == {"detail": "Item not found"}

def test_create_item():
    response = client.post(
        "/items/",
        headers={"X-Token": "coneofsilence"},
        json={"id": "foobar", "title": "Foo Bar", "description": "The Foo Barters"},
    )
    assert response.status_code == 200
    assert response.json() == {
        "id": "foobar", "title": "Foo Bar", "description": "The Foo Barters",
    }

def test_create_item_bad_token():
    response = client.post(
        "/items/",
        headers={"X-Token": "hailhydra"},
        json={"id": "bazz", "title": "Bazz", "description": "Drop the bazz"},
    )
    assert response.status_code == 400
    assert response.json() == {"detail": "Invalid X-Token header"}

def test_create_existing_item():
    response = client.post(
        "/items/",
        headers={"X-Token": "coneofsilence"},
        json={
            "id": "foo", "title": "The Foo ID Stealers",
            "description": "There goes my stealer",
        },
    )
    assert response.status_code == 409
    assert response.json() == {"detail": "Item already exists"}
```

### 5. 如何传各种数据

`TestClient` 的调用方式与 HTTPX/Requests 一致：

| 要传的数据 | 做法 |
|---|---|
| 路径参数、查询参数 | 拼进 URL |
| JSON 体 | `json=dict` |
| Form Data | `data=...` |
| Headers | `headers=dict` |
| Cookies | `cookies=dict` |

**注意**：`TestClient` 接收的是**可转化为 JSON 的数据**，不是 Pydantic 模型。若手里有 Pydantic 模型，先用 `jsonable_encoder` 转换再传。

### 6. 运行测试

```bash
uv run pytest
```

pytest 自动发现测试文件与 `test_` 开头的函数，执行并报告结果。

### 7. 易错点

| 易错点 | 正确做法 |
|---|---|
| 测试函数写成 `async def`、client 调用加 `await` | 用普通 `def` 和普通调用，pytest 直接可用 |
| 忘记装 `httpx` | `TestClient` 依赖它，先 `uv add httpx` |
| 把 Pydantic 模型直接传给 `json=` | 先用 `jsonable_encoder` 转成 JSON 兼容数据 |
| 测试文件与 app 不在同一包却用相对导入 | 同一包用 `from .main import app`，否则用绝对导入 |
| Form Data 误用 `json=` | 用 `data=` 参数 |
| 只测成功路径 | 同时断言 400/404/409 等错误分支的状态码与 detail |

## 二、NestJS 对比

| 维度 | FastAPI（Python） | NestJS（TypeScript） |
|---|---|---|
| 测试客户端 | `TestClient(app)`，基于 HTTPX | `@nestjs/testing` 的 `Test.createTestingModule()` + `app.getHttpServer()` 配 supertest |
| 测试框架 | pytest，普通 `def` + `assert` | Jest / Vitest，`describe/it/expect` |
| 应用装配 | 直接传 `app` 对象给 `TestClient` | 用 `TestingModule` 编译模块，可 mock Provider |
| 请求方式 | `client.get("/items/foo", headers=...)` | `request(app.getHttpServer()).get('/items/foo').set('X-Token', ...)` |
| 依赖替换 | 依赖覆盖有专门机制（高级主题） | `.overrideProvider(X).useValue(mock)` |
| 数据校验层 | 请求体是 Pydantic 模型，测试中传 dict/`json=` | DTO + `class-validator`，测试中传普通对象 |
| 错误断言 | `assert response.status_code == 400` + `response.json()` | `.expect(400).expect({ detail: ... })` |
| 异步函数测试 | 进阶可测 `async` 函数（高级教程） | 天然 async/await 测试 |

**核心差异一句话**：FastAPI 的测试是"pytest + 一个能直接吃 app 对象的 HTTPX 客户端"，测试函数保持同步写法、零脚手架；NestJS 要先编译 TestingModule 并借助 supertest，虽然样板更多，但能利用 DI 容器轻松替换 Provider 做隔离测试。

## 三、针对性练习题

### 题 1（基础）
使用 `TestClient` 前需要安装什么？写出测试 `GET /` 返回 `{"msg": "Hello World"}` 的最小测试代码。

<details>
<summary>参考答案</summary>

需要 `httpx`（`TestClient` 基于它）和 `pytest`。

```python
from fastapi import FastAPI
from fastapi.testclient import TestClient

app = FastAPI()

@app.get("/")
async def read_main():
    return {"msg": "Hello World"}

client = TestClient(app)

def test_read_main():
    response = client.get("/")
    assert response.status_code == 200
    assert response.json() == {"msg": "Hello World"}
```
</details>

### 题 2（理解）
为什么测试函数要用普通 `def` 而不是 `async def`，client 调用也不用 `await`？

<details>
<summary>参考答案</summary>

`TestClient` 在内部处理了 ASGI 应用的异步执行，对外暴露同步的 HTTPX 风格 API。这样测试函数可保持普通 `def`，pytest 无需 async 插件即可直接发现和执行，避免事件循环配置的麻烦。若确实需要在测试中调用应用的 `async` 函数，参见高级教程的异步测试。
</details>

### 题 3（辨析/代码）
要把 Pydantic 模型 `item` 作为 JSON 请求体传给 `client.post()`，下面写法为什么不妥？如何修正？同时说明传 Form Data 和 Headers 分别用什么参数。

```python
client.post("/items/", json=item)
```

<details>
<summary>参考答案</summary>

`TestClient` 接收的是**可转化为 JSON 的数据**，不直接接收 Pydantic 模型。应先转换：

```python
from fastapi.encoders import jsonable_encoder

client.post("/items/", json=jsonable_encoder(item))
```

传 Form Data 用 `data=...`，传 Headers 用 `headers=dict`，Cookies 用 `cookies=dict`，路径/查询参数拼进 URL。
</details>

### 题 4（进阶 · NestJS 迁移视角）
某接口有 `X-Token` 校验：token 错返回 400，item 不存在返回 404，创建重复 item 返回 409。写出对应的三条 FastAPI 测试（用 `headers` 传 token），并指出 NestJS 中 mock Provider 的对应机制。

<details>
<summary>参考答案</summary>

```python
def test_read_item_bad_token():
    response = client.get("/items/foo", headers={"X-Token": "hailhydra"})
    assert response.status_code == 400
    assert response.json() == {"detail": "Invalid X-Token header"}

def test_read_nonexistent_item():
    response = client.get("/items/baz", headers={"X-Token": "coneofsilence"})
    assert response.status_code == 404
    assert response.json() == {"detail": "Item not found"}

def test_create_existing_item():
    response = client.post(
        "/items/",
        headers={"X-Token": "coneofsilence"},
        json={"id": "foo", "title": "The Foo ID Stealers", "description": "..."},
    )
    assert response.status_code == 409
    assert response.json() == {"detail": "Item already exists"}
```

NestJS 通过 `Test.createTestingModule()` 编译模块，用 `.overrideProvider(Token).useValue(mock)` 替换 Provider 实现依赖隔离；FastAPI 的依赖覆盖属于高级主题，但同样支持。
</details>

### 题 5（思考）
为什么强调要同时测试 400/404/409 等错误分支，而不只是成功路径？

<details>
<summary>参考答案</summary>

错误分支是接口契约的一部分：`HTTPException` 的状态码和 `detail` 会被客户端用来判断失败原因、展示提示或重试。只测成功路径无法发现校验逻辑被破坏（如 token 校验失效、重复判定错误）或错误响应结构变化。对每条失败路径断言状态码与 `detail`，能保证安全性与行为一致性不回归。
</details>
