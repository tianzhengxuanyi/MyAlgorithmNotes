## RAG

### 什么是RAG？为什么需要RAG？

RAG（检索增强生产 Retrieval-Augmented Generation）先检索资料，在把资料放进上下文让模型回答。

解决：
1. 模型不知道私有文档
2. 模型训练时的知识不是最新知识
3. 频繁变化的事实不适合靠模型训练维护（如商品价格，政策等）

### RAG演进

| 阶段 | 典型链路 | 特点 |
| --- | --- | --- |
| Naive RAG | 文档切块 → Embedding → Top-K 检索 → LLM 生成 | 最基础、最容易实现，适合 Demo 和简单知识库 |
| Advanced RAG | Query Rewrite / HyDE → 混合检索 → Rerank → 上下文压缩 → LLM 生成 | 重点解决召回不准、上下文噪声和排序不稳 |
| Modular RAG | 检索器、重排器、压缩器、路由器、生成器等模块可插拔组合 | 按业务场景动态路由，适合生产系统和复杂 Agent |


### RAG如何评估效果？

1. 分层评估框架


| 层次 | 核心问题 | 典型指标 | 诊断价值 |
| --- | --- | --- | --- |
| 检索层 | 正确文档有没有被召回？排序好不好？ | Recall@K、MRR、NDCG@K | 检索塌了，后面不用测 |
| 切片层 | 切分方式是否有利于检索？ | 语义独立性、Recall 对比 | 切片的微小差异会放大到检索 |
| 生成层（忠实度） | 答案是否基于检索到的上下文？ | Faithfulness / Groundedness | 检索对了但模型"脑补" |
| 生成层（相关性） | 答案是否正面回应用户问题？ | Answer Relevancy | 材料对、没编，但跑题了 |


2. 检索层指标
- Recall@K：前 K 条里有没有正确答案，只看“找没找到”

- MRR：第一个正确结果排第几，适合唯一答案/FAQ

- NDCG@K：综合“有没有、排得前不靠前、有多相关”，最全面

健康参考：MRR > 0.7、Recall@K > 0.8、NDCG@K > 0.75

注意：Recall 高但 MRR/NDCG 低 = 找到了但排得后，体验仍差

3. 切片评估

切片对召回影响大，最佳与最差策略召回差距可达约 9%

方法一：固定查询，对比不同切片策略的 Recall、Precision、MRR（如 chunk-bench）

方法二：看语义独立性——chunk 之间语义独立性影响最大，减少跨块依赖

实操：先排除明显有害切法，不追求绝对最优

4. 生成层指标（RAGAS 四件套）
| 指标 | 评估什么 | 参考阈值 |
| --- | --- | --- |
| Faithfulness | 答案是否被上下文支撑，测幻觉 | ≥0.85；高风险≥0.90 |
| Answer Relevancy | 是否回应用户问题 | ≥0.80 |
| Context Precision | 检索上下文相关占比与排序 | 越高越好 |
| Context Recall | 上下文是否覆盖回答所需信息 | 越高越好 |
注意：Faithfulness ≠ Correctness。忠实只说明没超出上下文，不说明上下文本身正确。

5. 测评集建设
最小可行：50–100 条高频真实查询

每条包含：query、相关文档 ID 及最小证据片段、相关性等级、可接受答案/Rubric、无答案标记

标注粒度要到文档/片段级，否则算不了 Recall@K

必须包含知识库无答案的负样本，测系统会不会硬编

真实查询为主，合成数据补长尾；合成占比不要过半

金标准持续吸收线上 badcase，比公开榜单更贴合业务

6. 评估框架选型
RAGAS：LLM judge，开箱即用，适合快速迭代看趋势

ARES：小分类器 + PPI + 少量人标，适合人标预算有限但要统计置信度

可并存：日常 RAGAS，关键决策用 ARES 或人标校准

7. 面试速答
RAG 评估分层做：先看检索 Recall@K、MRR、NDCG；再看切片语义独立性和检索横向对比；最后看生成 Faithfulness 和 Answer Relevancy。测评集先建 50–100 条真实查询金标准，标到片段级，必须含无答案负样本；合成数据补长尾但不过半。不追求总分，按层定位病根。


#### 一、检索层指标

| 指标 | 公式核心 | 计算步骤 | 说明 |
| :--- | :--- | :--- | :--- |
| **Recall@K** | `\|TopK ∩ Rel\| / \|Rel\|` | 1) 确定查询 q 的相关文档集合 `Rel_q`；2) 取检索前 K 条 `TopK_q`；3) 求交集大小；4) 除以 `\|Rel_q\|`；5) 对所有查询取平均 | 只看“找没找到”，不看顺序。K 越大 Recall 越高，比较时必须固定 K |
| **Precision@K** | `\|TopK ∩ Rel\| / K` | 1) 取前 K 条；2) 数其中相关文档数；3) 除以 K | 衡量检索噪音。K 越大 Precision 通常越低，需与 Recall 一起看 |
| **MRR** | `1/\|Q\| · Σ 1/rank_q` | 1) 对每个查询找**第一个**相关结果的位置 `rank_q`（从 1 开始）；2) 取倒数 `1/rank_q`；3) 无相关结果记 0；4) 对所有查询取平均 | 只关注第一个相关结果，适合唯一答案/FAQ。后续相关结果被忽略 |
| **NDCG@K** | `DCG@K / IDCG@K`，其中 `DCG@K = Σ(2^{rel_i}-1)/log2(i+1)` | 1) 按检索顺序算 DCG@K；2) 按相关性降序算理想 DCG（IDCG@K）；3) 相除；4) 对所有查询取平均 | 同时考虑“有没有、排得前不靠前、有多相关”。范围 0–1，1 为完美排序 |
| **MAP** | `1/\|Q\| · Σ AP_q`，其中 `AP_q = 1/\|Rel_q\| · Σ P@k·rel(k)` | 1) 遍历检索结果；2) 在每个相关位置 k 计算 P@k；3) 求和后除以 `\|Rel_q\|` 得 AP_q；4) 对所有查询取平均 | 关注**所有**相关结果的位置，不只是第一个。比 MRR 更全面 |

#### 二、生成层指标（RAGAS）

| 指标 | 公式核心 | 计算步骤 | 说明 |
| :--- | :--- | :--- | :--- |
| **Faithfulness** | `被上下文支撑的声明数 / 答案总声明数` | 1) 把答案拆成独立声明（claim）；2) 逐条判断能否被检索上下文支撑；3) 支撑数除以总数 | 只测“有没有超出上下文”，**不测上下文本身对不对**。范围 0–1，越高越不易幻觉 |
| **Answer Relevancy** | `1/n · Σ cos(q, q_i)` | 1) 从答案反向生成 n 个“该答案能回答的问题” `q_i`；2) 计算原问题 q 与每个 `q_i` 的余弦相似度；3) 取平均 | 用**反向生成**衡量跑题程度。答案冗余、信息不完整会被惩罚 |
| **Context Precision@K** | `Σ(P@k · v_k) / \|Rel\|` | 1) 逐位检查前 K 条是否相关（`v_k`=1/0）；2) 在每个位置算 P@k；3) 加权求和后除以相关文档总数 | 相关文档排得越靠前分数越高。衡量**检索噪音和排序质量** |
| **Context Recall** | `被覆盖的参考声明数 / 参考总声明数` | 1) 把标准答案拆成声明；2) 判断每条能否在检索上下文中找到依据；3) 被覆盖数除以总数 | 衡量**信息遗漏**。依赖标准答案，没有金标准时无法计算 |
| **Answer Correctness** | `w1·F1 + w2·SemanticSim`，`F1 = 2TP/(2TP+FP+FN)` | 1) 声明级别比对答案与标准答案，统计 TP/FP/FN；2) 算 F1；3) 算 embedding 余弦相似度；4) 加权求和 | 默认 `w1=0.75, w2=0.25`，可按场景调整。综合事实与语义 |

#### 三、传统文本生成指标（辅助参考）

| 指标 | 公式核心 | 计算步骤 | 说明 |
| :--- | :--- | :--- | :--- |
| **BLEU** | `BP · exp(Σ w_n log p_n)` | 1) 计算各阶 n-gram 精确率 `p_n`；2) 算长度惩罚 `BP`；3) 加权几何平均 | 偏字面匹配，对同义改写不友好。RAG 中只作辅助 |
| **ROUGE-N** | `匹配的 n-gram 数 / 参考 n-gram 总数` | 1) 统计参考答案中的 n-gram；2) 统计与生成答案匹配的 n-gram；3) 匹配数除以参考总数 | 召回导向。ROUGE-L 基于最长公共子序列。同样不能替代忠实度和相关性 |
