# 单文件组件（`.vue`）到页面渲染的全过程（编译、虚拟 DOM、挂载）

## 简答

`.vue` 不是浏览器认识的文件。构建工具（vite-plugin-vue / vue-loader）在**打包期**把它拆成三块：`template` 编成 `render` 函数，`script` 当模块，`style` 当 CSS（scoped 会加属性选择器）。浏览器只跑产出的 JS/CSS。

运行时：`createApp(App).mount('#app')` 把根组件作成 VNode → 执行 `setup` / `render` 得到子树 VNode → `patch` 创建真实 DOM 插进容器。数据再变：同一组件的渲染 effect 再跑，新 VNode 和旧 VNode diff 后最小更新 DOM。

整条链分两段记：**构建期 SFC → render 函数；运行时 render → VNode → DOM。**

一句话：**.vue 在打包时变成 render + script；上线后只走虚拟 DOM 挂载和更新。**

---

## 四个关键词（卡住就说这四个）

1. **compiler-sfc**：拆块、编模板、处理 scoped。
2. **render 函数**：模板的运行时形态。
3. **VNode + patch**：先描述树，再挂到容器。
4. **组件递归**：子 `.vue` 还是同一个流程，父 render 里遇到组件 VNode 就 mountComponent。

---

## 构建期（SFC 编译）

一个文件典型结构：

```vue
<template>...</template>
<script setup>...</script>
<style scoped>...</style>
```

`@vue/compiler-sfc` 做的事：

1. **parse**：按块切开，得到 descriptor（template / script / styles / customBlocks）。
2. **compileTemplate**：模板字符串走完整模板编译（见第 20 题）→ 生成 `render`（以及 Vue3 的 `ssrRender`）。会打 patchFlag、静态提升。
3. **compileScript**：`<script setup>` 编译成普通 `setup()`：`defineProps` 等宏被换成运行时 props 声明；顶层绑定暴露给 render。
4. **样式**：`scoped` 给选择器加 `data-v-xxxxxx`，同时给组件根 VNode 打上同样的 scopeId，运行时 patch 时写到 DOM 属性上。`module` 则是 CSS Modules。
5. 打包器把 JS 模块和图里的 CSS 交给浏览器。HMR 时可以只换 render 或只换 style。

没有构建、用运行时编译：完整版 Vue 还能 `template:` 字符串现场 `compile`，生产不这么干，体积和性能都差。

## 运行时（到页面）

以根组件为例，和第 6、13 题接上：

```
createApp(App).mount('#app')
    → createVNode(App)
    → setupComponent（props、setup）
    → 渲染 effect 首次执行
        → render() 得到子树 VNode（里面可能还有组件、元素、文本）
        → patch(null, vnode, container) 递归挂载
            元素：createElement + 挂属性 + 挂子节点
            组件：再走 setup + render + patch
            文本：createTextNode
    → mounted 钩子
```

之后：

```
data 变更 → trigger → queueJob → nextTick flush
    → 组件 update：新 VNode
    → patch(oldVNode, newVNode)  diff
    → 只改该改的 DOM
```

模板里用到的响应式数据，在 **render 执行时**被 track，所以改了才会更新；render 没读到的字段不会拖着这个组件刷新。

## 和「纯 JS 组件」的关系

不用 `.vue`，自己写：

```js
export default {
  setup() { return { msg: ref('hi') } },
  render() { return h('div', this.msg) }
}
```

运行时完全一样。SFC 只是让模板、样式、逻辑写在一个文件里，**编译器帮你生成 render**。面试不要说「.vue 被浏览器直接解析」。

## 可能被追问

**Q：scoped 样式为什么子组件根元素也能选中？**

父模板里的子组件标签会带上父的 scopeId，子的根元素同时有自己的 scopeId 和父的 scopeId，所以父样式能作用到子根，进不去子内部。穿透用 `:deep()`。

**Q：runtime-only 和 runtime+compiler？**

生产打包一般是 runtime-only：模板都在构建期编完。带 compiler 的构建才能在运行时消化 `template` 选项。

**Q：`render` 和 `template` 同时有？**

`render` 优先，template 被忽略。SFC 编完其实已经是 render。

**Q：异步组件呢？**

`defineAsyncComponent` 先挂占位，chunk 回来再换成真正组件 VNode，仍然走同一套 patch。和 SFC 不冲突，只是这个模块晚点才下载。
