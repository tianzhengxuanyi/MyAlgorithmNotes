# Vue 实例挂载（`new Vue`）过程中发生了什么

## 简答

Vue2 通过 `new Vue(options)` 创建根实例；Vue3 废弃了 new Vue，改用 `createApp(Root).mount('#app')`。

## Vue2 new Vue 执行流程

1. 调用 Vue 构造函数，执行 `this._init(options)`；
2. `_init` 内部：合并全局与局部 options → 初始化生命周期、事件、props/inject → **触发 beforeCreate** → 初始化 data、computed、watch，转为响应式 → **触发 created**；
3. 如果配置了`el`，自动调用`$mount(el)`；没有 el 则需要手动调用`$mount`；
4. `$mount`：没有手写 render 函数时，编译模板 / 容器 HTML 生成 render 函数；
5. 创建**渲染 Watcher**，执行`_render()`调用 render 函数生成根 VNode；
6. 执行`_update(vnode)`，内部调用 patch，首次 patch 把 VNode 挂载成真实 DOM，替换容器；
7. DOM 挂载完成，触发`mounted`钩子。

## Vue3 createApp(Root).mount('#app')

不再使用类实例，`createApp` 创建独立应用上下文，隔离全局组件 / 指令；
调用`mount`时：

1. 创建根组件 VNode；
2. 处理根 props，执行 setup；
3. 执行 render 函数生成 VNode 树；
4. 调用渲染器`render`函数，走 patch 完成 DOM 挂载；

> 
> Vue3 没有渲染 Watcher，底层是响应式 effect；没有根实例 this。

一句话总结：Vue2 new Vue 先`_init`完成选项合并、响应式初始化，执行 beforeCreate/created；接着`$mount`编译模板生成 render，渲染 VNode 并 patch 挂载 DOM；Vue3 用 createApp 创建应用上下文，mount 完成根组件渲染与 patch。

## 四个关键词（卡住就说这四个）

1. **`_init`**：合并选项、初始化状态、created。
2. **`$mount`**：没有 render 就现场编译 template。
3. **渲染 Watcher / 渲染 effect**：第一次执行就是挂载，之后依赖变了再跑。
4. **`patch(null, vnode)`**：旧树是空，走挂载而不是 diff。

---

## Vue2：`new Vue` 时间线

源码入口：`src/core/instance/index.js`，原型上混入 `_init`、`$set`、`$on`、`$mount` 相关方法。

**1. mergeOptions**

用户 options 和 `Vue.options`（全局 mixin、组件、指令）合并。组件实例走内部优化过的 `initInternalComponent`，少做一层动态合并。

**2. 初始化一堆实例字段**

`initLifecycle`（`$parent` / `$root`）、`initEvents`、`initRender`（`$slots`、`createElement`）。此时还没有响应式 data。

**3. `beforeCreate`**

拿不到 `this.foo` 这种 data。插件若要尽早插手，会挂在这附近。

**4. `initInjections` → `initState` → `initProvide`**

`initState` 依次：props、methods、data（`observe`）、computed、watch。provide 必须在 inject 之后，这样祖先 provide 能被子孙 inject 到。

**5. `created`**

数据、计算属性、侦听器都好了，**还没有 `$el`**。

**6. 有 `el` 就 `$mount(el)`，没有就等你手动 `vm.$mount()`**

`$mount` 决定 render 的优先级：

```
render 函数 > template 字符串 > el 的 outerHTML
```

runtime-only 构建没有编译器，只能接受 render；完整构建才能把 template 编成 render。

**7. `mountComponent`**

- `beforeMount`
- `new Watcher(vm, updateComponent, ...)`，`updateComponent` 就是 `vm._update(vm._render())`
- 首次 `get`：执行 render（依赖收集）→ `patch(vm.$el, vnode)` 挂载
- `mounted`（根实例在这里调；子组件在 `patch` 插完子树后调）

之后数据变 → 这个 Watcher 再跑 → 新 VNode 和旧 VNode diff。

---

## Vue3：`createApp` + `mount`

```js
const app = createApp(App)
app.use(router).use(pinia)
app.mount('#app')
```

和 Vue2 全局 `Vue.use` 不同：插件、全局组件都挂在 **app 实例** 上，多应用互不影响。

`mount` 内部大致：

1. 创建根 VNode（`createVNode(根组件)`）
2. `render(vnode, container)`，空容器走挂载
3. 组件侧 `setupComponent`：初始化 props/slots → 调 `setup()` → 若有 Options 再 `applyOptions`（`beforeCreate` / `created`）
4. `setupRenderEffect`：渲染 effect 首次 run，`renderComponentRoot` 得到子树 VNode，`patch` 到容器
5. 根挂载结束，容器上挂 `__vue_app__` 之类引用，便于 `unmount`

没有 `el` 选项这套老 API；必须显式 `mount(容器)`。

## 可能被追问

**Q：`el` 和 `$mount` 什么关系？**

`el` 只是语法糖，内部还是 `$mount`。没有 `el` 时实例会停在 created，直到你 `$mount`。

**Q：为什么 runtime-only 不能写 template？**

编译器不打包进 runtime-only。template 必须在构建期（vue-loader / vite）编成 render。完整版 Vue 才带 `compile`。

**Q：首次渲染走 diff 吗？**

不走完整 diff。`patch(null, n2)` 或容器空时走 **mount**，按 VNode 树递归建 DOM。有旧树才 diff。

**Q：`this._data` 和 `this.xxx`？**

`initData` 后会把 data 的 key **代理**到实例上，访问 `this.xxx` 等于 `this._data.xxx`。Vue3 里 Options 的 data 类似，但 `setup` 返回值也会暴露到实例上（供模板用）。

**Q：Vue3 createApp 带来的隔离优势是什么？**

Vue2 的 `Vue.component` / `Vue.mixin` / `Vue.use` 全挂在 **同一个构造器** 上，页面上两个根实例也会抢全局配置，测试里一次注册污染全部。

`createApp` 每次返回独立的 `app`：全局组件、指令、provide、`config.globalProperties`、插件列表都在这份上下文里。`app1.component('X')` 不影响 `app2`。微前端、同一页多个 Vue 根、单测隔离都靠这个。卸载 `app.unmount()` 也只拆自己那棵树。

**Q：根组件和普通组件 mount 过程有什么区别？**

普通组件没有自己的 `el`：父 `render` 里碰到组件 VNode，走 `mountComponent` → setup → 渲染 effect → `patch` 到父给的锚点（或 fragment 占位）。生命周期挂在这个子实例上。

根组件多了 **应用层** 步骤：

1. `createApp` 建 appContext（配置、provide 根）
2. `mount(container)` 用容器创建根 VNode，`vnode.appContext = app._context`
3. 容器原先的 DOM 当占位，Vue3 会清空再挂（SSR 则 hydrate）
4. 根渲染函数跑完，整棵应用的第一块 DOM 才进页面
5. `app._container`、`unmount` 记在 app 上，不是记在某个子组件上

子组件「挂载」是 patch 算法的一个分支；根「挂载」是应用入口，还负责容器、卸载、插件上下文。

**Q：如果根组件 el 对应的 DOM 不存在，会发生什么？**

**Vue2：** `querySelector` 不到会 warn `Cannot find element: #app`，然后 **`document.createElement('div')` 造一个孤儿节点** 往上挂。页面上看不见应用，实例其实已经 created/mounted 在那块脱离文档的 div 上。

**Vue3：** `mount('#app')` 选不到节点直接 warn `Failed to mount app: mount target selector ... returned null`，**不挂载**，后面的应用逻辑等于没跑。必须保证 `index.html` 里已有对应节点，且 `mount` 在 DOM ready 之后（模块脚本默认 defer，一般没问题；若把脚本放 `head` 又非模块，可能选不到）。
