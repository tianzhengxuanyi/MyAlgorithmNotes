# Vue 模板编译原理（`template` → `render` 函数）

## 简答

Vue 模板是 HTML 风格 DSL，浏览器无法直接运行，需要编译器转换成 render 函数；执行 render 函数就能生成 VNode。整个编译分为三个阶段：

1. **parse 解析**
手写 HTML 解析器，把 template 字符串解析成**模板 AST**，节点类型包括元素、文本、注释；结构和 HTML DOM 相似，但只是 JS 对象，不是真实 DOM；处理标签、插值、基础属性。
2. **transform 转换（核心阶段）**
遍历模板 AST：

- 处理 v-if/v-for/v-bind/v-on 等指令，转换成对应的 JS 表达式节点；
- Vue3 在这里做编译优化：识别静态 / 动态节点，打上 patchFlag、构建 block 树、静态提升、事件缓存；
- 输出产物：JS AST（JS 抽象语法树）。

3. **generate /codegen 代码生成**
遍历 JS AST，拼接 JS 代码字符串，最终生成`function render() { return ... }`。
render 函数执行后返回 VNode 树，交给运行时 patch 生成 DOM。

两种打包版本：

- full build：包含编译器，支持运行时传入 template 在线编译，体积大；
- runtime-only：不带编译器，模板在打包阶段预编译为 render 函数，生产推荐，包体积更小。

> 
> 优先级：组件同时声明 template 和 render，render 函数优先级更高。

一句话总结：parse 把模板转模板 AST；transform 处理指令并添加 Vue3 优化标记，转为 JS AST；codegen 生成 render 函数；runtime-only 版本打包阶段提前编译模板。

---

## 四个关键词（卡住就说这四个）

1. **parse**：字符串 → 模板 AST。
2. **transform**：`v-if` / `v-for` / 插值变成对应 VNode 创建逻辑。
3. **generate**：AST → 可执行 JS 字符串（再变成函数）。
4. **编译期优化**：patchFlag、hoistStatic、`_openBlock`，运行时才能少 diff。

---

## 三阶段细节

**1. parse**

词法上按标签、文本、插值切 token（实现上 Vue3 多用状态机扫字符串，不一定先产出独立 token 数组）。语法上建成树：

- `Root`、`Element`（tag、props、children）
- `Text`、`Interpolation`（`{{ msg }}`）
- `Directive`（`v-if`、`v-for`、`v-bind`、`v-on`、`v-model`…）

例如 `<h1 v-if="ok">{{ title }}</h1>` 会得到带 `if` 指令和插值孩子的 Element。

**2. transform**

深度遍历模板 AST，插件化的一堆 transform：

- 语义检查：`v-else` 必须跟 `v-if`，`v-for` 和 `v-if` 同层优先级等
- 指令变换：`v-if` 变成条件表达式（三元 / 多个分支）；`v-for` 变成循环创建 VNode；`v-model` 拆成 prop + onUpdate；`v-bind`/`v-on` 进 props
- 优化：静态节点标记、`hoistStatic`、给动态节点 patchFlag、`createBlock` / `createElementVNode`
- Vue3 还会分析绑定类型，决定用 `toDisplayString`、`normalizeClass` 这些 runtime helpers

transform 之后，树上带的是「怎么生成代码」的信息，而不只是原始 HTML。

**3. generate**

遍历，拼字符串：

```js
function render(_ctx, _cache) {
  return (_openBlock(), _createElementBlock('div', null, [
    _createVNode('span', { class: 'ok' }, _toDisplayString(_ctx.msg), 1 /* TEXT */)
  ]))
}
```

数字 `1` 就是 patchFlag。`_cache` 给事件缓存用。生成的代码里调用的 `_createVNode` 等，运行时从 `vue` 包导入。

`new Function(code)` 或打包器直接当模块导出，得到真正的 `render`。

## 和运行时的交界

| 编译产物 | 运行时 |
| --- | --- |
| `render()` | 每次组件更新调用，产出新 VNode |
| patchFlag / dynamicChildren | `patchElement` / `patchBlockChildren` |
| 静态提升的 VNode | 多次 render 复用同一对象 |
| `ssrRender` | 服务端拼 HTML，不一定走 VNode |

手写 `h('div', ctx.msg)` 没有这些标记，走全量 props 比较。所以「为什么强调写模板」：不是语法偏好，是**给编译器可分析的结构**。

---

## Vue2 vs Vue3（编译）

Vue2 也是 parse → optimize → generate。optimize 会标 `static` / `staticRoot`，静态根可以跳过整棵子树。但没有 patchFlag 这种「节点内部哪类属性在变」，也没有 block 的动态节点列表，更新粒度更粗。

Vue3 把优化做细：同一元素可能只更文本；同层只更 dynamicChildren。这是第 8、16 题的编译侧来源。

## 可能被追问

**Q：`v-if` 和 `v-for` 谁先编译？**

Vue2 同节点上 **v-for 优先**，容易先循环再判断，性能坑。Vue3 **v-if 优先**，并警告不要写在一起。面试说「不要写在同一元素，拆一层 template」。

**Q：编译发生在何时？**

SFC / 构建：打包时。带 compiler 的完整构建：`$mount` 时。生产推荐前者。

**Q：AST 和 VNode 是不是同一个？**

不是。模板 AST 只存在于编译期，描述模板；VNode 是运行时描述本次 UI。render 函数是两者的桥。

**Q：`with(this)` 呢？**

Vue2 生成的 render 常用 `with` 访问实例属性。Vue3 默认用 `_ctx.xxx`，配合 `_withKeys` 等，严格模式和打包更友好，也方便识别未声明的变量。

**Q：模板 AST 和 JS AST 的区别？**

不是同一种树。

- **模板 AST**：和 HTML 同构。节点是 Element / Text / Interpolation / Directive，表示「模板长什么样」。只在编译期存在。
- **JS AST**（或 Vue 的 codegenNode）：描述「要生成哪段 JS」。节点是 `createVNode(...)` 这类调用结构，接近 ESTree。

parse 产出模板 AST；transform 一边改模板 AST，一边挂上 codegen 信息（有的实现是转成 JS AST）；generate 只吃这些代码生成信息，吐 render 字符串。运行时的 **VNode** 又是第三种东西：render **执行之后** 的 UI 快照。

**Q：静态提升提升的是什么？哪些节点不能静态提升？**

提升的是 **VNode 创建表达式**（以及静态 props 对象）到 `render` 函数外面，变成 `_hoisted_n`，每次渲染复用同一对象，少分配。不是把 DOM 提到外面。

能提：无任何动态绑定的元素子树、静态文本、静态 class 对象。

不能提：带插值 / `v-bind` / `v-on`（事件走 cache 不走 hoist vnode）、`ref`、指令、组件（实例不能共享）、依赖 v-for 作用域且会复用到多个 DOM 上的节点要 clone。详见第 8、16 题。

**Q：v-if 和 v-for 在模板编译时的处理，优先级？**

都会在 transform 阶段拆掉，不会留到运行时当「指令对象」再解释。

- `v-if` / `else`：变成三元或多个条件分支，每个分支一个 block（结构会变，必须嵌套 block）。
- `v-for`：变成循环生成 Fragment，带 `KEYED_FRAGMENT` / `UNKEYED_FRAGMENT`，内部走列表 Diff。

同元素上两者都写：

- Vue2：**v-for 优先**，先循环再 `v-if`，白循环被滤掉的项。
- Vue3：**v-if 优先**，并警告。正确写法是拆 `<template v-for>` 包一层，或先 computed 过滤再 `v-for`。

**Q：runtime-only 为什么不能传 template？**

runtime-only 没打进 `compile`。`template` 字符串没人翻译成 `render`，运行时只会报你在用 runtime-only。SFC 的 `<template>` 在打包时已经编完，产物里只有 `render`，所以用 runtime-only 完全够。要在浏览器里现场编字符串，得换 full build。

**Q：插值表达式 `{{ msg }}` 在编译三个阶段分别发生了什么？**

1. **parse**：扫到 `{{` `}}`，建 Interpolation 节点，里面是表达式 `msg`（SimpleExpression），不是运行时值。
2. **transform**：这个插值被当成动态文本。父元素往往因此带上 `patchFlag = TEXT`；表达式改写成 `toDisplayString(_ctx.msg)`（防 null、对象转字符串）。若和相邻静态文本合并，会变成一个复合文本节点。
3. **generate**：吐出类似 `_toDisplayString(_ctx.msg)` 作为 `createVNode` 的 children，并带 patchFlag `1`。运行时每次 render 读 `msg`，完成依赖收集；更新时只 patch 这段文本。
