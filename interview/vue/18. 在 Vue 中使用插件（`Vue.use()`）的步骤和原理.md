# 在 Vue 中使用插件（`Vue.use()`）的步骤和原理

## 简答

Vue 插件用于给框架增加全局扩展能力：注册全局组件、全局指令、挂载全局属性、全局 provide 注入，像 VueRouter、Pinia 都是通过插件安装。

插件有两种规范形式：

- 包含`install`方法的对象；
- 本身就是`install`函数。

## 使用步骤

1. 定义插件，编写`install(app, options)`；
2. 在创建 app 之后、`mount`挂载之前调用 `app.use(plugin, options)`；
3. 框架内部执行插件的 install 方法，传入当前 app 实例与配置项。

## 原理

app 内部维护`_installedPlugins`列表，每次`use`先检查插件是否已安装：

- 未安装：执行 install，把插件加入已安装列表；
- 已安装：直接跳过，保证同一个 app 上插件只会执行一次。

Vue2 和 Vue3 的区别：

- Vue2：`Vue.use(plugin, options)`，install 接收 Vue 构造函数；所有组件实例共用全局配置，多实例会污染。
- Vue3：`app.use(plugin, options)`，install 接收**当前应用实例 app**；不同 app 实例的插件安装列表相互独立，全局配置隔离。

install 内部可以通过 app 实例完成：注册全局组件、指令、挂载全局属性、全局 provide。

> 
> 注意：`app.use`必须写在 mount 之前，挂载完成后再注册插件不生效。

一句话总结：`app.use`会调用插件的 install 方法并传入 app 实例，app 缓存已安装插件保证只执行一次；Vue3 基于 app 实例实现全局能力隔离。

---

## 四个关键词（卡住就说这四个）

1. **`install(app, options)`**：插件入口。
2. **只装一次**：用数组/Set 记已安装插件。
3. **Vue3 挂 app 不挂全局 Vue**：`createApp` 多次互不影响。
4. **组件 ≠ 插件**：组件是页面积木；插件是给运行时加能力。

## 使用步骤

```js
// Vue3
const app = createApp(App)
app.use(router)
app.use(pinia)
app.use(MyPlugin, { locale: 'zh' })
app.mount('#app')
```

必须 **mount 之前** `use` 完。mount 后再装，根组件已经创建，全局组件/mixin 不一定还能作用到根。

自己写插件：

```js
const MyPlugin = {
  install(app, options) {
    app.config.globalProperties.$echo = (msg) => msg
    app.component('MyComp', Comp)
    app.directive('focus', { mounted: (el) => el.focus() })
    app.provide('pluginOptions', options)
  }
}
```

也可以 `export default function install(app, options) { ... }`，`app.use(install)` 同样认。

Vue2 则是 `install(Vue, options)` 里 `Vue.component`、`Vue.prototype.$xxx`、`Vue.mixin`。

## 原理（Vue3 `app.use`）

伪代码级：

```js
use(plugin, ...options) {
  if (installed.has(plugin)) return app
  if (typeof plugin === 'function') plugin(app, ...options)
  else plugin.install(app, ...options)
  installed.add(plugin)
  return app  // 链式调用
}
```

细节面试够用：

- 插件对象上除了 `install`，还可以带 `version` 等，框架不强制。
- `app.use(router)` 时，vue-router 的 install 会注册 `RouterView`、`RouterLink`，并 `app.config.globalProperties.$router = ...`，再 `provide` 路由实例。
- Pinia 类似：`install` 里 provide store，并挂 `$pinia`。

Vue2 `Vue.use` 把插件放进 `Vue._installedPlugins`，用 `indexOf` 去重；若 `plugin.installed` 已是 true 也会跳过。没有 `app` 的概念，**一次 use 污染整个构造器**，所有 `new Vue` 都能用到。

## 和组件、mixin 的边界

| | 组件 | 插件 |
| --- | --- | --- |
| 目的 | 复用一块 UI / 业务视图 | 扩展 Vue 本身 |
| 注册 | `component` / 局部 components | `use` |
| 形态 | SFC 或选项对象 | `install` |
| 例子 | Button、Table | vue-router、i18n、自己的埋点 SDK |

可以「插件里注册一批全局组件」，那是插件干了组件注册的事，本质仍是 install。

mixin 全局混入也常由插件来做（给每个组件塞 `$route`）。缺点同样：隐式、冲突，Vue3 更鼓励 provide / composable。

## 可能被追问

**Q：为什么 Vue3 不让 `Vue.use`？**

没有默认单例构造器了。全局 API 挂树上会导致两个 `createApp` 抢同一份配置。改成 app 级，测试里也能每个用例一个 app。

**Q：`app.use(pinia)` 和直接 `createPinia()` 的关系？**

`createPinia()` 只是创建实例；必须 `use` 进去，组件里的 `useStore()` 才能 `inject` 到这个实例。漏了 use，运行时会报找不到 pinia。

**Q：install 里能不能 `app.mount`？**

能但别这么干。插件不该决定应用何时挂载，只负责注册能力。

**Q：同一插件两个 app 各 use 一次？**

会 install 两次，这是对的，各自往自己的 app 上挂。去重范围是 **单个 app**，不是整个页面进程。

**Q：install 里面可以做哪些操作？不能做哪些操作？**

可以（也是插件的本职）：

- `app.component` / `app.directive` / `app.mixin`
- `app.config.globalProperties.$xxx`
- `app.provide(...)`
- 挂路由、store、改 `app.config`（errorHandler、compilerOptions）
- 返回值无要求，副作用注册即可

不该做：

- **`app.mount`**：何时挂载是应用的事，插件抢了入口
- 假设全局只有一个 app，去改 `window.xxx` 当单例（和 createApp 隔离对着干）
- 在 install 里发请求、操作 DOM（此时往往还没 mount，也没有组件实例）
- 偷偷替换用户的 root component

可以做但要谨慎：全局 mixin 会给每个组件加一份选项，和 mixin 的坑一样。

**Q：如果插件既包含 install 方法，本身又是函数，use 的时候执行哪一个？**

**走 `install`。** 源码先判断 `plugin.install` 是函数就 `plugin.install(app, ...options)`，否则才把插件本身当函数调 `plugin(app, ...options)`。

所以 `function Plugin() {}` 再挂 `Plugin.install = fn`，`use` 只跑 `install`，构造函数体不会当 install 跑。写插件选一种形态即可，别两种都塞逻辑。

**Q：app.use 链式调用的原理？**

`use` 末尾 `return app`，所以 `createApp(App).use(router).use(pinia).mount('#app')`。没有新对象，一直是同一个 app 引用。`mount` 返回的是 **根组件实例**，不是 app，所以 `use` 必须写在 `mount` 左边。

**Q：为什么 app.use 必须放在 mount 之前？**

`mount` 立刻创建根组件：setup、render、子组件解析都在这一刻。插件要注册的全局组件、mixin、provide、`$router`，根组件 **第一次** setup 就要用到。

mount 之后再 `use`：

- 根已经创建，根上拿不到这次 provide / mixin
- 全局组件对 **尚未创建** 的后继子组件可能仍有效，但对已经挂上的树不会补跑一遍
- vue-router / pinia 在根 setup 里 `inject` 失败，直接报错

所以约定：先 `use` 齐，最后 `mount`。
