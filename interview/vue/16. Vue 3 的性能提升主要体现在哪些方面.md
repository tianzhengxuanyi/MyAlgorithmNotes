# Vue 3 的性能提升主要体现在哪些方面

## 简答

Vue3 的性能提升是编译期、运行时、打包体积三方面组合优化：

1. **编译期优化（收益最大）**
编译器做静态提升、事件缓存、patchFlag、Block Tree。编译阶段标记哪些节点、哪些属性是动态的。渲染更新时，静态节点直接跳过 diff；只对比 block 收集的动态节点，并且 patch 时只校验 patchFlag 标记的变动类型，大幅减少比对工作量。
2. **运行时优化**
① 列表 diff 升级为快速 Diff：前后缀预处理 + 最长递增子序列 LIS，减少 DOM 移动操作；
② 响应式改用 Proxy：懒劫持，只在访问嵌套对象时才代理；原生支持对象新增、删除属性与数组监听，不再需要重写数组方法；
③ 调度器 scheduler：job 去重，同一 tick 多次修改状态，组件只更新一次；支持 pre/post/sync 多种 flush 时机。
3. **打包体积优化**
Vue3 采用 ES Module 模块化，API、内置组件、指令单独导出，支持 tree-shaking，未使用的代码打包时可以剔除。runtime-only 版本体积更小。
4. **其他体验优化**
Fragment 多根模板，不需要额外根 DOM 包裹，减少冗余节点；Teleport 可以把 DOM 挂载到任意容器，脱离父组件样式 / 滚动上下文，减少布局计算问题。

一句话总结：Vue3 编译器提前标记动态内容，运行时避免全量 diff；Proxy 带来更高效响应式；模块化支持 tree-shaking，同时 Fragment、快速 Diff 进一步降低 DOM 开销。

---

## 四个关键词（卡住就说这四个）

1. **patchFlag / block tree**：比哪部分、比哪些节点。
2. **静态提升 + 事件缓存**：少分配 VNode 和内联函数。
3. **Proxy**：补上 defineProperty 的缺，深层默认懒代理。
4. **Tree-shaking**：用不到的官方 API 打不进包。

---

## 1. 编译阶段（收益最大，结合第 8 题）

Vue2 组件一更新，同层节点（含纯静态 `<p>固定文案</p>`）都要走比对。模板明明大部分不会变，运行时却不知道。

Vue3 编译时就能看出来：

- **patchFlag**：这个元素变的是 TEXT 还是 CLASS/PROPS，`patchElement` 按位运算只更那一块。
- **block tree**：动态节点收进 `dynamicChildren`，更新时按下标对齐，静态兄弟直接跳过。
- **静态提升**：纯静态 VNode 提到 render 外，整个应用生命周期创建一次。
- **事件缓存**：`@click="foo"` 缓存函数引用，避免每次 render 新函数被当成动态 props。
- **SSR 相关**：编译还能生成字符串拼接的快路径，服务端少走完整 VNode。

手写 `h()` 吃不到这套，因为没有模板分析。

---

## 2. Diff 算法

同层比较、key 的语义没变。变的是**有 key 的乱序列表**：Vue2 双端四指针；Vue3 先处理简单前/后缀，中间用 LIS 判断哪些节点可以不动。节点多、移动复杂时更稳。细节见第 7 题。

---

## 3. 响应式

`Object.defineProperty` 要预先递归定义、加属性听不到、数组下标和 length 要黑科技。Proxy 一次代理整个对象，`add`/`delete`/`length` 都能 trigger，深层对象 **get 到才 reactive**，初始化更省。

组件更新粒度仍是**组件级**（不是每个属性绑一个 DOM 更新），靠异步队列去重。Vapor 模式才是细粒度 DOM 更新，那是另一条渲染管线，面试提到「未来/可选」即可，不要和默认 VDOM 混成已经全量替换。

---

## 4. Tree-shaking 与体积

Vue2 很多全局 API 挂在 `Vue` 对象上，打包器不敢删。Vue3 改成 **ESM 具名导出**：

```js
import { nextTick, computed } from 'vue'
```

没用到的 `Transition`、`KeepAlive`、指令实现可以摇掉。配合 Composition，逻辑用到的 API 才被引用。官方数据是运行时体积明显下降（具体数字随版本变，背「可摇树 + 更小」即可，别背死一个 KB 数）。

---

## 5. 和「写得快」无关的运行时细节

- **Fragment**：多根节点，少套一层无语义 div，diff 和 CSS 都少一层。
- **静态 props 提升**、**缓存内联 handler** 减少 GC。
- **编译器模块化**：core / compiler-dom / compiler-sfc 分开，按平台替换。

## 可能被追问

**Q：Vue3 一定比 Vue2 快吗？**

同复杂度、模板动态点很少时，编译优化最明显。全是动态列表、几乎没有静态节点，差距主要在 diff 和 Proxy，不会神话。错误使用（深层巨大 `reactive`、到处 `forceUpdate`）两边都慢。

**Q：Proxy 比 defineProperty 慢还是快？**

单次 get/set，Proxy 不一定更快，引擎实现各异。赢在**少做无用递归劫持、能覆盖的场景全、代码路径更简单**。整体应用性能看的是「少更新、少 diff」，不是单次 trap 打点。

**Q：和 React 比呢？**

React 靠用户 `memo` / 稳定引用减少重渲染；Vue 靠依赖收集默认少更新，再靠编译标动态点。别说成「Vue 一定比 React 快」，说清策略差异。

**Q：Object.defineProperty 和 Proxy 的对比，Proxy 有哪些短板？**

| | defineProperty | Proxy |
| --- | --- | --- |
| 粒度 | 属性 | 整个对象 |
| 增删属性 | 听不到，要 `$set` / `$delete` | ADD/DELETE 能 trigger |
| 数组下标 / length | 要改 7 个变异方法 | 能拦 |
| 初始化 | 递归把嵌套对象全 Observe | get 到才懒代理 |
| 兼容 | IE | 无 IE，不能 polyfill 完整行为 |

Proxy 短板（面试要主动说）：

- **不能代理原始值**，所以才有 `ref` 盒子。
- **代理对象 ≠ 原对象**：`proxy === raw` 为 false，`Map` 用原对象当 key 会对不上；需要 `toRaw` / `markRaw`。
- 对 **Set/Map/Date** 等要单独的 instrument，漏了就丢失响应式。
- 某些操作（`Object.preventExtensions` 边缘情况）和引擎实现细节比 defineProperty 更绕。
- 单次 get/set 未必比 defineProperty 便宜，赚的是少劫持、少更新。

**Q：BlockTree 和快速 Diff 分别解决什么场景的优化，两者会一起生效吗？**

**BlockTree**：模板结构稳定时，动态节点收进 `dynamicChildren`，更新按下标对齐，静态兄弟不参与。解决「一大片静态 + 几个插值」的无效遍历。

**快速 Diff**：`v-for` 这种 **长度、顺序会变** 的列表，用前/后缀 + 最长递增子序列，尽量少移动 DOM。

会一起生效：外层模板走 block（下标比动态点），里面的 `v-for` 是 **嵌套 block**（`KEYED_FRAGMENT`），块内部走快速 Diff。Block 决定「比谁」；列表 Diff 决定「会变长的那一组怎么对齐」。没有编译信息的 `h()` 两边都吃不到。

**Q：静态提升能提升哪些内容，什么内容不能静态提升？**

能提：纯静态元素整棵子树、静态文本、静态 props 对象（`{ class: 'x' }`）。提到 `render` 外只创建一次，vnode 打 `HOISTED = -1`。大段静态还可 `createStaticVNode` 一次 `innerHTML`。

不能提到模块级：插值、动态 class/style/属性、`ref`、自定义指令、依赖作用域的 slot、每次要新实例的组件。`v-for` 里的纯静态节点可以提升，但挂载时 `cloneIfMounted`，防止多个 li 共用一个 `vnode.el`。

事件不是提升 vnode，是 `_cache` 缓存函数引用。

**Q：runtime-only 和 full build 的区别？**

**runtime-only**：不含模板编译器，包更小。只能跑已经编好的 `render`。SFC、`vite`/`vue-loader` 产出的就是这种。生产默认这条。

**full（runtime + compiler）**：能在运行时把 `template:` 字符串 / `innerHTML` 编成 render，`$mount` 时现场 compile。体积大，CDN 演示、在线 playground 才需要。

选错了：runtime-only 里写 `template: '<div>'` 会报「You are using the runtime-only build」。

**Q：Vue3 相比 Vue2 内存方面有什么优化？**

- **懒代理**：深层对象用到才 `reactive`，不会启动时把整棵 data 递归 Observe 一遍。
- **静态提升 / 事件缓存**：少分配 VNode 和内联函数，GC 压力小。
- **跳过静态树**：HOISTED 不进 diff，少保留对照信息。
- **`markRaw` / `shallowRef`**：大列表、不可变数据、第三方实例不进响应式。
- **EffectScope**：组件卸时一棵副作用一起停，watcher/effect 不泄漏。
- **Tree-shaking**：没用到的运行时代码不进包，运行时对象也更少。
- Vue2 每个属性一个 Dep + 观察者；Vue3 `targetMap` 按对象分桶，配合组件级 effect，订阅者数量更可控。
