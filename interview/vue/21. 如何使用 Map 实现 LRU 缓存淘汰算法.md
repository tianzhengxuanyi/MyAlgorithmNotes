# 如何使用 Map 实现 LRU 缓存淘汰算法

## 简答

LRU （Least Recently Used）全称最近最少使用缓存：缓存达到最大容量时，优先淘汰**最久没有被访问**的数据；get 读取、put 更新都视为一次访问，该数据标记为最近使用。
ES6 Map 可以简化实现 LRU，因为 Map 会**保留 key 的插入顺序**，迭代顺序：最早插入在前，最新插入在后。底层标准 LRU 是哈希表 + 双向链表；Map 相当于内置了有序哈希结构。

逻辑：

1. `get(key)`：
   - 如果不存在，返回 undefined；
   - 如果命中：先 delete 删除该 key，再 set 写入，把 key 移动到 Map 末尾（最新位置），返回 value。
2. `put(key, value)`：
   - key 已存在：delete 旧 key，set 新值，更新到末尾；
   - key 不存在：判断当前大小是否等于最大容量；
   ✅ 容量未满：直接 set；
   ✅ 容量已满：拿到迭代器第一个 key（最久未访问），执行 delete 淘汰，再 set 新增数据。

> 
> Map 的 set /get/delete 哈希操作平均 O (1)；
> 局限：适合小规模缓存；海量数据场景手写双向链表会更高效。

---

## 四个关键词（卡住就说这四个）

1. **插入顺序 = 时间顺序**。
2. **刷新 = delete + set**。
3. **队头淘汰**：`keys().next()`。
4. **和链表 LRU 等价**：链表 + HashMap 是经典写法；Map 是语言自带的顺序哈希。

## 实现（面试可默写）

```js
class LRUCache {
  constructor(capacity) {
    this.capacity = capacity
    this.map = new Map()
  }

  get(key) {
    if (!this.map.has(key)) return -1
    const value = this.map.get(key)
    this.map.delete(key)
    this.map.set(key, value) // 挪到最新
    return value
  }

  put(key, value) {
    if (this.map.has(key)) {
      this.map.delete(key)
    } else if (this.map.size >= this.capacity) {
      const oldest = this.map.keys().next().value
      this.map.delete(oldest)
    }
    this.map.set(key, value)
  }
}
```

手写例子：容量 2

```
put(1,1)          → {1}
put(2,2)          → {1, 2}
get(1)            → 把 1 挪到最后，{2, 1}
put(3,3)          → 满了删最老 2，{1, 3}
get(2)            → -1
```

## 和「哈希表 + 双向链表」的关系

LeetCode 146 经典解法：

- HashMap：key → 链表节点，O(1) 查找
- 双向链表：头是最新、尾是最老（或反过来），O(1) 挪节点、删尾

`Map` 在 JS 引擎里本来就是「有序哈希」，把链表的顺序职责交给了语言。面试两种都能写；被追问复杂度时要说：规范上 Map 的 delete/set 是平均 O(1)，不要声称自己维护了真正的 O(1) 链表指针，除非你写了链表。

不要用普通对象 `{}` 当 LRU：键顺序对整数 key 有坑，删了再加也不保证当「新插入」。

## Vue 里哪里用到（加分，KeepAlive）

`KeepAlive` 要限制 `max` 个组件实例。Vue3 **不是双向链表**，而是：

- `cache: Map` 存 vnode
- `keys: Set` 利用 Set 的插入顺序做 LRU

命中缓存：`keys.delete(key); keys.add(key)`。超 `max`：淘汰 `keys.values().next().value`，`pruneCacheEntry` 真正卸载组件（会走到 `unmounted`）。

业务缓存容量通常很小，Set 删除要走一遍桶，工程上可接受。和本题「用 Map 做 LRU」是同一思想。

## 可能被追问

**Q：为什么 get 也要调整顺序？**

LRU 的「最近」包括读。只 put 刷新、get 不刷新，那是另一种策略，不是 LRU。

**Q：put 已存在的 key 只改 value 要不要刷新？**

要。这是一次使用。上面实现是先 delete 再 set，顺序自然到最后。

**Q：线程安全？**

浏览器 JS 单线程，面试说 Map 实现不考虑锁。后端多线程要另说。

**Q：和 FIFO、LFU 的区别？**

FIFO 只按进缓存时间，不管中间有没有被读。LFU 按频次，要额外计数。LRU 跟「最近一次被碰到」绑定，缓存局部性好的访问模式更合适。

**Q：Map 实现 LRU 和原生双向链表 + 哈希表实现 LRU 相比，优缺点？**

| | Map 保序 | HashMap + 双向链表 |
| --- | --- | --- |
| 代码量 | 十几行 | 要手写节点、dummy、搬指针 |
| get/put | 平均 O(1)（引擎实现） | 严格 O(1) 挪指针 |
| 顺序 | 语言保证插入序 | 自己维护 head/tail |
| 可控性 | 不能 O(1) 取「中间某个节点」再链到头以外的位置 | 链表想怎么接怎么接 |
| 面试 | JS 实用解 | LeetCode 146 经典解、语言无关 |

JS 里 Map 已经是有序哈希，再手写链表通常没收益。其它语言没有插入序 Map 时必须链表。KeepAlive 用 Map + Set 也是图省事，max 很小，不追求理论 O(1) 删除 Set 元素。

短板：依赖引擎；不能自定义「同等 key 的稳定次序」之外的结构；若要 O(1) 删除任意节点且节点还挂别的元数据，链表更直观。

**Q：`Map.keys().next()` 拿到的为什么是最久未访问 key？**

`Map` 迭代顺序 = **现在还在表里的插入顺序**。我们约定：每次访问都 `delete` 再 `set`，等于把它从原位置拿掉、当作新插入排到 **最后**。于是：

- 迭代器第一个 = 最早插入且中间没被刷新 = **最久没访问**
- 最后一个 = 刚刚 get/put 过的

`keys()` 返回的迭代器不拷贝数组，`.next().value` 就是队头那个键。

**Q：put 更新已有 key 的时候，为什么必须先 delete 再 set？只 set 行不行？**

**不行。** 规范里对已存在的 key `set` 只改 value，**不改变它在插入序里的位置**。只 `set` 的话，这个键仍停在「很老」的位置，下一轮淘汰可能把它当 LRU 删掉，明明刚刚才用过。

所以更新必须：`delete(key)` 打断旧序 → `set(key, newVal)` 排到末尾。`get` 同理，否则读过的键不会变「新鲜」。
