# vue双向数据绑定的实现原理（v-model的作用和实现细节）

## 简答

v-model 的本质是**语法糖**，Vue 遵循单向数据流，v-model 只是把「Model -> View 的数据传递」和「View -> Model 的事件回写」封装在一起，看起来像双向绑定，分为原生表单 DOM 和自定义组件两种场景：

1. **原生表单元素**
Vue2：编译成 `:value="val"` + `@input="val = $event.target.value"`。checkbox/radio/select 会使用 checked 和 change 事件。
Vue3：编译时会对应生成运行时指令 `vModelText / vModelCheckbox`。挂载时给 DOM 赋值；更新时在 `beforeUpdate` 做值对比，避免中文输入法组字（`compositionstart`）阶段频繁更新导致光标跳至末尾。
修饰符：`.trim`、`.number` 在回调里对输入值预处理；`.lazy` 会把 input 事件改为 change，失去焦点才更新数据。
2. **自定义组件**
Vue2：默认 prop 是`value`，事件`input`；支持`model`选项修改 prop 和事件名；`.sync`修饰符用于单个属性双向绑定。
Vue3：取消`.sync`，默认 prop `modelValue`，事件 `update:modelValue`；支持多个 v-model，写法 `v-model:xxx`。
Vue3.4 新增 `defineModel` 宏，底层依旧是 `modelValue` prop + `update:modelValue` emit。它返回一个代理 ref，修改这个 ref 会内部触发 emit，通知父组件更新，不能直接修改 props。
3. **完整闭环**
用户在视图触发输入事件，回写数据，触发响应式系统 `trigger`，调度器执行组件更新，patch 阶段更新 DOM，完成单向数据流闭环。

> 
> 高频坑点：自定义组件中，**不能直接修改 props.modelValue**，必须 emit 事件；直接修改 props 不会让父组件数据更新，还会违反单向数据流规范。

---

## 四个关键词（卡住就说这四个）

1. **语法糖，不是第三套响应式**：拆开就是「绑值」+「听事件写回」。
2. **原生 vs 组件**：原生动 DOM 的 `value/checked`；组件走 prop / emit。
3. **Vue2 `value+input` → Vue3 `modelValue+update:modelValue`**：避免和原生属性撞名，并支持多个 v-model。
4. **修饰符在运行时落地**：`.lazy` 换事件，`.trim` / `.number` 改写回值；组件上变成 `modelModifiers` 传给子组件。

---

## 整体流程（按时间线背）

以 `<input v-model="msg">` 为例。

**1. 编译期拆糖**

模板 AST 上的 `v-model` 指令走 `transformModel`。原生元素生成运行时指令 + 赋值函数；组件生成 prop + `onUpdate:*`。

**2. 首次渲染：Model → View**

`msg` 是响应式。渲染 effect 读 `msg`（track），指令 `mounted` / 属性 `value` 把值写到 input 上。

**3. 用户输入：View → Model**

`input`（或 `change`）触发。Vue3 取 `el.value`，过 trim/number，调 `el._assign`（也就是编译出来的 `msg = $event` / `msg.value = $event`）。Vue2 则是编译出来的赋值表达式直接跑。

组字中：`compositionstart` 打标，`input` 直接 return；`compositionend` 再赋值。否则拼音过程会把半成品写进数据。

**4. 数据变了再回来**

赋值走响应式 set → trigger → `queueJob` → 再 render。`vModelText.beforeUpdate` 比较 `el.value` 和绑定值，不同才改 DOM，不然光标会跳。

```
msg（响应式）
    │  编译：绑值 + 赋值函数
    ▼
input.value  ◄── mounted / beforeUpdate
    │
用户输入 ──► onInput ──► msg = 新值 ──► trigger ──► patch
```

## 原生元素（源码）

**Vue2 编译器** `platforms/web/compiler/directives/model.js`：按标签/type 分发 `genDefaultModel` / `genCheckboxModel` / `genRadioModel` / `genSelect`。文本框大致生成：

```js
{
  value: msg,
  on: { input: $event => { msg = $event.target.value } }
}
```

**Vue3 编译器** `@vue/compiler-dom` 的 `transformModel`：原生不生成 `:value`+`@input`，而是 `withDirectives` + 指令：

| 元素 | 运行时指令 | 默认事件 |
|------|------------|----------|
| text / textarea | `vModelText` | `input`（`.lazy` 则 `change`） |
| checkbox | `vModelCheckbox` | `change` |
| radio | `vModelRadio` | `change` |
| select | `vModelSelect` | `change` |
| `:type` 动态 | `vModelDynamic` | 运行时再选上面某一个 |

`runtime-dom/src/directives/vModel.ts` 要点：

- `created`：`el._assign = vnode.props['onUpdate:modelValue']`，绑事件；`lazy/trim/number` 在监听器里处理。
- checkbox 绑的是数组时：勾选 `push`，取消按值 `splice`；单布尔则赋 `true/false`。
- select 多选读 `option.selected` 拼数组。
- `beforeUpdate`：刷新 `_assign`（函数可能变），并按需同步 DOM。

## 自定义组件（源码）

**Vue2** `create-component.js` 里 `transformModel`：

```js
prop  = options.model.prop  || 'value'
event = options.model.event || 'input'
data.attrs[prop] = data.model.value
data.on[event]   = data.model.callback
```

子组件：`this.$emit('input', val)`。`model` 选项用来改成例如 `checked` + `change`。

**Vue3** `compiler-core` 的 `transformModel`：

```js
props: {
  modelValue: foo,
  'onUpdate:modelValue': $event => (foo = $event)
}
```

`v-model:title="foo"` 则是 `title` + `onUpdate:title`。子组件：

```js
emit('update:modelValue', newVal)
// 或 3.4+
const model = defineModel()  // 读 props.modelValue，写则 emit
model.value = newVal
```

修饰符：`v-model.trim="foo"` 在组件上会多传 `modelModifiers: { trim: true }`，子组件自己决定怎么用。原生修饰符由指令处理，不会变成这个 prop。

Vue2 的 `.sync` 在 Vue3 里就是 `v-model:foo`，没有单独语法了。

---

## Vue2 vs Vue3（必背）

| | Vue2 | Vue3 |
|---|---|---|
| 原生实现 | 编译成 value + 事件 | `vModel*` 指令 + `onUpdate:modelValue` |
| 组件默认 | `value` + `input` | `modelValue` + `update:modelValue` |
| 改名 | `model: { prop, event }` | `v-model:arg`，可多个 |
| 其它字段双向 | `.sync` | `v-model:foo` |
| 子组件写法 | `$emit('input')` | `emit('update:modelValue')` / `defineModel` |

Vue3 换默认名字，是因为 `value`/`input` 太容易和原生表单语义冲突，也方便一个组件绑多个双向字段。

## 可能被追问

**Q：Vue 是不是整个框架都是双向绑定？**

不是。默认都是**单向**：数据变 → 视图变。`v-model` 只是在表单/组件上额外听了用户事件再写回数据。插值、`:prop` 都没有 View → Model。

**Q：为什么不直接 `:value` + `@input`，还要指令？**

可以，Vue2 就是这么编的。Vue3 抽成指令是为了统一处理 IME、光标、checkbox 数组、select 多选、修饰符，避免每个输入框都在 codegen 里塞一大段。组件仍然是纯 prop + emit，没有 `vModelText`。

**Q：`v-model` 在组件上能拆成哪两行？**

Vue3：`:modelValue="foo"` + `@update:modelValue="foo = $event"`。Vue2：`:value="foo"` + `@input="foo = $event"`。

**Q：checkbox 的 v-model 为什么有时是布尔、有时是数组？**

绑布尔：`checked` 对上 `true/false`。绑数组：`change` 时把当前 `value` 加进去或删掉。源码在 `vModelCheckbox`（Vue2 是 `genCheckboxModel`）。

**Q：`.lazy` / `.number` / `.trim` 分别干什么？**

`.lazy`：听 `change` 不听 `input`，失焦或回车才同步。`.trim`：写回前去首尾空格。`.number`：`looseToNumber`，转不成数字则保留原字符串。组件上这三者进 `modelModifiers`，原生上在指令监听器里做。

**Q：中文输入为什么不会每个拼音字母都更新？**

`compositionstart` 把 `el.composing = true`，期间 `input` 不 `_assign`；`compositionend` 再赋一次。选词完成才写进数据。

**Q：`defineModel` 和自己写 props + emit 有区别吗？**

没有新协议。`defineModel('foo')` 就是声明 `foo` prop、写 `foo.value` 时 `emit('update:foo')`。修饰符、默认值走它的 options。面试说「编译+运行时糖，底层仍是 v-model 那对 prop/事件」即可。

**Q：v-model 和 `.sync` 的区别？Vue3 为什么去掉 `.sync`？**

Vue2 里是**两套糖，编译结果同类**：

| | v-model | `.sync` |
|---|---|---|
| 写法 | `<Comp v-model="n">` | `<Comp :foo.sync="n">` |
| 拆开 | `:value` + `@input` | `:foo` + `@update:foo` |
| 数量 | 一个组件默认只能一个（`model` 选项改名也还是一个） | 多个 prop 都能 `.sync` |
| 用途 | 「主值」双向，表单组件 | 其它字段双向 |

`.sync` 没有第三套运行时，就是少写两行绑定。Vue3 用 **`v-model` 带参数** 把两套并成一套：默认 `v-model` → `modelValue`；`v-model:foo` 等价旧 `.sync`。再留 `.sync` 只是重复 API，也和「组件默认改成 modelValue」对不上，所以删掉。

**Q：`defineModel` 比手写 modelValue + emit 强在哪？原理有差别吗？**

**协议没差别。** 编译宏会给组件声明对应 prop / emit，运行时 `useModel` 返回一个 ref：get 读 `props.xxx`，set 走 `emit('update:xxx')`。父组件看到的仍是 `:modelValue` + `@update:modelValue`。

强在写法：少声明 props/emits、少拼 `'update:modelValue'` 字符串；返回的 ref 可以直接 `v-model` 到内部 input；`default`、`get/set` 转换、`model.modifiers` 都挂在这个 API 上。手写容易直接改 `props.modelValue`（改了父级也不知道），defineModel 的 setter 强制走 emit，更不容易踩单向数据流。

**Q：中文输入 composition，Vue3 v-model 具体怎么拦的？**

源码在 `vModelText`（`runtime-dom/directives/vModel.ts`），靠 DOM 上的 `el.composing` 标记：

1. 非 `.lazy` 时额外监听 `compositionstart` / `compositionend`（Safari 再听一次 `change`，组字结束不可靠）。
2. `compositionstart`：`el.composing = true`。
3. 之后的 `input`：发现 composing 直接 return，**不调用 `_assign`**，拼音半成品不进数据。
4. `compositionend`：清标记，再 **手动 dispatch 一次 `input`**，走同一套赋值（含 trim/number）。
5. `beforeUpdate`：若仍在 composing，**不改 `el.value`**，免得把输入法候选框/光标打乱。

`.lazy` 听的是 `change`，组字过程本来就不会每键同步，这条路径可以不绑 composition。

**Q：为什么不搞「真双向」，坚持单向数据流？**

所有视图更新仍应能追溯到**一份数据源**。子组件若直接改父级的数据，谁改的、何时改的看不出来，调试和协作都会乱。Vue 的约定是 **props 向下、事件向上**：子组件只提议，父组件决定写不写。

`v-model` 看起来像双向，拆开仍是这条约定，只是编译帮你写了赋值。真双向（子组件默默改 prop、或到处共享一份可变对象乱改）会让数据所有权不清。所以自定义组件里不能 `props.modelValue = x`，必须 emit；父组件的 `@update:modelValue` 才是唯一写入口。

**Q：同一个组件上多个 v-model 怎么做？**

Vue3 给指令带参数，每个参数一对 prop/事件：

```vue
<UserForm v-model:firstName="first" v-model:lastName="last" />
```

编译结果：

```js
{
  firstName: first,
  'onUpdate:firstName': $event => (first = $event),
  lastName: last,
  'onUpdate:lastName': $event => (last = $event)
}
```

子组件 `defineModel('firstName')`、`defineModel('lastName')`，或手写两对 props + `emit('update:firstName')`。默认那个不带参数的仍叫 `modelValue`。修饰符：默认是 `modelModifiers`，带参数的是 `firstNameModifiers`。

Vue2 做不到多个 v-model，其它字段只能 `.sync`。
