# 虚拟 DOM 的实现思路

## 简答

虚拟 DOM 的实现思路，可以从**分层架构**和**完整执行流程**两个维度来讲：

### 一、整体分层架构

Vue3 渲染器核心分为三层：

1. VNode 层：`createVNode`（h 是它的语法糖）用来创建 VNode 对象，描述节点类型、props、子节点；运行时做子节点规范化；
2. 渲染器核心层：`patch`是渲染唯一入口，统一处理挂载、更新、卸载；内部根据节点类型走不同处理分支；
3. 平台适配层：`nodeOps`封装平台原生操作 API，比如创建元素、插入、删除 DOM，让 patch 逻辑不直接依赖浏览器 document，实现跨平台。
调度器属于独立模块，和响应式系统配合，控制 patch 异步批量执行，不属于渲染器本身。

### 二、核心执行流程

#### 1. 构建 VNode

模板在编译阶段生成 render 函数，render 内部调用 h/createVNode 生成 VNode 树。

- `shapeFlag`：位运算标记 VNode 自身类型 + children 类型（文本子节点 / 数组子节点），优化 patch 分支判断；
- `patchFlag`：**编译期提前标记**VNode 的动态部分（动态文本、动态 props），运行时 diff 只对比动态内容，跳过静态节点。
`createVNode`运行时负责规范化子节点，比如字符串转文本 VNode。

#### 2. 首次挂载 mount

调用`render(vnode, container)`，内部执行`patch(null, newVNode, container)`
旧节点`n1`为 null，走挂载分支：

1. 通过`nodeOps.createElement`创建真实 DOM；
2. `patchProps`设置属性、事件；
3. 根据 shapeFlag 递归 patch 子节点；
4. `nodeOps.insert`插入容器；
5. 将真实 DOM 引用挂载到 `vnode.el`。

#### 3. 更新阶段 patch + diff

数据变更触发组件重新执行 render，生成新 VNode，再次调用`patch(oldVNode, newVNode)`。
patch 第一步判断：

- 如果`type`或者`key`不一致：直接卸载旧节点，挂载新节点；
- type 相同，但 shapeFlag 不同：同样销毁重建；
- type、key、shapeFlag 都相同：复用旧节点的`el`，更新 props；然后对子节点执行 diff。

子节点 diff：

- Vue2：双端 Diff，头尾交叉比对，构建 key 映射表复用节点；
- Vue3：快速 Diff。先同步头部、尾部相同节点；剩下乱序节点建立 key 映射；利用**最长递增子序列找到不需要移动的节点**，其余节点执行移动操作，最小化 DOM 移动次数。

#### 4. 卸载

调用`render(null, container)`触发卸载，递归删除 VNode 对应的真实 DOM，清理副作用、事件监听。容器会缓存上一次的`_vnode`，作为下一次 patch 的旧节点。

### 三、跨平台

所有原生操作都抽离到 nodeOps，渲染逻辑 patch 完全平台无关。渲染小程序、原生视图时，只替换 nodeOps 实现，patch 核心代码不用改动。

一句话总结：虚拟 DOM 本质是用 VNode 描述 UI，patch 作为统一入口，借助 diff 算法最小化 DOM 操作；通过 nodeOps 抽象平台能力，实现声明式渲染和跨端。

## 四个关键词（卡住就说这四个）

1. **`h` / `createVNode`**：统一造树，不直接碰 DOM。
2. **`patch(n1, n2)`**：n1 空=挂载，n2 空=卸载，都在=更新。
3. **相同节点才复用 `el`**：`type`+`key` 一致才改属性，否则整段替换。
4. **children 分形态**：文本、数组、空，两两组合决定是改文本还是走 Diff。

---

## 创建

```js
h('div', { id: 'app', onClick }, [h('span', null, msg)])
```

Vue3 `createVNode` 产出的对象核心是 `type / props / children / key / el`，再加：

- `shapeFlag`：元素还是组件、子节点是文本还是数组，后面 patch 用位运算分发。
- `patchFlag`：编译器标「这个节点动态的是 class / 文本 / props」，更新时少扫。

子节点规范化：`'hi'` → 文本 vnode；数组里的原始值同样包一层。组件 `render` 返回根 vnode，子树都在 `children` 里。

Vue2 是 `new VNode(tag, data, children, text, elm)`，`_c` / `createElement` 生成，语义一样。

---

## 挂载（`n1 == null`）

`mountElement` 顺序（笔记第7章）：

1. `el = createElement(vnode.type)`，`vnode.el = el`
2. 遍历 props：`onXxx` 绑事件，其余走 `patchProp`（class/style、attribute vs DOM property）
3. children 是字符串 → `setElementText`；是数组 → 对每个 child `patch(null, child, el)`
4. `insert(el, container, anchor)`

组件节点不是造一个 tag，而是创建实例、跑 `setup`/`render`，再 patch 它的 `subTree`。Fragment 不造元素，只挂子节点。卸载不能只 `remove`：要递归卸子树、停 effect、走组件 `unmounted`。

## 比较与更新（`patch`）

```
patch(n1, n2, container, anchor)
  n2 空        → unmount(n1)
  n1 空        → mount(n2)
  类型/key 不同 → unmount(n1)，mount(n2)
  否则         → 复用 el，patch 自身，再 patch children
```

Vue3 相同节点：`n1.type === n2.type && n1.key === n2.key`。元素走 `patchElement`：

1. `n2.el = n1.el`
2. **props**：新旧 key 做差，改的 `patchProp`，没了的删除。事件用 invoker 包一层，更新只改 `invoker.value`，不 `removeEventListener`。
3. **children** 四态：`null / 文本 / 数组 / 组件`。新文本且旧是数组要先卸子节点再设 text；新数组且旧是文本先清空再 mount；**新旧都是数组** → Diff（无 key 按下标；有 key 走双端或快速 Diff）。

`type` 变了（`div`→`p`、元素→组件）不能复用标签，必须拆掉重建。跨层不比，只比兄弟。

---

## 和响应式怎么接

组件更新函数包在 `effect` 里：第一次 `render` + `patch(null, vnode)`；数据变 → scheduler 排队 → 再 `render` 得到 n2 → `patch(n1, n2)`。容器记住 `container._vnode` / 组件实例上的 `subTree`，作为下一次的 n1。

多次 `set` 只 flush 一次，所以是「多次数据、一次造树、一次 patch」，不是每次赋值都操作 DOM。

## 最小闭环（对照笔记代码）

```js
function render(vnode, container) {
  if (vnode) patch(container._vnode || null, vnode, container)
  else if (container._vnode) unmount(container._vnode)
  container._vnode = vnode
}

function patch(n1, n2, container) {
  if (n1 && n1.type !== n2.type) {
    unmount(n1)
    n1 = null
  }
  if (!n1) mount(n2, container)
  else {
    n2.el = n1.el
    patchProps(n1, n2)
    patchChildren(n1, n2)
  }
}
```

平台相关的 `createElement / insert / remove / setElementText / patchProp` 从 `createRenderer(options)` 注入，这就是跨平台。

## Vue2 vs Vue3（实现差异，面试补一句）

| | Vue2 | Vue3 |
|---|---|---|
| 创建 | `new VNode`，`_c` | `createVNode` / `h`，带 shapeFlag |
| 比较 | `sameVnode` 还看 tag、data、input type | `type` + `key` |
| 更新 | 同层全量比 children | `patchFlag` + block tree，尽量只比动态节点 |
| 列表 Diff | 双端 | 快速 Diff（最长递增子序列） |

思路没变：还是创建、挂载、patch。Vue3 把「比什么」编译期收窄了。

## 可能被追问

**Q：`h` 和 `createVNode` 什么关系？**

`h` 是给手写 render 用的参数重载（2 个或 3 个参数）。最终都进 `createVNode`。模板编译直接调 `createVNode` / `createElementVNode`。

**Q：为什么更新事件不重新 `addEventListener`？**

挂的是稳定 invoker，真正回调在 `invoker.value`。props 更新只换函数引用，监听器不用拆。

**Q：`patch` 为什么要传 `anchor`？**

`insertBefore` 需要参考节点。Fragment、多个子节点、Diff 移动时，要插到「下一个兄弟」前面，不能只会 `appendChild`。

**Q：组件 vnode 和元素 vnode 的 patch 有何不同？**

元素：改 DOM。组件：比 props/slots 决定子组件更不更新；要更新就跑子组件自己的 `render`，再对它的 `subTree` 做元素级 patch。组件 vnode 的 `el` 指向子树根。
