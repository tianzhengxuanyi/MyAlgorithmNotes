# Vue 组件间通信方式有哪些

## 简答

组件之间作用域相互独立，通信方案可以按照组件关系来选择：

| 关系 | 优先方案 |
| --- | --- |
| 父 → 子 | props；多余属性走 attrs。Vue3 中`$listeners`已废弃，事件也合并到`$attrs` |
| 子 → 父 | 首选 `emit` 触发自定义事件；`v-model` 是语法糖，等价于 `modelValue` prop + `update:modelValue` 事件，Vue3 支持组件多 v-model |
| 父调子方法 | ref + `defineExpose` |
| 跨多层（插件、主题、i18n） | provide / inject，注意：传递普通原始值不具备响应式，要传 ref/reactive 对象；缺点是耦合较强，适合主题、i18n 这类底层配置，不适合业务全局状态 |
| 任意组件、要可追溯 | Pinia / Vuex，适合业务共享数据 |
| 兄弟 | 状态提升到共同父，或 store |

一句话总结：父子优先 props+emit；父调子组件用 ref+defineExpose；跨层配置用 provide/inject；全局共享状态用 Pinia；EventBus、$parent 尽量避免。

---

## 四个关键词（卡住就说这四个）

1. **单向数据流**：props 往下，事件往上，别让子直接改 prop。
2. **v-model**：就是 prop + emit 的语法糖。
3. **provide / inject**：不是响应式响应式要自己 `ref`/`reactive` 提供出去。
4. **store**：跨页面、多处读写、需要调试时再上。

---

## 各方案要点

**1. props / emit**

父传子声明 `props`（对象形式可写 type、required、default）。子不能改 prop，改了 Vue 会警告；要写回就 `$emit('update:xxx', val)` 或自定义事件。这是面试第一答案。

**2. v-model**

Vue2 默认 `value` + `input`；Vue3 默认 `modelValue` + `update:modelValue`，可多个 `v-model:title`。自定义组件上就是 props + emit，见第 3 题。

**3. `$attrs`（Vue2 还有 `$listeners`）**

父传了但子没声明成 prop 的，进 `attrs`。Vue3 里 class/style 和 `onXxx` 监听都在 attrs 里，**没有 `$listeners` 了**。配合 `v-bind="$attrs"` 做透明包装（比如再包一层 Input）。`inheritAttrs: false` 可禁止自动贴到根元素上。

**4. provide / inject**

祖先 `provide('key', value)`，后代 `inject('key')`，不用层层 props。Vue3 建议 `provide(key, readonly(state))`，避免子孙乱改。不适合频繁的业务数据同步，调试比 store 差。

**5. ref**

父在子组件标签写 `ref="comp"`，`mounted` 之后才能拿到实例。Vue3 `<script setup>` 默认不对外暴露，要 `defineExpose({ open })`。适合「父命令子」：打开弹窗、校验表单。不要用 ref 当 props 的替代品到处掏数据。

**6. Pinia / Vuex**

全局单例状态。Pinia 对 Vue3 更轻：没有 mutation，action 可同步可异步。适合购物车、用户信息、权限。组件通信「用 store」是可以的，但局部 UI 状态没必要进全局。

**7. EventBus**

Vue2 常用 `new Vue()` 当总线，`$on` / `$emit`。Vue3 去掉了实例 `$on`，要自己引入 mitt。缺点：事件满天飞、生命周期忘了 `$off` 就泄漏。新项目不推荐。

**8. `$parent` / `$root` / `$children`**

强耦合，组件一挪就断。Vue3 **没有 `$children`**。基本只在面试里当「还有但不建议」提一句。

**9. 插槽 / 作用域插槽**

也是一种通信：父把模板传给子，子把内部数据通过 slot props 回传。适合布局和列表的「样子由父定、数据由子定」。

## 可能被追问

**Q：兄弟组件怎么通信？**

最干净：状态放到共同父组件，props 下去 emit 上来。再大就 Pinia。不要为了兄弟专门搞 EventBus。

**Q：provide 的对象改了子孙会更新吗？**

看你 provide 的是不是响应式对象。provide 一个普通 object，子孙 inject 到的是同一个引用，字段若没变成 reactive 就不会更新；provide 一个 `ref`/`reactive`，子孙要保持 `.value` 或保持对象引用去读属性。

**Q：Vue2 `.sync` 呢？**

` :foo.sync` 等价于 `:foo` + `@update:foo`。Vue3 用 `v-model:foo` 取代。

**Q：跨层级必须 provide 吗？**

不是。三层以内 props 往下传完全可以。provide 适合「整棵子树都可能用」的依赖注入，不是为了偷懒少写一个 prop。

**Q：provide/inject 怎么保证响应式？如果传普通字符串会怎么样？**

provide **不会**把值自动变成响应式，只是把你给的引用交给子孙。

- 传 `ref` / `reactive` / `computed`：子孙 `inject` 到同一个对象，读 `.value` 或属性时照常 track，源变了会更新。推荐 `provide('state', readonly(state))`，防子孙直接改。
- 传普通字符串、数字：那是拷值。父后来改自己的变量，inject 到的还是旧字符串，**不会更新**。要变，必须 provide 一个 ref：`const title = ref('a'); provide('title', title)`，子孙 `inject('title').value`。

默认 `inject` 不是深层只读拷贝；响应式完全取决于你塞进去的是不是响应式对象。

**Q：Vue3 组件多个 v-model 底层原理？**

`v-model` 默认是 `modelValue` + `update:modelValue`。带参数的 `v-model:title` 编译成：

```html
:title="title" @update:title="title = $event"
```

多个就是多对 prop + `update:xxx`。子组件 `emit('update:title', v)`，父赋值，单向数据流没破。`defineModel('title')` 是宏，编出来仍是这个 prop + emit，再包一层可写的 computed。Vue2 一个组件默认只能一个 `v-model`（`.sync` 补其它字段）；Vue3 这条是语法糖升级，不是另搞一套总线。

**Q：props 为什么是单向数据流？子组件直接修改 props 会发生什么？**

状态所有权在父。子改 prop 等于改父的数据，来源乱、调试难，兄弟也会被连带改。

运行时：

- 对象/数组 prop：子改 **字段**（`prop.obj.x = 1`）能改到父的同一引用，Vue **不一定报错**（改的不是 prop 绑定本身），但这是坏实践。
- 子写 `prop.foo = 1` 或 `props.count++`（改绑定）：开发环境警告 `Avoid mutating a prop directly`。Vue3 对 props 对象是 shallow readonly，赋值无效或警告。
- 正确：`emit` 让父改；或本地 `ref` 拷一份当初始值。

**Q：defineExpose 原理，不写的话父组件 ref 为什么拿不到子组件变量？**

`<script setup>` 里的绑定是模块局部变量，编译后关在 setup 闭包里，**默认不挂到组件实例上**，避免内部状态被父随便掏。

`defineExpose({ open, count })` 编译成 `expose({ open, count })`，写到 `instance.exposed`。父 `ref` 拿到的是一个代理：优先访问 `exposed` 上的键，没有才落到实例公共字段（`$el`、`$emit`）。

不写 `defineExpose`：父 `childRef.value.xxx` 拿不到 setup 里的变量（是 `undefined`），不是 ref 没挂上，是没暴露。Options API 不需要这步，`data`/`methods` 本来就在实例上。

**Q：Pinia 对比 Vuex 有哪些改进？**

- **去掉 mutation**：改 state 在 action 里直接改，或 `$patch`，少一层样板。
- **不再强求 modules 嵌套**：每个 `defineStore` 一块，按需 `useStore()`，TS 推断完整。
- **Vue3 优先**：store 本身是 reactive，解构用 `storeToRefs` 保响应式；也兼容 Vue2。
- **体积小、无必须的 mutations/mapXxx 全家桶**；DevTools 仍能追时间旅行。
- **允许多个 Pinia 实例**（测试、SSR 每请求一个），和 `app.use(pinia)` 对齐。

Vuex 4 也能用在 Vue3，但新项目没理由再上 Vuex，除非存量模块。
