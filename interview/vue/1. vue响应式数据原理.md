# vue 响应式数据原理


## 简答

Vue3 的响应式核心基于 ES6 Proxy，搭配 Reflect，通过 `reactive` / `ref` 创建响应式对象，整个流程分为依赖收集、派发更新、调度执行三部分：

1. **依赖收集 track**
组件渲染函数会包装成 `ReactiveEffect`（副作用函数）执行。执行时会把当前 effect 赋值给全局 `activeEffect`。当访问代理对象属性，触发 Proxy 的 get 拦截器，通过 `Reflect.get` 获取值；如果存在 `activeEffect`，就把这个 effect 收集到一个WeakMap中。(targetMap 是三层结构：`WeakMap<目标对象, Map<属性key, Set<effect>>>`, WeakMap 的 key 是原始对象，不阻止 GC。)

2. **派发更新 trigger**
修改响应式数据，触发 set /deleteProperty 等拦截器，使用 Reflect 完成赋值。找到 WeakMap 中对应 key 收集的所有 effect，交给调度器处理。

3. **调度器 scheduler 批量更新**
调度器不会同步立刻执行更新。effect 会推入任务队列并去重，在默认在下一个微任务中统一刷新队列。这确保了同一 tick 多次修改数据，只会触发一次组件渲染。

- `reactive`：代理对象类型，**懒代理**：初始化只代理第一层，访问子对象时才对子对象进行代理，避免初始化递归遍历大对象带来性能损耗。
- `ref`：因为 Proxy 只能代理对象，原始类型（string/number/boolean）无法直接代理，ref 包装成一个包含 `.value` 的对象，再用 Proxy 代理这个外层对象。
- shallowReactive /shallowRef：浅层响应式，只代理第一层，不会递归对子对象做响应式。

相比 Vue2 的 Object.defineProperty：Proxy 可以监听新增属性、删除属性、数组下标、length 修改，不需要 $set。

---

## 四个关键词（卡住就说这四个）

1. **Proxy + Reflect**：拦 get/set/delete/ownKeys；`Reflect` 的 `receiver` 保证访问器里 `this` 指向代理，依赖才能收到。
2. **track / trigger**：读收集，写通知。桶是 `WeakMap<target, Map<key, Set<effect>>>`。
3. **effect + scheduler**：渲染、computed、watch 都是 effect。组件更新走 scheduler 做异步去重。
4. **lazy 深代理**：get 到嵌套对象才 `reactive(res)`，同一对象用 `reactiveMap` 缓存，避免重复代理。

## 整体流程（按时间线背）

以组件里 `const state = reactive({ count: 0 })`，模板用 `state.count` 为例。

**1. 创建响应式**

`setup` 里调用 `reactive(obj)`。源码走 `createReactiveObject`：校验对象、查 `reactiveMap` 有没有现成 proxy，没有就 `new Proxy(target, mutableHandlers)`，缓存「原始对象 ↔ 代理」。此时 **不会** 递归把所有嵌套属性都变成响应式。

**2. 挂上渲染 effect**

组件挂载时，把更新函数（跑 `render` + `patch`）包进 `ReactiveEffect`，立刻 `run()` 第一次。执行前把当前 effect 设为 `activeEffect`（3.5 叫 `activeSub`）。

**3. 首次渲染：track**

`render` 读 `state.count` → Proxy **get**：

1. `Reflect.get(target, 'count', receiver)` 取出值
2. `track(target, 'count')`：按 `target → key → deps` 把当前渲染 effect 放进集合
3. 若值是对象且不是 shallow，再 `reactive(res)` 返回嵌套代理

读完，依赖关系建立：**`state.count` 变了就要通知这个组件的更新 effect**。

**4. 修改数据：trigger**

`state.count++` → Proxy **set**：

1. 看是新增还是修改（数组还要看下标是否 `< length`）
2. `Reflect.set` 写回原始对象
3. 值真变了才 `trigger(target, 'count')`，取出该 key 上的 effect
4. 新增/删除还会通知 `ITERATE_KEY`（`for...in` / `Object.keys` 那类依赖）

**5. 调度，不是立刻渲染**

渲染 effect 配了 scheduler：`queueJob(instance.update)`。同一组件多次 `set` 只入队一次。`queueFlush` 用 `Promise.then` 在微任务里 `flushJobs`，这就是 **nextTick 只更一次视图** 的来源。

**6. 重新渲染**

微任务里 effect 再 `run()`：先 **cleanup** 清掉旧依赖，再执行 `render`，重新 track，新旧 vnode 做 **patch**。

一句话串起来：**创建代理 → 渲染时读就收集 → 写就通知 → 调度合并 → 再渲染 patch。**

```
reactive/ref
    │
    ▼
Proxy get  ──track──►  targetMap(target → key → effects)
    │
render / computed / watch（都是 effect）
    │
Proxy set  ──trigger──► scheduler（组件：queueJob）
    │
    ▼
微任务 flush ──► effect.run ──► render + patch
```

## 依赖怎么存

```
targetMap: WeakMap
  └── target（原始对象，弱引用，方便 GC）
        └── depsMap: Map
              └── key  →  Dep（Set / 链表里的多个 effect）
```

`WeakMap` 的 key 是弱引用：业务不再拿这个对象，依赖表不会拖住它，避免泄漏。`Map` 是强引用，不适合当最外层。

effect 自己也记一份 `deps`，供下次执行前 cleanup：从旧的 Set 里把自己删掉，再按这次实际读到的 key 重新收集。不然分支切换后（`ok ? obj.text : 'no'`），`ok` 变 false 后改 `text` 还会白跑一次。

## Proxy 拦什么（对象篇）

| 操作 | 捕获器 | track 的 key | 何时 trigger |
|------|--------|--------------|--------------|
| `obj.k` | get | `k` | 读 |
| `obj.k = v` | set | `k` | SET（改已有）/ ADD（新增） |
| `'k' in obj` | has | `k` | in |
| `for...in` / `Object.keys` | ownKeys | `ITERATE_KEY` | **只有新增、删除** 才通知，改值不通知 |
| `delete obj.k` | deleteProperty | `k` | DELETE |

`Reflect.get/set(..., receiver)`：访问器属性里的 `this` 必须是 **proxy**，否则内部再读其他属性会打到原始对象上，track 收集不到。

set 里还有一句源码细节：`target === toRaw(receiver)` 才 trigger，避免改到原型链上把子对象也通知一遍。

## Vue3 源码怎么对应

核心模型和笔记里的 `effect` / `track` / `trigger` 一致，类名不同。

**Vue 3.4（更常被问，和笔记一一对应）**

- `reactive()` → `createReactiveObject` → `new Proxy(target, mutableHandlers)`
- get：`track(target, TrackOpTypes.GET, key)`，对象再 `toReactive(res)`（懒深代理）
- set：`hasChanged` 才 `trigger`；区分 `ADD` / `SET`
- `ReactiveEffect.run()`：设置 `activeEffect`，执行 fn，结束恢复
- 嵌套 effect 用 `parent` 链表，不是手写 `effectStack`，作用一样：收集时永远拿「当前正在跑的那个」
- 组件：`instance.update = new ReactiveEffect(updateFn)`，scheduler 是 `queueJob`

**Vue 3.5+（说出来是加分项）**

依赖从「Set 存 effect」改成 **Dep ↔ Subscriber 双向链表**：

- 当前订阅者叫 `activeSub`
- `track` 给 dep 和 effect 之间建一条 `Link`
- `trigger` 走 `dep.notify()`，沿链表通知
- computed 自己实现 `Subscriber`，不再外包一层 `ReactiveEffect`（见 `computed.md`）

面试先把 **Proxy + track/trigger + 调度更新** 讲完，再补一句 3.5 用链表订阅即可。

## 和 Vue2 的区别（必背）

| | Vue2 | Vue3 |
|---|---|---|
| 拦截方式 | `Object.defineProperty` 逐属性劫持 | `Proxy` 拦整个对象 |
| 初始化 | 递归 walk 所有 key，一次性变响应式 | 访问到嵌套对象才代理 |
| 新增 / 删除 | 检测不到，要 `$set` / `$delete` | set / deleteProperty 直接能拦 |
| 数组 | 重写 7 个变异方法；下标、length 不听 | 下标、length 都能拦；变异方法用 `pauseTracking` 防死循环 |
| 原始值 | data 里的字段可以 | Proxy 不能代理，用 `ref` |
| 依赖结构 | 每个属性一个 `Dep` + `Watcher` | `targetMap` + `ReactiveEffect` |

Vue2 改数组下标、给对象加新字段都不更新，是 defineProperty 的硬伤，不是业务忘了 `$set`。

## 可能被追问

**Q：为什么用 Proxy 不用 defineProperty？**

Proxy 拦的是对象的操作，不是某个已有属性。所以能听新增、删除、`in`、`for...in`、数组下标和 `length`。defineProperty 只能定义当下已有的 key，还要递归 walk，初始化贵。

**Q：`obj.foo++` 为什么可能死循环？框架怎么挡？**

先 get 收集当前 effect，再 set 又 trigger 同一个 effect，会递归爆栈。trigger 时若待跑的就是 `activeEffect`，跳过。数组 `push` 会读/写 `length`，同源问题，源码对变异方法 `pauseTracking()`。

**Q：scheduler 和 nextTick 什么关系？**

trigger 不直接跑渲染函数，把 job 推进队列，微任务一次性 flush。`nextTick(fn)` 就是把 fn 挂到同一轮 flush 之后，所以能拿到更新后的 DOM。多次改数据只 patch 一次。

**Q：for-in 为什么要 ITERATE_KEY？**

`for...in` 没有具体 key，ownKeys 里用一个 Symbol 当依赖名。只有 ADD/DELETE 会改变可枚举 key 列表，改已有属性的值不该让 `for...in` 重跑。

**Q：shallowReactive / readonly 呢？**

`shallowReactive` 只代理第一层，嵌套对象原样返回。`readonly` 的 set/delete 直接警告，get 里不 track（没人能改，收集无意义），嵌套继续包成 readonly。

**Q：effect 嵌套怎么处理？**

组件套组件就是嵌套 effect。只用一个全局 `activeEffect` 会被内层覆盖，外层读到的属性会挂到内层上。源码用 parent 指针（笔记里是栈）：进 effect 指向自己，结束恢复父级。

**Q：targetMap 为什么用 WeakMap，而不是 Map？**

最外层的 key 是**原始对象**。`WeakMap` 对 key 是弱引用：业务代码不再拿这个对象时，GC 可以连同它在桶里的依赖表一起回收。`Map` 是强引用，即使对象已经没人用，桶还握着它，依赖集合里的 effect 也释放不掉，会泄漏。另外 `WeakMap` 的 key 只能是对象，正好和「只代理对象」一致。内层用 `Map` 是因为 key 是字符串 / Symbol，不能当 WeakMap 的 key。

**Q：track 为什么要判断 activeEffect？普通函数读响应式数据会收集吗？**

`activeEffect` 表示**当前正在执行的副作用**，track 必须知道「这次读取是谁在读」，才能把依赖挂到正确的 effect 上。没有它就不知道数据变了该通知谁。

普通函数读响应式数据：**不会收集**。Proxy get 还是会进，但 `track` 里 `if (!activeEffect)` 直接 return。只有 `effect.run()` / 渲染函数 / computed getter / watch getter 执行期间才会设 `activeEffect`（3.5 是 `activeSub`）。这是有意的：随便 `console.log(state.count)` 不该注册更新。数组 `push` 期间还会 `pauseTracking()`，即使有 activeEffect 也不收集，避免读写 `length` 套娃。

**Q：Proxy 为什么要搭配 Reflect？Reflect 干什么？**

Proxy 只负责拦截，真正读/写交给 `Reflect`，并传入 `receiver`（一般是代理对象）。两件关键事：

1. **返回值语义对齐**：`set` / `deleteProperty` 必须返回 boolean。`Reflect.set` 返回成功与否；直接 `target[key] = val` 返回的是值，和陷阱约定对不上。
2. **receiver 修正 this（高频）**：属性如果是 getter，`target[key]` 里 `this` 指向**原始对象**，内部再读其他属性不会走 Proxy，**漏收集**。`Reflect.get(target, key, receiver)` 让 getter 里的 `this` 指向 **proxy**，后续访问继续被拦截、继续 track。

```js
const obj = {
  foo: 1,
  get bar() { return this.foo } // this 必须是 proxy，foo 才能被收集
}
```

**Q：懒代理下，深层对象不访问会被代理吗？**

**不会。** `reactive(obj)` 只给根对象包一层 Proxy。嵌套对象是在 **get 陷阱里** 发现值是对象，再 `reactive(res)` 返回。从没读过的深层属性一直是普通对象，不会创建 Proxy，这也是相对 Vue2 初始化递归 walk 的性能点。一旦访问过，结果会进 `reactiveMap`，同一对象不会重复代理。

**Q：ref 和 reactive 怎么取舍？**

- **reactive**：本来就是对象 / 数组，想直接 `state.x` 不用 `.value`。
- **ref**：原始值（Proxy 代理不了）；需要**整体替换**（`count.value = 1` / `list.value = []`）；组合式函数对外返回（调用方解构也不容易把根弄丢）。`ref` 包对象时，内部仍会 `toReactive`，深层一样是代理。

习惯上 setup 里统一用 ref 也可以，少记一套规则。解构 reactive 要 `toRefs`；ref 在模板顶层会自动脱 `.value`。

**Q：解构 reactive、整个对象被换掉，为什么丢响应？**

丢的不是「数据变了」，是**之后的读写不再经过那层 Proxy**。

1. **解构**：`const { foo } = state`。`foo` 若是原始值，拷出来就是普通 number/string，再改 `foo` 和代理无关，也不会 trigger。嵌套对象倒还可能是已经代理过的引用，但根上的绑定已经断了。解决：`toRefs(state)` / `toRef(state, 'foo')`，读写仍打到源对象。
2. **整对象替换**：`let state = reactive({ count: 0 }); state = { count: 1 }`。左边变量改指向一个**新的普通对象**，原来的 proxy 被丢掉。渲染 effect 订阅的是旧 proxy，新对象上的赋值不会 trigger。解决：不要换掉代理本身，改属性；或用 `ref`，`state.value = { count: 1 }` 仍走 `triggerRef`。

展开 `{ ...state }` 同理，得到的是当前值的快照普通对象。

**Q：批量更新为什么用微任务，不用宏任务？**

要在**当前同步代码跑完之后、浏览器绘制之前**把同一轮改动合并成一次 DOM 更新。

微任务（`Promise.then`）正好插在：同步调用栈结束 → **flush 微任务** → 绘制。所以一次点击里改十次数据，只 patch 一次，用户只看到最终画面。`nextTick` 也挂在这轮 flush 后面，回调里能读到更新后的 DOM，通常还赶在绘制前。

若用 `setTimeout`（宏任务）：顺序是同步代码 → 微任务 → **先绘制旧 DOM** → 才轮到宏任务去 patch → 再绘制。会多一帧过期画面，`nextTick` 语义也晚了，和用户代码里的 `Promise.then` 顺序还可能乱。Vue3 的 `queueFlush` 就是 `resolvedPromise.then(flushJobs)`。
