# Vue 生命周期的整体理解（钩子函数、执行顺序）和实现原理

## 简答

组件生命周期，就是组件实例从创建、挂载、更新到销毁的完整流程，框架在关键节点抛出钩子函数供开发者执行自定义逻辑。
Vue2 Options 钩子：beforeCreate /created/beforeMount /mounted/beforeUpdate /updated/beforeDestroy /destroyed
Vue3 Options：把销毁钩子改为 beforeUnmount /unmounted；Composition API 使用`onBeforeMount、onMounted`等 onXxx 系列钩子。
额外钩子：keep-alive 缓存组件专属 activated /deactivated，全局捕获异常 errorCaptured。

## 一、各阶段钩子作用与可用资源

1. 创建阶段

- beforeCreate：实例刚初始化，data、props、computed 还未处理；Vue3 setup**在 beforeCreate 之前执行**，setup 可拿到 props，但拿不到 this、data。
- created：响应式数据、computed、watch 已经初始化完成；**没有真实 DOM，$el 不存在**，适合发起不需要 DOM 的接口请求。

2. 挂载阶段

- beforeMount：render 函数执行生成 VNode，即将执行 patch 挂载 DOM，此时 DOM 还未渲染。
- mounted：真实 DOM 已经挂载完成，可以访问 $el、ref、操作 DOM、引入第三方 DOM 库。

3. 更新阶段（数据变更触发）

- beforeUpdate：新 VNode 已经生成，即将 patch，此时 DOM 还是旧的。
- updated：DOM 更新完毕，注意不要在这里修改状态，容易引发无限循环更新。

4. 销毁阶段

- beforeUnmount：实例开始卸载，DOM 还在；适合清理定时器、事件监听、取消请求等副作用。
- unmounted：组件 DOM 已经移除，实例销毁，不要再操作组件 DOM。

## 二、父子组件执行顺序

挂载：父 beforeCreate → 父 created → 父 beforeMount → 子全套创建挂载钩子 → 父 mounted
更新：父 beforeUpdate → 子 beforeUpdate → 子 updated → 父 updated
销毁：父 beforeUnmount → 子全套销毁钩子 → 父 unmounted
一句话记忆：**挂载先父启、子先完成；销毁父先启、子先销毁**

## 三、实现原理

Options API：组件初始化时，把 options 里声明的钩子收集到实例的`$options`中；框架在组件每个阶段，判断组件状态，遍历执行对应钩子数组。
Composition API：`onMounted`这类生命周期函数，会把回调注册到当前活动组件实例对应的回调队列；等到框架运行到对应生命周期节点，取出队列回调依次执行。所以 onXxx 必须写在 setup 中，依赖当前组件实例。

一句话总结：created 有数据无 DOM，mounted 才有 DOM；更新、销毁钩子成对触发；挂载销毁父子有固定嵌套顺序；底层是框架在组件不同阶段，调用预先注册好的回调函数。

## 四个关键词（卡住就说这四个）

1. **有没有 DOM**：created 没有，mounted 才有。
2. **父子顺序**：挂载父→子→子完成→父完成；销毁相反，父先 before，子先没完父不能完。
3. **setup 时机**：Vue3 里 `setup` 在 Options 的 `beforeCreate` **之前**。
4. **失活 ≠ 卸载**：keep-alive 走 `deactivated / activated`，不走 `unmounted`。

---

## 钩子清单（Vue3 为主，括号里 Vue2）

| 阶段 | 钩子 | 此时状态 |
| --- | --- | --- |
| 创建 | `setup` → `beforeCreate` → `created` | 数据、注入已就绪；无 DOM |
| 挂载 | `beforeMount` → `mounted` | 首次 render + patch 完成 |
| 更新 | `beforeUpdate` → `updated` | 仅模板用到的数据变了才会走 |
| 销毁 | `beforeUnmount`（`beforeDestroy`）→ `unmounted`（`destroyed`） | 解绑、清副作用 |
| 缓存 | `activated` / `deactivated` | keep-alive 激活 / 失活 |
| 错误 | `errorCaptured` / `onErrorCaptured` | 捕获子孙错误 |

Composition：`onMounted`、`onUpdated`、`onBeforeUnmount` 等，只能在 `setup` 同步执行时注册。

**不能用箭头函数写 Options 钩子**，否则没有组件 `this`。

## 父子执行顺序（高频，背口诀）

假设 Parent 里渲染 Child。

**挂载**

```
父 beforeCreate → 父 created → 父 beforeMount
  → 子 beforeCreate → 子 created → 子 beforeMount → 子 mounted
→ 父 mounted
```

口诀：**创建/挂载都是父先开始，子先 mounted，父后 mounted。** 因为父的模板里有子组件，要等子挂完，父才算挂完。

**更新**（父数据变导致子也更新）

```
父 beforeUpdate → 子 beforeUpdate → 子 updated → 父 updated
```

**销毁**

```
父 beforeUnmount → 子 beforeUnmount → 子 unmounted → 父 unmounted
```

口诀：**销毁父先发号，子先拆完，父最后拆完。**

---

## created vs mounted 请求数据

两边都能发请求。差别在「你需不需要 DOM」。

- **只拉数据填页面**：`created` / `setup` 里就可以。更早发出，有机会和后续挂载并行。SSR 时服务端会跑 `setup`/`created`，不会跑 `mounted`，所以同构请求放创建阶段。
- **依赖真实 DOM**（算高度、初始化地图、图表）：必须 `mounted`。`created` 里没有 `$el`。
- 注意：同步子组件在父 `mounted` 之前已经 `mounted` 完；不保证异步子组件已解析，也不保证图片等资源加载完。

## 可能被追问

**Q：DOM 渲染完成在哪个钩子之后？**

首次在 `mounted` 之后；数据更新后在 `updated` 或 `nextTick` 之后。`created` 不行。

**Q：`updated` 里改数据？**

会再触发更新，可能死循环。要改，必须有终止条件，或改到 `nextTick` 且判断新旧值。

**Q：`beforeCreate` 里为什么拿不到 data？**

Vue2 的 `initState` 在 `beforeCreate` **之后**。Vue3 的 `setup` 已经能用 props，但 Options 的 `this.xxx` 同样要等到 `created`。

**Q：keep-alive 组件切走会 destroyed 吗？**

不会。只 `deactivated`。再次进入 `activated`，不会再 `mounted`。被 LRU 淘汰或 KeepAlive 自己卸载，才会 `unmounted`。

**Q：setup 和 beforeCreate 谁先执行？setup 里为什么不能使用 this？**

**setup 先。** Vue3 创建组件：处理 props/slots → 调 `setup()` → 再 `applyOptions` 里才 `beforeCreate` / `created`。

setup 执行时 Options 那套实例代理还没建完：`data`、`methods`、`computed` 都还没挂到 `this` 上。框架直接把 `this` 设成 `undefined`（严格模式），逼你用 `props`、`ctx.emit`、返回值，避免一半 Composition、一半 `this.xxx` 时序错乱。`<script setup>` 同理，编译成的 setup 里也没有可用的 Options `this`。

**Q：keep-alive 包裹组件，生命周期执行顺序是什么？**

KeepAlive 是抽象组件，自己不渲染 DOM。被缓存的是内侧那一个子组件。

**首次进入 A：** 按正常挂载走完，多一个激活。

```
父 beforeMount
  → A beforeCreate → created → beforeMount → mounted → activated
→ 父 mounted
```

**从 A 切到 B：** A **不卸载**。

```
A beforeUpdate?（父更新）→ A deactivated
→ B 若第一次：beforeCreate … mounted → activated
→ B 若已缓存：只 activated（DOM 从隐藏容器搬回来）
```

**再切回 A：** 只有 `A.activated`，没有第二次 `mounted`。

**A 被 max LRU 丢掉 / KeepAlive 自己卸：** `deactivated` → `unmounted`，这才是真销毁。

**Q：mounted 一定能保证所有子组件 DOM 都挂载完成吗？**

**同步子组件：能。** 父的 `mounted` 在子树 `patch` 全部结束之后才调，所以父 `mounted` 里 `ref` 到的同步子组件，DOM 和子 `mounted` 都已经过了。

保证不了的：

- `defineAsyncComponent` 还在 loading，占位还在，真正子组件可能还没来
- Teleport 的 DOM 不在当前容器里，但一般已经挂到目标节点
- 图片、iframe、字体加载完
- `v-if` 当时为 false 的那棵子树

要等异步组件：对组件 ref `await` 或看 `onMounted` 写在异步组件自己里面。

**Q：在 updated 钩子修改响应式数据会发生什么？**

`updated` 时 DOM 已经是新的。再改模板用到的数据 → 再 `queueJob` → 再 `beforeUpdate` / `updated`。没有收敛条件就是死循环。开发环境 Vue 会警告。必须改时：比新旧值、或改的字段不进模板，或只在特定条件下改一次。

**Q：同一个 onMounted 可以注册多个回调吗？原理是什么？**

可以。`onMounted(fn)` 本质是 `injectHook('m', fn)`：往当前实例的 `m` 数组 `push` 一个包装后的 hook。挂载结束 `invokeArrayFns(instance.m)` 按注册顺序全跑。

所以一个组件里多次 `onMounted`、多个 `useXxx()` 各自 `onMounted`，都会生效，互不覆盖。必须在 `setup` **同步**阶段注册：异步回调里再 `onMounted` 拿不到当前实例，会警告。 Options 的 `mounted()` 只能写一个函数，要多段逻辑只能自己在里面拆；Composition 靠数组叠。
