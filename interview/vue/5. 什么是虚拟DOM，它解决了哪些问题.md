# 什么是虚拟DOM，它解决了哪些问题

## 简答

虚拟 DOM 是用普通 JS 对象（VNode）描述 UI 结构，是真实 DOM 的轻量抽象。VNode 记录节点类型、属性、子节点；挂载完成后会保存对应真实 DOM 引用`el`。列表渲染中的`key`是同级节点唯一标识，diff 时用来识别节点，实现 DOM 复用。

虚拟 DOM 主要解决 3 个核心问题：

1. **支持声明式编程**
开发者只描述 UI 目标状态，不用手动调用`createElement`这类命令式 DOM API。框架渲染器自动把 VNode 映射成真实 DOM，DOM 操作的复杂度交给框架处理。
2. **实现高效更新，减少 DOM 操作**
数据变化触发 render 函数生成新 VNode 树，新旧 VNode 执行 diff 算法。diff 遵循**同层对比，不跨层级移动 DOM**，只找出变化节点，最小化真实 DOM 增删改。配合异步更新队列，多次数据变更合并为一次 DOM 渲染，减少回流重绘。

> 
> 注意：Vue2 diff 也是同层比较，缺陷是同层所有节点都参与 diff，静态节点也要遍历；Vue3 通过编译期优化：patchFlag 标记动态节点、静态提升缓存静态节点、block tree，只对动态节点做 diff，大幅降低比对开销。

3. **提供跨平台渲染能力**
VNode 只是平台无关的 UI 描述对象。渲染器把 DOM 操作抽象成`nodeOps`接口，不同平台替换底层实现：浏览器操作 DOM、小程序渲染原生组件、客户端渲染原生视图，实现一套 UI 描述多端渲染。

虚拟 DOM 不是银弹：生成 VNode 和 diff 计算本身存在 CPU、内存开销，**不一定比手动精准操作原生 DOM 更快**，它的价值是提升开发效率，在复杂视图场景自动优化 DOM 操作。

一句话总结：虚拟 DOM 是框架的中间 UI 描述，支撑声明式开发，通过 diff 最小化 DOM 操作，同时实现跨端渲染。

---

## 四个关键词（卡住就说这四个）

1. **JS 对象树**：轻量描述，不是浏览器里那个带几百属性的 Element。
2. **render → vnode → patch**：数据变了重跑 render，不是直接改 DOM。
3. **同层 diff + key 复用**：不跨层比；key 相同才认为是同一个节点。
4. **跨平台抽象**：最大架构收益；性能是「少瞎改 DOM」，不是 magically 更快。

## 一个 vnode 长什么样

```js
{
  type: 'div',          // 或组件、Text、Fragment、Comment
  props: { id: 'app', onClick },
  children: [ /* 子 vnode 或文本 */ ],
  key: 'a',
  el: HTMLDivElement    // 挂载后才有
}
```

Vue3 还会带 `shapeFlag`（节点种类）、`patchFlag`（这块动态在哪）。真实 DOM 一个空 `div` 就有几十上百个属性，vnode 只留渲染用得到的字段，创建和对比都在 JS 里完成。

---

## 它在更新链路里干什么

```
数据变 → trigger 渲染 effect
      → render() 生成 新 vnode 树
      → patch(旧树, 新树)
           ├ type 不同：卸旧挂新
           ├ type 相同：改 props，再比 children
           └ 子节点是数组：走 Diff（key / 双端 / 快速 Diff）
      → 只对真实 DOM 做 insert / remove / 改文本
```

无旧树就是 mount；新树是 `null` 就是卸载。

**为什么有了响应式还要 diff？**  
`count++` 只告诉你「这个组件的 effect 要跑」。模板里可能同时绑了文本、class、列表。Vue 不会给每个插值单独挂一个 DOM Watcher（Vue1 接近那样，组件一大就爆炸）。现在粒度是组件：整棵子树重新描述一遍，由 diff 决定 DOM 动哪。

---

## Diff 和虚拟 DOM 的关系（笔记里的三条线）

Diff 不是虚拟 DOM 的全部，只是 **两组子节点都是数组时** 怎么复用 DOM。

| | 做法 | 谁在用 |
|---|---|---|
| 无 key | 按下标就地 `patch`，多的卸、少的挂 | 静态短列表 |
| 简单 Diff | 按 key 找节点，`lastIndex` 判断是否移动 | 教学；头插会乱移 |
| 双端 Diff | 旧头/旧尾/新头/新尾四个指针 | **Vue2** |
| 快速 Diff | 先对齐前后缀，中间乱序用**最长递增子序列**决定谁不用挪 | **Vue3** |

共同前提：**只比同一层，不跨层**。`div` 不会拿去和里面的 `span` 比。`key` 表示身份，不能用 index 当列表 key——插入删除后下标全错，会错误复用 DOM（输入框串值）。

Vue3 额外靠编译：静态节点提升、动态节点 `patchFlag`，很多时候不必全树走一遍 Diff。

---

## 解决了什么 / 没解决什么

**解决了**

- 命令式 DOM 难维护：状态一变要自己想清楚改哪、删哪。
- 无脑 `innerHTML` 整页重绘：diff 后只动脏节点。
- 和平台绑死：同一套 vnode + `createRenderer(nodeOps)`。

**没保证**

- **一定比直接操作 DOM 快。** 建树 + diff 本身有 JS 成本。改一个文本，`el.textContent = x` 往往更快。虚拟 DOM 赢在更新复杂、要复用、要跨平台、要和声明式模型配合。
- **精确到属性级的数据追踪。** 那是响应式的事；vnode 管的是「这棵 UI 树怎么落到节点上」。

## 可能被追问

**Q：虚拟 DOM 一定比真实 DOM 快吗？**

不一定。快的是「少做无效 DOM / 少重排」，不是 JS 对象天生比 DOM 快。小更新、可手写精确 DOM 时，vdom 是多余层。列表大变动、组件树深、还要跨平台时，这层才划算。Vue3 用编译优化把这层成本往下压。

**Q：既然能侦测哪个数据变了，为什么不直接改对应 DOM？**

侦测粒度是组件，不是 DOM 节点。一个数据可能影响模板多处；列表还会移位。每次把新 UI 描述成树再 diff，比给每个插值建 Watcher 更稳，也方便 `v-if` / `v-for` 结构变化。Vue1 细粒度绑定在大组件上扛不住，才改成「组件级更新 + vdom」。

**Q：key 的本质是什么？**

diff 用来判断「是同一个 vnode 还是两个不同节点」。相同 key + 相同 type 才复用 `el`，只 patch 属性/子节点。没有 key 只能按下标对齐，换位就会拆了重建或把状态贴错节点。

**Q：Vue2 / Vue3 Diff 差在哪？**

都是同层比。Vue2 双端四指针，头尾插入友好，长列表乱序移动偏多。Vue3 快速 Diff：前后相同先跳过，中间用最长递增子序列，尽量少 `insertBefore`；再叠加 `patchFlag`，静态部分根本不进 Diff。

**Q：虚拟 DOM 最大的好处是性能吗？**

面试里更稳的说法：**最大好处是渲染过程抽象，才能跨平台、声明式；diff 是这层抽象上顺带把 DOM 改动收小。** 尤雨溪也强调过跨平台，而不是「vdom 银弹」。

**Q：diff 为什么不跨层级比较？跨层移动 DOM 会怎样？**

完整树编辑距离是接近 **O(n³)** 的，组件一深就跑不动。Vue/React 用启发式：**只和同一父节点下的兄弟比**，复杂度压到约 O(n)。父子关系变了，不认为是「同一个节点挪了层」，而是旧位置 **unmount**、新位置 **mount**。

所以跨层「移动」实际是拆掉再建：真实 DOM 不复用（或至少组件实例不复用），本地状态、输入框内容、子组件生命周期都会走销毁/创建。这是用正确性换性能的取舍。若业务真要把一块 DOM 挪到另一棵子树，框架不会帮你保留身份，该用 `Teleport` 这类专门 API。

**Q：列表 key 用 index 有什么问题？什么时候可以？**

index 随位置变，不代表「这一项数据」。中间插入、删除、排序后，后面项的 index 全错，diff 会把 **A 的 DOM 复用给 B**：输入框串值、组件内部 state 贴错人。

可以安全用的情况（官方也认）：列表是静态的，不会插入/删除/重排；项上没有局部状态（没输入框、没带状态的子组件）。纯展示、每次都整表替换也可以。只要项会移位或自己有状态，就用业务 id。

**Q：虚拟 DOM 一定比原生 DOM 快吗？什么时候反而亏？**

不一定。vdom 多了「每次 render 建对象树 + diff」的 CPU 和 GC。典型更慢的场景：

- 只改一个文本 / 一个 class，手写 `el.textContent` 更短。
- 首屏：先造一整棵 vnode 再造 DOM，比直接 `innerHTML` / 模板克隆多一截。
- 超大列表每次更新都全量 render，vnode 分配会挤爆（要虚拟列表或 `v-once` / 编译优化）。

它赢在你说不清该动哪、列表要复用、还要声明式和跨平台。Vue3 的静态提升、`patchFlag` 就是在砍这笔固定税。

**Q：VNode 和真实 DOM 有何区别？`el` 何时赋值？**

| | VNode | 真实 DOM |
|---|---|---|
| 是什么 | 普通对象 | 浏览器宿主对象 |
| 有无排版 | 无，改它不回流 | 改它可能回流重绘 |
| 字段 | type / props / children / key | tagName、style、事件、布局几何 |

`el` 是挂载结果，**创建 vnode 时是空的**：

- `mount`：`hostCreateElement` 之后立刻 `vnode.el = el`，子节点 insert 进这个 el。
- `patch` 且 type 相同：`n2.el = n1.el`，复用旧节点，不新建。
- 组件 vnode：`el` 等于子树根（`subTree.el`）；Fragment 没有单一根，取锚点相关节点。
- SSR hydration：对着已有 DOM 填 `el`，而不是 `createElement`。

卸载后引用还在旧 vnode 上，但节点已从文档拿掉。下次 render 是新 vnode，再走 mount 或从旧树接 `el`。
