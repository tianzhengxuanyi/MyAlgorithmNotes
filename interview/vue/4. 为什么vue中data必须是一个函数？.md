# 为什么vue中data必须是一个函数？

## 简答

组件是可复用的，当多个组件实例共用同一个 data 对象引用时，修改一个实例的数据，其他实例状态会跟着变化，造成状态污染。
所以组件的 data 必须是**工厂函数**，每次创建实例时调用，返回全新对象，保证每个实例数据相互隔离。
根实例`new Vue`只创建单个实例，不存在多实例共享问题，因此根实例 data 可以直接写对象。

Vue2 中定义组件时会走`Vue.extend`和`mergeOptions`合并组件配置。
如果组件 data 写的是对象字面量，这个对象会挂载到子类构造器的 options 上，所有实例共用这一个对象引用。
在组件实例初始化阶段，`initData`会做校验：**组件的 data 必须是函数，否则抛出警告**。之后执行`data.call(vm)`拿到返回的新对象，再做响应式劫持。
根实例不走组件复用的这套校验逻辑，允许直接传对象。

Vue3 OptionsAPI 的组件依旧强制 data 是函数，隔离多实例状态的设计思想不变，只是底层移除了 Vue.extend。
而 Composition API 的 setup，每次组件实例化都会执行一次 setup 函数，内部声明的 ref/reactive 天然属于当前实例，自带实例隔离，不需要再通过 data 函数来保证状态独立。

一句话总结：组件 data 要求是函数，本质是为了**每个组件实例拥有独立的数据对象，避免多实例状态互相污染**。
---

## 四个关键词（卡住就说这四个）

1. **组件多实例、选项单份**：构造函数上的 `data` 被所有实例共用。
2. **对象是引用**：同一块内存，互相污染。
3. **函数是工厂**：每次 `call` 返回新对象。
4. **根实例可以是对象**：只有一个，不存在串数据。

---

## 为什么会串（用原型讲）

组件选项类似挂在构造函数上：

```js
function Comp() {}
Comp.prototype.data = { count: 0 }  // 所有实例同一对象

const a = new Comp()
const b = new Comp()
a.data.count++   // b.data.count 也变成 1
```

改成工厂：

```js
Comp.prototype.data = function () {
  return { count: 0 }
}
// 每个实例 this.data = this.data()，地址不同
```

Vue 组件复用（列表里一堆 `<Item>`、keep-alive 前后多个）就是这个模型。

## 源码对应

**Vue2 `initData`**（`src/core/instance/state.js`）：

```js
data = vm._data = typeof data === 'function'
  ? getData(data, vm)   // data.call(vm, vm)
  : data || {}
```

实例化时对象也能跑，真正卡组件的是选项合并。

**Vue2 `strats.data`**（`src/core/util/options.js`）：

```js
if (!vm) {
  // 定义组件 / extend / mixin 合并，还没有实例
  if (childVal && typeof childVal !== 'function') {
    warn('The "data" option should be a function that returns a per-instance value...')
    return parentVal
  }
}
```

`!vm` 表示在**构造函数层**合并选项。这里必须留下一个函数，后面每个实例再调。根实例 `new Vue` 合并时带着 `vm`，对象能过。

`getData` 用 `data.call(vm, vm)`：`this` 是实例，props 已经 init 完，所以 `data()` 里能读 `this.xxx`（prop）。

**Vue3** `applyOptions`：同样 `isFunction(dataOptions) ? dataOptions.call(publicThis, publicThis) : dataOptions`，再 `reactive(data)`。开发环境对象形式同样警告。Composition API 不走这条，但 `setup()` 每实例跑一次，效果一样。

mixin / 继承的 `data` 都是函数的话，会按策略 **mergeData**：每个实例分别调用父、子函数，再浅合并到一份新对象上，仍然不会跨实例共享。

---

## Vue2 vs Vue3

| | Vue2 | Vue3 |
|---|---|---|
| 根实例 | `data` 对象或函数 | 根也是组件，建议函数；对象会警告 |
| 子组件 | **必须函数** | Options API 必须函数 |
| Composition | 无 | `setup` 里 `ref`/`reactive`，天然按实例创建 |
| 合并校验 | `strats.data` 在 `!vm` 时校验 | `applyOptions` 开发环境警告 |

## 可能被追问

**Q：根实例为什么可以写成对象？**

整页只有一个 `new Vue` / 一个 `createApp` 根，不存在第二个实例去抢同一份 data。组件定义会被复用，才强制工厂函数。

**Q：写成对象会怎样？**

开发环境警告。生产环境 Vue2 组件定义那份对象可能被丢掉或直接共用（看合并结果）。一旦共用，所有该组件实例改的是同一块数据，列表里点一个全亮。

**Q：那我函数里 `return shared`，return 同一个外部对象呢？**

照样共享。框架只保证「每次调用函数」，不保证你 return 的是新引用。必须在函数体内字面量 / 新对象。

**Q：为什么不深拷贝对象，非要函数？**

拷贝处理不了函数、循环引用、需要按 props 算初始值的情况，也更贵。工厂函数让你自己决定初始值，还可以 `return { n: this.foo }` 用 props。浅拷贝还会让嵌套对象仍然共享。

**Q：`data()` 里能用 props 吗？**

能。初始化顺序是 props → methods → data → computed → watch。`data.call(vm)` 时 props 已经代理到实例上。注意不要和 prop 同名，源码会警告，prop 优先。

**Q：Vue3 只用 setup，还要 data 函数吗？**

不用。`setup` 每创建一个实例执行一次，里面的 `ref`/`reactive` 就是这份实例的状态。Options 的 `data()` 和它是同一思想：不要把状态放在模块顶层的普通对象上给所有实例共用。

**Q：组件 data 写成箭头函数会怎样？**

隔离还在：`() => ({ count: 0 })` 每次调用仍是新对象，**不会串数据**。坏在 **`this` 丢了**。源码是 `data.call(vm, vm)`，箭头函数忽略 `call` 的 this，`this.xxx` 拿不到实例，props 读不到，可能是 `undefined` 或外层作用域。

要用 props 别写箭头；或者用第二个参数：`data: (vm) => ({ n: vm.foo })`，源码把实例当作第一个实参传进来了。

**Q：`Vue.extend` 出多个子类实例，data 写对象会污染吗？**

分清对象挂在哪。

`Vue.extend({ data: { n: 0 } })` 合并时 **没有 vm**，`strats.data` 判定不是函数就警告并 **丢掉这份对象**（`return parentVal`）。后面 `new Sub()` 多次，构造器上根本没有这份 data，谈不上共用它。

会污染的是「同一引用被多次实例化用」：

```js
const shared = { n: 0 }
new Sub({ data: shared })
new Sub({ data: shared })  // 两个实例 initData 拿到同一对象
```

或绕过校验把对象挂到 `Sub.options.data` 上再多次 `new`。

对比：`new Vue({ data: { n: 0 } })` 能写对象，是因为这个字面量只属于**这一次** new 的 options，没有挂到 `Vue.options` 上给以后所有根实例共用。`extend` / `component` 的选项在构造器上，天生会被多次 `new`，所以必须函数。

**Q：setup 和 `data()` 隔离原理有何不同？**

**思想一样，都是「每实例调用一次工厂」。** 不一样的是状态放哪。

| | `data()` | `setup()` |
|---|---|---|
| 共享的是 | 构造器上那一个函数 | 构造器上那一个 setup |
| 每实例做的事 | `data.call(vm)` → 一个对象 → `observe`/`reactive` → 代理到 `this` | `setup(props, ctx)` → 函数体内 `ref`/`reactive`，可 return 或闭包 |
| 隔离失败 | return 了外部同一对象 | 把 `ref` 写在 **模块顶层**、setup 外面 |

`data` 必须 return 一个普通对象，键都挂实例上。`setup` 可以状态只留在闭包里不挂 `this`，还能返回方法、computed。Vue3 顺序是 setup 先于 `applyOptions`，所以 `data()` 能读到 setup return 的东西，setup 里读不到 `data()`。

**Q：为什么不在框架里自动克隆，非要用户写函数？**

自动深拷贝解决不了、也会帮倒忙：

1. `Date` / `Map` / 类实例 / 函数 / 循环引用，拷不干净或很贵。
2. 浅拷贝嵌套对象还是共享，问题只是换个层。
3. 初始值常常依赖 props：`return { n: this.foo }`，静态对象克隆不出来。
4. 有时就要共享（注入同一 store、单例）。函数里 `return shared` 是你的选择；偷偷克隆会改语义。
5. mixin 合并是「各调各的 data 函数再浅合并」，工厂模型天然适配；先克隆再合并更绕。

所以与其框架猜「这份对象怎么复制」，不如规定工厂函数：每次实例、由你产出那份初始状态。
