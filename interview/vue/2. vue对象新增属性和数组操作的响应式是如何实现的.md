# Vue 如何让对象新增属性具备响应式能力，如何检测数组变化？

## 简答

分为 Vue2 和 Vue3 两部分：

### Vue2（Object.defineProperty）

1. 对象新增属性
初始化时只会对已存在的 key 添加 getter/setter。后续新增的属性没有被劫持，无法触发视图更新。
解决方案：`this.$set(obj, key, value)`。原理：调用`defineReactive`把新 key 转为响应式，手动触发 Watcher 更新。注意：**不能给根 data 对象新增属性**。
2. 数组变化检测
Vue2 没有对数组下标和 length 做劫持，因为性能开销太大。采用原型链覆盖，重写 7 个变异方法：`push、pop、shift、unshift、splice、sort、reverse`。
调用变异方法时，先执行原生逻辑，再对新增元素做响应式处理，手动派发更新。
直接 `arr[index] = val` 或修改`arr.length`不会更新视图。解决办法：`$set`（内部调用 splice）或者直接使用 splice。
非变异方法 map/filter 返回新数组，不会自动更新。

### Vue3（Proxy）

Proxy 的 set 拦截器可以区分新增属性和修改已有属性，所以对象新增 key 天然响应式，不再需要`$set`。
数组本质也是对象，Proxy 可以监听数组下标赋值、修改 length。
源码细节：执行 push 这类方法时，会同时读取并修改 length，为了避免读取 length 收集依赖，修改 length 触发自身 effect 造成死循环，内部使用`pauseTracking`临时暂停依赖收集。
当数组 length 缩小，超出长度的索引相当于被删除，触发 deleteProperty，自动派发对应 effect 更新。根因都是拦截粒度不同：Vue2 拦的是**已经存在的属性**，Vue3 拦的是**对整个对象的操作**。

**Vue2** 用 `Object.defineProperty`，初始化时 `walk` 已有 key，事后 `obj.x = 1` 没有 setter，必须 `this.$set(obj, 'x', 1)`：内部 `defineReactive` 给新 key 装 getter/setter，再 `ob.dep.notify()`。数组**不会**给每个下标装 defineProperty（性能），`arr[i] = v`、改 `length` 听不到。做法是把数组 `__proto__` 换成改写过的原型，拦截 7 个变异方法 `push/pop/shift/unshift/splice/sort/reverse`：先调原生，新元素 `observeArray`，再 `ob.dep.notify()`。给下标赋值用 `$set` / `splice`。

**Vue3** 用 Proxy，set 能区分已有 key（SET）和没有的 key（ADD），新增、删除、`for...in`（`ITERATE_KEY`）都能 trigger，**不需要 `$set`**。数组也是对象：改下标、改 `length` 都进 set。`length` 截断时要把被删下标上的 effect 一起通知。`push` 这类方法内部会读/写 `length`，容易和当前 effect 套娃，源码对变异方法 `pauseTracking()`，不是因为 Proxy 听不到 push。

一句话：**Vue2 补丁（$set + 7 方法）；Vue3 Proxy 原生就能拦新增和下标。**

---

## 四个关键词（卡住就说这四个）

1. **defineProperty 只劫持已有 key** → 新增要 `$set`。
2. **Vue2 数组改原型**：7 个变异方法 + `observeArray`，下标赋值不行。
3. **Proxy set 分 ADD / SET**：新属性、数组扩容都能 trigger。
4. **Vue3 仍改写 push**：`pauseTracking` 防 `length` 死循环，不是听不到。

---

## Vue2：对象新增

初始化 `new Observer` → 普通对象走 `walk` → `Object.keys` → `defineReactive`。只有当时那些 key 有 getter/setter。

```js
obj.newKey = 1        // 不更新，没有 setter
this.$set(obj, 'newKey', 1)
delete obj.newKey     // 不更新，要用 $delete
```

`$set(target, key, val)` 源码逻辑：

1. 目标是数组且 key 是合法下标 → 扩 `length`，走 `splice`（走得到改写过的变异方法）。
2. key 已经在对象上 → 直接赋值，本来就有 setter。
3. 对象身上有 `__ob__` → `defineReactive(obj, key, val)`，再 `ob.dep.notify()`。

必须 `notify` 对象自己的 `dep`：旧 Watcher 只订阅过已有 key，新 key 还没被 track 过，不通知整对象，视图不会重跑，新属性也就永远收集不到。

---

## Vue2：数组

数组和对象分叉：不 `walk` 下标，只做两件事。

1. **改原型**：`value.__proto__ = arrayMethods`（`Object.create(Array.prototype)` 上挂 7 个方法）。
2. **observeArray**：递归 observe 每个**元素**（元素是对象才变响应式），不是给 `0/1/2` 装 defineProperty。

所以：

| 操作 | 能不能更新 |
|------|------------|
| `push/pop/shift/unshift/splice/sort/reverse` | 能，改写方法里 `ob.dep.notify()` |
| `arr[0] = 1` | 不能 |
| `arr.length = 0` | 不能 |
| `arr[arr.length] = 1` | 不能，等同新增下标 |

改写下标：`this.$set(arr, i, v)` 或 `arr.splice(i, 1, v)`。

渲染时读 `this.list` 会 `childOb.dep.depend()`，变异方法通知的就是这个 **数组自己的 dep**，所以不靠下标 getter 也能更新。

变异方法里若是 `push/unshift/splice`，对新插入的项再 `observeArray`，否则推进去的对象不是响应式。

## Vue3：对象新增

Proxy **set**：

```js
const hadKey = Object.prototype.hasOwnProperty.call(target, key)
Reflect.set(...)
if (!hadKey) trigger(target, key, 'ADD')
else if (值变了) trigger(target, key, 'SET')
```

ADD 还会 trigger `ITERATE_KEY`，`for...in` / `Object.keys` 才会更新。`deleteProperty` 同理。直接 `obj.x = 1`、`delete obj.x` 即可，没有 `$set`。

---

## Vue3：数组

数组当对象代理，下标就是 key，`length` 是特殊 key。

- `arr[i] = v`：`i < length` 是 SET，否则是 ADD（扩容），ADD 还要通知依赖 `length` 的 effect。
- `arr.length = n`：n 变小则把所有 `index >= n` 的依赖也 trigger 一遍（截断）。
- `for...in` 数组时，ownKeys 收集的是 **`length`**，不是对象那种 `ITERATE_KEY`。

`push/pop/shift/unshift/splice` 仍然包了一层 **arrayInstrumentations**：内部先读 `length` 再写下标和 `length`。若当前正在跑渲染 effect，会 track `length` 又 trigger `length`，同一 effect 递归。所以执行原生方法前 `pauseTracking()`，跑完再恢复。真正的更新还是后面 Proxy set 触发的。

`includes/indexOf/lastIndexOf` 也会被改写：先按代理找，找不到再 `toRaw` 找一遍，避免「存的是 raw、查的是 proxy」误判。

---

## 对比（必背）

| | Vue2 | Vue3 |
|---|---|---|
| 对象加属性 | 不行，`$set` = defineReactive + notify | Proxy set → ADD，直接赋值 |
| 对象删属性 | `$delete` | `deleteProperty` |
| 数组下标赋值 | 不行 | set 拦截下标 |
| 改 length | 不行 | set 拦截；缩短要通知被删下标 |
| 变异方法 | 必须改写 7 个才能 notify | Proxy 能拦；仍改写是为了 pauseTracking |
| 新元素是对象 | 变异方法里 `observeArray` | get 到对象再懒代理 |

## 可能被追问

**Q：Vue2 为什么不给数组下标 defineProperty？**

数组会频繁改下标和 length，逐个劫持太贵；而且 `push` 等会一次性动很多下标。改 7 个方法 + 数组级 `ob.dep` 更划算。副作用就是下标赋值、改 length 成了盲区。

**Q：`$set` 一个已经存在的属性呢？**

走直接赋值。那个 key 初始化时已经有 setter，再 defineReactive 没意义。

**Q：Vue3 还要 `Vue.set` 吗？**

不要。兼容写法里就算调用，也只是 `target[key] = val`。新增属性 Proxy 已经能拦。

**Q：`arr.push` 在 Vue3 为什么还可能死循环？**

渲染 effect 里如果读了数组，再 `push`：方法内部读 `length` → track 当前 effect，写 `length` → trigger 又跑当前 effect。`pauseTracking` 让这段读写不收集。trigger 侧还会跳过 `effect === activeEffect`。

**Q：只改数组里某个对象的字段，Vue2 能更新吗？**

能。`observeArray` 把元素对象 walk 过了，改已有字段走的是对象的 setter，跟下标盲区不是一回事。盲区是「换掉这个元素 / 改下标 / 改 length」。


**Q：Vue2 `$set` 为什么不能给根 data 添加属性？**

源码里两道闸：`target._isVue`（不能往实例上加）和 `ob.vmCount`（根 `$data` observe 时会 `vmCount++`）。根 data 的 key 在 `initData` 时被 **proxy 到 vm 上**，模板里 `{{ foo }}`、`this.foo` 走的都是这层代理。运行时再往根上加 key，就算 `defineReactive` 了，**也不会补一次 proxy**，`this.newKey` 仍然没有，模板读不到，和 `$data.newKey` 两套入口不一致。所以直接警告并 return。

嵌套对象 `vmCount === 0`，没有往实例上挂属性这一步，`$set(this.user, 'age', 18)` 可以。正确做法：根上的字段一开始就在 `data()` 里声明；动态字段放嵌套对象里再 `$set`。

**Q：Vue2 数组变异方法和非变异方法有什么区别？**

| | 变异方法 | 非变异方法 |
|---|---|---|
| 例子 | `push/pop/shift/unshift/splice/sort/reverse` | `map/filter/concat/slice` |
| 原数组 | **改原数组** | **不改**，返回新数组 |
| Vue2 | 改写了原型，执行后 `observeArray` + `ob.dep.notify()` | **没改写**，调用本身不 notify |
| 视图 | 直接更新 | 要把返回值赋回去：`this.list = this.list.filter(...)`，走的是 `list` 这个属性的 setter |

改下标、改 `length` 两派都不是，所以也不更新。非变异方法不是“失效”，是根本没改你绑定的那份数组。

**Q：Vue3 把 reactive 对象整个换掉为什么丢响应式？**

丢的是 **变量上的那层 Proxy**，不是“新对象没法变响应式”。

```js
let state = reactive({ count: 0 })
state = { count: 1 }   // 变量指向普通对象，旧 proxy 被丢掉
```

渲染 effect 订阅的是旧 proxy。新对象没经过 `reactive()`，赋值也不会 trigger。`const` 对象上改字段、或 `state.nested = { a: 2 }` 都还在 proxy 里，set 能拦，get 时懒代理，**不丢**。

要整体替换：用 `ref`，`state.value = { count: 1 }` 走 `triggerRef`；或挂在外层 reactive 的某个 key 上，只换那个 key。

**Q：`pauseTracking` / `enableTracking` 还有哪些场景？**

两者是一对 **shouldTrack 栈**：pause 压入 false，enable 压入 true，`resetTracking` 弹出恢复。不只数组能用。

1. **数组变异方法**（主场景）：`push` 等内部读/写 `length`，pause 防止当前渲染 effect 被 length 收集后又 trigger 自己。
2. **嵌套 effect**：外层 pause 着，内层 `effect.run()` 会 `shouldTrack = true`（enable），让内层照样收集自己的依赖，跑完再 reset 回外层的暂停态。
3. **内部读取**：访问 `__v_raw`、批量把新 props 写进 props 对象等，不希望这些读写算成业务依赖。
4. 自己做批量赋值、又不想被当前 effect 收集时也可以 pause；一般业务代码用不到。

`track` 里是 `if (!activeEffect || !shouldTrack) return`，pause 的就是后半截。

**Q：Vue3 里 `Object.assign` 给 reactive 对象新增属性，还响应式吗？**

**改的是同一个 proxy，就响应式。** `Object.assign(state, { b: 2 })` 对每个 key 走 `[[Set]]`，进 Proxy set：新 key 是 ADD，旧 key 是 SET，和 `state.b = 2` 一样。

下面这种 **不响应式**，因为得到的是新普通对象：

```js
const next = Object.assign({}, state, { b: 2 })
state = Object.assign({}, state, { b: 2 })
```

对比 Vue2：往原对象 `Object.assign` 加新 key 没有 setter，官方才让你 `this.obj = Object.assign({}, this.obj, { b: 2 })` 整份替换、走属性 setter。Vue3 不必绕这一下，原地 assign 即可。
