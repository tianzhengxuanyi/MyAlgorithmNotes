# Vue3 block tree、patchFlag 原理

## 简答

Vue2 组件更新要 **同层所有 vnode 都走一遍 Diff**，静态 `p` 也要比。Vue3 靠编译器告诉运行时「谁会变、变的是哪类」，更新时 **只碰动态节点**。

两件套：

1. **patchFlag**：创建动态 vnode 时打上位标记（`TEXT=1`、`CLASS=2`、`STYLE=4`、`PROPS=8`…）。`patchElement` 若 `patchFlag > 0`，只更新对应那一块，不必扫全部 props。动态 key 用 `FULL_PROPS`，退回完整比。
2. **Block tree**：`_openBlock()` 开始收集，带 flag 的节点推进当前 block 的 `dynamicChildren`。根是 `_createElementBlock` / `_createBlock`。更新走 `patchBlockChildren`：**按下标对齐新旧 dynamicChildren**，中间的静态兄弟直接跳过。`v-if` / `v-for` 自己再开嵌套 block（结构会变，不能摊进父 block）。

再配 **静态提升**（vnode 提到 `render` 外，flag 为 `HOISTED=-1`）和 **事件缓存**（`_cache[i]` 固定函数引用，避免每次都当动态 PROPS）。

一句话：**patchFlag 标明「怎么改」；block 标明「改哪些」；静态节点不进 Diff。**

---

## 四个关键词（卡住就说这四个）

1. **编译期信息**：模板结构已知，才能打标，纯 `h()` 吃不到这套。
2. **patchFlag 位运算**：一个节点可以同时 TEXT|CLASS。
3. **dynamicChildren**：block 上那条「只含动态节点」的扁平列表。
4. **结构一变就嵌套 block**：`v-if`/`v-for` 不能和父级按下标死对齐。

---

## 为什么要有它们

```html
<div>
  <p>静态</p>
  <p>{{ msg }}</p>
  <p>静态</p>
</div>
```

Vue2：三个 `p` 都进 Diff。Vue3：block 的 `dynamicChildren` 里往往只有中间那个文本节点，更新只 patch 它。`shapeFlag` 描述「这是什么」（元素/组件/子节点形态），`patchFlag` 描述「会变什么」，别混。

---

## patchFlag（源码 `PatchFlags`）

| 值 | 含义 | patch 时 |
|---|---|---|
| `TEXT = 1` | 动态文本 | 只改文本 |
| `CLASS = 2` | 动态 class | 只改 class |
| `STYLE = 4` | 动态 style | 只改 style |
| `PROPS = 8` | 动态属性（不含 class/style） | 只扫 `dynamicProps` 里那些 key |
| `FULL_PROPS = 16` | 属性名也是动态的 | 全量比 props |
| `STABLE_FRAGMENT = 64` | 子节点顺序稳定的 Fragment | 可按优化路径 |
| `KEYED_FRAGMENT = 128` | 带 key 的 Fragment（`v-for`） | 走快速 Diff |
| `UNKEYED_FRAGMENT = 256` | 无 key 的 Fragment | 按下标 patch |
| `DYNAMIC_SLOTS = 1024` | 动态插槽 | 插槽要当不稳定 |
| `HOISTED = -1` | 静态提升 | 不参与 diff |
| `BAIL = -2` | 放弃优化 | 回退全量 |

`patchElement` 里 `if (patchFlag > 0)` 按位与走快路径；`<= 0` 或手写渲染没有 flag，走和 Vue2 类似的完整更新。

```js
_createVNode("div", null, _toDisplayString(_ctx.msg), 1 /* TEXT */)
```

## Block tree

编译结果长这样：

```js
return (_openBlock(), _createElementBlock("div", null, [
  _hoisted_1,  // 静态，不进 dynamicChildren
  _createVNode("p", null, _toDisplayString(_ctx.msg), 1 /* TEXT */)
]))
```

- `_openBlock()`：栈顶换一个新的收集数组。
- 随后 `createVNode` 若带正数 flag，push 进这个数组。
- `_createElementBlock` 把收集结果挂到根 vnode 的 **`dynamicChildren`**，这个根就是一个 block。

更新：`n1.dynamicChildren` 与 `n2.dynamicChildren` **按下标一对一 patch**（模板没变，动态点数量和顺序稳定）。不必再遍历中间静态 vnode。

**嵌套：**

- `v-if`：每个分支一个 block，父级 `dynamicChildren` 只收这个分支根。切换分支等于换一块子树，不会把 true/false 两套内部动态节点错位对齐。
- `v-for`：生成 `KEYED_FRAGMENT` block，内部仍用快速 Diff，因为列表长度、顺序会变，不能按父 block 下标硬对齐。

所以 Block tree 是「动态块构成的树」，不是把整棵 vnode 树拍扁。

---

## 静态提升、事件缓存（常和 block 一起问）

**静态提升**：纯静态 vnode 放到 `render` 外面，每次渲染复用同一对象，打 `HOISTED`。少分配，Diff 也跳过。

**事件缓存**：`onClick: _cache[0] || (_cache[0] = (...args) => _ctx.onClick(...args))`。引用不变，按钮往往不再带 `PROPS` flag，父 block 甚至可以不把它当动态节点。

三者一起：**少创建、少收集、少比较。**

---

## 和列表 Diff 的分工

| 层 | 干什么 |
|---|---|
| Block / patchFlag | 组件内部：跳过静态、按 flag 改属性 |
| 快速 Diff | `v-for` 这种长度/顺序会变的一组节点 |

没有模板、全是 `h()` 时没有 block 信息，退回「同层全量 + 快速 Diff」。这是编译 + 运行时框架的收益，不是运行时自己猜出来的。

## 可能被追问

**Q：dynamicChildren 按下标对齐为什么安全？**

同一套模板、没有 `v-if`/`v-for` 打乱结构时，每次 render 动态节点出现的次序不变，新旧数组等长同位。结构不稳定的部分被编译成**子 block**，父级只拿子 block 根当一个动态子节点，不会把两套内部列表对在一起。

**Q：`shapeFlag` 和 `patchFlag` 区别？**

`shapeFlag`：节点类型、children 是文本还是数组，用来分发 mount/patch 分支。`patchFlag`：优化用，指出这次更新关心哪类变化。一个 vnode 两个字段都有。

**Q：什么时候拿不到优化？**

手写 `h`、`render` 函数没走编译器；属性名动态（`:[foo]`）→ `FULL_PROPS`；运行时 `BAIL`。这些走完整 props / 完整 children Diff。

**Q：和 Vapor 什么关系？**

Block + patchFlag 还是 **组件级 render + 缩小范围的 vdom**。Vapor 编译成细粒度 DOM 更新，不再造整棵 vnode。面试先把 Block 讲清，Vapor 当加分。
