# Vue3 block tree、patchFlag 原理

## 简答

Vue2 组件更新时，同层级所有 VNode（包括纯静态节点）都要参与 diff 比对。Vue3 在编译阶段做优化，让运行时只处理动态节点，核心就是 patchFlag 和 block tree，再搭配静态提升、事件缓存。

1. **patchFlag：标记单个节点内部哪些部分会变化**
编译模板时，给动态 VNode 打上二进制位标记：TEXT 文本、CLASS 类名、STYLE 样式、PROPS 属性等。
运行时 `patchElement` 判断 patchFlag > 0，只去比对标记对应的内容，不用遍历全部 props。
特殊标记 `FULL_PROPS`：当属性名是动态绑定`:[key]="xxx"`，编译期无法预知哪些属性变化，此时需要完整比对全部 props。
2. **Block Tree：收集当前模板内所有动态节点**
编译器遇到 `_openBlock()` 开启 block；只有 patchFlag>0 的动态节点，才会被收集进 `dynamicChildren` 数组；静态节点不会放入。
block 的 dynamicChildren 数组里节点顺序**和模板 DOM 顺序保持一致**。更新时执行`patchBlockChildren`，直接**按数组下标一一比对新旧 dynamicChildren**，不需要走复杂列表 diff 算法。
v-if、v-for 会创建嵌套 block：因为它们会改变节点数量与顺序，不能合并到父 block，嵌套 block 拥有独立的 dynamicChildren。

配套优化：

- **静态提升**：完全静态的 VNode，直接提升到 render 函数外部，只创建一次，不会每次渲染新建 VNode。注意 HOISTED 是 VNode 的标记，**不属于 patchFlag**。
- **事件缓存 `_cache`**：模板内事件函数缓存引用，避免每次 render 生成新函数，防止被判定为动态 props。

> 
> 注意：block tree 优化针对模板中顺序固定的动态节点；`v-for`循环渲染出来的列表，节点顺序不稳定，依旧走快速 Diff 算法。

一句话总结：patchFlag 控制单个节点**比对哪些属性**；block tree 收集当前块内所有动态节点，更新时只比对这一批动态节点，静态节点直接不参与 diff。

---

## 四个关键词（卡住就说这四个）

1. **编译期信息**：模板结构已知，才能打标，纯 `h()` 吃不到这套。
2. **patchFlag 位运算**：一个节点可以同时 TEXT|CLASS。
3. **dynamicChildren**：block 上那条「只含动态节点」的扁平列表。
4. **结构一变就嵌套 block**：`v-if`/`v-for` 不能和父级按下标死对齐。

## 为什么要有它们

```html
<div>
  <p>静态</p>
  <p>{{ msg }}</p>
  <p>静态</p>
</div>
```

Vue2：三个 `p` 都进 Diff。Vue3：block 的 `dynamicChildren` 里往往只有中间那个文本节点，更新只 patch 它。`shapeFlag` 描述「这是什么」（元素/组件/子节点形态），`patchFlag` 描述「会变什么」，别混。

---

## patchFlag（源码 `PatchFlags`）

| 值 | 含义 | patch 时 |
|---|---|---|
| `TEXT = 1` | 动态文本 | 只改文本 |
| `CLASS = 2` | 动态 class | 只改 class |
| `STYLE = 4` | 动态 style | 只改 style |
| `PROPS = 8` | 动态属性（不含 class/style） | 只扫 `dynamicProps` 里那些 key |
| `FULL_PROPS = 16` | 属性名也是动态的 | 全量比 props |
| `STABLE_FRAGMENT = 64` | 子节点顺序稳定的 Fragment | 可按优化路径 |
| `KEYED_FRAGMENT = 128` | 带 key 的 Fragment（`v-for`） | 走快速 Diff |
| `UNKEYED_FRAGMENT = 256` | 无 key 的 Fragment | 按下标 patch |
| `DYNAMIC_SLOTS = 1024` | 动态插槽 | 插槽要当不稳定 |
| `HOISTED = -1` | 静态提升 | 不参与 diff |
| `BAIL = -2` | 放弃优化 | 回退全量 |

`patchElement` 里 `if (patchFlag > 0)` 按位与走快路径；`<= 0` 或手写渲染没有 flag，走和 Vue2 类似的完整更新。

```js
_createVNode("div", null, _toDisplayString(_ctx.msg), 1 /* TEXT */)
```

## Block tree

编译结果长这样：

```js
return (_openBlock(), _createElementBlock("div", null, [
  _hoisted_1,  // 静态，不进 dynamicChildren
  _createVNode("p", null, _toDisplayString(_ctx.msg), 1 /* TEXT */)
]))
```

- `_openBlock()`：栈顶换一个新的收集数组。
- 随后 `createVNode` 若带正数 flag，push 进这个数组。
- `_createElementBlock` 把收集结果挂到根 vnode 的 **`dynamicChildren`**，这个根就是一个 block。

更新：`n1.dynamicChildren` 与 `n2.dynamicChildren` **按下标一对一 patch**（模板没变，动态点数量和顺序稳定）。不必再遍历中间静态 vnode。

**嵌套：**

- `v-if`：每个分支一个 block，父级 `dynamicChildren` 只收这个分支根。切换分支等于换一块子树，不会把 true/false 两套内部动态节点错位对齐。
- `v-for`：生成 `KEYED_FRAGMENT` block，内部仍用快速 Diff，因为列表长度、顺序会变，不能按父 block 下标硬对齐。

所以 Block tree 是「动态块构成的树」，不是把整棵 vnode 树拍扁。

---

## 静态提升、事件缓存（常和 block 一起问）

**静态提升**：纯静态 vnode 放到 `render` 外面，每次渲染复用同一对象，打 `HOISTED`。少分配，Diff 也跳过。

**事件缓存**：`onClick: _cache[0] || (_cache[0] = (...args) => _ctx.onClick(...args))`。引用不变，按钮往往不再带 `PROPS` flag，父 block 甚至可以不把它当动态节点。

三者一起：**少创建、少收集、少比较。**

---

## 和列表 Diff 的分工

| 层 | 干什么 |
|---|---|
| Block / patchFlag | 组件内部：跳过静态、按 flag 改属性 |
| 快速 Diff | `v-for` 这种长度/顺序会变的一组节点 |

没有模板、全是 `h()` 时没有 block 信息，退回「同层全量 + 快速 Diff」。这是编译 + 运行时框架的收益，不是运行时自己猜出来的。

## 可能被追问

**Q：dynamicChildren 按下标对齐为什么安全？**

同一套模板、没有 `v-if`/`v-for` 打乱结构时，每次 render 动态节点出现的次序不变，新旧数组等长同位。结构不稳定的部分被编译成**子 block**，父级只拿子 block 根当一个动态子节点，不会把两套内部列表对在一起。

**Q：`shapeFlag` 和 `patchFlag` 区别？**

`shapeFlag`：节点类型、children 是文本还是数组，用来分发 mount/patch 分支。`patchFlag`：优化用，指出这次更新关心哪类变化。一个 vnode 两个字段都有。

**Q：什么时候拿不到优化？**

手写 `h`、`render` 函数没走编译器；属性名动态（`:[foo]`）→ `FULL_PROPS`；运行时 `BAIL`。这些走完整 props / 完整 children Diff。

**Q：和 Vapor 什么关系？**

Block + patchFlag 还是 **组件级 render + 缩小范围的 vdom**。Vapor 编译成细粒度 DOM 更新，不再造整棵 vnode。面试先把 Block 讲清，Vapor 当加分。

**Q：block tree 为什么能按下标比对 dynamicChildren，不用 key Diff？**

因为编译器保证：**同一个 block 每次 render，动态节点的个数和出现次序都不变**（就是模板源码顺序）。静态节点不进数组，所以 `dynamicChildren[i]` 永远对应模板里第 i 个动态点，是元组不是可插删的列表。

会变结构的（`v-if` 换分支、`v-for` 变长）被做成**嵌套 block**，父级只收「这一个块根」，长度仍然稳定。需要 key Diff 的是「兄弟之间会增删换位」——那是 v-for 块**内部**的 children，不是父 block 的 dynamicChildren。

按下标仍会调用 `patch(n1[i], n2[i])`：type 变了照样卸旧挂新。只是省掉在静态兄弟里搜 key。

**Q：patchFlag 有哪些枚举？`FULL_PROPS` 何时出现？**

正数是位标记，可组合；负数是特殊值，不会走 `patchFlag > 0` 的位分支（所以口播里也可以说 HOISTED 不是那种「按位的 patchFlag」）。

| 枚举 | 值 | 何时 |
|------|-----|------|
| TEXT | 1 | `{{ }}` / 动态文本子节点 |
| CLASS | 2 | `:class` |
| STYLE | 4 | `:style` |
| PROPS | 8 | `:id` 这类**属性名编译期已知** |
| FULL_PROPS | 16 | 属性名运行时才知道 |
| NEED_HYDRATION | 32 | 带事件，hydration 要用 |
| STABLE_FRAGMENT | 64 | 子节点顺序稳定的 Fragment |
| KEYED_FRAGMENT | 128 | 带 key 的 `v-for` |
| UNKEYED_FRAGMENT | 256 | 无 key 的 Fragment |
| NEED_PATCH | 512 | 本身几乎静态但有 ref/指令，还要走 patch |
| DYNAMIC_SLOTS | 1024 | 动态插槽名 / `v-for` 插槽 |
| HOISTED | -1 | 静态提升 |
| BAIL | -2 | 放弃优化，全量比 |

`FULL_PROPS`：`v-bind="obj"`（对象展开，key 集合未知）、`:['id']="x"` / 动态参数 `:[foo]`。编译器没法生成固定的 `dynamicProps` 数组，只能每次把新旧 props 做完整 diff。

**Q：静态提升会提升什么？什么不能提？**

能提：不含任何绑定的元素整棵子树、静态文本、静态 props 对象（`_hoisted_2 = { class: 'x' }`）。放到 `render` 外面只创建一次。大段静态 HTML 还可能变成 `createStaticVNode`，客户端直接 `innerHTML`。

不能提到模块级：插值、`:class`/`:style`/动态属性、`ref`、自定义指令、依赖作用域的 slot、要每次 new 实例的组件。`v-for` 里的纯静态子节点可以提升，但运行时会 `cloneIfMounted`，避免多个 li 共用同一个 `vnode.el`。

事件不是提升 vnode，而是 `_cache` 缓存函数引用，避免被当成动态 PROPS。

**Q：`v-for` 为什么必须单独开 block，不能摊进父级 dynamicChildren？**

父级 dynamicChildren **按下标死对齐、长度固定**。列表长度、顺序一变，父数组就会忽长忽短，项和模板槽对不上。

所以 `v-for` 自己是一个 `KEYED_FRAGMENT` block：父级只有「整表」这一个动态子节点；表内部 children 走快速 Diff（有 key）或就地复用（无 key）。嵌套 block 把「结构不稳定」关在块内，外面的下标优化才能成立。

**Q：block tree 和虚拟 DOM Diff 什么关系？有了 block 是不是不用 Diff 了？**

**没有废掉 Diff。** Block 只缩小「要比的集合」：静态兄弟不进 `dynamicChildren`，动态点按下标交给 `patch`。

仍然要 Diff / patch 的场景：

- 每一对 `dynamicChildren[i]` 内部还要 `patchElement`（看 patchFlag 改文本/class）
- `v-for` 块内部照样快速 Diff
- `v-if` 切换等于不同 type，卸旧挂新
- 没有编译信息的 `h()` 仍是全量同层 Diff

关系：**Block 决定比谁；patchFlag 决定比节点的哪部分；列表 Diff 决定会变长的那一组怎么对齐。** 三者叠在 vdom 上，不是互相替代。
