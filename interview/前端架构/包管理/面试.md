## 一、npm 高频面试题

1. **npm 安装依赖的过程？**  
   解析 `package.json` → 构建依赖树 → 下载/解压 → 扁平化 hoist → 写入 `node_modules` 和 lock 文件。npm v7+ 使用 Arborist 构建理想树和实际树。
    | 树 | 来源 | 是否可写 | 作用 |
    | --- | --- | --- | --- |
    | Virtual Tree | lock 文件 | 只读 | 提供已知的依赖解析快照 |
    | Ideal Tree | package.json + Virtual Tree + 本次操作 | 可写 | 本次安装的最终目标 |
    | Actual Tree | 磁盘上的 node_modules | 可写 | 当前真实状态 |

2. **package-lock.json 的作用？**  
   锁定依赖版本、下载地址、integrity 哈希，保证团队和 CI 安装结果一致；`npm ci` 强依赖它。

3. **npm ci 和 npm install 的区别？**  
   `npm ci` 是用于 CI/CD 的干净安装命令，它要求锁文件存在且与 package.json 同步，先删除 `node_modules`，再严格按锁文件安装，不修改锁文件，保证依赖安装的可复现性。
   `npm ci` 要求存在 lock 文件，先删除 `node_modules`，严格按 lock 安装，速度快、可复现；`npm install` 会更新 lock，可安装单个包。

4. **`^1.2.3` 和 `~1.2.3` 的区别？**  
   `^` 允许不改变主版本，如 `1.x.x`；`~` 允许不改变次版本，如 `1.2.x`；精确版本则完全固定。

5. **为什么会产生幽灵依赖？**  
   npm/yarn v1 把传递依赖提升到根 `node_modules`，项目代码即使没声明也能 require 到，这就是幽灵依赖。

6. **npm 的扁平化 hoist 策略？**  
   尽量把依赖提升到根目录减少重复；版本冲突时，一个版本提升，其他版本嵌套在依赖自己的 `node_modules` 中。

7. **peerDependencies 是什么？**  
   表示该包期望宿主环境提供的依赖，如 React 插件期望宿主装 React(防止多实例安装)。npm v7+ 默认自动安装 peer 依赖，冲突时报错；v6 只警告。

8. **dependencies、devDependencies、peerDependencies、optionalDependencies 区别？**  
   `dependencies` 运行时依赖；`devDependencies` 开发/构建依赖；`peerDependencies` 宿主提供；`optionalDependencies` 安装失败可忽略。

9.  **npx 的原理？**  
   临时下载并执行包，优先使用本地 `node_modules/.bin`，没有则从远程拉取到缓存执行。pnpm使用`pnpm dlx <pkg> <script>`。

10. **npm run 的生命周期？**  
    执行 `pre<script>` → `<script>` → `post<script>`；npm 会把 `node_modules/.bin` 加入 PATH。

11. **npm link 的原理？**  
    在全局 `node_modules` 创建符号链接，再在项目中 link 到全局包，用于本地调试。缺点是容易污染全局和依赖解析。

12. **npm 缓存机制？**  
    缓存下载的 tarball 和元数据，默认在 `~/.npm`；`npm ci --offline` 可离线安装。

13. **npm workspaces 是什么？**  
    npm v7+ 支持在根 `package.json` 声明 `workspaces`，统一管理子包依赖和脚本。

14. **package-lock.json 冲突怎么处理？**  
    不要手动乱改，通常删除 lock 和 `node_modules` 后重新 install；CI 用 `npm ci` 保证一致。

15. **npm audit 和 overrides 的作用？**  
    `audit` 检查漏洞；`overrides` 强制指定传递依赖版本，解决安全或版本冲突。

## 二、pnpm 高频面试题

1. **pnpm 为什么快、省磁盘？**  
   内容寻址存储 + 硬链接 + 符号链接。相同版本包只在 store 存一份，项目里硬链接到 `.pnpm`，不重复复制。

2. **pnpm 的 node_modules 结构？**  
   根 `node_modules` 只放直接依赖的符号链接；真实包在 `node_modules/.pnpm/<pkg>@<version>/node_modules/<pkg>`；每个包旁边只链接它声明的依赖。

3. **硬链接和符号链接的区别？**  
   硬链接指向同一 inode，共享文件内容，不能跨文件系统；符号链接是路径引用，可跨目录，Node 默认 realpath 解析。

4. **pnpm 如何解决幽灵依赖？**  
   项目根不暴露传递依赖；Node 从真实路径向上查找时，每个包只能看到自己 `package.json` 声明的依赖，未声明就找不到。

5. **`.pnpm` 目录是什么？**  
   pnpm 的虚拟存储目录，存放每个包版本的真实文件和它的依赖链接视图。

6. **pnpm 的 hoist 配置有哪些？**  
   `hoist`、`hoist-pattern`、`public-hoist-pattern`、`shamefully-hoist`。默认 hoist 到 `.pnpm/node_modules`，不是项目根。

7. **`shamefully-hoist=true` 会怎样？**  
   把依赖提升到根 `node_modules`，兼容老项目，但幽灵依赖问题会回来。

8. **pnpm 如何处理 peerDependencies？**  
   默认较严格，会为不同 peer 组合生成不同实例；pnpm v8 默认 `auto-install-peers=true`，但冲突仍会提示。

9. **pnpm-lock.yaml 和 package-lock 的区别？**  
   pnpm lock 记录依赖图、peer 后缀、完整性等，更贴近 pnpm 的隔离布局。

10. **pnpm 的 store 在哪里？跨磁盘会怎样？**  
    默认在 `~/.pnpm-store` 或项目所在盘。硬链接不能跨盘，跨盘时会退化为复制。

11. **pnpm 与 npm/yarn 的核心差异？**  
    npm/yarn v1 扁平化 hoist；pnpm 默认隔离 + 符号链接；yarn Berry 可用 PnP 无 `node_modules`。

12. **`node-linker` 有哪些模式？**  
    `isolated` 默认；`hoisted` 类似 npm；`pnp` 无 `node_modules`。

13. **pnpm patch 和 overrides 怎么用？**  
    `pnpm patch` 修改第三方包并生成补丁；`pnpm.overrides` 强制传递依赖版本。

14. **pnpm 在 CI 中如何缓存？**  
    缓存 pnpm store，而不是整个 `node_modules`；用 `pnpm fetch` + `--offline` 加速。

15. **为什么 pnpm 需要符号链接？**  
    用符号链接构造每个包的“依赖视图”，既共享 store 文件，又实现依赖隔离。

## 三、monorepo 高频面试题

1. **什么是 monorepo？优缺点？**  
    多个包放一个仓库。优点：代码复用、原子提交、统一工具链、重构方便；缺点：仓库大、构建慢、权限和发布复杂。

2. **monorepo 与 multirepo 对比？**  
    monorepo 统一管理但耦合高；multirepo 独立但跨仓协作、版本同步成本高。

3. **常见 monorepo 方案有哪些？**  
    pnpm workspace、yarn workspace、npm workspace、Lerna、Nx、Turborepo、Rush。

4. **pnpm workspace 怎么配置？**  
    根目录 `pnpm-workspace.yaml` 写 `packages: - 'packages/*'`，子包用 `workspace:*` 互相引用。

5. **`workspace:*` 的作用？发布时如何处理？**  
    本地开发链接工作区包；`pnpm publish` 时自动替换为实际版本号。

6. **pnpm --filter 常用语法？**  
    `--filter pkg` 选包；`--filter pkg...` 选包及其依赖；`--filter ...pkg` 选依赖它的包；`-r` 递归所有包。

7. **如何管理 monorepo 版本和发布？**  
    常用 Changesets：`changeset add`、`changeset version`、`changeset publish`；Lerna 也可做 version/publish。

8. **如何做任务编排和缓存？**  
    Turborepo/Nx：定义 pipeline、`dependsOn`、`outputs`，支持本地和远程缓存，只跑受影响包。

9. **如何解决构建顺序和循环依赖？**  
    按依赖图拓扑排序构建；循环依赖通过拆包、事件、依赖注入解决，构建工具会检测。

10. **如何统一依赖版本？**  
    根 `package.json` 用 `overrides`/`resolutions`，pnpm 用 `pnpm.overrides`；配合 lint 检查重复版本。

11. **monorepo 中会有幽灵依赖吗？**  
    会。即使 pnpm，子包也可能通过向上查找访问根 `node_modules` 的依赖。规范做法是每个子包显式声明依赖，避免 `shamefully-hoist`。

12. **如何做增量构建和 CI 优化？**  
    用 Turborepo/Nx 的受影响包检测、远程缓存、并行执行；CI 只构建变更包及其依赖者。

13. **如何共享 TS/ESLint 配置？**  
    建 `packages/tsconfig`、`packages/eslint-config` 等内部包，子包 extends 引用。

14. **monorepo 发布流程？**  
    改代码 → changeset → CI 校验 → version 更新版本和 changelog → publish 到 npm → 打 tag。

15. **monorepo 治理难点？**  
    依赖版本漂移、构建缓存失效、权限控制、发布协调、仓库体积、CI 成本。

## 四、综合对比与场景题

1. **为什么 npm 有幽灵依赖，pnpm 没有？**  
   npm 扁平化提升到根；pnpm 根只暴露直接依赖，传递依赖隔离在 `.pnpm`，按真实路径解析。

2. **pnpm 的符号链接和硬链接分别解决什么？**  
   硬链接共享 store 文件节省磁盘；符号链接构造依赖隔离视图。

3. **如何从 npm/yarn 迁移到 pnpm？**  
   删 `node_modules` 和旧 lock → 装 pnpm → `pnpm import` 或重新 install → 配 `.npmrc` → CI 改缓存和命令。

4. **如何排查幽灵依赖？**  
   删 `node_modules` 重装、用 `pnpm why`、`npm ls`、depcheck、ESLint import/no-extraneous-dependencies。

5. **peerDependencies 冲突怎么解决？**  
   对齐宿主版本、用 overrides、升级插件、pnpm 中检查 peer 实例，必要时 `--strict-peer-dependencies=false`。

6. **锁文件冲突怎么办？**  
   不要手改，基于主分支重新 install 生成；CI 用 frozen lockfile。

7. **npm、pnpm、yarn 怎么选？**  
   新项目/ monorepo 优先 pnpm；老项目兼容选 npm/yarn；追求 PnP 可试 yarn Berry。

8. **如何设计 monorepo 目录？**  
   `apps/` 放应用，`packages/` 放库，`tooling/` 放配置，根放 workspace、CI、changesets。

9. **Turborepo 远程缓存原理？**  
   对任务输入生成哈希，命中缓存直接恢复 `outputs`，团队共享远程缓存减少重复构建。

10. **如何保证 CI 可复现？**  
    提交 lock 文件，用 `pnpm install --frozen-lockfile` 或 `npm ci`，固定 Node 版本，缓存 store。

## 五、面试高频 TOP 关键词

如果时间紧，优先准备这些：

- 幽灵依赖：npm 扁平化 vs pnpm 隔离
- pnpm：硬链接、符号链接、`.pnpm`、store、hoist
- lock 文件：`package-lock.json`、`pnpm-lock.yaml`、`npm ci`
- peerDependencies：npm v6/v7、pnpm 处理
- monorepo：pnpm workspace、`workspace:*`、`--filter`
- 发布：Changesets、Lerna
- 构建缓存：Turborepo、Nx、远程缓存
- 依赖治理：overrides、resolutions、版本统一
- CI：frozen lockfile、store 缓存、增量构建
