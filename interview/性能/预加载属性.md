
## 1. 预加载/资源提示指令对比

| 指令 | 语法示例 | 核心作用 | 优先级/时机 | 典型场景 | 注意事项 |
|---|---|---|---|---|---|
| `preload` | `<link rel="preload" href="font.woff2" as="font" type="font/woff2" crossorigin>` | 提前下载**当前导航关键**资源 | 高，尽早 | 字体、首屏 CSS/JS、LCP 图片、视频海报 | 必须正确设置 `as`；字体需 `crossorigin`；未使用会告警 |
| `modulepreload` | `<link rel="modulepreload" href="/src/main.js">` | 预加载 ES 模块及其依赖，并解析进 module map | 较高 | 现代 ESM 入口、路由模块、Vite 构建产物 | 只对 module 脚本有效；不会执行代码；Vite 会自动注入 |
| `prefetch` | `<link rel="prefetch" href="/next-page.js">` | 浏览器**空闲时**预取未来可能用的资源 | 低，空闲 | 下一个路由、非首屏页面、可能点击的链接 | 不要滥用；跨域需注意缓存与 CORS |
| `preconnect` | `<link rel="preconnect" href="https://cdn.example.com" crossorigin>` | 提前完成 DNS + TCP + TLS 握手 | 中高 | 关键第三方域：CDN、字体、API | 最多用于 4~6 个关键源；跨域带 `crossorigin` |
| `dns-prefetch` | `<link rel="dns-prefetch" href="//cdn.example.com">` | 仅提前 DNS 解析 | 低 | 非关键但可能用到的第三方域 | 开销小、兼容好；常与 `preconnect` 搭配作降级 |
| `fetchpriority` | `<img src="hero.webp" fetchpriority="high">` | 提示资源获取优先级 | 可调高/低 | LCP 图片调高、非关键资源调低 | 取值 `high` / `low` / `auto`；不要全站滥用 |
| `imagesrcset` / `imagesizes` | `<link rel="preload" as="image" imagesrcset="..." imagesizes="...">` | 预加载**响应式图片**，按视口选候选 | 高，配合 preload | 首屏响应式 Hero 图、LCP 图 | 与 `<img srcset/sizes>` 对应；现代浏览器支持 |

## 2. 相关属性/参数对比

| 属性 | 作用 | 可用元素 | 常用取值 | 示例 | 说明 |
|---|---|---|---|---|---|
| `as` | 指定资源类型，影响优先级、CSP、缓存 | `link[rel=preload]` | `script`、`style`、`image`、`font`、`fetch`、`document`、`video`、`audio`、`worker` | `as="font"` | 不写或写错会导致重复下载 |
| `crossorigin` | 跨域请求模式 | `link`、`script`、`img` 等 | `anonymous`、`use-credentials` | `crossorigin="anonymous"` | 字体、跨域 JS/CSS 常需要 |
| `type` | MIME 类型提示 | `link[rel=preload]` | `font/woff2`、`image/webp` 等 | `type="font/woff2"` | 浏览器不支持时可跳过下载 |
| `media` | 条件预加载 | `link[rel=preload]` | 媒体查询 | `media="(max-width: 600px)"` | 只在匹配时预加载 |
| `fetchpriority` | 提示获取优先级 | `img`、`link`、`script`、`iframe` | `high`、`low`、`auto` | `fetchpriority="high"` | LCP 图片可设 `high` |
| `imagesrcset` | 响应式图片候选集 | `link[rel=preload][as=image]` | `url 400w, url 800w` | `imagesrcset="hero-400.webp 400w, hero-800.webp 800w"` | 与 `img srcset` 对应 |
| `imagesizes` | 响应式图片尺寸规则 | `link[rel=preload][as=image]` | 媒体查询 + 长度 | `imagesizes="(max-width: 600px) 400px, 800px"` | 浏览器据此选择候选 |
| `href` | 资源地址 | `link` | URL | `href="/hero.webp"` | 使用 `imagesrcset` 时仍可作 fallback |
| `onload` | 加载后回调 | `link` | JS 表达式 | `onload="this.rel='stylesheet'"` | 常用于 preload 转 stylesheet |

## 3. 选择建议/场景对照

| 目标 | 推荐指令/属性 | 说明 |
|---|---|---|
| 首屏 LCP 图片加速 | `preload as="image"` + `fetchpriority="high"` | 图片在初始 HTML 中不可发现时尤其有效 |
| 响应式 LCP 图片 | `preload as="image"` + `imagesrcset` + `imagesizes` | 按视口提前下载正确候选 |
| 首屏字体 | `preload as="font" type="font/woff2" crossorigin` | 避免字体闪烁，必须 `crossorigin` |
| 首屏 CSS/JS | `preload` 或 `modulepreload` | JS 模块优先 `modulepreload` |
| 下一个路由/页面 | `prefetch` | 浏览器空闲时下载，不阻塞当前页 |
| 关键第三方域 | `preconnect` | 提前握手，适合 CDN、字体、API |
| 非关键第三方域 | `dns-prefetch` | 开销小，可作为 `preconnect` 的降级 |
| 降低非关键资源优先级 | `fetchpriority="low"` | 如首屏下方图片、非关键脚本 |
| 提高关键资源优先级 | `fetchpriority="high"` | 配合 `preload` 或直接用于 `img` |

## 4. 优先级与缓存/时机对比

| 指令 | 优先级 | 执行时机 | 是否解析依赖 | 是否执行 | 典型缓存 |
|---|---|---|---|---|---|
| `preload` | 高 | 当前导航尽早 | 否 | 否 | HTTP 缓存 |
| `modulepreload` | 较高 | 当前导航尽早 | 是 | 否 | module map + HTTP 缓存 |
| `prefetch` | 低 | 浏览器空闲 | 否 | 否 | HTTP 缓存 |
| `preconnect` | 中高 | 尽早 | — | — | 连接池 |
| `dns-prefetch` | 低 | 尽早 | — | — | DNS 缓存 |
| `fetchpriority` | 调整 | 随所在元素 | — | — | — |
| `imagesrcset` | 高 | 随 preload | — | — | HTTP 缓存 |

## 5. 关键注意点

1. **`preload` 要匹配后续真实请求**：`as`、`type`、`crossorigin` 必须一致，否则可能重复下载。  
2. **字体必须 `crossorigin`**：即使同域，字体请求也按 CORS 处理。  
3. **`preconnect` 不宜过多**：一般 4~6 个关键源，过多会争抢连接资源。  
4. **`prefetch` 不要预取过多**：避免占用带宽，影响当前页。  
5. **`fetchpriority` 不要滥用**：只标记真正关键或非关键资源，否则失去提示意义。  
6. **`imagesrcset` 与 `img` 的 `srcset/sizes` 保持一致**：否则预加载的候选可能不是最终使用的图片。  
7. **`modulepreload` 适合 ESM**：传统 script 用 `preload as="script"`。  
8. **Vite 项目**：构建时可用插件自动注入 `modulepreload`、`preload`，路由级预加载可结合动态 `import()` 与 Federation manifest。
