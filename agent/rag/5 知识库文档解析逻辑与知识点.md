# 知识库文档解析逻辑与知识点

对应代码目录：`backend/src/modules/ai/core/parser/`  
Pipeline 入口：`backend/src/modules/ai/ingestion/nodes/parser.node.ts`  
下游消费：ENHANCER → CHUNKER（见 [`3`](./3%20知识库摄取Pipeline节点梳理.md)、[`4`](./4%20知识库Chunk分块策略与实现.md)）

---

## 1. 在摄取链路中的位置

```text
FETCHER（fileBuffer + mimeType）
    → PARSER（按 MIME 选实现 → Block[]）
    → ENHANCER（清洗）
    → CHUNKER（结构感知分块）
```

解析的核心产出不是「纯字符串」，而是 **结构化 `Block[]`**：给结构感知切分提供 heading / 段落 / 表 / 代码等类型信号。MIME 选错或结构抽烂，后面 CHUNKER 再强也救不回来。

| `excel-document.parser.ts` | exceljs 按 sheet → Heading + 窗口 TableBlock |

### 2.1 选择逻辑（Selector）

```text
1. 规范化 MIME（小写、去掉 charset= 等参数、alias 折叠）
2. 若为 application/zip，peek ZIP 条目映射 docx/xlsx/pptx
3. filter: mimeSupported(supportedMimeTypes, mime)
4. sort: getOrder() 升序
5. 取第一个；无匹配 → throw No parser found for mimeType: ...
6. 若 options.maxFileSize > 0 且文件更大 → throw
```

| Parser | MIME | order |
| --- | --- | --- |
| Markdown | `text/markdown`、`text/x-markdown` | 10 |
| HTML | `text/html`、`application/xhtml+xml` | 12 |
| 纯文本 | `text/plain` | 15 |
| PDF | `application/pdf` | 20 |
| DOCX | `application/vnd.openxmlformats-officedocument.wordprocessingml.document` | 30 |
| Excel | `...spreadsheetml.sheet`、`application/vnd.ms-excel` | 40 |

Fetcher：`file-type` 魔数 → ZIP 则 OOXML peek → 扩展名回退；内容与后缀不一致时打告警，仍以内容为准。

### 2.2 ParserNode

| 项 | 说明 |
| --- | --- |
| 输入 | `ctx.get('fileBuffer')`、`ctx.mimeType` |
| 输出 | `ctx.blocks`；`ctx.metadata` 写入 `parser` / `language` / `wordCount` / `pageCount` / 可选 `rawHtml` |
| config | `preserveRaw`（HTML/DOCX 写入 `metadata.rawHtml`）、`maxFileSize`（Selector 拒绝超限）、`tableRowWindow`（Excel 默认 40） |
| 失败 | 缺 buffer/mime → 抛错；无 Parser → Selector 抛错；扫描 PDF → 明确错误 |

## 3. 统一产物：`Block` / `ParsedDocument`

### 3.1 Block 六种类型

| type | 含义 | 谁主要产出 | CHUNKER 行为（回顾） |
| --- | --- | --- | --- |
| `heading` | 标题 + `level` | MD / HTML / DOCX / Excel sheet / PDF（启发式） | 只更新 outline，不产 chunk |
| `paragraph` | 段落 | 全部 | 贪心合并 |
| `list` | 列表 + `items`/`ordered` | MD / HTML / DOCX | 贪心合并 |
| `table` | `headers`/`rows` + Markdown 表字符串 `content` | MD / HTML / DOCX / Excel | **原子** |
| `code` | `language` + 源码 | MD / HTML | **原子** |
| `image` | `src`/`alt` | MD；HTML/DOCX（DOCX 为占位 src，不嵌二进制） | **原子** |

公共字段：`id`、`content`、`outlinePath`、可选 `metadata`。PDF Block 带 `metadata.page`。

`outlinePath`：解析时用栈维护章节路径（heading 按 level 弹栈再 push），写入每个后续块，供检索过滤与切片展示。

### 3.2 `ParsedDocument`

| 字段 | 现状 |
| --- | --- |
| `blocks` | 主产物 |
| `title` | 首 heading / `<title>` / PDF Info.Title / Excel 首 sheet 名 |
| `language` | 启发式：`zh` / `en` / `null`（CJK vs 拉丁占比，未引入 franc） |
| `metadata.parser` | 如 `markdown` / `html-jsdom` / `pdf-parse` / `mammoth-html` / `exceljs` |
| `metadata.pageCount` | 仅 PDF 有 |
| `metadata.wordCount` | CJK 按字、其余按空白分词 |
| `metadata.rawHtml` | `preserveRaw` 时 HTML/DOCX 保留 |

每次 `parseStructured` 使用局部 id 计数器（`md-1` / `pdf-1` …），不再用实例字段跨请求累加。

## 4. 各 Parser 实现要点

### 4.1 Markdown

**库**：`marked.lexer`

| Token | → Block |
| --- | --- |
| `heading` | HeadingBlock，`depth` → `level`，维护 outline 栈 |
| `paragraph` | 纯文本 → Paragraph；内联 `image` 拆成 ImageBlock |
| `code` | CodeBlock + `lang` |
| `list` | ListBlock |
| `table` | TableBlock |
| `blockquote` | 递归抽文本，标记 `metadata.blockquote` |
| `html` | 含 table/标题/列表等则走 htmlToBlocks，否则剥标签为段落 |
| `space` / `hr` | 丢弃 |

`text/plain` **不再**走本 Parser。

### 4.2 PDF（文本层 + 弱结构）

**库**：`pdf-parse` v2（`getText().pages[]`）

```text
按页抽 text → Block.metadata.page = 页码
→ 页内按空行切段
→ 正则：
    ^第[一二三…]+[章节]\s*(.+)$  → heading level 1
    ^(\d+\.\d+)\s+(.+)$         → heading level 2
→ 其余 → paragraph
→ 全文字符过少（约 < max(30, 8×页数)）→ 抛错（疑似扫描件）
```

**能力边界**：无真正版面/字体/目录树；**不产出** table / code / list。双栏、页眉页脚质量差。MinerU 等视觉解析仍为扩展点。

### 4.3 DOCX

```text
mammoth.convertToHtml（图片转为 docx-image: 占位 src，不嵌入 data URI）
→ htmlToBlocks（jsdom）→ heading/list/table/image/paragraph
```

与 HTML Parser 共用 DOM 遍历，表格不再被正则剥掉。

### 4.4 Excel

**库**：`exceljs`

```text
每个 sheet：
  HeadingBlock（sheet 名，level 1）
  第 1 行 → headers，其余 → rows
  有表头且有数据行 → 按 tableRowWindow（默认 40）切多个 TableBlock，表头重复
  否则每行 → ParagraphBlock
```

旧式 `.xls` MIME 已声明，但 `workbook.xlsx.load` 主路径偏 **xlsx**。

### 4.5 HTML / 纯文本

- HTML：jsdom 识别 h1–h6 / p / ul-ol / table / pre / img / blockquote。
- 纯文本：按空行分段为 Paragraph，避免 `#`、`-` 被当成 Markdown。

| 无 `text/html` Parser | `.html` 无法进解析 | **已补** HtmlDocumentParser |

| 无 PPT / 旧 doc / RTF / 图片 OCR | 这些类型仍失败 | 未做（P2/成本项） |

### 5.2 结构保真

| 问题 | 影响 | 状态 |
| --- | --- | --- |
| PDF 只有段落+弱标题 | structure_aware 收益有限 | 仍弱；需 MinerU 等 |
| PDF 无页码进 Block | 难做「第 N 页」引用 | **已补** `metadata.page` |
| DOCX HTML→MD 过简 | 表/图丢失 | **已改** HTML→Block |
| MD 未处理 image | ImageBlock 闲置 | **已补** |
| Excel 整表一个原子块 | 大表超上下文 | **已补** 行窗口 |

### 5.3 选项与质量信号

| 问题 | 影响 | 状态 |
| --- | --- | --- |
| `preserveRaw` / `maxFileSize` 未落地 | 配置无效 | **已落地** |
| `language` 恒 null | 多语种策略用不上 | **已补** 启发式（非 franc） |
| `wordCount` ≈ 字符数 | 统计失真 | **已按字/词修正** |
| idCounter 实例字段 | 跨请求只增 | **已改为每次 parse 局部计数** |
| 扫描版 PDF | 空 blocks 静默入库 | **已检测并抛明确错误**（仍无 OCR） |

### 5.4 与上下游契约

- 解析质量直接限制 CHUNKER；PDF 弱结构时，调 `maxChars` 也只是在切「大段纯文本」。
- ENHANCER 只做空白归一，**不能**补回已丢失的表结构。
- 前端预览读的是原文件；检索用的是解析+分块后的文本——两边不一致时排查要分清链路。

## 6. 需要掌握的文档解析知识点

### 6.1 解析在 RAG 中的角色

```text
字节流 →（版面/格式理解）→ 逻辑结构 →（分块）→ 向量
```

「解析」解决的是 **结构与噪声**，不是 embedding 本身。行业上常把 Parser 分成：

| 层级 | 做什么 | 例子 |
| --- | --- | --- |
| 字节/容器 | 解压 OOXML、读 PDF xref | ZIP peek、`file-type` |
| 文本提取 | 拿到可读字符串 | pdf-parse、mammoth |
| 结构还原 | 标题/表/栏/阅读顺序 | 版面分析、DOM/AST |
| 清洗 | 去页眉页脚、水印、重复 TOC | ENHANCER / Boilerplate |

本仓库：**MD/HTML/DOCX/Excel 偏结构还原；PDF 仍偏「提取 + 弱推断」。**

### 6.2 数字原生 vs 扫描件

| 类型 | 特征 | 常见手段 |
| --- | --- | --- |
| 数字原生 PDF | 有文字对象 | pdf.js / pdf-parse / PyMuPDF 抽文本 |
| 扫描 / 拍照 PDF | 只有图 | OCR（Tesseract、PaddleOCR）或 VLM（MinerU、GPT-4o 等） |
| 混合 | 部分可选中 | 先检测有无文字层，再决定 OCR |

当前策略：没有足够文字层则 **拒绝入库并提示**，避免空库；OCR/MinerU 管线尚未接入。

### 6.3 阅读顺序与版面

双栏、侧注、页眉页脚、脚注：简单「按 y 排序拼行」会把左右栏交错或页眉混入正文。进阶方案：

- **版面分析**（layout）：检测栏、块、阅读顺序（如 Docling、LayoutParser、商业 OCR）
- **结构树**：标题层级、列表嵌套、表单元格合并

本仓库 PDF：**无版面模型**，只按空行分段。

### 6.4 HTML / OOXML 中间表示

常见流水线：

```text
DOCX → HTML（mammoth）→ DOM → Block
HTML → DOM → Block
PDF  →（结构化工具）→ HTML/JSON → Block
```

中间表示越接近 DOM/AST，表和图越好保。本仓库 HTML/DOCX 已走 jsdom；生产若要更强 Markdown 互转仍可用 turndown，但主路径不再依赖剥标签。

### 6.5 MIME 与 Parser 路由（安全/正确性）

- 扩展名、`Content-Type`、魔数三者可不一致；**内容优先**（见文档 3 §2.1.1）。
- OOXML（docx/xlsx）魔数常是 ZIP → peek `word/`、`xl/` 再映射到具体 MIME。
- Parser 路由已 **规范化 MIME**（小写、去参数 `charset=`），并做 alias（`text/x-markdown` ↔ `text/markdown`）。

### 6.6 表格怎么进 RAG

| 策略 | 说明 |
| --- | --- |
| 整表一个 chunk | 小表 OK；CHUNKER 对 table 仍是原子，不二次切 |
| 按行 / 按窗口行 | Excel 已按窗口切 TableBlock，表头重复 |
| 自然语言描述行 | LLM 把行写成句子再向量化，贵但问答友好 |
| 双索引 | 表结构元数据 + 行文本 |

### 6.7 图片与多模态

- 仅存 `src`/`alt`：检索几乎靠 alt。DOCX 图片为占位 src，不把二进制写进 chunk。
- **Caption / OCR**：抽图内文字再进段落。
- **多模态 embedding**：图文同空间（成本高）。

### 6.8 编码与语言

- 文本文件注意 UTF-8 / GBK；错误编码会「全文乱码仍成功 parse」。当前按 UTF-8 解码，未做 GBK 探测。
- `language` 启发式可用于分词/选模型的粗分流；要更高准确率再接 franc / fastText。

### 6.9 可观测与评测

解析质量应用用例集回归，而不只看「不抛错」：

- 标题层级是否正确
- 表行列是否完整
- 页眉是否误入正文
- 与人工 Block 标注的一致性（或下游 recall@k）

PDF 原生 vs MinerU 对比，和 CHUNKER 的 BlockAware vs fixed_size 对比，同属简历级量化证据。

### 6.10 扩展 Parser 的工程模式（本仓库已具备）

1. 实现 `DocumentParser`（`supportedMimeTypes` / `getOrder` / `parseStructured`）
2. 在 `ParserModule` 的 `providers` + `DOCUMENT_PARSER` factory `inject` 列表注册
3. 保证 Fetcher MIME（含魔数映射）与 `supportedMimeTypes` **规范化后一致**

这是标准的 **策略 + 多实现注入**，与 Embedding/LLM Client 路由同构。

## 9. 一句话总结

本仓库解析层是 **「MIME 策略路由 + 六实现」**：Markdown / HTML / DOCX / Excel 能保住标题、列表和表格；PDF 仍是抽文本 + 弱标题，但会带页码并拒绝扫描件空库。RAG 效果瓶颈经常在 **解析保真与 MIME 路由**；PPT/旧 doc/OCR/MinerU 仍是下一档成本项。
